# 上下文管理与 Token 优化

> 阶段：系统设计 | 状态：定稿 | 说明：对话压缩、Token 预算、优先级槽

> :warning: System Prompt 注入机制在详细设计阶段已从简单的 ContextSlot（Pinned/Regular/Ephemeral）
> 升级为 **8 槽位确定性注入**架构（Slot[1]~Slot[8]），其中 Slot[4] 用于 L2 语义记忆注入。
> 最新设计见 [03-Persona与SystemPrompt注入设计](../../04-详细设计阶段/03-记忆与上下文/03-Persona与SystemPrompt注入设计.md)。
> 上下文压缩算法详见 [02-上下文压缩算法设计](../../04-详细设计阶段/03-记忆与上下文/02-上下文压缩算法设计.md)。

## 概述

大型语言模型的上下文窗口是有限的资源。当对话轮次增多、工具调用结果不断追加时，上下文很快会触及上限。本文档描述 Astro Agent 的三个核心机制：**对话压缩**、**Token 预算**、**上下文优先级**，确保长对话仍能高效运行。

---

## 1. 上下文压缩（三级级联策略）

> **架构决策**：采用三级阈值自动升级的级联压缩策略，替代原有的单一阈值+策略选择模式。完整算法详见 `51-上下文压缩算法设计.md`。

```rust
pub struct ContextManager {
    model_window: u32,
    budget: TokenBudget,  // 自适应槽位分配（按模型窗口大小调整）
}

impl ContextManager {
    pub fn compression_level(&self, used_tokens: u32) -> CompressionLevel {
        let ratio = used_tokens as f32 / self.model_window as f32;
        if ratio >= 0.95 { CompressionLevel::Emergency }
        else if ratio >= 0.85 { CompressionLevel::Summary }
        else if ratio >= 0.75 { CompressionLevel::Light }
        else { CompressionLevel::None }
    }
}

pub enum CompressionLevel {
    None,       // < 75%: 不压缩
    Light,      // 75-85%: 滑动窗口 + 低分消息移除（保护 tool pair）
    Summary,    // 85-95%: LLM 生成摘要（失败时降级到 Emergency）
    Emergency,  // > 95%: 紧急丢弃（仅保留最近 N 条 + pinned + tool pairs）
}
```

> **关键保护**：所有级别的压缩都执行 `enforce_tool_pairs()`，保证 tool_call/tool_result 配对不被拆散。
>
> **注意**：`used_tokens` 包含 System Prompt 的全部槽位开销，而非仅对话历史。

## 2. Token 预算

### Token 预算目标

为每个任务分配 Token 配额，防止单次运行消耗过多。子 Agent 和 Skill 各自占用父任务配额，形成树状预算管理。

### 超出预算时的降级策略

| 策略 | 行为 |
| ---- | ---- |
| `block` | 拒绝继续调用，返回错误 |
| `warn` | 记录警告，允许继续（用于非关键任务） |
| `downgrade` | 自动切换到更便宜的模型（如 claude-haiku） |
| `truncate` | 截断输入，仅保留最关键部分 |

### TokenBudget 实现

```rust
// crates/agent-core/src/context/budget.rs

/// Token 预算分配器（上下文窗口各槽位的 token 配额）
#[derive(Debug)]
pub struct TokenBudget {
    pub total: usize,
    pub system_prompt: usize,
    pub tool_definitions: usize,
    pub memory_snapshot: usize,
    pub knowledge_context: usize,
    pub history_reserve: usize,
}

impl TokenBudget {
    pub fn from_model(model_context_window: usize) -> Self {
        let total = model_context_window;
        Self {
            total,
            system_prompt: total * 15 / 100,
            tool_definitions: total * 10 / 100,
            memory_snapshot: total * 10 / 100,
            knowledge_context: total * 10 / 100,
            history_reserve: total * 55 / 100,
        }
    }

    pub fn remaining_for_history(&self) -> usize {
        self.total
            .saturating_sub(self.system_prompt)
            .saturating_sub(self.tool_definitions)
            .saturating_sub(self.memory_snapshot)
            .saturating_sub(self.knowledge_context)
    }
}
```

### 与 BudgetManager（成本预算）的协同

`TokenBudget`（token 数量控制，本文档）和 `BudgetManager`（USD 成本控制，见 08-成本预算控制.md）服务两个不同目标，但在以下场景需要协同：

| 场景 | TokenBudget 职责 | BudgetManager 职责 |
| ---- | ---------------- | ------------------ |
| 上下文窗口即将超限 | 触发压缩策略（滑动窗口/LLM 摘要/紧急丢弃） | 无直接影响 |
| 成本预算超限 | 无直接影响 | 阻止 LLM 调用或降级模型 |
| 模型降级后 | 根据新模型的 context window 重新计算各槽位配额 | 后续 `record_cost` 使用降级模型单价 |

> `TokenBudget` 负责上下文窗口的**槽位分配**（静态），`BudgetManager` 负责 USD 成本的**运行时追踪**（动态）。两者通过 `AgentExecutor` 协同，不直接互相调用。

## 3. 上下文优先级

### ContextSlot 枚举

```rust
// crates/agent-core/src/context/slot.rs

/// 上下文槽位，决定消息在压缩时的保留优先级
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ContextSlot {
    /// 固定槽：始终保留在上下文头部，不被压缩淘汰
    /// 用于：用户偏好、任务目标、系统提示词、关键约束
    Pinned,

    /// 普通槽：正常对话消息，可能被压缩
    /// 用于：普通对话轮次、工具调用结果
    Regular,

    /// 临时槽：最低优先级，优先被淘汰
    /// 用于：调试信息、中间步骤、已完成的工具调用过程
    Ephemeral,
}

/// 带槽位信息的消息
/// content 使用 Vec<ContentPart> 支持多模态内容（文本、图片等），
/// ContentPart 定义见 01-多模态Provider.md
#[derive(Debug, Clone)]
pub struct Message {
    pub role: MessageRole,
    pub content: Vec<ContentPart>,
    pub slot: ContextSlot,
    /// Token 数量（缓存）
    pub token_count: usize,
    /// 创建时间戳
    pub created_at: chrono::DateTime<chrono::Utc>,
}

impl Message {
    pub fn system(content: impl Into<String>, slot: ContextSlot) -> Self {
        Self {
            role: MessageRole::System,
            content: vec![ContentPart::Text { text: content.into() }],
            slot,
            token_count: 0,
            created_at: chrono::Utc::now(),
        }
    }

    /// 基于内容特征计算重要度分（0.0 ~ 1.0）
    /// 仅对文本部分进行关键词匹配；非文本内容（图片等）不影响评分
    pub fn importance_score(&self) -> f32 {
        // 提取所有文本部分拼接后进行关键词匹配
        let text: String = self.content.iter().filter_map(|part| {
            if let ContentPart::Text { text: t } = part { Some(t.as_str()) } else { None }
        }).collect::<Vec<_>>().join("");

        let mut score: f32 = 0.5; // 基础分

        // 关键词加分
        let keywords = ["目标", "结论", "重要", "注意", "错误", "成功", "用户要求"];
        for kw in &keywords {
            if text.contains(kw) {
                score += 0.1;
            }
        }

        // 工具调用结果适度保留
        if text.contains("tool_result") {
            score += 0.05;
        }

        // 越新的消息分越高（最近 5 条内满分）
        score.min(1.0)
    }

    pub fn to_text(&self) -> String {
        let text: String = self.content.iter().filter_map(|part| {
            if let ContentPart::Text { text: t } = part { Some(t.as_str()) } else { None }
        }).collect::<Vec<_>>().join("");
        format!("[{}] {}", self.role, text)
    }
}

#[derive(Debug, Clone)]
pub enum MessageRole {
    System,
    User,
    Assistant,
    Tool,
}

impl std::fmt::Display for MessageRole {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            MessageRole::System => write!(f, "system"),
            MessageRole::User => write!(f, "user"),
            MessageRole::Assistant => write!(f, "assistant"),
            MessageRole::Tool => write!(f, "tool"),
        }
    }
}
```

### 上下文构建器

```rust
// crates/agent-core/src/context/builder.rs

/// 按优先级顺序构建最终发送给 LLM 的消息列表
pub struct ContextBuilder {
    max_tokens: usize,
    messages: Vec<Message>,
}

impl ContextBuilder {
    pub fn new(max_tokens: usize) -> Self {
        Self { max_tokens, messages: vec![] }
    }

    pub fn add(&mut self, msg: Message) {
        self.messages.push(msg);
    }

    /// 构建上下文：Pinned 优先，Regular 次之，Ephemeral 最后
    /// 超出 max_tokens 时从低优先级开始丢弃
    pub fn build(mut self) -> Vec<Message> {
        // 按 Pinned > Regular > Ephemeral 排序，保持各组内时间顺序
        let mut pinned: Vec<Message> = vec![];
        let mut regular: Vec<Message> = vec![];
        let mut ephemeral: Vec<Message> = vec![];

        for msg in self.messages.drain(..) {
            match msg.slot {
                ContextSlot::Pinned => pinned.push(msg),
                ContextSlot::Regular => regular.push(msg),
                ContextSlot::Ephemeral => ephemeral.push(msg),
            }
        }

        let mut result = vec![];
        let mut used_tokens = 0usize;

        // 先填充 Pinned（必须保留）
        for msg in &pinned {
            used_tokens += msg.token_count;
            result.push(msg.clone());
        }

        // 再填充 Regular（从最新开始，反向遍历后 reverse）
        let mut temp_regular = vec![];
        for msg in regular.iter().rev() {
            if used_tokens + msg.token_count > self.max_tokens {
                break;
            }
            used_tokens += msg.token_count;
            temp_regular.push(msg.clone());
        }
        temp_regular.reverse();
        result.extend(temp_regular);

        // 最后填充 Ephemeral（如果还有剩余空间）
        for msg in ephemeral.iter().rev() {
            if used_tokens + msg.token_count > self.max_tokens {
                break;
            }
            used_tokens += msg.token_count;
            result.push(msg.clone());
        }

        result
    }
}
```

## 4. Pending 消息队列

### 队列目标

Agent 运行期间，用户可能追加新消息（补充需求、中途修改指令）。这些消息不应打断当前执行轮次，而是入队等待，在本轮完成后注入下一轮 context。

> **持久化决策**：Pending 消息仅保存在内存，不写入数据库。Agent 崩溃时队列丢失，用户需重新输入。此决策基于实现简洁性——崩溃概率低，且用户能通过界面感知 Agent 异常终止。

### PendingQueue 实现

```rust
// crates/agent-runtime/src/pending_queue.rs

use std::sync::Arc;
use tokio::sync::Mutex;

pub struct PendingQueue {
    messages: Arc<Mutex<Vec<PendingMessage>>>,
}

#[derive(Debug, Clone)]
pub struct PendingMessage {
    pub content: String,
    pub attachments: Vec<Attachment>,
    pub enqueued_at: chrono::DateTime<chrono::Utc>,
}

impl PendingQueue {
    pub fn new() -> Self {
        Self { messages: Arc::new(Mutex::new(vec![])) }
    }

    /// 前端追加消息时调用（Agent 运行中）
    pub async fn push(&self, msg: PendingMessage) {
        self.messages.lock().await.push(msg);
    }

    /// 轮次开始时取出所有 pending 消息并清空队列
    pub async fn drain(&self) -> Vec<PendingMessage> {
        std::mem::take(&mut *self.messages.lock().await)
    }
}
```

### AgentRuntime 集成点

```rust
// crates/agent-runtime/src/runtime.rs

impl AgentRuntime {
    pub async fn round_loop(&self) -> Result<()> {
        loop {
            // ① 注入 pending 消息（上一轮结束后用户追加的消息）
            for msg in self.pending_queue.drain().await {
                self.context.add(Message::user(
                    vec![ContentPart::Text { text: msg.content }],
                    ContextSlot::Regular,
                ));
            }

            // ② LLM 调用（含自适应规划指令注入 System Prompt）
            let response = self.llm_call().await?;

            // ③ 工具执行（经 HumanGuard，含 L1/L2/L3 + YOLO 判断）
            self.execute_tools(&response).await?;

            // ④ 无更多工具调用 → 退出，等待下一轮用户输入
            if !response.has_tool_calls() {
                break;
            }
        }
        Ok(())
    }
}
```

### Tauri Command

```rust
// src-tauri/src/commands/agent.rs

/// 用户在 Agent 运行期间追加消息
#[tauri::command]
pub async fn append_pending_message(
    conversation_id: String,
    content: String,
    state: State<'_, AppState>,
) -> Result<(), String> {
    let runtime = state.get_runtime(&conversation_id)
        .ok_or("Agent 未运行")?;
    runtime.pending_queue.push(PendingMessage {
        content,
        attachments: vec![],
        enqueued_at: chrono::Utc::now(),
    }).await;
    Ok(())
}
```

```toml
# config/context.toml

[context]
# 三级级联压缩阈值（自动升级，无需手动选择策略）
light_threshold = 0.75       # 75%: 轻量压缩（滑动窗口 + 低分消息移除）

[context.summary]
```
