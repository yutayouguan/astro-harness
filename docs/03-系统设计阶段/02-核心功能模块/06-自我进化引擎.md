# 自我进化系统

> **版本分期实施**：
>
> - **v0.1**：TaskTrace 记录（简化版）+ 用户反馈 UI（👍👎）+ 进化提案展示（仅展示，不自动执行）
> - **v0.2**：批量轨迹分析 + Prompt 版本历史与手动回滚 + 进化预算控制 + 人工审批工作流
> - **v0.3**：Skill 合成（人工审批）+ Eval 门控 + 自动退役 + 上线后监控 + 熔断器
> - **v0.4+**：Prompt 自动优化（DSPy 锦标赛）+ 记忆蒸馏 + 工具生成

## 进化能力全景

```
自我进化引擎
├── 经验采集层       → 记录每次任务的完整轨迹
├── 反思引擎         → 分析成功/失败，提取规律
├── Skill 合成器     → 从经验中创造新 Skill
├── Prompt 优化器    → 自动改进 Prompt 模板（DSPy 风格）
├── 工具生成器       → 动态生成新工具（Rhai/WASM）
├── 记忆蒸馏器       → 情节记忆 → 语义知识
└── 进化调度器       → 控制何时触发进化，防止震荡
```

### 用户反馈采集

每次 Agent 完成任务（`AgentState::Done`）后，在最后一条 AI 回复下方展示反馈入口：

```text
┌─────────────────────────────────────┐
│  AI 回复内容...                       │
├─────────────────────────────────────┤
│  这个回答有帮助吗？  👍  👎  [详细反馈] │
└─────────────────────────────────────┘
```

- **👍 / 👎**：快速反馈，映射到 `user_rating = 1.0 / 0.0`
- **详细反馈**：展开文本框，用户可输入具体改进建议，存入 `TaskMetrics.user_feedback: Option<String>`
- **不打断**：反馈入口在对话底部静默展示，不弹窗，3 秒后自动淡入，不影响继续对话
- **持久化**：反馈写入 `task_traces.user_rating` 和 `task_traces.user_feedback` 字段

> 用户反馈是进化引擎最重要的信号源。`quality_score`（LLM 自评）存在自我评价偏差，`user_rating` 提供真实的外部验证。进化引擎在分析 Pattern 时，优先参考有用户反馈的 TaskTrace。

## Skill 合成器

从成功轨迹中提炼新 Skill，流程：

1. LLM 生成 Skill 定义（manifest）
2. 生成 Skill 的 Prompt 模板
3. 若需要逻辑编排，生成 Rhai 脚本
4. 沙箱验证（用历史轨迹的输入做回放测试）
5. 验证通过后注册到 SkillRegistry

**合成触发条件**：

- 至少 **3 次**相似成功任务
- 沙箱验证通过率 **≥ 70%**
- 用户反馈（如有）平均 ≥ 0.6（排除无反馈的任务）

```rust
pub struct SkillSynthesizer {
    llm: Arc<dyn TextClient>,
    skill_registry: Arc<SkillRegistry>,
    sandbox: Arc<Sandbox>,
}

impl SkillSynthesizer {
    pub async fn synthesize_from_traces(
        &self,
        traces: &[TaskTrace],
        pattern: &LearnedPattern,
    ) -> Result<SynthesizedSkill>;

    // 合并功能相似的 Skill（cos 相似度 > 0.9 则合并）
    pub async fn merge_skills(&self, skills: Vec<String>) -> Result<SynthesizedSkill>;

    // 让已有 Skill 适应新的任务变体
    pub async fn adapt_skill(
        &self,
        skill_name: &str,
        new_examples: &[TaskTrace],
    ) -> Result<SkillPatch>;
}
```

### 合成 Skill 安全扫描

Skill 合成后、注册前，对生成的 SKILL.md 正文执行 `PromptGuard::scan()`：

```rust
let skill_content = synthesizer.synthesize_from_traces(&traces).await?;

// 安全扫描：防止恶意 TaskTrace 数据被固化为 Skill 内容
if let Err(scan_err) = PromptGuard::scan(&skill_content.body) {
    tracing::warn!("合成 Skill 安全扫描失败: {:?}, 拒绝注册", scan_err);
    evolution_log.record(EvolutionAction::SynthesisRejected {
        reason: format!("安全扫描失败: {}", scan_err),
    });
    return Err(EvolutionError::SecurityScanFailed(scan_err));
}
```

> 这防止了攻击者通过精心构造的任务输入，影响 TaskTrace 数据，进而将 Prompt 注入内容固化为 Skill。

## 进化调度器

```rust
pub struct EvolutionConfig {
    pub reflect_after_every_task: bool,
    pub batch_reflect_interval: Duration,
    pub skill_synthesis_threshold: usize,   // N 条相似轨迹后合成新 Skill
    pub prompt_optimize_interval: Duration,

    // 安全护栏
    pub max_skills_per_day: u32,
    pub require_human_approval: Vec<EvolutionKind>,
    pub rollback_on_regression: bool,
    pub min_evidence_count: usize,          // 至少 N 个证据才能进化

    // 进化专属预算（独立于主 Agent token 预算）
    pub max_evolution_tokens_per_day: u64,       // 默认 100,000 tokens/天
    pub max_evolution_cost_per_month_usd: f64,    // 默认 $5/月
    pub require_human_approval: Vec<EvolutionActionKind>, // 默认仅 CreateSkill 需人工审批
}

impl Default for EvolutionConfig {
    fn default() -> Self {
        Self {
            // ... existing defaults ...
            max_evolution_tokens_per_day: 100_000,
            max_evolution_cost_per_month_usd: 5.0,
            require_human_approval: vec![
                EvolutionActionKind::CreateSkill,
            ], // 默认仅 CreateSkill 需人工审批
        }
    }
}
```

> 进化预算与主 Agent 的 BudgetManager 独立计算。进化引擎的 LLM 调用（反思、合成、优化、评估）从进化预算扣减，不影响用户对话的费用上限。

触发时机：
- **即时**：每次任务完成后异步反思（不阻塞主流程）
- **定期**：`batch_reflect_interval` 周期触发深度进化
- **阈值**：相似轨迹达到 `skill_synthesis_threshold` 时触发 Skill 合成

## 护栏设计

| 风险 | 护栏 |
|------|------|
| Skill 无限增殖 | 每日上限 + 相似度去重（cos > 0.9 则合并） |
| 进化方向漂移 | 每次进化与 baseline 对比，回归则自动回滚 |
| 动态代码安全 | Rhai/WASM 沙箱，无系统调用权限 |
| Prompt 过度优化 | 保留版本历史，人工可一键回滚 |
| 高风险进化 | `require_human_approval` 配置名单，暂存待审 |
| 数据污染 | `min_evidence_count` 防止单次异常触发进化 |

### 上线后持续监控

每个进化产物（Skill 版本、Prompt 版本）部署后维护 30 天滑动窗口指标：

```rust
pub struct EvolutionMonitor {
    pool: SqlitePool,
}

impl EvolutionMonitor {
    /// 检查进化产物是否退化（每小时调度）
    pub async fn check_regression(&self) -> Vec<RegressionAlert> {
        let alerts = vec![];
        
        // 查询最近 30 天内上线的进化 Skill
        let evolved_skills = sqlx::query_as::<_, EvolvedSkill>(
            "SELECT s.id, s.name, s.version, el.baseline_score
             FROM skills s JOIN evolution_log el ON s.id = el.target_id
             WHERE el.action = 'deployed' AND el.created_at > ?
             AND s.status = 'ready'"
        )
        .bind(thirty_days_ago_ms())
        .fetch_all(&self.pool).await?;
        
        for skill in evolved_skills {
            // 计算最近 20 次调用的平均 success_rate
            let recent_rate = self.recent_success_rate(&skill.id, 20).await?;
            if recent_rate < skill.baseline_score * 0.9 {
                // 退化超过 10%，触发告警
                alerts.push(RegressionAlert {
                    skill_id: skill.id,
                    skill_name: skill.name,
                    baseline: skill.baseline_score,
                    current: recent_rate,
                    action: if recent_rate < skill.baseline_score * 0.7 {
                        RegressionAction::AutoRollback  // 退化 > 30%，自动回滚
                    } else {
                        RegressionAction::NotifyUser    // 退化 10-30%，通知用户
                    },
                });
            }
        }
        
        alerts
    }
}
```

> 退化检测在 Scheduler 中每小时运行一次。退化超过 30% 自动回滚到上一版本；10-30% 发送通知让用户决定。

### 进化熔断器

当进化产物整体质量持续下降时，自动暂停所有进化活动：

```rust
pub struct EvolutionCircuitBreaker {
    window_hours: u32,          // 监控窗口，默认 24 小时
    min_success_rate: f32,      // 最低平均成功率，默认 0.6
}

impl EvolutionCircuitBreaker {
    pub async fn should_halt(&self, pool: &SqlitePool) -> bool {
        let avg_rate = sqlx::query_scalar::<_, f64>(
            "SELECT AVG(quality_score) FROM task_traces
             WHERE skills_used != '[]'
             AND created_at > ?
             AND quality_score IS NOT NULL"
        )
        .bind(now_ms() - self.window_hours as i64 * 3600 * 1000)
        .fetch_one(pool).await.unwrap_or(1.0);
        
        avg_rate < self.min_success_rate as f64
    }
}
```

调度器每次执行进化前检查熔断器。触发熔断后：

1. 暂停所有自动进化（需人工 `/evolution resume` 恢复）
2. 发送系统通知："进化质量异常，已自动暂停"
3. 记录 evolution_log（action='circuit_break'）

### TaskTrace 数据保留策略

| 数据类型 | 保留期限 | 理由 |
| ---- | ---- | ---- |
| trace_steps.reasoning（CoT） | 30 天 | 含用户交互上下文，隐私风险 |
| trace_steps.input_json/output_json | 90 天 | 进化引擎需要回放验证 |
| task_traces 聚合指标 | 永久 | 质量趋势分析 |
| task_traces.user_feedback | 永久 | 进化决策依据 |

清理由 `ForgetScheduler` 执行（复用记忆系统的定时任务框架）：

```rust
// 每日凌晨执行
pub async fn cleanup_traces(pool: &SqlitePool) {
    // 30 天前的 CoT 推理内容脱敏
    sqlx::query(
        "UPDATE trace_steps SET reasoning = '[已清理]'
         WHERE created_at < ? AND reasoning IS NOT NULL"
    )
    .bind(thirty_days_ago_ms())
    .execute(pool).await?;
    
    // 90 天前的详细输入输出清理
    sqlx::query(
        "UPDATE trace_steps SET input_json = NULL, output_json = NULL
         WHERE created_at < ?"
    )
    .bind(ninety_days_ago_ms())
    .execute(pool).await?;
}
```
