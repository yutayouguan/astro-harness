# 可观测性

> **Harness 定位（2026-09-07）**：观测主键统一为 session/thread id、turn id、submission id、item id 和 tool call id。`EventMsg/TurnItem`、rollout JSONL（权威历史）、`usage.db`（`crates/agent-usage`，per-agent 统计与路由感知成本估算）、hook/tool/sandbox audit 共同实现重放和归因；仅有日志或仅有 token 计数不构成 Harness 可观测性。

> 阶段：系统设计 | 状态：定稿 | 说明：结构化日志、OpenTelemetry、成本追踪

Agent 系统的调试难度远高于普通服务，链路可能跨越多个子 Agent、多次 LLM 调用和多个外部工具。从第一天起就需要完整的可观测性体系。

---

## 三个核心维度

```
可观测性
├── 结构化日志     → 每个操作可检索、可过滤
├── 分布式追踪     → 可视化 Agent 执行链路
└── 成本追踪       → token 消耗和 API 费用统计
```

## 结构化日志

所有日志必须携带关联字段，确保可以从任意一条日志追溯到完整任务链路。

```rust
// crates/agent-core/src/telemetry/logger.rs

// 每个操作的标准字段
pub struct LogContext {
    pub trace_id: Uuid,     // 顶层任务 ID，贯穿整个调用链
    pub span_id: Uuid,      // 当前操作 ID
    pub agent_id: Uuid,
    pub agent_depth: u8,    // 0 = 主 Agent，1+ = 子 Agent
    pub task_summary: String,
}

// 使用示例（tracing 宏）
tracing::info!(
    trace_id  = %ctx.trace_id,
    span_id   = %ctx.span_id,
    agent_id  = %ctx.agent_id,
    depth     = ctx.agent_depth,
    tool      = "web_search",
    duration_ms = elapsed,
    "tool_call_complete"
);
```

关键事件类型及日志级别：

| 事件 | 级别 |
|------|------|
| 任务开始/结束 | INFO |
| Tool/Skill 调用 | DEBUG |
| LLM 请求（含 token 数） | DEBUG |
| 子 Agent 派生 | INFO |
| 进化动作触发 | INFO |
| Provider 降级切换 | WARN |
| 沙箱验证失败 | WARN |
| 任务失败 | ERROR |

## 分布式追踪（OpenTelemetry）

```toml
# Cargo.toml workspace 新增依赖
opentelemetry        = "0.27"
opentelemetry-otlp   = { version = "0.27", features = ["grpc-tonic"] }
tracing-opentelemetry = "0.28"
```

```rust
// crates/agent-core/src/telemetry/tracer.rs

pub fn init_tracer(config: &TelemetryConfig) -> anyhow::Result<()> {
    let exporter = opentelemetry_otlp::new_exporter()
        .tonic()
        .with_endpoint(&config.otlp_endpoint); // 默认 http://localhost:4317

    let tracer = opentelemetry_otlp::new_pipeline()
        .tracing()
        .with_exporter(exporter)
        .with_trace_config(
            opentelemetry_sdk::trace::Config::default()
                .with_resource(Resource::new(vec![
                    KeyValue::new("service.name", "astro-agent"),
                    KeyValue::new("service.version", env!("CARGO_PKG_VERSION")),
                ])),
        )
        .install_batch(opentelemetry_sdk::runtime::Tokio)?;

    tracing_subscriber::registry()
        .with(tracing_opentelemetry::layer().with_tracer(tracer))
        .with(tracing_subscriber::fmt::layer().json()) // 结构化 JSON 日志
        .with(EnvFilter::from_default_env())
        .init();

    Ok(())
}
```

### 日志轮转与保留

```yaml
logging:
  log_dir: "~/.astro/logs/"
  log_format: json
  log_level: info
  rotation:
    strategy: daily            # 按天轮转（每日一个日志文件）
    retention_days: 7          # 保留最近 7 天
    compress_rotated: true     # 旧日志 gzip 压缩
  sensitive_filter:
    redact_api_keys: true      # 自动替换 API Key 为 [REDACTED]
    redact_user_content: false # 默认不过滤用户输入（调试需要）
    max_field_length: 1000     # 截断超长字段
```

### 诊断包导出

用户遇到问题时可通过设置页"导出诊断包"按钮生成 `.astro-diag.zip`：

- `logs/` — 最近 3 个日志文件（已脱敏 API Key）
- `config.yaml`（移除 secrets 引用）
- `agent.db` 的 `schema_version` 和表统计（行数、大小，不含数据）
- 系统信息（OS 版本、Astro 版本、Rust 版本、已安装 MCP Server 列表）

```rust
#[tauri::command]
async fn export_diagnostics(state: State<'_, AppState>) -> Result<PathBuf, AppError> {
    let diag_path = state.data_dir.join("astro-diag.zip");
    // 收集日志 + 配置 + 系统信息 → ZIP
    DiagnosticsExporter::new(&state).export(&diag_path).await?;
    Ok(diag_path)
}
```
