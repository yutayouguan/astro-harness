# 工具系统设计

> **Harness 基线（2026-09-01）**：工具通过 `ToolRegistry -> ResponsesRequest.tools -> StepContext -> ToolRouter` 进入执行闭环，不把工具描述当作 system prompt 正文。当前原生协议包含 Function/Freeform/Namespace/ToolSearch/WebSearch，暴露和权限是两个独立维度。见 [Codex 原生工具协议与 Code Mode](../../04-详细设计阶段/04-工具与扩展生态/05-Codex原生工具协议与CodeMode详细设计.md)。

> 版本：v1.0 | 日期：2026-08-05 | 状态：草稿

---

## 1. 设计目标与原则

### 1.1 统一抽象

内置工具（Rust 实现）、MCP 工具（通过 McpToolBridge 适配）、Skills（高层编排单元）三类工具对上层调用方呈现完全一致的接口。LLM 返回的 `tool_call` 无需区分工具来源，ToolRegistry 负责路由与分发。

### 1.2 安全沙箱

每个工具在定义时必须显式声明所需 `Permission` 集合与 `RiskLevel`。运行时在执行前强制校验当前工作区权限配置，未声明的权限不得访问。高风险工具必须通过 HumanGuard 审批后方可执行。

### 1.3 可观测

每次工具调用生成完整追踪记录，包含调用者、参数摘要、执行耗时、结果状态，统一写入 `audit_logs` 表。慢工具触发告警，异常工具自动上报。

### 1.4 可扩展

用户可通过 Skills 系统（SKILL.md 格式）定义新工具，也可在运行时动态注册新 MCP Server，ToolRegistry 提供标准化注册 API 无需重启应用。

## 2. Tool Trait 完整定义

```rust
use async_trait::async_trait;
use serde::{Deserialize, Serialize};
use serde_json::Value;
use uuid::Uuid;

/// 工具风险等级（与 PRD F-38 L1/L2/L3 对应）
#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
pub enum RiskLevel {
    Low,        // L1：只读 / 无副作用，自动执行，无弹窗
    Medium,     // L2：写文件 / 网络写，弹窗确认，30s 超时自动拒绝
    High,       // L3：Shell 任意命令 / 删除，必须手动确认，无超时
    Critical,   // 极高：进化/自修改，强制任务暂停
}

/// 权限声明枚举（crates/agent-core/src/security/permissions.rs 权威定义）
/// 与 `06-安全边界.md` 和 `11-人工接管与授权详细设计.md` 保持一致
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum Permission {
    // 文件系统
    ReadFile,
    WriteFile,
    DeleteFile,

    // 网络（读写分离，粒度更细）
    NetworkRead,                        // HTTP GET / 只读请求
    NetworkWrite,                       // HTTP POST / PUT / DELETE

    // 代码执行（执行环境明确隔离）
    ExecuteBash,
    ExecuteRhai,
    ExecuteWasm,

    // 环境变量
    ReadEnv,
    WriteEnv,

    // 浏览器自动化
    BrowserControl,

    // Agent 派生
    SpawnAgent,
    SpawnAgentWithTools(Vec<String>),   // 限定子 Agent 可用工具集合

    // 外部服务
    UseMcp(String),                     // 指定 MCP server 名
    UseProvider(String),                // 指定 provider（如 "minimax/speech-2.8-hd"）
}

/// 工具输入
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolInput {
    pub tool_name: String,
    pub parameters: Value,           // 已解析的 JSON 参数
    pub call_id: String,             // LLM 返回的 tool_call id
    pub context: ToolCallContext,    // 调用上下文（会话 id、工作区等）
}

/// 工具调用上下文
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolCallContext {
    pub session_id: String,
    pub workspace_id: String,
    pub agent_id: Uuid,
    pub agent_depth: u8,
    pub turn_index: u32,
}

/// 工具输出内容类型
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ToolContent {
    Text(String),
    Image { data: Vec<u8>, mime_type: String },
    Structured(Value),
    Error(String),
}

/// 工具输出
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolOutput {
    pub call_id: String,
    pub contents: Vec<ToolContent>,
    pub truncated: bool,             // 结果是否被截断
    pub duration_ms: u64,
}

/// 工具错误
#[derive(Debug, thiserror::Error)]
pub enum ToolError {
    #[error("参数验证失败: {field} — {message}")]
    InvalidParameter { field: String, message: String },
    #[error("权限不足: 需要 {0:?}")]
    PermissionDenied(Permission),
    #[error("执行超时（{timeout_ms}ms）")]
    Timeout { timeout_ms: u64 },
    #[error("工具内部错误: {0}")]
    Internal(String),
    #[error("用户拒绝执行")]
    UserRejected,
    #[error("并发冲突: {tool} — {message}")]
    ConcurrencyConflict { tool: String, message: String },
}

/// Tool trait —— 所有工具的统一抽象
#[async_trait]
pub trait Tool: Send + Sync {
    /// 工具唯一名称，如 "file_read"（名词_动词格式）
    fn name(&self) -> &str;

    /// 人类可读描述，直接注入 LLM system prompt
    fn description(&self) -> &str;

    /// JSON Schema（draft-07），描述 parameters 结构
    fn input_schema(&self) -> Value;

    /// 风险等级
    fn risk_level(&self) -> RiskLevel;

    /// 运行所需的最小权限集合
    fn required_permissions(&self) -> Vec<Permission>;

    /// 是否为只读工具（不修改任何外部状态）
    fn is_readonly(&self) -> bool;

    /// 执行超时（毫秒），默认 30_000
    fn timeout_ms(&self) -> u64 { 30_000 }

    /// 核心执行方法
    async fn execute(&self, input: ToolInput) -> Result<ToolOutput, ToolError>;
}
```

## 3. 内置工具清单

**命名规范**：统一采用 `名词_动词` 格式，名词在前按领域聚类，动词在后明确操作意图。

**原子批量原则**：对同类数据的增删改操作，合并为单个工具的 `operations[]` 参数，在一个 SQLite 事务内执行，任一失败则全部回滚。适用分类：`file_edit`、`memory_manage`、`skill_manage`、`knowledge_manage`。

### 文件操作并发安全（乐观锁）

多子 Agent 并发修改同一文件时，采用乐观锁防止静默覆盖：

```rust
/// file_write / file_edit 执行前检查文件是否被其他 Agent 修改
pub async fn file_write_safe(
    path: &Path,
    content: &str,
    expected_hash: Option<String>,  // 上次 file_read 时记录的文件 SHA-256
) -> Result<ToolOutput, ToolError> {
    if let Some(expected) = &expected_hash {
        let current_hash = sha256(&fs::read(path).await.unwrap_or_default());
        if &current_hash != expected {
            return Err(ToolError::ConcurrencyConflict {
                tool: "file_write".into(),
                message: format!(
                    "文件 {} 已被其他 Agent 修改（预期 hash: {}，当前: {}）。请重新 file_read 后重试。",
                    path.display(), &expected[..8], &current_hash[..8]
                ),
            });
        }
    }
    fs::write(path, content).await?;
    Ok(ToolOutput::text("文件写入成功"))
}
```

**工作流程**：

1. `file_read` 返回文件内容时，同时返回 `metadata.content_hash`
2. LLM 后续调用 `file_write` 时，自动附带 `expected_hash` 参数
3. 写入前比较 hash，不匹配则返回 `ConcurrencyConflict` 错误
4. LLM 收到冲突错误后重新 `file_read` 获取最新内容再重试

> **注意**：此机制仅适用于子 Agent 并发场景。单 Agent 串行执行时 `expected_hash` 为 `None`，跳过检查。

## 4. ToolRegistry 设计

```rust
pub struct ToolRegistry {
    builtin: HashMap<String, Arc<dyn Tool>>,
    tools: HashMap<String, Arc<dyn Tool>>,
    priority: HashMap<String, i32>,
    frozen: HashSet<String>,
}

impl ToolRegistry {
    /// 注册内置工具（frozen，不可被外部覆盖）
    pub fn register_builtin(&mut self, tool: Arc<dyn Tool>);

    /// 注册外部工具（MCP / Skills），名称冲突时拒绝注册
    pub fn register(&mut self, tool: Arc<dyn Tool>, priority: i32) -> Result<(), ToolError>;

    /// 按名称查找
    pub fn get(&self, name: &str) -> Option<Arc<dyn Tool>>;

    /// 列出所有工具
    pub fn list_all(&self) -> Vec<ToolMeta>;

    /// 动态更新 MCP 工具（新 MCP Server 连接时调用）
    pub async fn refresh_mcp(&mut self, server_id: &str, tools: Vec<Arc<dyn Tool>>);

    /// 移除指定 MCP Server 的所有工具
    pub fn remove_mcp_server(&mut self, server_id: &str);
}
```

**命名冲突解决**：MCP 工具始终使用命名空间前缀 `mcp__<server_name>__<tool_name>` 注册。若外部工具尝试注册与内置工具同名的条目，注册将被拒绝并返回错误（不再静默添加前缀）。`frozen` 集合中的工具名称不可被覆盖。

## 5. 工具调用完整流程

```
LLM 返回 tool_call
        │
        ▼
┌─────────────────────┐
│  参数 JSON Schema 验证 │  ── 失败 ──▶ 返回 InvalidParameter 错误给 LLM
└─────────────────────┘
        │ 通过
        ▼
┌─────────────────────┐
│   ToolRegistry 路由  │  ── 未找到 ──▶ 返回 ToolNotFound 错误给 LLM
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│  权限检查（工作区配置）│  ── 不足 ──▶ 返回 PermissionDenied
└─────────────────────┘
        │
        ▼
┌─────────────────────┐   risk >= High
│   HumanGuard 审批   │ ◀──────────────── risk_level 判断
└─────────────────────┘
   │ 批准       │ 拒绝
   │           ▼
   │    返回 UserRejected
   ▼
┌─────────────────────┐
│  tool.execute(input) │  ── 超时/异常 ──▶ 包装为 ToolError
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│  结果大小检查与截断  │
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│  写入 audit_logs    │
└─────────────────────┘
        │
        ▼
  ToolOutput 注入对话上下文 → 下一轮 LLM 推理
```

## 6. 参数验证规范

使用 `jsonschema` crate 对 `ToolInput.parameters` 进行 JSON Schema draft-07 验证。

**类型映射**

| JSON Schema 类型 | Rust 类型 |
|-----------------|-----------|
| `string` | `String` |
| `integer` | `i64` |
| `number` | `f64` |
| `boolean` | `bool` |
| `array` | `Vec<Value>` |
| `object` | `HashMap<String, Value>` |
| `null` | `Option<_>` |

**验证失败返回格式**（告知 LLM 具体问题）：

```json
{
  "type": "error",
  "code": "INVALID_PARAMETER",
  "errors": [
    { "field": "path", "message": "必须是字符串类型，收到 integer" },
    { "field": "recursive", "message": "缺少必填参数" }
  ]
}
```

## 7. 执行沙箱与权限模型

### 7.1 工作区权限配置

每个工作区的 `workspace.toml` 中声明允许的权限集合：

```toml
[tool_permissions]
allowed = ["ReadFile", "WriteFile", "NetworkRead", "NetworkWrite"]
# 未列出的权限默认拒绝

[sandbox]
file_root = "/home/user/projects/my-project"  # 文件操作根路径限制
network_whitelist = ["api.github.com", "*.openai.com"]  # 域名白名单
```

### 7.2 沙箱实现

- **路径限制**：`file_read` / `file_write` 等工具在执行前将 `path` 规范化为绝对路径，检查是否在 `file_root` 范围内，超出则返回 `PermissionDenied`。
- **网络域名白名单**：`http_get` / `http_post` 在建立连接前解析目标域名，与白名单匹配；`*` 通配符支持子域名。
- **Rhai 沙箱**：`rhai_exec` 使用 Rhai Engine 的受限模式，禁用文件 I/O 与 FFI，仅开放纯计算能力。

## 8. 工具调用结果规范

### 8.1 大小限制与截断策略

| 内容类型 | 最大大小 | 截断方式 |
|---------|---------|---------|
| Text | 100 KB | 末尾截断 + 提示剩余字节数 |
| Image | 5 MB | 降分辨率后重试；仍超则报错 |
| Structured | 500 KB | 深层字段折叠为 `"..."` |

`ToolOutput.truncated = true` 时，在 `contents` 末尾追加说明文本告知 LLM 结果不完整。

### 8.2 错误结果标准格式

```json
{
  "type": "error",
  "code": "PERMISSION_DENIED",
  "message": "工具 file_write 需要权限 WriteFile，当前工作区未授权",
  "details": { "required": "WriteFile", "workspace_id": "ws-abc123" }
}
```

## 9. 自定义工具开发规范

### 9.1 通过 SKILL.md 定义工具

在 Skills 目录下创建 `SKILL.md`，声明工具元信息：

```markdown
---
name: fetch_weather
description: 查询指定城市的实时天气
risk_level: Low
permissions: [NetworkRead]
is_readonly: true
input_schema:
  type: object
  properties:
    city: { type: string, description: "城市名称（中文或英文）" }
  required: [city]
---
```

### 9.2 Rhai 脚本工具示例

```rhai
// skills/fetch_weather/main.rhai
let city = params["city"];
let url = `https://wttr.in/${city}?format=j1`;
let resp = http_get(url);  // 沙箱内置函数，对应 http_get 工具
resp["current_condition"][0]["temp_C"]
```

### 9.3 发布到 Skills Hub

1. 在本地通过 `astro skill validate` 验证 SKILL.md 格式与 schema 完整性。
2. 运行 `astro skill publish --hub`，CLI 将 skill 打包为 `.astro-skill` 归档并上传到 Hub。
3. Hub 侧自动运行沙箱安全扫描，通过后标记 `verified` 徽章，其他用户可一键安装。

## 10. 可观测性

### 10.1 audit_logs 字段

每次工具调用写入 `audit_logs` 表，包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 调用唯一 ID |
| `session_id` | String | 所属会话 |
| `workspace_id` | String | 所属工作区 |
| `tool_name` | String | 工具名称 |
| `tool_source` | Enum | Builtin / Mcp / Skill |
| `risk_level` | Enum | 风险等级 |
| `params_digest` | String | 参数 SHA256 摘要（不存原始值） |
| `status` | Enum | Success / Failed / Rejected / Timeout |
| `error_code` | String? | 失败时的错误码 |
| `duration_ms` | u64 | 执行耗时 |
| `result_bytes` | u64 | 输出大小 |
| `truncated` | bool | 结果是否被截断 |
| `approved_by` | Enum? | Auto / Human（HumanGuard 审批方式） |
| `created_at` | DateTime | 调用时间 |

### 10.2 慢工具告警

默认阈值：执行耗时超过 **10 秒**的工具调用记录为慢查询，写入 `slow_tool_alerts` 视图；超过 **30 秒**触发 Tauri 桌面通知。可在工作区配置中自定义阈值：

```toml
[observability]
slow_tool_threshold_ms = 10_000
slow_tool_notify_ms = 30_000
```
