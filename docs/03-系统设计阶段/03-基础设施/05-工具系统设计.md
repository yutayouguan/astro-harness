# 工具系统设计

> **当前实现基线（2026-09-07）**：工具系统使用 `ToolEntry + CoreToolRuntime` 双对象注册，以 `ToolRegistry` 为唯一事实源，并为每个模型采样 Step 冻结独立 `ToolRouter`。内置工具、MCP、Workflow/Extension 和 Skills 不得建立旁路执行链。

> 阶段：系统设计 | 状态：当前代码契约

---

## 1. 设计目标

- **统一注册与执行**：元数据和 runtime 使用同一 registered name，统一从 `ToolRegistry::dispatch` 执行。
- **Step 级隔离**：一次模型请求看到的 schema 与可执行路由来自同一不可变快照。
- **原生身份**：保留 Responses `(namespace, name)`，内部键不泄露给模型。
- **披露与授权分离**：Direct/Deferred/Hidden 只决定可见性，不替代 approval、sandbox 或权限检查。
- **失败关闭**：缺失 runtime、未发现 Deferred、非法参数、重复身份或未知 MCP 名均拒绝执行。
- **原生历史**：调用与 matching output 按 `call_id` 写入 `ResponseItem` 和 rollout。

---

## 2. 分层模型

```text
Tool implementation
  -> ToolExecutor / CoreToolRuntime
  -> ToolRegistry { ToolEntry + runtime }
  -> ToolRouter { registry snapshot, routes, model_routes, model_visible_specs }
  -> StepContext
  -> Prompt.tools
  -> ResponsesRequest.tools
  -> ResponseItem tool call/output
```

| 层 | 职责 |
| --- | --- |
| `ToolEntry` | 名称、namespace、schema、toolset、exposure、审批、sandbox 与输出预算元数据 |
| `CoreToolRuntime` | 真实执行能力 |
| `ToolRegistry` | 注册、gate、schema 投影和统一分发 |
| `ToolRouter` | 当前 Step 的原生身份映射与可调用边界 |
| `StepContext` | 冻结 turn、history、prompt context 和 Router |
| Provider adapter | 把 `Prompt.tools` 降低为目标 Responses 请求格式 |

---

## 3. 工具来源

### 3.1 内置工具

`submit_builtin_tool!` 为 inventory 模块生成原生 `ToolExecutor`。`register_all()` 收集 registrar、拒绝重复注册名，并把 `ToolEntry` 与 runtime 一起写入 Registry。

已删除的旧机制：`BuiltinToolHandler`、`LegacyToolAdapter`、全局 handler table 和 `dispatch_tool` 兼容入口。

### 3.2 MCP

`McpHub` 发现健康且启用的 Server 工具后，`attach_mcp_tools()` 通过 `register_mcp_tool_entries()` 为每个工具调用 `register_dynamic()`：

```text
ToolEntrySpec
  -> ToolEntry { namespace, qualified key, approval, output budget }
  + DynamicToolAdapter { McpHub::call_tool }
  -> ToolRegistry
```

Resources/Prompts broker 使用同一动态 runtime 模型。

### 3.3 Skills

Skill 本身不注册为工具；模型调用内置 `skills` runtime 加载 `SKILL.md`。成功 `load/view` 后，`astro_tools` 只 additive 激活已有 toolset，并在下一 Step 重新计算可见性。

### 3.4 Workflow / Extension

动态 Workflow/Extension 工具必须提供 `ToolEntry` 和 `CoreToolRuntime`，遵循同一 Registry、Router、审批与结果链。

---

## 4. 暴露模型

| Exposure | 初始模型可见 | `tool_search` 可发现 | 说明 |
| --- | --- | --- | --- |
| `Direct` | 是 | 是 | 常用工具 |
| `Deferred` | 否 | 是 | 发现后下一 Step 可调用 |
| `Hidden` | 否 | 否 | 仅内部路径 |
| `DirectModelOnly` | 是 | 是 | 不在用户目录展示 |
| `DeferredModelOnly` | 否 | 是 | 模型按需能力 |
| `CodeModeOnly` | 否 | 否 | 仅 Code Mode 下可用 |

当模型不支持原生 `tool_search` 时，只允许 `allow_eager_fallback=true` 的 Deferred 工具进入 eager 投影。完成的 `ToolSearchOutput` 是后续 Step 的持久发现授权。

---

## 5. 命名与路由

```rust
pub enum ToolName {
    Plain(String),
    Namespaced { namespace: String, name: String },
}
```

- 默认 function namespace：`None`、空字符串和 `functions` 等价。
- MCP 模型身份：`(mcp__server, native_name)`。
- MCP 内部执行键：`mcp__server__native_name`。
- Browser、Media、Cron、Workflow 等 namespace 同样由 `ToolRouter` 映射。
- 模型直接输出内部展平键不会命中原生 namespace 路由。

---

## 6. 执行链

```text
capture_step_context
  -> reload tool gates / Workflow / MCP
  -> freeze ExtensionSnapshot and ToolRegistry
  -> build_tool_router
  -> model_visible_specs -> Prompt.tools -> ResponsesRequest.tools
  -> provider ResponseItem call
  -> ToolRouter::build_tool_call
  -> model_can_call / routes_tool
  -> interaction mode / approval / sandbox
  -> PreToolUse
  -> ToolRouter::dispatch -> ToolRegistry::dispatch
  -> CoreToolRuntime::handle
  -> TransformToolResult / PostToolUse / output budget
  -> matching ResponseItem output
  -> rollout + SessionStore
```

`ToolRouter.routes` 是完整执行集合，`model_routes` 是模型顶层可调用子集。Code Mode nested 工具可存在于前者但不能自动进入后者。

---

## 7. MCP 链路

```text
ExtensionSnapshot.mcp_servers
  -> McpHub reload + tools/list
  -> enabled_tool_entries
  -> register_dynamic
  -> Step namespace route
  -> MCP approval
  -> McpHub::call_tool
  -> raw/final output_token_limit
  -> ResponseItem output
```

任何 MCP 条目都必须同时有 metadata 和 runtime。配置或工具列表变化先更新 Hub/Registry，后续 Step 才能看到新路由。

---

## 8. Skill 链路

```text
ExtensionSnapshot.skill_index
  -> prompt name + description
  -> skills(action=load|view)
  -> SKILL.md ToolOutput
  -> astro_tools additive gate
  -> next Step Router
```

只有成功 `load/view` 激活 toolset；`list/curate/manage` 不激活。Skill 不创建 runtime、不提升权限，也不能让 Deferred 工具跳过 `tool_search`。

---

## 9. 安全与结果约束

- `PreToolUse` 可以阻止或修改输入；`TransformToolResult` / `PostToolUse` 处理输出。
- 工具审批与 permission profile、sandbox attempt 分开计算，任何一层都不能扩大上一层权限。
- MCP annotations 只提供风险提示，不是授权。
- MCP `output_token_limit` 在 Hub 原始输出与 Core hook 后结果各应用一次。
- 大结果使用 spill/压缩视图；canonical 历史保持原生调用与输出身份。
