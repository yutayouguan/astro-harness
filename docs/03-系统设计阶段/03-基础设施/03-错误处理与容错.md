# 错误处理与容错策略

> **Harness 基线（2026-08-29）**：错误处理必须保留 Provider、tool、approval、sandbox/network policy、persistence 和 cancellation 的来源语义。Provider fallback 仅在安全的首个可见 chunk 前切换；结构化 policy denial 不得被当作普通 I/O 失败自动提权。

> 阶段：系统设计 | 状态：定稿 | 说明：错误分类、重试退避、Provider 自动切换

> :warning: 本文档的 AgentError 体系在详细设计阶段已拆分并细化。ProviderError 已统一定义于 agent-types crate，
> 最新定义见 [01-agent-providers详细设计](../../04-详细设计阶段/02-Provider与模型层/01-agent-providers详细设计.md)。
> 完整错误处理架构（含 ErrorEvent 持久化、结构化错误码体系）见 [08-错误处理详细设计](../../04-详细设计阶段/06-安全与基础设施/06-错误处理详细设计.md)。

Agent 系统的错误来源远比普通服务复杂：除了常规的网络故障、数据库异常之外，还需要面对 LLM 调用失败、Tool 执行崩溃、子 Agent 异常退出、MCP 协议错误、用户输入非法等多个维度的问题。每一层错误都可能导致整个任务链断裂，因此需要在系统设计层面建立统一的错误分类、传播和恢复机制。

## 错误分类体系

使用 Rust enum 统一表达所有错误类型，避免错误类型碎片化。

```rust
// crates/agent-core/src/error/mod.rs

use thiserror::Error;

#[derive(Debug, Error)]
pub enum AgentError {
    /// LLM 调用失败（网络、超时、模型拒绝）
    #[error("LLM 调用失败: {provider} - {message}")]
    LlmError {
        provider: String,
        message: String,
        #[source]
        source: Option<Box<dyn std::error::Error + Send + Sync>>,
    },

    /// 工具执行失败
    #[error("工具 `{tool_name}` 执行失败: {message}")]
    ToolError {
        tool_name: String,
        message: String,
        retriable: bool,
    },

    /// MCP 协议错误
    #[error("MCP 协议错误: {0}")]
    McpError(#[from] mcp_client::Error),

    /// 任务预算超支
    #[error("预算超支: 已使用 ${used:.4}，预算 ${budget:.4}")]
    BudgetExceeded { used: f64, budget: f64 },

    /// 权限不足
    #[error("权限不足: 操作 `{action}` 需要 `{required_permission}` 权限")]
    PermissionDenied {
        action: String,
        required_permission: String,
    },

    /// 上下文 Token 溢出
    #[error("上下文溢出: 当前 {current_tokens} tokens，最大 {max_tokens} tokens")]
    ContextOverflow {
        current_tokens: usize,
        max_tokens: usize,
    },

    /// 自我进化引擎错误
    #[error("进化引擎错误: {0}")]
    EvolutionError(String),

    /// 子 Agent 崩溃
    #[error("子 Agent `{agent_id}` 崩溃: {message}")]
    SubAgentCrash { agent_id: String, message: String },

    /// 用户输入无效
    #[error("用户输入无效: {0}")]
    InvalidInput(String),

    /// 数据库操作失败
    #[error("数据库错误: {0}")]
    DatabaseError(#[from] sqlx::Error),

    /// 未预期的内部错误（最后兜底）
    #[error("内部错误: {0}")]
    Internal(#[from] anyhow::Error),
}

impl AgentError {
    /// 判断错误是否可以重试
    pub fn is_retriable(&self) -> bool {
        match self {
            AgentError::LlmError { .. } => true,
            AgentError::ToolError { retriable, .. } => *retriable,
            AgentError::McpError(_) => true,
            AgentError::BudgetExceeded { .. } => false,
            AgentError::PermissionDenied { .. } => false,
            AgentError::ContextOverflow { .. } => false,
            AgentError::EvolutionError(_) => false,
            AgentError::SubAgentCrash { .. } => true,
            AgentError::InvalidInput(_) => false,
            AgentError::DatabaseError(_) => false,
            AgentError::Internal(_) => false,
        }
    }

    /// 返回用户友好的错误类型标识
    pub fn error_category(&self) -> &'static str {
        match self {
            AgentError::LlmError { .. } => "model_error",
            AgentError::ToolError { .. } => "tool_error",
            AgentError::McpError(_) => "mcp_error",
            AgentError::BudgetExceeded { .. } => "budget_exceeded",
            AgentError::PermissionDenied { .. } => "permission_denied",
            AgentError::ContextOverflow { .. } => "context_overflow",
            AgentError::EvolutionError(_) => "evolution_error",
            AgentError::SubAgentCrash { .. } => "sub_agent_crash",
            AgentError::InvalidInput(_) => "invalid_input",
            AgentError::DatabaseError(_) => "database_error",
            AgentError::Internal(_) => "internal_error",
        }
    }
}

pub type AgentResult<T> = Result<T, AgentError>;
```

## LLM 调用容错

### 指数退避重试

当 LLM 调用失败且错误可重试时，使用指数退避策略：最多重试 3 次，初始间隔 1 秒，每次翻倍，并加入随机抖动避免雷群效应。

```rust
// crates/agent-core/src/error/retry.rs

use std::time::Duration;
use tokio::time::sleep;
use tracing::{warn, info};
use crate::error::{AgentError, AgentResult};

#[derive(Debug, Clone)]
pub struct RetryConfig {
    pub max_attempts: u32,
    pub initial_interval: Duration,
    pub multiplier: f64,
    pub max_interval: Duration,
    pub jitter_ratio: f32,          // ±比例抖动，如 0.25 表示 ±25%
}

impl Default for RetryConfig {
    fn default() -> Self {
        Self {
            max_attempts: 3,
            initial_interval: Duration::from_secs(1),
            multiplier: 2.0,
            max_interval: Duration::from_secs(30),
            jitter_ratio: 0.25,
        }
    }
}

/// 带指数退避的重试函数
pub async fn retry_with_backoff<F, Fut, T>(
    config: &RetryConfig,
    operation_name: &str,
    mut f: F,
) -> AgentResult<T>
where
    F: FnMut() -> Fut,
    Fut: std::future::Future<Output = AgentResult<T>>,
{
    let mut attempt = 0;
    let mut interval = config.initial_interval;

    loop {
        attempt += 1;
        match f().await {
            Ok(result) => {
                if attempt > 1 {
                    info!(
                        operation = operation_name,
                        attempt,
                        "重试成功"
                    );
                }
                return Ok(result);
            }
            Err(err) if err.is_retriable() && attempt < config.max_attempts => {
                let wait = {
                    let base_ms = interval.as_millis() as f64;
                    let jitter_range = base_ms * config.jitter_ratio as f64;
                    let jitter_ms = (rand::random::<f64>() * 2.0 - 1.0) * jitter_range;
                    Duration::from_millis((base_ms + jitter_ms).max(0.0) as u64)
                };

                warn!(
                    operation = operation_name,
                    attempt,
                    max_attempts = config.max_attempts,
                    wait_ms = wait.as_millis(),
                    error = %err,
                    "操作失败，准备重试"
                );

                sleep(wait).await;

                // 计算下次等待时间
                interval = (interval.mul_f64(config.multiplier)).min(config.max_interval);
            }
            Err(err) => return Err(err),
        }
    }
}
```

### Provider Fallback 链

`model_targets: Vec<ModelTarget>` — primary + 最多 `MAX_MODEL_FALLBACKS`（3）个备用。首个可见 chunk 前失败则自动切换到下一目标。

```text
ModelTarget[0] (primary)
  ├── 连接/认证失败 → ModelTarget[1]
  ├── ModelTarget[1] 失败 → ModelTarget[2]
  └── 全部失败 → 返回错误
```

- `ModelTarget.api_mode` 随链路传播到 `ProviderConfig`，确保探测和聊天走同一协议
- 辅助任务各有独立目标链，缺省回退到 primary
- Provider fallback 仅在安全的首个可见 chunk 前切换；已产生输出后不再切换

### 速率限制处理

当收到 429 响应时，读取 `retry-after` 头部等待指定时间：

```rust
// crates/agent-core/src/error/rate_limit.rs

use std::time::Duration;
use tokio::time::sleep;
use tracing::info;

pub async fn handle_rate_limit(response: &reqwest::Response) -> Duration {
    // 优先读取 retry-after 头部（秒数或 HTTP 日期）
    if let Some(retry_after) = response.headers().get("retry-after") {
        if let Ok(value) = retry_after.to_str() {
            if let Ok(seconds) = value.parse::<u64>() {
                let wait = Duration::from_secs(seconds);
                info!(wait_seconds = seconds, "触发速率限制，等待 retry-after");
                sleep(wait).await;
                return wait;
            }
        }
    }

    // 默认等待 60 秒
    let default_wait = Duration::from_secs(60);
    info!("触发速率限制，使用默认等待时间 60s");
    sleep(default_wait).await;
    default_wait
}
```

## Tool 执行容错

### 超时控制

使用 `tokio::time::timeout` 包裹所有 Tool 调用：

```rust
// crates/agent-core/src/tools/executor.rs

use tokio::time::{timeout, Duration};
use crate::error::{AgentError, AgentResult};

pub struct ToolExecutor {
    timeout: Duration,
}

impl ToolExecutor {
    pub async fn execute(
        &self,
        tool: &dyn Tool,
        input: ToolInput,
    ) -> AgentResult<ToolOutput> {
        let tool_name = tool.name().to_string();

        match timeout(self.timeout, tool.execute(input)).await {
            Ok(Ok(output)) => Ok(output),
            Ok(Err(err)) => Err(AgentError::ToolError {
                tool_name,
                message: err.to_string(),
                retriable: false,
            }),
            Err(_elapsed) => Err(AgentError::ToolError {
                tool_name,
                message: format!("工具执行超时（超过 {}s）", self.timeout.as_secs()),
                retriable: true,
            }),
        }
    }
}
```

### 工具错误处理策略

当工具执行失败时，Agent 按以下优先级决策：

1. **可重试错误**：等待后重试，最多 2 次
2. **不可重试但有替代工具**：切换到功能等价的备用工具
3. **无法恢复**：记录错误，向用户汇报，等待人工介入或任务终止

```rust
pub async fn handle_tool_failure(
    &mut self,
    tool_name: &str,
    error: &AgentError,
    context: &mut AgentContext,
) -> AgentResult<ToolRecoveryAction> {
    match error {
        AgentError::ToolError { retriable: true, .. } => {
            if context.tool_retry_count(tool_name) < 2 {
                context.increment_tool_retry(tool_name);
                Ok(ToolRecoveryAction::Retry)
            } else {
                Ok(ToolRecoveryAction::ReportToUser)
            }
        }
        _ => {
            if let Some(alternative) = self.find_alternative_tool(tool_name) {
                Ok(ToolRecoveryAction::SwitchTool(alternative))
            } else {
                Ok(ToolRecoveryAction::ReportToUser)
            }
        }
    }
}

pub enum ToolRecoveryAction {
    Retry,
    SwitchTool(String),
    ReportToUser,
    Abort,
}
```

## 子 Agent 容错（V2 Agent Threads）

子 Agent（V2 Agent Thread）崩溃不能影响父 Agent 的运行。当前架构使用 `AgentControl` 根级控制器管理线程生命周期：

- **状态隔离**：每个子 Agent Thread 拥有独立 Session、`IterationBudget` 和执行循环
- **RAII 预留**：`AgentSpawnReservation` 在 commit/abort/drop 前保证资源守恒——spawn 失败释放路径和身份预留，turn 退出释放执行槽位
- **状态转移**：`RunnerEvent` 驱动状态投影（`TurnCompleted → Completed`、`TurnErrored → Errored`、`RuntimeTerminated → Shutdown`）
- **运行时句柄**：`RuntimeHandleRegistry` 持有中断/终止回调，`interrupt_agent` 可安全中断目标线程
- **容错保证**：completed/interrupted/errored 线程保持可寻址，可通过 `followup_task` 重新激活
- **资源配额**：`AgentRegistry::Limits`（max_threads=32、max_depth=8、max_running=8）防止资源耗尽

详见 [Subagent 系统设计](../02-核心功能模块/05-Subagent系统设计.md)。

## 错误上下文链

使用 `anyhow::Context` 在每一层调用中附加上下文信息，便于追踪错误来源：

```rust
use anyhow::Context;

// 底层数据库操作
async fn load_task_trace(trace_id: &str) -> anyhow::Result<TaskTrace> {
    sqlx::query_as!(TaskTrace, "SELECT * FROM task_traces WHERE id = ?", trace_id)
        .fetch_one(&pool)
        .await
        .with_context(|| format!("加载 TaskTrace 失败: trace_id={}", trace_id))
}

// 中层 Agent 逻辑
async fn resume_task(trace_id: &str) -> anyhow::Result<()> {
    let trace = load_task_trace(trace_id)
        .await
        .with_context(|| format!("恢复任务失败: trace_id={}", trace_id))?;

    // 错误信息会自动拼接所有上下文层级：
    // "恢复任务失败: trace_id=abc123: 加载 TaskTrace 失败: trace_id=abc123: ..."
    Ok(())
}
```

## 错误恢复策略

当前权威恢复源是 `agent-rollout` append-only 时间线，不是独立 checkpoint row 或最后一条 message 猜测。

```text
恢复流程：
  1. Server 以 rollout snapshot + live boundary 投影
  2. SessionStore 从 rollout 重建为查询/FTS/UI 视图
  3. 断裂的工具调用通过 repair_dangling_tool_calls 修复
  4. V2 Agent Thread 通过 followup_task 重新激活已完成线程
```

恢复核心原则：
- rollout JSONL 是权威历史，SessionStore 是可重建投影
- 恢复只能保持或收窄权限，不得借重启扩权
- `IterationBudget` 和 `TurnState` 不跨进程恢复（安全默认）
