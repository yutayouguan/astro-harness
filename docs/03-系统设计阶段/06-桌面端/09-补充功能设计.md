## 一、F-26 OCR 截图识别

### 1.1 技术方案

采用双引擎策略：
- **在线模式**：调用多模态 LLM 的 Vision 能力（Claude / GPT-4o / Gemini）识别图片文字，复用现有 TextClient trait
- **离线模式**：集成 Tesseract OCR（通过 `tesseract-rs` crate），支持中英文识别

### 1.2 数据流

```text
用户上传图片 / 截取屏幕区域
    ↓
OCR 引擎选择（在线优先，离线降级）
    ↓
在线：构造 Vision 请求（ContentPart::Image + Prompt "提取图中所有文字"）
离线：tesseract-rs 本地识别
    ↓
识别结果 → 填入输入框（可编辑确认）
    ↓
用户确认 → 作为普通文本消息发送
```

### 1.3 截图功能

- macOS：调用 `screencapture -i -c` 系统命令截取屏幕区域到剪贴板
- Windows：调用 `Snipping Tool` API 或 `win32 PrintWindow`
- 快捷键：`Cmd/Ctrl+Shift+O` 触发截图 OCR

### 1.4 Tauri Command

```rust
// apps/desktop/src-tauri/src/commands/ocr.rs

#[tauri::command]
async fn ocr_image(image_path: String, engine: OcrEngine) -> Result<OcrResult, AppError> { ... }

#[tauri::command]
async fn screenshot_ocr() -> Result<OcrResult, AppError> { ... }

pub enum OcrEngine {
    Auto,       // 在线优先，离线降级
    Online,     // 强制在线（Vision API）
    Offline,    // 强制离线（Tesseract）
}

pub struct OcrResult {
    pub text: String,
    pub confidence: Option<f32>,  // 离线模式有置信度
    pub regions: Vec<TextRegion>, // 文字区域坐标（用于表格识别）
}
```

### 1.5 表格识别（P2）

表格识别通过在线 Vision API 实现，Prompt 指定输出格式为 Markdown 表格。离线模式不支持表格识别。

## 三、F-35 多执行后端

### 3.1 架构设计

```rust
// crates/agent-core/src/execution/backend.rs

#[async_trait]
pub trait ExecutionBackend: Send + Sync {
    fn name(&self) -> &str;
    fn backend_type(&self) -> BackendType;
    async fn health_check(&self) -> Result<bool, BackendError>;
    async fn execute(&self, request: ExecRequest) -> Result<ExecResult, BackendError>;
    async fn cancel(&self, execution_id: &str) -> Result<(), BackendError>;
    async fn cleanup(&self) -> Result<(), BackendError>;
}

pub enum BackendType {
    Local,    // 本地进程沙箱（默认）
    Docker,   // Docker 容器
    Ssh,      // SSH 远程执行
}

pub struct ExecRequest {
    pub id: String,
    pub language: Language,
    pub code: String,
    pub timeout_secs: u32,        // 默认 30s
    pub resource_limits: ResourceLimits,
    pub env_vars: HashMap<String, String>,
}

pub struct ResourceLimits {
    pub max_memory_mb: u64,       // 默认 512MB
    pub max_cpu_secs: u64,        // 默认 30s
    pub max_output_bytes: u64,    // 默认 1MB
    pub network_access: bool,     // 默认 false
}
```

### 3.2 Docker 沙箱执行（P1）

```text
ExecRequest 到达
    ↓
DockerBackend::execute()
    ↓
docker run --rm \
  --network none \           # 禁止网络
  --cap-drop ALL \           # 删除所有 Linux capabilities
  --read-only \              # 只读根文件系统
  --memory 512m \            # 内存限制
  --cpus 1 \                 # CPU 限制
  --tmpfs /tmp:size=100m \   # 临时写入区
  -v code.py:/app/code.py:ro \
  astro-sandbox:python3.12 \
  python /app/code.py
    ↓
stdout/stderr 收集 → ExecResult
```

预置镜像：
- `astro-sandbox:python3.12` -- Python 3.12 + numpy/pandas/matplotlib
- `astro-sandbox:node20` -- Node.js 20 LTS
- `astro-sandbox:rust` -- Rust stable

### 3.3 SSH 远程执行（P2）

```rust
// crates/agent-core/src/execution/ssh.rs

pub struct SshConfig {
    pub host: String,
    pub port: u16,               // 默认 22
    pub username: String,
    pub auth: SshAuth,
    pub working_dir: String,     // 远程工作目录
}

pub enum SshAuth {
    Key { private_key_path: String },
    Password { password: String },    // 加密存储
    Agent,                            // SSH Agent 转发
}
```

通过 `russh` crate 建立 SSH 连接，在远程服务器执行代码。

### 3.4 工作区配置

每个工作区可独立选择执行后端：

```yaml
# workspace.yaml
execution:
  backend: docker           # local | docker | ssh
  docker:
    image: astro-sandbox:python3.12
    auto_pull: true
  ssh:
    host: dev-server.local
    username: deploy
    auth: agent
```
