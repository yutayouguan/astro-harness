# Astro Agent 数据迁移策略

> 阶段：系统设计 | 状态：定稿 | 说明：版本化迁移（sqlx）、回滚、SQLCipher

> **当前 Harness 基线（2026-08-29）**：迁移必须按职责数据库分别验证，不能再假定单一 `agent.db`。`agent-home` 是 canonical 路径的唯一 resolver：Session、usage、Agent Graph、artifacts、knowledge 和 Cron 运行库均位于 `{base}/data/`。启动迁移将 SQLite 主库与 `-wal`/`-shm` 作为一组移动；旧库和 canonical 库同时存在时 fail closed，禁止静默覆盖或继续读写双库。

## 一、版本化迁移方案

**schema_migrations 表设计**

> 注：项目实际使用 sqlx 内置的 `_sqlx_migrations` 表管理迁移版本，本节的 `schema_migrations` 表仅作为迁移原理说明，不在实际代码中创建。

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     INTEGER PRIMARY KEY,
    name        TEXT NOT NULL,
    applied_at  TEXT NOT NULL DEFAULT (datetime('now')),
    checksum    TEXT NOT NULL
);
```

**迁移文件命名规范**

迁移文件统一放在 `crates/agent-core/migrations/` 目录，命名格式遵循 sqlx 约定：

```text
{version}_{描述}.sql
示例：
0001_init.sql              # 基础表结构（workspaces/conversations/messages 等）
0002_vec_tables.sql        # sqlite-vec 虚拟表 embeddings
0003_media_artifacts.sql   # media_tasks / ai_artifacts / messages.reasoning_content
0004_memory_versioning.sql # memory_entries：half_life_days/valid_from/valid_to/superseded_by
0005_fts.sql               # FTS5 虚拟表 + 触发器
```

版本号为 4 位递增整数，每次只允许追加，禁止修改已执行迁移的内容。sqlx 通过内置的 `_sqlx_migrations` 表追踪已执行版本，无需手动维护 `schema_migrations` 表。

## 二、迁移执行流程

应用启动时 Rust 层执行如下流程：

1. 确保 `schema_migrations` 表存在（首次启动创建）
2. 读取 `migrations/` 目录下所有迁移文件，按版本号升序排列
3. 查询已执行的最大版本号 `current_version`
4. 依次执行 `version > current_version` 的迁移，每条迁移包裹在独立事务中
5. 每条迁移执行成功后立即写入 `schema_migrations`，记录版本、名称、时间戳与 SQL 的 SHA-256 checksum
6. 任意迁移失败立即回滚当前事务，停止后续迁移，应用拒绝启动并弹出错误提示

## 三、迁移 SQL 模板示例

### 新增列（SQLite ADD COLUMN 不支持带约束的非常量 DEFAULT，须用常量）

```sql
-- 0003_media_artifacts.sql
ALTER TABLE messages ADD COLUMN reasoning_content TEXT;

-- 0004_memory_versioning.sql
ALTER TABLE memory_entries ADD COLUMN half_life_days   INTEGER NOT NULL DEFAULT 30;
ALTER TABLE memory_entries ADD COLUMN valid_from       INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000);
ALTER TABLE memory_entries ADD COLUMN valid_to         INTEGER;
ALTER TABLE memory_entries ADD COLUMN superseded_by    TEXT REFERENCES memory_entries(id);

-- 新增部分唯一索引（替代原 UNIQUE 约束，允许多历史版本）
DROP INDEX IF EXISTS memory_entries_workspace_id_category_key;
CREATE UNIQUE INDEX idx_memory_active_key
    ON memory_entries(workspace_id, category, key) WHERE valid_to IS NULL;
```

### 新增表（0003_media_artifacts.sql）

```sql
CREATE TABLE IF NOT EXISTS media_tasks (
    task_id      TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    modality     TEXT NOT NULL CHECK(modality IN ('asr','image','video','music','lyrics')),
    status       TEXT NOT NULL DEFAULT 'pending',
    progress_pct INTEGER,
    file_paths   TEXT NOT NULL DEFAULT '[]',
    error        TEXT,
    provider     TEXT NOT NULL,
    model        TEXT NOT NULL,
    created_at   INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000),
    finished_at  INTEGER
);

CREATE TABLE IF NOT EXISTS ai_artifacts (
    id              TEXT PRIMARY KEY,
    conversation_id TEXT REFERENCES conversations(id) ON DELETE SET NULL,
    workspace_id    TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    artifact_type   TEXT NOT NULL CHECK(artifact_type IN ('code','report','article','data','other')),
    title           TEXT NOT NULL,
    file_path       TEXT NOT NULL,
    mime_type       TEXT NOT NULL,
    size_bytes      INTEGER NOT NULL DEFAULT 0,
    created_at      INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000)
);
```

### 数据回填（存量记忆条目补 half_life_days）

```sql
-- 按 category 值设置合理默认半衰期
UPDATE memory_entries SET half_life_days = 14  WHERE category = 'daily_event';
UPDATE memory_entries SET half_life_days = 30  WHERE category = 'case_lesson';
UPDATE memory_entries SET half_life_days = 120 WHERE category = 'work_pattern';
```

## 四、回滚策略

**备份时机**：每次迁移开始前，自动将数据库文件复制为 `agent.db.bak-{timestamp}`，保留最近 3 份备份，旧备份自动清理。

**回滚触发条件**：迁移事务失败、checksum 校验不匹配、启动后版本号与二进制内嵌期望版本不一致。

**数据恢复步骤**：
1. 停止应用进程
2. 将 `.bak` 文件覆盖主数据库文件
3. 降级应用版本或修复迁移文件后重启

SQLite 单文件特性使恢复操作简单可靠，无需 dump/restore。

## 五、大表迁移方案

百万行级别迁移禁止直接 `UPDATE table SET ...`，改用分批提交：

```rust
let batch_size = 5000;
loop {
    let affected = conn.execute(
        "UPDATE messages SET processed = 1
         WHERE processed IS NULL LIMIT ?1",
        params![batch_size],
    )?;
    if affected == 0 { break; }
    // 可选：短暂 yield 避免长时间持锁
}
```

结构变更使用"影子表"模式：创建新表 → 分批复制数据 → 原子性重命名（SQLite 支持 `ALTER TABLE RENAME TO`）→ 删除旧表。整个过程仅在最终 rename 时短暂加锁。

## 六、SQLCipher 加密数据库的特殊处理

加密库需在连接建立后、任何 SQL 执行前立即设置密钥：

```rust
conn.execute_batch(&format!("PRAGMA key = '{}';", passphrase))?;
conn.execute_batch("PRAGMA cipher_page_size = 4096;")?;
```

迁移期间若需变更密钥（如用户修改密码），使用 `PRAGMA rekey`，而非重建数据库。备份文件同样为加密格式，备份时需携带相同密钥，切勿明文落盘。

## 七、Rust 实现结构（sqlx）

项目使用 `sqlx` + `sqlx::migrate!` 宏，迁移文件在**编译期内嵌**进二进制，发布包自包含，无需外部文件系统。版本追踪由 sqlx 内置的 `_sqlx_migrations` 表管理，无需手动维护。

```rust
// crates/agent-core/src/storage/mod.rs
use sqlx::sqlite::{SqliteConnectOptions, SqlitePoolOptions, SqliteJournalMode};

pub async fn open(path: &Path) -> anyhow::Result<SqlitePool> {
    let options = SqliteConnectOptions::new()
        .filename(path)
        .create_if_missing(true)
        .journal_mode(SqliteJournalMode::Wal)
        .foreign_keys(true);

    let pool = SqlitePoolOptions::new()
        .max_connections(5)
        .connect_with(options)
        .await?;

    // 编译期内嵌 migrations/ 目录下所有 .sql 文件，按版本号顺序执行
    sqlx::migrate!("./migrations").run(&pool).await?;

    Ok(pool)
}
```

**迁移失败处理**：`sqlx::migrate!` 任意迁移失败时自动回滚当前事务，抛出错误中止启动；已执行迁移的 checksum 若被篡改，sqlx 会在下次启动时检测到并拒绝执行，防止静默数据损坏。

**sqlite-vec 扩展加载**（须在迁移前完成）：

```rust
// sqlite-vec 为 C 扩展，需在连接建立后手动加载
use sqlite_vec::sqlite3_vec_init;
pool.before_acquire(|conn, _| Box::pin(async move {
    unsafe { sqlite3_vec_init(conn.as_raw_handle().as_ptr()); }
    Ok(true)
})).await;
```
