# 前后端数据结构文档

> **Harness 契约（2026-09-04）**：当前执行边界以 `agent-protocol::Op/EventMsg/TurnItem` 和 protobuf Thread RPC 为准；前端 DTO 是投影，不得反向定义 Core 状态机。本文中未与协议类型对应的旧 DTO 仅作历史参考。

> 阶段：系统设计 | 状态：定稿 | 说明：核心 DTO（TS+Rust）、枚举、命名规范

## 零、当前 Thread 契约

- `ThreadSnapshot` 携带 nullable `provider_id`、`backend_id`、`model`、
  `reasoning_effort`。冷 Thread 从最后一条 `ThreadSettingsApplied` 恢复，热 Thread 使用当前
  Session 设置；Desktop 不用本地模型偏好、草稿或布局覆盖快照。
- `AgentMessageItem.questions?: AsyncUserInputQuestion[]` 承载
  `request_user_input_async` 的结构化问题；历史缺失字段可反序列化，但旧工具名不再执行。
- `ChatRequest.persistent_instructions` 只由 Desktop 从 OpenAI 模型目录填充。选择
  `persistent` 时该字段必须非空，Server 会重复验证。
- `UpdateTurnSettingsRequest` 只修改 active turn 下一次 sampling 的 model、reasoning、summary
  与 service tier；返回 `applied | target_unavailable | rejected`。
- `ReconcileExtensionsResponse` 返回 changed extension IDs 与 MCP/Skills/Hooks/toolsets refresh
  flags，新 snapshot 从下一 turn 生效。

## 一、命名规范

Tauri IPC 层统一采用 **camelCase ↔ snake_case 自动转换**策略：

- Rust 端所有 struct 字段使用 `snake_case`，并标注 `#[serde(rename_all = "camelCase")]`，序列化后自动输出 camelCase JSON。
- TypeScript 端所有 interface 字段使用 `camelCase`，与 JSON 键名一一对应，无需手动映射。
- 枚举变体在 Rust 端使用 `PascalCase`，通过 `#[serde(rename_all = "SCREAMING_SNAKE_CASE")]` 序列化为全大写下划线形式，TypeScript 端用字符串字面量联合类型匹配。

## 五、可选字段与必填字段设计原则

- **业务主键、时间戳、状态枚举**：必填，保证数据完整性。
- **关联外键**（如 `workspaceId`）、**衍生数据**（如 `relevanceScore`）、**扩展属性**：设为可选（Rust `Option<T>`，TypeScript `?`），由消费方做空值防御。
- **`metadata` / `extra`** 字段使用无结构 JSON，承载未来扩展，不破坏当前约束。
- 禁止在必填字段中使用空字符串代替 null；前端收到 `undefined` 与 `null` 语义等同，统一处理。

## 六、版本兼容性策略

1. **新增字段**：Rust 端用 `#[serde(default)]` + `Option<T>` 接收旧数据中缺失的字段；TypeScript 端接口新增可选字段，不影响已有消费代码。
2. **废弃字段**：先保留字段并标注 `@deprecated` / Rust 文档注释，至少跨两个 minor 版本后移除，移除前在 Tauri command 层做填充兼容。
3. **枚举扩展**：新增变体时 Rust 端加 `#[serde(other)]` 兜底变体（如 `Unknown`），TypeScript 端联合类型末尾加 `| string`，防止反序列化崩溃。
4. **结构重命名**：通过 `#[serde(alias = "oldName")]` 同时接受新旧字段名，平滑迁移窗口期内两端均可读写。
5. **IPC command 版本号**：命令名采用 `v1_get_conversation` 形式；大版本不兼容时新增命令，旧命令保留至客户端强制更新。
