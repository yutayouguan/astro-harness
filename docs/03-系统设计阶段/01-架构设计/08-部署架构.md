# Astro Agent 部署架构设计文档

> 阶段：系统设计 | 状态：定稿 | 说明：本地部署、多平台打包、自动更新

> **当前 Harness 基线（2026-09-07）**：桌面端默认是 Tauri 内嵌 gRPC backend（`run_embedded()`，随机端口 `127.0.0.1:0`），单实例，系统托盘。数据目录为 `~/.astro/`，配置文件为 `config.toml`（非 config.yaml），多 SQLite DB 分离存储（state.db、artifacts.db、knowledge.db、usage.db、cron\_v1.db、subagents.db）。

## 1. 本地部署模型

Astro Agent 采用单机本地优先架构，三层组件协同运行：

```text
┌───────────────────────────────────────────────────────────────┐
│                        Tauri v2 Shell                         │
│  ┌───────────────┐  ┌────────────────────────────────────┐   │
│  │  React UI     │  │         gRPC 内嵌 Backend          │   │
│  │  (WebView2/   │  │  agent-server::run_embedded()      │   │
│  │   WKWebView)  │  │  随机端口 127.0.0.1:0              │   │
│  └───────┬───────┘  └────────┬───────────────────────────┘   │
│          │ gRPC subscribe     │                               │
│          └───────────────────►│                               │
│                    ┌──────────┴────────┐                     │
│                    │  ~/.astro/ 目录   │                     │
│                    │  多 SQLite DB     │                     │
│                    │  rollout JSONL    │                     │
│                    └──────────────────┘                     │
└──────────────────────────────┬────────────────────────────────┘
                               │ HTTPS（联网时）
           ┌───────────────────┼───────────────────┐
           ▼                   ▼                   ▼
   ┌──────────────┐   ┌──────────────┐   ┌──────────────────┐
   │  Anthropic   │   │  OpenAI /    │   │  Google / MiniMax│
   │  Claude API  │   │  DeepSeek /  │   │  Gemini / Lyria3 │
   │              │   │  兼容厂商    │   │  Veo3.1 / M3 等  │
   └──────────────┘   └──────────────┘   └──────────────────┘
```

**内嵌 gRPC 架构**：Tauri 进程内嵌 `agent-server`（`run_embedded()`），前端通过 gRPC `Thread subscribe` 订阅事件流。5 种 `ApiMode` 路由到对应 Provider（ChatCompletions / Responses / AnthropicMessages / Interactions / GeminiNative）。Provider Fallback 链支持首个 chunk 前自动切换备用目标。所有对话数据与媒体缓存留存本地，API Key 仅存于本机配置，不经过第三方服务器。

## 2. 多平台打包方案

| 平台 | 格式 | 特殊处理 |
| ---- | ---- | -------- |
| Windows | MSI + NSIS | 需内嵌 WebView2 离线引导程序；签名依赖代码签名证书 |
| macOS | DMG + pkg | 须通过 Apple 公证 (notarize)；Universal Binary 兼容 M 系列 |
| Linux | AppImage | 捆绑所有依赖；另提供 .deb/.rpm 给包管理器用户 |

各平台 Ollama 二进制需单独打包：Windows 使用 `.exe`，macOS 使用 arm64/x86_64 fat binary，Linux 使用 ELF 64-bit 可执行文件。打包时通过 `tauri.conf.json` 的 `externalBin` 字段声明 sidecar 路径。

## 3. 自动更新流程

```text
应用启动
  └─► 查询 GitHub Releases API（latest tag）
        └─► 比对本地版本号
              ├─► 无更新 → 继续启动
              └─► 有更新 → 下载 .sig + 安装包
                    └─► Tauri Updater 验证 Ed25519 签名
                          ├─► 签名合法 → 静默安装，重启生效
                          └─► 签名非法 → 丢弃，告警用户
```

私钥离线保存，公钥编译进二进制。GitHub Release Assets 须包含 `latest.json`（含版本号、下载链接、签名摘要），供 Updater 端点解析。

## 4. 数据目录结构

```text
~/.astro/
├── config.toml              # 全局统一配置（agent 设置 + MCP + custom_providers）
├── providers.json           # 前端 Provider 配置状态
├── agents/                  # 全局自定义 agent 定义
│   ├── *.toml               # Agent 定义文件
│   └── {agent_id}/          # Per-agent 数据目录
│       ├── SOUL.md          # Agent 人格
│       ├── MEMORY.md        # 项目记忆（快照）
│       ├── USER.md          # 用户画像（快照）
│       ├── config.json      # AgentRuntimeConfig
│       └── tools_enabled.json  # tool gate 热加载
├── sessions/
│   ├── state.db             # 消息、会话、FTS5（schema v22）
│   ├── artifacts.db         # 文件空间索引
│   └── knowledge.db         # 知识内容 FTS
├── cache/
│   └── models.json          # 模型元数据缓存（API + OpenRouter + TOML 合并）
├── cron/
│   ├── cron_v1.db           # Cron 执行历史
│   └── jobs.json            # Cron job 定义
├── workflows/
│   └── workflows.json       # 工作流定义
├── subagents.db             # V2 Agent 线程图、邮箱、状态事件
├── usage/
│   └── usage.db             # 用量事件 DB
├── logs/                    # 应用日志（按日期滚动）
└── tmp/                     # 临时文件，启动时清空
```

> **注**：旧的 `agent.db` 单数据库已拆分为多个职责独立的 SQLite DB（state.db、artifacts.db、knowledge.db、usage.db、cron\_v1.db、subagents.db），各由对应 crate 管理。配置文件从 YAML 迁移至 TOML（`config.toml`）。rollout JSONL 文件为线程历史的权威事实源。

## 5. Ollama Sidecar 管理

Rust Core 在启动时通过 `tauri::api::process::Command` 以子进程方式拉起 Ollama，并监听 `localhost:11434`。

- **启动**：检测端口是否已占用，已占用则复用（用户自行安装的 Ollama），否则启动内置 sidecar。
- **版本检测**：调用 `GET /api/version` 接口，若版本低于最低要求则提示更新。
- **停止**：应用退出时发送 SIGTERM（Windows 为 `TerminateProcess`），等待 3 秒后强制终止。
- **健康检查**：每 30 秒轮询一次，进程异常退出后自动重启，最多重试 3 次。

## 6. 配置文件分层

```text
环境变量（ANTHROPIC_API_KEY / GOOGLE_API_KEY 等）  ← 最高优先级（CI/开发环境）
  └─► 覆盖：~/.astro/config.toml                    ← 全局统一配置（agent 设置 + MCP + custom_providers）
        └─► 覆盖：<project>/.astro/config.toml       ← 受信任的项目级 agent 设置覆盖
```

配置层级由 `agent-config` crate 管理，使用 `ConfigLayer` + `ConfigLayerSource`（4 级优先级）+ `ConfigKeyPath` 实现逐键 provenance 追溯。

- **`config.toml`**：全局统一配置，包含 agent 设置、MCP 服务器声明、custom\_providers 定义。TOML 自定义 Provider 可零代码接入任何 OpenAI 兼容 API。
- **`providers.json`**：前端 Provider 配置状态（由 UI 维护）。
- **`<project>/.astro/config.toml`**：受信任的项目级覆盖。`.codex` 不作为 Astro 配置输入。
- **`agents/*.toml`** / **`<project>/.astro/agents/`**：自定义 agent 定义，全局和项目级。

## 7. 首次启动流程

```text
1. 检测 ~/.astro/ 是否存在
   └─► 不存在 → 创建目录树，写入默认 config.toml
       同时创建 agents/、sessions/、cache/、cron/、usage/、logs/、tmp/ 目录

2. 初始化各 SQLite 数据库
   └─► SessionStore: sessions/state.db（schema v22，FTS5）
       ArtifactsDb: sessions/artifacts.db
       KnowledgeDb: sessions/knowledge.db
       UsageDb: usage/usage.db
       CronRunDb: cron/cron_v1.db
       SubagentsDb: subagents.db
       各 DB 由对应 crate 独立管理，WAL 模式 + auto-vacuum

3. 启动内嵌 gRPC backend
   └─► agent-server::run_embedded()
       随机端口 127.0.0.1:0，单实例检测

4. API Key 引导（首次启动专属步骤）
   └─► 检测环境变量或配置中是否存在至少一个有效 Key
       ├─► 无 Key → 弹出 Provider 配置向导（至少填写一个）
       └─► 有 Key → 跳过向导，静默验证 Key 有效性（异步，失败仅 Toast 提示）

5. 模型元数据初始化
   └─► 三层合并：API 厂商端点发现 → OpenRouter 模型表 enrich
       → 已知能力补丁（apply_known_capability_overrides）
       持久化到 cache/models.json

6. 渲染主界面（React/Vite），建立 gRPC subscribe 连接
```

整个初始化过程在 Tauri `setup` 钩子中完成，任一步骤失败均写入 `logs/` 并展示可读错误信息；步骤 4 的 Key 验证失败不阻断启动，用户可稍后在 Settings 补填。
