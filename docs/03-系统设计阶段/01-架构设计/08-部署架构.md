# Astro Agent 部署架构设计文档

> 阶段：系统设计 | 状态：定稿 | 说明：本地部署、多平台打包、自动更新

> **当前 Harness 基线（2026-08-29）**：桌面端默认是 Tauri 内嵌 backend；远程 Supervisor、SSH Agent 与容器化执行仅在存在当前可运行源码路径时才可标为已实现。部署层承载 Harness 运行环境，但不替代 Thread/Session/Task 生命周期和 attempt 级沙箱边界。

## 1. 本地部署模型

Astro Agent 采用单机本地优先架构，三层组件协同运行：

```text
┌───────────────────────────────────────────────────────────────┐
│                        Tauri v2 Shell                         │
│  ┌───────────────┐  ┌────────────────────────────────────┐   │
│  │  React UI     │  │            Rust Core               │   │
│  │  (WebView2/   │  │  Commands / Events / AppState      │   │
│  │   WKWebView)  │  └────────┬───────────────────────────┘   │
│  └───────────────┘           │                               │
│                    ┌─────────┴─────────┐                     │
│                    │   SQLite (local)  │                     │
│                    └─────────┬─────────┘                     │
│                              │                               │
│                    ┌─────────┴─────────┐                     │
│                    │  Ollama Sidecar   │  ← 离线本地推理      │
│                    │  (子进程, :11434) │                     │
│                    └───────────────────┘                     │
└──────────────────────────────┬────────────────────────────────┘
                               │ HTTPS（联网时）
           ┌───────────────────┼───────────────────┐
           ▼                   ▼                   ▼
   ┌──────────────┐   ┌──────────────┐   ┌──────────────────┐
   │  Anthropic   │   │  OpenAI /    │   │  Google / MiniMax│
   │  Claude API  │   │  DeepSeek /  │   │  Gemini / Lyria3 │
   │              │   │  兼容厂商    │   │  Veo3.1 / M3 等  │
   └──────────────┘   └──────────────┘   └──────────────────┘
```

**混合架构**：联网时路由至云端 AI Provider（Claude / Gemini / MiniMax 等）；离线时降级到 Ollama 本地推理。Rust Core 通过 Tauri Command 接口与前端通信，同时管理 SQLite 读写和 Ollama 子进程生命周期。所有对话数据与媒体缓存留存本地，API Key 仅存于本机配置，不经过第三方服务器。

## 2. 多平台打包方案

| 平台 | 格式 | 特殊处理 |
| ---- | ---- | -------- |
| Windows | MSI + NSIS | 需内嵌 WebView2 离线引导程序；签名依赖代码签名证书 |
| macOS | DMG + pkg | 须通过 Apple 公证 (notarize)；Universal Binary 兼容 M 系列 |
| Linux | AppImage | 捆绑所有依赖；另提供 .deb/.rpm 给包管理器用户 |

各平台 Ollama 二进制需单独打包：Windows 使用 `.exe`，macOS 使用 arm64/x86_64 fat binary，Linux 使用 ELF 64-bit 可执行文件。打包时通过 `tauri.conf.json` 的 `externalBin` 字段声明 sidecar 路径。

## 3. 自动更新流程

```text
应用启动
  └─► 查询 GitHub Releases API（latest tag）
        └─► 比对本地版本号
              ├─► 无更新 → 继续启动
              └─► 有更新 → 下载 .sig + 安装包
                    └─► Tauri Updater 验证 Ed25519 签名
                          ├─► 签名合法 → 静默安装，重启生效
                          └─► 签名非法 → 丢弃，告警用户
```

私钥离线保存，公钥编译进二进制。GitHub Release Assets 须包含 `latest.json`（含版本号、下载链接、签名摘要），供 Updater 端点解析。

## 4. 数据目录结构

```text
~/.astro/
├── agent.db                 # 全局数据库（单文件，通过 workspace_id 外键实现工作区逻辑隔离）
├── config.yaml              # 全局配置（主题、语言、代理、更新策略）
├── providers.toml           # Provider 路由配置（API Key 引用、模型列表、默认路由、fallback 链）
├── secrets/                 # API Key 加密备份（Keychain 不可用时的降级存储）
│   ├── anthropic.key        # AES-256-GCM 加密，密钥由主密码派生
│   ├── openai.key
│   ├── google.key
│   ├── deepseek.key
│   └── minimax.key
├── workspaces/
│   ├── default/
│   │   ├── workspace.yaml        # 工作区配置（模型偏好、上下文窗口、系统提示词）
│   │   ├── knowledge_base/       # 知识库文档原文 + 向量索引（sqlite-vec）
│   │   │   ├── vectors.db        # 向量存储（六种分块策略产出的 Chunk）
│   │   │   └── documents/        # 原始文档缓存
│   │   ├── media/                # 多媒体生成缓存（按类型分目录，LRU 自动清理）
│   │   │   ├── tts/         # TTS 合成音频（.mp3）
│   │   │   ├── images/      # 生成图像（.png / .jpg）
│   │   │   ├── videos/      # 生成视频（.mp4）
│   │   │   └── music/       # 生成音乐（.mp3）
│   │   ├── files/                # 用户自行管理的文件
│   │   └── ai-docs/              # AI 产物归档根目录（随工作区物理隔离）
│   │       ├── code/        # 代码文件（.py .rs .ts .sh 等）
│   │       ├── reports/     # 报告、分析、总结（.md .pdf 等）
│   │       ├── articles/    # 文章、文案、文档（.md .txt 等）
│   │       ├── data/        # 数据文件（.csv .json .xlsx 等）
│   │       └── other/       # 其他类型
│   └── <uuid>/              # 其他工作区（同结构）
├── models/                  # 本地模型缓存（Ollama 拉取的 GGUF）
├── logs/                    # 应用日志（按日期滚动）
└── tmp/                     # 临时文件（含分享生成的 HTML/ZIP），启动时清空
```

## 5. Ollama Sidecar 管理

Rust Core 在启动时通过 `tauri::api::process::Command` 以子进程方式拉起 Ollama，并监听 `localhost:11434`。

- **启动**：检测端口是否已占用，已占用则复用（用户自行安装的 Ollama），否则启动内置 sidecar。
- **版本检测**：调用 `GET /api/version` 接口，若版本低于最低要求则提示更新。
- **停止**：应用退出时发送 SIGTERM（Windows 为 `TerminateProcess`），等待 3 秒后强制终止。
- **健康检查**：每 30 秒轮询一次，进程异常退出后自动重启，最多重试 3 次。

## 6. 配置文件分层

```text
环境变量（ANTHROPIC_API_KEY / GOOGLE_API_KEY 等）  ← 最高优先级（CI/开发环境）
  └─► 覆盖：系统 Keychain / secrets/<provider>.key   ← 生产用户存储（Keychain 优先，加密文件降级）
        └─► 覆盖：~/.astro/providers.toml            ← Provider 路由 & 模型配置
              └─► 覆盖：~/.astro/config.yaml          ← 全局 UI / 行为配置
                    └─► 覆盖：workspaces/<id>/workspace.yaml  ← 工作区本地偏好
```

- **`config.yaml`**：主题、语言、代理地址、更新通道、日志级别。不含 API Key。
- **`providers.toml`**：对应 `configs/providers.toml` 结构；记录各 Provider 的 base_url、模型列表、默认路由、fallback 链；API Key 通过 `api_key_env` 字段引用环境变量或 secrets/ 路径，**明文 Key 不写入此文件**。
- **`secrets/`**：API Key 的加密文件降级存储；主存储为系统 Keychain（macOS Keychain / Windows Credential Manager / Linux Secret Service），通过 `keyring` crate 读写。当系统 Keychain 不可用时，降级写入 `secrets/<provider_id>.key` 加密文件（AES-256-GCM，密钥由主密码派生）。首次启动引导用户填写，后续可在 Settings > Providers 页面修改。
- **`workspace.yaml`**：仅影响当前工作区的默认模型、系统提示词、上下文窗口大小，不覆盖全局代理和更新策略。

## 7. 首次启动流程

```text
1. 检测 ~/.astro/ 是否存在
   └─► 不存在 → 创建目录树，写入默认 config.yaml 和 providers.toml
       同时创建 secrets/（0700 权限）、logs/、tmp/、models/ 目录

2. 初始化全局数据库 agent.db
   └─► 创建 ~/.astro/agent.db，执行 migrations/ 下所有 .sql 文件，建立表结构
       表：workspaces / conversations / messages / memory_entries / ai_artifacts / skills / task_traces 等
       所有工作区数据通过 workspace_id 外键逻辑隔离于同一数据库文件

3. 创建默认工作区
   └─► 生成 UUID，写入 workspaces/default/workspace.yaml
       同时创建子目录：
       files/ | knowledge_base/{vectors.db, documents/} |
       media/{tts/, images/, videos/, music/} |
       ai-docs/{code/, reports/, articles/, data/, other/}

4. API Key 引导（首次启动专属步骤）
   └─► 检测系统 Keychain 或 secrets/ 下是否存在至少一个有效 Key
       ├─► 无 Key → 弹出 Provider 配置向导（至少填写一个）
       │     展示各 Provider 特性：Claude（推理强）/ Gemini（多媒体）/ MiniMax（国内+音乐）等
       │     Key 优先写入系统 Keychain，Keychain 不可用时降级写入 secrets/ 加密文件
       └─► 有 Key → 跳过向导，静默验证 Key 有效性（异步，失败仅 Toast 提示）

5. 检测网络连通性
   ├─► 联网 → 查询 GitHub Releases，异步预热更新检查
   └─► 离线 → 跳过更新，标记离线模式，优先使用本地 Ollama

6. 启动 Ollama Sidecar（见第 5 节）

7. 渲染主界面，引导用户选择或配置默认模型
```

整个初始化过程在 Tauri `setup` 钩子中完成，UI 侧显示进度条（共 7 步），任一步骤失败均写入 `logs/` 并展示可读错误信息；步骤 4 的 Key 验证失败不阻断启动，用户可稍后在 Settings > Providers 补填。
