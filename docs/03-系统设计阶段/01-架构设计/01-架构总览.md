## 项目定位

Astro Agent 是一个 Rust 实现的 AI Agent 框架，支持：

- 多 Provider、多模态（文本、图像、音频、视频、音乐、嵌入）；Agent 对话只接收 Responses-capable Provider，以原生 `ResponseItem` 保存历史；Chat Completions、Anthropic、Gemini/Interactions 等适配仅服务工具、媒体或其他非 Agent 调用
- MCP 协议（作为 client 接入外部 MCP server，也可暴露为 MCP server）
- Skills 系统（高层能力单元，可编排多个 Tool）
- 子 Agent 派生（树状/图状多 Agent 协作）
- 自我进化（反思、Skill 合成、Prompt 优化、工具生成、记忆蒸馏）
- **自适应规划**：LLM 自判断任务复杂度，预计超过 3 步工具调用或涉及不可逆操作时自动生成执行计划等待用户确认；简单任务直接执行
- **Pending 消息队列**：Agent 运行中用户追加的消息入队，当前轮次完成后注入下一轮 context
- **YOLO 开关**：临时跳过 L2/L3 审批弹窗；费用超限时强制关闭；三个机制正交（自适应规划 ⊥ L1/L2/L3 风险门控 ⊥ YOLO）
- **交互控制面**：在同一 Thread 有序提交 Realtime、MCP elicitation 回复、回合内模型设置、Guardian 精确重试授权与用户 Shell，不绕过 Session 生命周期
- **Realtime 会话**：独立 `agent-realtime` 子系统提供 WebSocket、WebRTC 和 ExistingCall，解析 V2/V3 typed event，并支持 rollout transcript、Codex handoff/BEM 与 V3 sideband reconnect
- Tauri v2 桌面端（React + TypeScript）

```text

│   ├── agent-providers/            # 多厂商 LLM/图像 Provider
```

## 核心能力层次

### 事件管线（单一事实链）

```text
AstroThread::submit(Op)
  → bounded(512) submission channel
  → Session::submission_loop — 有序 Op 分发
  → SessionTask::run_turn — 模型/工具循环
  → EventMsg — Core 单一事件格式
  → rollout policy + JSONL append（权威历史）
  → Core event queue（单 receiver）
  → Server ThreadListener（单 listener per Thread）
  → ThreadHistoryBuilder（活跃 Turn 快照）
  → per-connection bounded(128) queues
  → Tauri ThreadEventsBridge / exec / external Thread clients
```

### 交互控制面

Realtime 和人在回路中的控制不直接改写运行时共享状态，而是通过与普通输入相同的 Thread submission queue 串行化：

```text
React UI / external client
  → Tauri command / gRPC
  → AstroThread::submit(control Op)
  → Session::submission_loop
     ├─ agent-realtime: transport / version / typed event / handoff
     ├─ MCP elicitation broker: resolve one (server, request)
     ├─ TurnContext: atomically update next sampling step
     ├─ GuardianRetryState: authorize one exact retry
     └─ UserShellTask: attach to active turn or start standalone task
  → typed reply and/or EventMsg
  → rollout/live projection according to event persistence policy
```

关键边界：

- Realtime `start` 在 transport-specific readiness 边界后才返回成功：WebSocket 等待 session handshake，WebRTC 等待 call 创建与 SDP answer，ExistingCall 完成参数校验并启动 sideband 生命周期；连接 target/凭据不改写普通文本回合路由。
- WebRTC 使用 unified SDP 创建 call 并通过 call id 打开 server sideband；ExistingCall 只附加 sideband，不重写已存在 call 的 session 配置。
- Realtime V2/V3 是 Astro wire 协议代号，不是模型版本或 OpenAI 产品代际：V2 映射
  OpenAI/Azure GA `/v1/realtime` 事件族；V3 必须显式选择并仅用于 Codex `/live`，其
  frameless sideband 断开后使用有界指数退避重连。
- Realtime 完整 transcript 以 `RolloutItem::RealtimeItem` 持久化；原始 delta 保持 transient，避免冗余重放和音频落盘。
- 每次模型响应后追加 `TokenUsageRecord`，保存 latest/cumulative 与 compaction checkpoint；resume 恢复，fork 清零父 Thread 累计值。
- typed handoff 可启动或 steer 普通 Agent turn，并按 thinking、commentary 或 BEM tags 将输出回传至 Realtime call。
- `ResolveElicitation` 用 `(server_name, request_id)` 定位一个 pending request，且 `accept` / `decline` / `cancel` 不发生语义降级。
- `TurnSettings` 必须命中当前 active turn，整体校验后原子替换设置快照，只影响下一次 sampling。
- `ThreadSettingsApplied` 持久化 provider/backend/model/reasoning；loaded 与 unloaded Thread 都从权威设置恢复，Desktop 不用本地偏好反向覆盖。
- `persistent` reasoning 只在 OpenAI 目录提供非空 `persistent_instructions` 时可选，wire effort 映射为 `disabled`，其他 Provider fail closed。
- `ReconcileExtensions` 只发布下一 turn 的 pending snapshot；当前 turn 继续使用已冻结的 MCP、Skills、Hooks 与 toolsets 视图。
- Guardian 授权与 tool name + arguments 的摘要绑定，且只能消费一次；相同操作的多个授权按 FIFO 独立保留。
- 用户 Shell 是明确的用户操作，不是模型工具；其不进入 Agent sandbox，但纳入 task cancellation 和命令事件时间线。

### 工具执行与延迟加载

```text
LLM 初始上下文
    │
    ▼  schemas_for_api() 仅含 Direct 工具
ToolRouter 工具路由
    │
    ├─ Direct 工具    → 直接可见，正常调用
    ├─ tool_search    → BM25 搜索 Deferred 工具
    │                   → 原生 tool_search_output → 下一 Step 可路由
    ├─ Namespace      → 结构化 (namespace, child) 身份
    ├─ MCP 工具       → namespace=mcp__{server} + name={tool}
    ├─ Skill soft-alias → 自动改写为 skills(action=load)
    └─ 子 Agent 工具   → spawn_agent / send_message 等 V2 工具
```

`ToolRouter.routes` 和 `model_routes` 都以 `ToolName` 为键。模型返回的
`namespace` 和 `name` 在 StepContext 校验、审批、sandbox、hook、handler 分发和
`function_call_output` 回写中始终保持分离；点号形式只用于日志与 UI。

### 子 Agent 系统

```text
AgentControl（根级共享控制器）
    ├─ AgentGraphStore（subagents.db 线程图/邮箱/状态事件）
    ├─ AgentRegistry（RAII 预留/配额）
    └─ ActivityBus（事件等待）

状态：PendingInit → Running → Completed / Interrupted / Errored → Shutdown
```

## 已实现架构概览

- 24 个 Rust crate + 1 个 Tauri 桌面应用
- 15+ LLM 厂商支持（OpenAI、Claude、Google Interactions、DeepSeek、MiniMax、Ollama、Azure 等）
- ToolExposure 五级暴露（Direct/DirectModelOnly/Deferred/DeferredModelOnly/Hidden）+ ToolMode（Direct/CodeMode/CodeModeOnly）+ BM25 工具搜索
- V2 Agent Thread 子 Agent 系统（6 个模型工具）
- 三总线 Hook 系统（Plugin 进程内同步、Gateway 文件扫描外部 manifest、Shell config-map 异步 shell 命令）
- JSONL rollout 权威历史 + SessionStore 投影重建
- Thread 交互控制面（Realtime / Elicitation / TurnSettings / Guardian retry / UserShell）
- Realtime 独立子系统（WebSocket / WebRTC / ExistingCall，V2/V3，rollout transcript，handoff/BEM）
- Extension reconcile（turn 内冻结、下一 turn 激活）+ process-owned MCP event-stream manager 基础
- Durable Thread settings、usage checkpoint 与 gated OpenAI persistent reasoning
- 沙箱权限控制（PermissionProfile）+ 受管网络代理
- 可视化工作流引擎（29 种节点、DAG 执行）
- AG-UI 声明式生成式 UI（22 种组件）

交互操作的任务归属、恢复和安全不变量见 [Agent 生命周期详细设计](../../04-详细设计阶段/01-核心引擎层/07-Agent生命周期详细设计.md)，Realtime 传输与 handoff 契约见 [Realtime 子系统](../../realtime-subsystem.md)，近期对齐记录见 [2026-09-01 生命周期对齐](../../更新说明/2026-09-01-Codex生命周期对齐.md) 与 [2026-09-03 源码对齐](../../更新说明/2026-09-03-Codex源码对齐.md)。
