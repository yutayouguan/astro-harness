# 架构总览

> 阶段：系统设计 | 状态：定稿 | 说明：架构总览、技术栈选型、Monorepo 结构

## 项目定位

Astro Agent 是一个 Rust 实现的 AI Agent 框架，支持：

- 多 Provider、多模态（文本、图像、音频、视频、音乐、嵌入）；支持 Anthropic、OpenAI（Chat Completions + Responses API）、Google Gemini（Interactions API + generateContent API）、DeepSeek（专属客户端，含 reasoning_content 回传）、MiniMax（专属客户端，含 reasoning_split / base_resp 处理）、以及月之暗面等 OpenAI 兼容厂商（配置即接入）
- MCP 协议（作为 client 接入外部 MCP server，也可暴露为 MCP server）
- Skills 系统（高层能力单元，可编排多个 Tool）
- 子 Agent 派生（树状/图状多 Agent 协作）
- 自我进化（反思、Skill 合成、Prompt 优化、工具生成、记忆蒸馏）
- **自适应规划**：LLM 自判断任务复杂度，预计超过 3 步工具调用或涉及不可逆操作时自动生成执行计划等待用户确认；简单任务直接执行
- **Pending 消息队列**：Agent 运行中用户追加的消息入队，当前轮次完成后注入下一轮 context
- **YOLO 开关**：临时跳过 L2/L3 审批弹窗；费用超限时强制关闭；三个机制正交（自适应规划 ⊥ L1/L2/L3 风险门控 ⊥ YOLO）
- Tauri v2 桌面端（React + TypeScript）

```text
├── apps/

│       └── src/                    # 前端 React + TypeScript

├── skills/                         # Skill 定义文件（每个 Skill 一个子目录，含 SKILL.md）
├── prompts/                        # Prompt 模板

├── mcp-servers/                    # 本地 MCP server 配置

├── Cargo.toml                      # workspace root
├── package.json
└── pnpm-workspace.yaml
```

## 核心能力层次

```text
用户请求
    │
    ▼  ① 注入 pending 消息队列（运行中追加的消息）
AgentRuntime::round_loop()
    │
    ▼  ② LLM 调用（含自适应规划指令注入 System Prompt）
LLM Response
    │
    ├─ [LLM 输出含 <agent_plan> 块？]
    │   ├─ YES → 推送 plan_confirmation_required 事件
    │   │         等待用户"确认 / 修改后确认 / 取消"
    │   │         → 确认后继续，取消则终止本轮
    │   └─ NO  → 直接进入工具执行阶段
    │
    ▼  ③ 工具执行（每个工具调用必须经过 HumanGuard）
ToolRegistry.execute_checked()
    │
    ├─ YOLO 开关 ON？ → 跳过 L2/L3 弹窗，直接执行
    ├─ L1（低风险）   → 自动执行
    ├─ L2（中风险）   → 弹窗确认，30s 超时自动拒绝
    ├─ L3（高风险）   → 弹窗确认，无超时，必须手动
    │
    ├─ ToolCall  → ToolRegistry.execute()
    │               ├─ 本地 Tool (builtin)
    │               └─ McpToolBridge → MCP server
    │
    ├─ SkillCall → SkillRegistry.execute()
    │               └─ Skill 内部可再次调用 Tool / 派生子 Agent
    │
    └─ SpawnAgent → Supervisor.spawn()（depth ≤ 3）
                    └─ 子 AgentCore（独立状态，共享 LlmClient）
    │
    ▼  ④ 本轮完成 → 将 pending 消息注入下一轮 context，触发新一轮
```

### 三维控制体系（正交）

| 维度 | 控制目标 | 机制 |
| ---- | -------- | ---- |
| 自适应规划 | 任务复杂度 | LLM 自判断，输出 `<agent_plan>` 触发确认 |
| L1/L2/L3 | 工具风险 | HumanGuard 按风险等级决定是否弹窗 |
| YOLO 开关 | 信任程度 | AtomicBool 临时跳过 L2/L3；费用超限强制关闭 |

## 技术栈

### 后端（Rust）

| 用途 | 库 |
| ---- | --- |
| 异步运行时 | tokio |
| 序列化 | serde + serde_json |
| 错误处理 | anyhow + thiserror |
| 异步 trait | async-trait |
| 链路追踪 | tracing |
| 动态脚本（轻量工具） | Rhai |
| 动态 Skill（复杂逻辑） | WASM (wasmtime) |
| HTTP 客户端 | reqwest |
| 向量存储 | qdrant-client / sqlite-vec |

| 用途 | 库 |
| ---- | --- |
| 桌面框架 | Tauri v2 |
| 前端框架 | React + TypeScript |
| UI 组件 | shadcn/ui + Radix UI |
| 样式 | Tailwind CSS v4 |
| 状态管理 | Zustand |
| 路由 | TanStack Router |
| 构建 | Vite |
| 代码高亮 | Shiki |
| 音频可视化 | wavesurfer.js |
| Markdown | react-markdown + remark-gfm |
| 动画 | Motion (Framer Motion v12) |
