## 二、各 Crate 核心 Trait / Struct

### agent-types（最底层，零依赖纯类型层）

- `Message` / `ContentPart` / `MessageRole` — 统一消息格式
- `Tool` trait / `ToolInput` / `ToolOutput` / `ToolError` / `ToolCall` / `ToolResult` — 原子能力单元接口
- `TextClient` / `EmbeddingClient` / `TtsClient` / `AsrClient` / `ImageClient` / `VideoClient` / `MusicClient` trait — Provider 接口族
- `Skill` trait / `SkillManifest` — 高层能力单元接口
- `MediaContent` / `MediaData` — 多模态内容载体
- `Permission` / `PermissionSet` / `RiskLevel` — 权限模型
- `AgentError` / `ProviderError` / `ToolError` — 统一错误类型
- `CostRecord` — 成本追踪记录
- `TurnContext` struct — 短生命周期每轮上下文（见 AgentSession/TurnContext 拆分说明）

### agent-providers（Provider 实现层，依赖 agent-types）

- `TextClient` trait — 统一文本生成接口，支持流式输出
- `EmbeddingClient` trait — 向量嵌入接口
- `ImageClient / TtsClient / AsrClient / VideoClient / MusicClient` trait — 多模态接口族
- `ProviderRegistry` struct — 运行时 Provider 路由表；按**模型子类型**（对话 / 多媒体 / 嵌入 / 辅助）分组路由，每种子类型维护独立的默认模型配置，运行时动态拉取 `/v1/models` 并支持离线缓存回退
- `MediaContent` enum — 统一多模态内容载体（Text/Image/Audio/Video）

**Provider 实现分层：**

| 实现 | 接口协议 | 覆盖厂商 |
| ---- | -------- | -------- |
| `AnthropicClient` | Anthropic Messages API | Claude 系列 |
| `OpenAIChatClient` | OpenAI Chat Completions API（`POST /v1/chat/completions`） | OpenAI 原生 |
| `OpenAIResponsesClient` | OpenAI Responses API（`POST /v1/responses`，含内置工具/状态管理） | OpenAI 原生 |
| `OpenAICompatClient` | Chat Completions 纯兼容，只做 base URL + API Key 替换，不含任何厂商私有逻辑 | 月之暗面、零一万物、智谱 AI 等格式标准的国内厂商 |
| `DeepSeekClient` | Chat Completions，专属实现；工具调用时自动将 `reasoning_content` 随完整 message 回传（否则 400）；**DeepSeek Responses API 和 Anthropic API 兼容层不使用**（MCP 工具调用静默失效） | DeepSeek 系列 |
| `MiniMaxClient` | **文本**：Chat Completions 专属，始终附 `reasoning_split: true`，用 `max_completion_tokens`，解析 `base_resp` 错误码，M2.x thinking 强制开启；**MiniMax Responses API 不用**（MCP 工具调用静默失效）。**多媒体**（全部为独立专属 endpoint，不走 Chat Completions）：TTS `POST /v1/t2a_v2`（`speech-2.8-hd`，流式/情感标签/字幕/音色设计/声音克隆）、ASR `asr-01`、图像 `POST /v1/image_generation`（`image-01/image-01-live`，含图生图/人物参考/画风）、视频 `video-01`（Task 轮询）、音乐 `POST /v1/music_generation`（`music-3.0`/`music-cover` 翻唱）、歌词生成 `POST /v1/lyrics_generation`、音色设计 `POST /v1/voice_design` | MiniMax-M3（推荐，1M 上下文）、M2.x 系列；多媒体接口独立 |
| `GoogleInteractionsClient` | Google Interactions API（GA，2026-06）；服务端状态管理，无需客户端重传 history；**同时承载 Lyria 3 音乐生成**（`lyria-3-pro-preview` / `lyria-3-clip-preview`，44.1 kHz，支持文本+图片输入） | Gemini 2.5/3 系列对话/Agent，Lyria 3 音乐生成；**默认用于对话 / Agent 多轮 / 工具调用 / 音乐生成** |
| `GoogleGenerateContentClient` | Google generateContent API（旧版，无废弃时间线）；无状态，支持 Batch / 上下文缓存 / 自定义安全设置；**同时承载 Imagen 3 图像生成**（`imagen-3.0-generate-002`）和 **Veo 3.1 视频生成**（`veo-3.1-generate-preview`，8 秒，720p/1080p/4k，含原生音频，LongRunning 轮询） | Gemini 全系列嵌入/RAG，Imagen 3 图像，Veo 3.1 视频；**用于批量嵌入 / RAG / 上下文缓存 / 图像生成 / 视频生成** |

**MiniMaxClient `base_resp.status_code` → 标准错误映射：**

| status_code | 含义 | 映射为 |
| ----------- | ---- | ------ |
| 1002 | 触发限流 | `RateLimit` |
| 1004 | 鉴权失败 | `AuthError` |
| 1008 | 余额不足 | `QuotaExceeded` |
| 1027 | 输出内容过滤 | `ContentFilter` |
| 1039 | Token 超限 | `ContextTooLong` |
| 2013 | 参数错误 | `InvalidRequest` |

`ProviderRegistry` 按模型子类型自动路由：Google 对话/音乐 → `GoogleInteractionsClient`；Google 嵌入/图像/视频 → `GoogleGenerateContentClient`；MiniMax 文本 → `MiniMaxClient`（Chat Completions）；MiniMax 多媒体 → `MiniMaxClient`（各专属 endpoint）。

**思考模式（Thinking Mode）——跨 Provider 一等公民：**

```rust
pub struct ThinkingConfig {
    pub enabled: bool,
    pub effort: Option<ThinkingEffort>, // Low / Medium / High / Max
}

pub struct GenerateResponse {
    pub content: String,
    pub thinking_content: Option<String>, // 统一字段，各 Provider 映射如下
    pub raw_message: serde_json::Value,   // 完整 message 对象，含 reasoning_content
    // ...
}
```

各 Provider 思考字段映射与工具调用回传规则：

| Provider | 请求开启方式 | 响应字段 | 工具调用时回传要求 |
| -------- | ------------ | -------- | ------------------ |
| DeepSeek（`DeepSeekClient`） | `reasoning_effort` 参数 | `message.reasoning_content` | **必须回传完整 message（含 reasoning_content），否则 400** |
| MiniMax M3（`MiniMaxClient`） | `thinking.type: adaptive/disabled` + 自动附加 `reasoning_split: true` | `message.reasoning_content` | 同 DeepSeek，回传完整 message |
| MiniMax M2.x（`MiniMaxClient`） | thinking 强制开启，`disabled` 静默忽略；自动附加 `reasoning_split: true` | `message.reasoning_content` | 同上 |
| Claude（`AnthropicClient`） | `thinking` content block | `thinking` block | 必须回传 |
| OpenAI o 系列（`OpenAIResponsesClient`） | `reasoning.effort` | reasoning tokens（不透出） | 框架自动处理，无需手动干预 |
| Gemini 2.5（`GoogleInteractionsClient`） | `thinking_config` | `thinking_content` | 框架自动处理 |

`AgentContext` 消息历史存储 **完整 raw_message 对象**（而非只存 `content` 字符串），`OpenAICompatClient` 在 thinking 模式下检测响应是否含 `reasoning_content`，若有则在下一轮请求中自动附加，**Agent Runtime 层无需感知此细节**。

### agent-core（核心领域层，依赖 agent-types）

- 内置工具实现（`tools/builtin/`）— 实现 `agent-types::Tool` trait
- 存储访问层 — SQLite 连接池、Repository 模式
- `AgentState` enum — 状态机（Idle/Planning/ExecutingTool/Reflecting/Done/Failed）
- `Supervisor` struct — 管理子 Agent 生命周期，控制 `max_depth`/`max_concurrent`/`max_iterations`
- `WorkspaceManager` struct — 管理最多 20 个工作区的生命周期（创建/切换/删除/重命名）；每个工作区物理隔离（共享 agent.db（workspace_id 逻辑隔离） + `files/` + `ai-docs/` + `knowledge_base/`）；支持 5 种创建模板（通用/代码/写作/研究/空白）；Agent 可通过本地关键词规则触发切换建议（每 Session 最多 1 次，只提示不自动切换）
- `Chunker` struct / `ChunkStrategy` enum — 知识库六种分块策略：`ByParagraph`、`ByTokenCount`、`SlidingWindow`、`Semantic`（余弦相似度阈值切割）、`ParentChild`（大块检索上下文 + 小块精确匹配）、`Proposition`（LLM 改写为原子事实句）；产出 `Chunk { content: String, metadata: Value, parent_content: Option<String> }`
- `AiArtifact` struct — AI 产物元数据（`file_path + conversation_id + message_id + created_at`），对应 SQLite `ai_artifacts` 表

> **注意**：原 `AgentContext` 已拆分为 `AgentSession`（位于 agent-runtime）和 `TurnContext`（位于 agent-types）。agent-core 不再定义 `Tool`/`Skill` trait 和 `Message` 等共享类型，这些已迁移至 agent-types。

### agent-runtime（动态执行层，依赖 agent-core + agent-providers + agent-types）

- `AgentSession` struct — 长生命周期会话上下文，持有 ToolRegistry/SkillRegistry/ProviderRegistry 等 Arc 引用，整个会话复用；`AgentExecutor` 持有 `AgentSession`，每次 `round_loop` 从 session 构建临时 `TurnContext`（定义于 agent-types）
- `RhaiRuntime` struct — Rhai 脚本沙箱，用于轻量工具动态生成
- `WasmRuntime` struct — wasmtime 沙箱，用于复杂 Skill 热加载
- `SandboxPolicy` struct — 资源限制策略（CPU时限、内存上限、网络白名单）
- `SharePackager` struct — 对话导出引擎：检测媒体附件大小/类型，路由到单文件 HTML 或 ZIP 包策略

### agent-mcp-server（协议暴露层）

- `McpServer` struct — 标准 MCP stdio 服务端，将 Agent 能力暴露为 resource/tool
- `McpHandler` trait — 请求路由，映射 MCP 调用到 ToolRegistry/SkillRegistry
- `McpToolBridge` struct — 双向桥接，Agent 也可作为 MCP client 接入外部服务

### agent-evals（独立评测层）

- `EvalRunner` struct — 批量运行评测用例，并行执行
- `Benchmark` trait — 单个评测任务定义，含 `score()` 方法
- `EvalReport` struct — 汇总评分、耗时、Token 消耗

## 五、模块边界规则

**禁止跨层调用（强制约束）：**

1. `agent-types` 不得 `use` 任何其他内部 crate——它是零依赖的纯类型层，任何反向依赖均构成循环。
2. `agent-providers` 只允许依赖 `agent-types`，不得依赖 `agent-core` 或 `agent-runtime`。
3. `agent-core` 只允许依赖 `agent-types`，不得依赖 `agent-providers` 或 `agent-runtime`——运行时沙箱由上层（src-tauri 或进化调度器）注入，通过 `Arc<dyn Runtime>` trait 解耦。
4. `agent-mcp-server` 与 `agent-evals` 互相不可见——两者均为独立可执行入口，不得形成水平依赖。
5. 前端组件不得绕过 `store` 直接调用 `invoke`——所有 Tauri 调用必须经过 `lib/tauri.ts` 的类型化封装层，禁止在组件内散落裸 `invoke` 字符串。
6. `pages/` 层不得导入其他 `pages/` 模块——页面间通信只能通过 Zustand store 或路由参数，禁止直接 import。
7. Tauri `commands/` 层只能依赖 `agent-core` 和 `agent-providers`，禁止在命令处理函数内实现业务逻辑——业务逻辑必须下沉到对应 crate。
