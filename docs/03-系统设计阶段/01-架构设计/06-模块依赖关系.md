## 二、各 Crate 核心 Trait / Struct

### agent-types（最底层，零依赖纯类型层）

- `Message` / `ContentPart` / `MessageRole` — 统一消息格式
- `Tool` trait / `ToolInput` / `ToolOutput` / `ToolError` / `ToolCall` / `ToolResult` — 原子能力单元接口
- `TextClient` / `EmbeddingClient` / `TtsClient` / `AsrClient` / `ImageClient` / `VideoClient` / `MusicClient` trait — Provider 接口族
- `Skill` trait / `SkillManifest` — 高层能力单元接口
- `MediaContent` / `MediaData` — 多模态内容载体
- `Permission` / `PermissionSet` / `RiskLevel` — 权限模型
- `AgentError` / `ProviderError` / `ToolError` — 统一错误类型
- `CostRecord` — 成本追踪记录
- `TurnContext` struct — 短生命周期每轮上下文（见 AgentSession/TurnContext 拆分说明）

### agent-providers（Provider 实现层，依赖 agent-types）

- `TextClient` trait — 统一文本生成接口，支持流式输出
- `EmbeddingClient` trait — 向量嵌入接口
- `ImageClient / TtsClient / AsrClient / VideoClient / MusicClient` trait — 多模态接口族
- `ProviderRegistry` struct — 运行时 Provider 路由表；按**模型子类型**（对话 / 多媒体 / 嵌入 / 辅助）分组路由，每种子类型维护独立的默认模型配置，运行时动态拉取 `/v1/models` 并支持离线缓存回退
- `MediaContent` enum — 统一多模态内容载体（Text/Image/Audio/Video）

**Provider 实现分层：**

| 实现 | 接口协议 | 覆盖厂商 |
| ---- | -------- | -------- |
| `AnthropicClient` | Anthropic Messages API | Claude 系列 |
| `OpenAIChatClient` | OpenAI Chat Completions API（`POST /v1/chat/completions`） | OpenAI 原生 |
| `OpenAIResponsesClient` | OpenAI Responses API（`POST /v1/responses`，含内置工具/状态管理） | OpenAI 原生 |
| `OpenAICompatClient` | Chat Completions 纯兼容，只做 base URL + API Key 替换，不含任何厂商私有逻辑 | 月之暗面、零一万物、智谱 AI 等格式标准的国内厂商 |
| Responses adapter | Agent-only 原生 `ResponseItem` 输入；`supports_responses` capability gate；不向 Chat 降级 | OpenAI、DeepSeek、Azure、百炼、MiniMax、Mimo 等已标记 profile |
| Chat / Anthropic / Gemini / Interactions adapters | 非 Agent 兼容调用、连接验证或厂商专用能力 | 不参与 Agent primary/fallback |
| `GoogleGenerateContentClient` | Google generateContent API（旧版，无废弃时间线）；无状态，支持 Batch / 上下文缓存 / 自定义安全设置；**同时承载 Imagen 3 图像生成**（`imagen-3.0-generate-002`）和 **Veo 3.1 视频生成**（`veo-3.1-generate-preview`，8 秒，720p/1080p/4k，含原生音频，LongRunning 轮询） | Gemini 全系列嵌入/RAG，Imagen 3 图像，Veo 3.1 视频；**用于批量嵌入 / RAG / 上下文缓存 / 图像生成 / 视频生成** |

**MiniMaxClient `base_resp.status_code` → 标准错误映射：**

| status_code | 含义 | 映射为 |
| ----------- | ---- | ------ |
| 1002 | 触发限流 | `RateLimit` |
| 1004 | 鉴权失败 | `AuthError` |
| 1008 | 余额不足 | `QuotaExceeded` |
| 1027 | 输出内容过滤 | `ContentFilter` |
| 1039 | Token 超限 | `ContextTooLong` |
| 2013 | 参数错误 | `InvalidRequest` |

`ProviderRegistry` 仍按能力注册 adapter；Agent 入口先通过 Responses capability gate，再进入 registry。媒体和 embedding 使用各自专用能力，不改变 Agent 的 Responses-only 约束。

**思考模式（Thinking Mode）——跨 Provider 一等公民：**

```rust
pub struct ThinkingConfig {
    pub enabled: bool,
    pub effort: Option<ThinkingEffort>, // Low / Medium / High / Max
}

pub struct GenerateResponse {
    pub content: String,
    pub thinking_content: Option<String>, // 统一字段，各 Provider 映射如下
    pub raw_message: serde_json::Value,   // 完整 message 对象，含 reasoning_content
    // ...
}
```

各 Provider 思考字段映射与工具调用回传规则：

| Provider | 请求开启方式 | 响应字段 | 工具调用时回传要求 |
| -------- | ------------ | -------- | ------------------ |
| DeepSeek（`DeepSeekClient`） | `reasoning_effort` 参数 | `message.reasoning_content` | **必须回传完整 message（含 reasoning_content），否则 400** |
| MiniMax M3（`MiniMaxClient`） | `thinking.type: adaptive/disabled` + 自动附加 `reasoning_split: true` | `message.reasoning_content` | 同 DeepSeek，回传完整 message |
| MiniMax M2.x（`MiniMaxClient`） | thinking 强制开启，`disabled` 静默忽略；自动附加 `reasoning_split: true` | `message.reasoning_content` | 同上 |
| Claude（`AnthropicClient`） | `thinking` content block | `thinking` block | 必须回传 |
| OpenAI o 系列（`OpenAIResponsesClient`） | `reasoning.effort` | reasoning tokens（不透出） | 框架自动处理，无需手动干预 |
| Gemini 2.5（`GoogleInteractionsClient`） | `thinking_config` | `thinking_content` | 框架自动处理 |

`AgentContext` 消息历史存储 **完整 raw_message 对象**（而非只存 `content` 字符串），`OpenAICompatClient` 在 thinking 模式下检测响应是否含 `reasoning_content`，若有则在下一轮请求中自动附加，**Agent Runtime 层无需感知此细节**。

### agent-core（运行时核心，当前实现）

Agent 运行时核心 — `Session` 状态机、`AstroThread` 句柄、`submission_loop` 有序提交、`SessionTask`/`ActiveTurn` 任务生命周期、`TurnContext`/`StepContext` 层级上下文、工具路由（`ToolRouter`）、流式补全、上下文压缩、HITL 控制、prompt 组装。

主要子模块：

- **`runtime/`** — Session 生命周期、`AstroThread`、`SessionIo`、`submission_loop`、`SessionState`、`SessionServices`、`TurnContext`、`StepContext`、`ToolRouter`、`ToolRuntime`、`budget`（`IterationBudget`）、`turn_budget`（`TurnState`）
- **`tasks/`** — 可恢复任务生命周期：`SessionTask`、`ActiveTurn`、`TaskKind`
- **`streaming/`** — 流式补全：fallback、HITL bridge、多轮 streaming、provider 抽象、tool 执行
- **`exec/`** — `AgentControlDirectory`、`AgentRuntimeManager`、subagents dispatch、cron、background、memory review、title generation
- **`compression/`** — `maintain_tool_context()` 三阶段：prune → LLM 辅模型摘要 → head/tail fallback
- **`control/`** — HITL gate、中断状态机、schema 校验、`SmartApprovalContext`、`approval_cache`、网络审批
- **`prompt/`** — 上下文组装、hook 集成、消息变换、prompt builder、sanitization

### agent-tools（工具实现层，当前实现）

全部内置工具实现（`register_all`）、`ToolRegistry`（`ToolExposure` 五级暴露 + BM25 工具搜索）。工具域：exec\_command（原 terminal）、apply\_patch（Freeform 补丁，Lark 语法）、write\_stdin、request\_permissions、code\_exec、memory、skills、subagents（6 个 V2 工具）、tool\_search、media。

### 以下为历史设计方案（不存在于当前 workspace）

> `agent-runtime`（AgentExecutor/RhaiRuntime/WasmRuntime）、`agent-mcp-server`（McpServer）、`agent-evals`（EvalRunner）均为早期设计，已被 `agent-core::Session`、`agent-mcp`（MCP Client）、`agent-evolution`（评估/进化）取代。

## 五、模块边界规则

**禁止跨层调用（强制约束）：**

1. `agent-types` / `agent-config` / `agent-protocol` 不得 `use` 上层 crate——它们是零业务逻辑的底层基础，任何反向依赖均构成循环。
2. `agent-providers` / `agent-tools` / `agent-mcp` 不拥有 turn 生命周期——只提供能力，由 `agent-core::Session` 编排执行。
3. `agent-core` 是运行时核心，依赖 `agent-tools`、`agent-providers` 等，但 `agent-server` 不得反向依赖 `agent-core` 的内部模块（仅通过 Thread / Session 公开接口交互）。
4. `agent-rollout` 记录权威事实源（JSONL），`SessionStore` 为可重建投影——禁止从 SessionStore 反向影响 rollout。
5. 前端组件不得绕过 `store` 直接调用 gRPC——所有通信必须经过类型化封装层。
6. `pages/` 层不得导入其他 `pages/` 模块——页面间通信只能通过 Zustand store 或路由参数，禁止直接 import。
