> **状态说明（2026-09-07）**：本文保留五层物理分层作为历史概念参考；其中 `agent-runtime`、`agent-mcp-server`、`agent-evals`、`AgentExecutor`、`delegate_task`、`Rhai 脚本解释器`、`WASM Skill 执行器` 与下方旧 Provider 对话路由均不存在于当前 workspace。当前共 28 个 crate + 1 个桌面应用 = 29 个 workspace 成员（见 [Crate 结构详解](03-Crate结构.md)）。Agent 对话只走 Responses API，子 Agent 使用 Codex V2 Agent Threads（6 个模型工具）。现行主链见 [Agent Harness 总体架构](11-Agent-Harness总体架构.md) 与 [Responses 原生 Agent 运行时架构](12-Responses原生Agent运行时架构.md)。

## 零、当前实现分层

```text
React UI
  -> Tauri shell / gRPC client
  -> agent-server (Thread ownership + live projection)
  -> agent-core (Session/Turn/Step orchestration)
  -> providers / tools / mcp / extensions / realtime / subagents
  -> protocol + rollout + session + usage + sandbox/network
```

Agent 对话只走 Responses；rollout 是 durable 事实源；Extension 在 turn 内冻结；MCP 只作为
Client 接入；权限由 `SessionPermissions + PermissionProfile + attempt SandboxPolicy` 执行。

## 二、各层职责说明

**L1 用户界面层**
负责所有用户可见的交互界面，包括对话流、多模态媒体展示（音频波形、代码高亮、Markdown 渲染）和 Agent 状态可视化。状态由 Zustand 统一管理，保持单向数据流；TanStack Router 处理页面导航与深度链接。

**L2 桌面壳层**
Tauri v2 作为原生能力的桥接层，向上暴露 `invoke` 命令与 `event` 流，向下持有 Rust 应用状态（`AppState`）。负责操作系统级权限沙箱、原生文件选择器、系统托盘、应用自动更新，以及通过 `tauri-plugin-share` 唤起 macOS Share Sheet / Windows 系统分享菜单（F-25 分享功能的原生层支撑），将 Web 上下文与底层 Rust 运行时安全隔离。

**L3 运行时编排层（agent-runtime）**
实现 Agent 的执行主循环：接收用户意图 → 规划 Skill 序列 → 调度工具调用 → 收集结果 → 触发反思。支持 Rhai 脚本实现轻量动态工具、WASM 沙箱运行复杂 Skill，并通过反思引擎驱动 Prompt 自优化与记忆蒸馏。每个工作区对应一个持久 `AgentContext`（主 Agent），通过 `delegate_task` 临时派生子 Agent 处理复杂子任务；工作区切换不销毁上下文，缓存复用确保切换延迟 < 500 ms。系统最多支持 8 个工作区并发存在，每个工作区逻辑隔离（共享 `agent.db` + `workspace_id` 外键约束；知识库向量索引、媒体文件、AI 产物仍按工作区物理独立存储于各自目录）。

**L4a 核心抽象层（agent-core）**
定义全项目共用的 Rust trait（`AgentTrait`、`ToolTrait`、`MemoryTrait`、`SkillTrait`）及多模态数据类型（`Message`、`ModalityContent`、`EmbeddingVector`）。所有其他 crate 依赖此层接口，禁止反向依赖，保障依赖倒置原则落地。

**L4b Provider 层（agent-providers）**
分为两条明确边界：Agent completion 只经 `agent_responses_stream()` 使用 Responses API 和原生 `ResponseItem`；媒体、embedding、连接验证和其他非 Agent 调用可继续使用 Chat Completions、Anthropic Messages、Gemini Native、Interactions 或厂商专用 API。`ApiMode` 是通用 adapter 选择，不是 Agent 模式开关；Agent primary/fallback 必须声明 `supports_responses`。

每个 Provider 按模型子类型分组管理——**对话模型**（始终存在）、**多媒体模型**（图像生成/TTS/ASR/视频/音乐，按能力显示）、**嵌入模型**（按能力显示）、**辅助模型**（摘要/分类/意图，始终存在）——每种子类型维护独立的默认模型配置，运行时动态拉取 `/v1/models` 并支持离线缓存回退。**多媒体能力（TTS/ASR/图像/视频/音乐）以 Google 和 MiniMax 为主力**：Google 负责 Imagen 3（图像）、Veo 3.1（视频，8秒含原生音频）、Lyria 3（音乐，via Interactions API）、Cloud TTS Chirp3-HD、Cloud STT；MiniMax 负责 speech-2.8-hd（TTS，含流式/音色设计/声音克隆）、asr-01（ASR）、image-01/image-01-live（含图生图）、video-01、music-3.0 + music-cover（翻唱）；OpenAI 多媒体接口（DALL-E/Whisper/TTS-1）仅作降级备选。**思考模式（Thinking Mode）作为跨 Provider 一等公民**，通过统一的 `ThinkingConfig { enabled, effort }` 开启，响应统一映射到 `thinking_content: Option<String>`，Provider 层透明处理各厂商差异（DeepSeek `reasoning_content` 回传、Claude thinking block、OpenAI reasoning tokens 等），Agent Runtime 无需感知。每个 Provider 实现均通过 `agent-evals` 的评估套件进行回归验证。

**L4c MCP 协议层（agent-mcp-server）**
既作为 MCP 客户端连接外部工具服务，也可对外暴露为 MCP Server，使第三方应用能调用本 Agent 能力。负责 Tool 的注册、路由与协议版本协商，通过标准化接口统一工具生态。

**L5 存储与基础设施层**
SQLite 持久化对话历史、技能元数据与用户记忆；`ai_artifacts` 表记录 AI 产物文件路径与来源 `conversation_id + message_id`，支持文件管理页跳回源对话；BM25 倒排索引驱动本地语义检索；工作区文件系统分为 `files/`（用户自管理）和 `ai-docs/`（AI 产物，按类型分入 `code/reports/articles/data/other/` 子目录，随工作区物理隔离）；分享功能在此层生成静态 HTML 或 ZIP 包后交由 L2 唤起系统分享框；`tracing` crate 提供结构化可观测性；`agent-evals` crate 负责离线评估与基准对比。

## 三、层间通信机制

| 边界 | 通信机制 |
| ---- | -------- |
| L1 → L2 | Tauri `invoke()` 同步命令；`listen()` 订阅 Rust 事件；流式响应通过 Tauri `Channel` 或 SSE-like event 推送 |
| L2 → L3 | Rust 直接函数调用，`AppState` 共享 Arc 引用；tokio 异步 spawn |
| L3 → L4a/b/c | `async-trait` 动态分发，运行时通过依赖注入选择具体 Provider |
| L4b → 外部 API | `reqwest` HTTP 客户端，SSE 流式解码；WebSocket（`tokio-tungstenite`）用于实时音频 |
| L4c → 外部 MCP | JSON-RPC over stdio / HTTP，符合 MCP 协议规范 |
| L3/L4 → L5 | `sqlx` 异步 SQLite 读写；`serde_json` 序列化存储结构 |

## 四、关键设计原则

- **依赖倒置**：所有上层 crate 只依赖 `agent-core` 中的 trait 接口，不持有具体实现；Provider 可在运行时热插拔。
- **单向数据流**：前端 Zustand store 仅通过 `dispatch action → Tauri invoke → Rust event` 单方向更新，禁止跨 store 直接修改。
- **多模态统一类型**：`ModalityContent` 枚举在 L4a 统一表达文本/图像/音频/视频，各层无需关心具体模态差异。
- **沙箱隔离**：Rhai 脚本与 WASM Skill 在 L3 内受限执行环境中运行，无法直接访问文件系统或网络。
- **可评估性优先**：`agent-evals` crate 与业务逻辑解耦，任何 Provider 或 Skill 变更均可独立回归。

## 五、与 Hermes Agent 架构的差异点

| 维度 | Astro Agent | Hermes Agent（典型 Python 系） |
| ---- | ----------- | ------------------------------ |
| **运行时语言** | Rust + tokio，内存安全、零 GC 停顿 | Python，GIL 限制并发，依赖 asyncio |
| **桌面集成** | Tauri v2 原生壳，单二进制分发 | 通常需外部 Electron 或 Web 服务 |
| **工具扩展** | Rhai 脚本 + WASM 双轨，强类型沙箱 | Python 插件，动态但安全边界弱 |
| **多模态处理** | 统一 `ModalityContent` 枚举，编译期保证 | 字典/动态类型，运行时才暴露格式错误 |
| **MCP 定位** | 双向（Client + Server），可对外暴露能力 | 多数实现仅作 MCP Client |
| **状态管理** | SQLite + BM25 本地闭环，离线可用 | 常依赖外部向量数据库（Pinecone 等） |
| **自我进化** | Skill 合成 + Prompt 优化内置于 runtime | 需额外 Fine-tuning 管线，迭代周期长 |
