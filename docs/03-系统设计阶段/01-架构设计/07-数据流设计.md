# Astro Agent 数据流设计

> **当前 Harness 主流（2026-09-07）**：`Op -> AstroThread -> submission_loop -> SessionTask -> run_turn -> provider stream -> tool execution -> EventMsg -> rollout JSONL append -> Core event queue -> Server ThreadListener -> ThreadHistoryBuilder -> per-connection queues -> Tauri/clients`。子 Agent 以 Codex V2 Agent Threads 为准（6 个模型工具）。见 [Agent Harness 总体架构](11-Agent-Harness总体架构.md)。

> 阶段：系统设计 | 状态：定稿 | 说明：主对话/工具调用/记忆/Skills/子Agent 数据流

---

## 1. 主对话数据流（含流式 SSE 返回）

```text
用户输入
  │
  ▼
React 前端（useChat hook / Zustand store）
  │  gRPC Thread submit
  ▼
AstroThread::submit(Op)
  │  bounded(512) submission channel
  ▼
Session::submission_loop — 有序 Op 分发
  │  拼装 system prompt + history + memory 注入
  ▼
SessionTask::run_turn — 模型/工具循环
  │  PromptContract 组装 Vec<ResponseItem> canonical history
  ▼
ProviderStreamer::stream_response
  │  选择 Provider — 5 种 ApiMode：
  │    ChatCompletions / Responses / AnthropicMessages /
  │    Interactions（Google Gemini）/ GeminiNative
  │  各 Provider 发起各自协议请求，stream=true
  ▼
Provider API（HTTP/2 SSE / JSON-RPC / LongRunning 按 Provider 而定）
  │  token chunk 流
  ▼
agent-providers（StreamDecoder）
  │  解析 delta.text / delta.tool_use / thinking_content
  ▼
EventMsg — Core 单一事件格式
  │  rollout policy + JSONL append（权威历史）
  ▼
Core event queue（单 receiver）
  │  → Server ThreadListener（单 listener per Thread）
  │  → ThreadHistoryBuilder（活跃 Turn 快照）
  ▼
per-connection bounded(128) queues
  │  → Tauri ThreadEventsBridge / exec / external Thread clients
  ▼
React 前端
  │  Zustand append token → 触发 re-render
  ▼
UI 实时显示（流式打字效果）
```

整个路径为全异步 tokio 流水线。`EventMsg` 是 Core 唯一事件格式，`SessionStore` 为可重建投影，rollout JSONL 为权威历史。

## 2. 工具调用数据流

```text
SessionTask 接收到 tool_use block（ResponseItem 中的 function_call）
  │
  ▼
ToolRouter（根据 ToolName + namespace 路由）
  ├── 内置工具（exec_command / apply_patch / code_exec / memory / skills 等）
  │     │  StepContext 校验 → approval + sandbox + hooks → 执行
  │     │  返回 ToolOutput
  │     ▼
  ├── MCP 工具（McpHub — per-agent 进程级连接池）
  │     │  namespace=mcp__{server}, name=tool
  │     │  JSON-RPC call → MCP Server（外部进程 / 远程）
  │     │  等待响应 / 超时
  │     ▼
  └── Subagent 工具（spawn_agent / send_message / wait_agent 等 6 个 V2 工具）
        │  通过 AgentControl 与 Agent Graph 交互
        ▼
ToolOutput { content, is_error }
  │  tool 结果 ≥ DEFAULT_SPILL_THRESHOLD_BYTES 时落盘（tool spill）
  │
  ▼
matching output item 持久化（call id 精确配对）
  │  call/output 成对进入下一次 Responses input
  │
  │  ⚠️  Thinking 模式 reasoning_content 回传（DeepSeek / MiniMax 强制要求）
  │  OpenAICompatible trait 的 THINKING_FORMAT 控制转换
  │  Provider 层透明处理，运行时无需感知
  ▼
Provider API（携带 tool_result + canonical ResponseItem 历史的下一次请求）
  │
  ▼
继续 sampling 或完成 turn → 返回主对话流
```

工具调用支持并行派发（多个 tool_use block 同时执行），结果汇总后统一注入。`FreeformToolFormat`（Lark 语法）支持 apply_patch 等非 JSON 工具输入。

## 3. 记忆读写数据流

```text
【会话开始 - 读取】
Session 初始化
  │  MemoryManager 加载 MEMORY.md / USER.md 快照
  │  workspace bootstrap
  ▼
PromptContract 组装（system prompt）
  │  记忆内容注入到 instructions
  ▼
LLM 具备历史上下文感知

【对话结束 - 写入】
memory review（exec/ 模块后台任务）
  │
  ▼
MemoryManager（dreaming 管道）
  │  提取关键事实 / 偏好 / 决策
  │  待审批记忆队列、decision log
  ▼
MEMORY.md / USER.md 快照更新
  │  权限审计
  ▼
agents/{agent_id}/ 目录持久化
```

记忆写入为异步后台任务（`AuxiliaryTask`），不阻塞当前响应流。

## 4. Skills 执行数据流

```text
模型发出 skill 名称作为工具调用
  │  Skill soft-alias：自动改写为 skills(action=load, skill_id=...)
  │
  ▼
agent-skills（SkillRegistry）
  │  BM25 全文索引检索（基于 skill 名称 + 描述）
  │  返回匹配的 skill
  ▼
SKILL.md 加载（从文件系统读取 skill 定义）
  │  解析 metadata、trigger 条件
  │  Skill frontmatter `astro_tools` 可 additive 开放 toolset
  ▼
Skill 内容注入当前对话上下文
  │  展开为 system prompt 级指令
  ▼
SessionTask 继续后续推理（使用 skill 提供的工具和指令）
```

## 5. 子 Agent 派生数据流

```text
主 Agent 决策需要委托子任务
  │  spawn_agent { name, instructions, ... }
  ▼
AgentControl（根级共享控制器）
  │  AgentRegistry 检查配额（max_threads=32, max_depth=8, max_running=8）
  │  RAII 预留/配额
  ▼
AgentGraphStore（subagents.db）
  │  创建线程节点，状态：PendingInit → Running
  │  从 ~/.astro/agents 和 <project>/.astro/agents 加载自定义 agent 定义
  ▼
子 AstroThread 独立运行
  │  拥有独立 Session / submission_loop / IterationBudget
  │  可继续派生孙 Agent（树状结构，受 max_depth 限制）
  ▼
6 个模型工具交互：
  │  spawn_agent / list_agents / send_message /
  │  followup_task / wait_agent / interrupt_agent
  │  桌面控制面：read_subagent_thread / close_subagent_thread
  ▼
子 Agent 完成 → Completed { last_message }
  │  或 Interrupted / Errored { message }
  ▼
主 Agent 通过 wait_agent / send_message 获取结果
  │  followup_task 可向已完成 agent 发后续任务并重新激活
  ▼
主 Agent 综合所有子结果，输出最终回复
```

每次 spawn 失败释放路径和身份预留；每次 turn 退出释放执行槽位；completed/interrupted/errored 线程保持可寻址。

## 6. 错误传播路径

```text
Provider API 请求发出
  │
  ├── 超时（timeout > 30s）
  │     │  tokio timeout 触发
  │     ▼
  │   RetryPolicy（指数退避，最多 3 次）
  │     │  重试同一 Provider
  │     ▼
  │   仍失败 → ProviderFallback
  │     │  ProviderRouter 切换备用 Provider
  │     │  （如 Claude → DeepSeek）
  │     ▼
  │   备用成功 → 正常流程继续
  │   备用也失败 → AgentError::AllProvidersFailed
  │
  ├── 速率限制（429 / MiniMax base_resp.status_code=1002）
  │     │  解析 Retry-After header（HTTP 429）
  │     │  MiniMaxClient 解析 base_resp.status_code 并映射为标准错误：
  │     │    1002→RateLimit / 1004→AuthError / 1008→QuotaExceeded
  │     │    1027→ContentFilter / 1039→ContextTooLong / 2013→InvalidRequest
  │     ▼
  │   RateLimiter 等待后重试
  │
  └── 其他错误（4xx/5xx）
        │  anyhow::Error 向上传播
        ▼
      Tauri Command 层捕获
        │  emit("agent_error", { code, message, recoverable })
        ▼
      React 前端（ErrorBoundary / Toast 通知）
        │  展示用户友好提示
        │  提供"重试"或"切换模型"操作按钮
        ▼
      用户可手动干预或自动降级继续
```

所有错误均通过 `tracing::error!` 记录结构化日志，可接入 OpenTelemetry 追踪链路。

## 7. AI 产物归档数据流

```text
用户点击 AI 回复消息中的「💾 保存」按钮
  │
  ▼
前端弹出 AiSaveDialog
  │  展示：AI 推断的文件名（YYYY-MM-DD_<title>.<ext>）
  │  展示：推断的目标目录（ai-docs/code/ 或 reports/ 等）
  │  用户可修改文件名和目标目录，点击「确认」
  ▼
invoke("save_ai_artifact", { conversation_id, message_id, filename, target_subdir })
  │
  ▼
Tauri Command Layer
  │  根据 target_subdir 确定完整路径：
  │  workspaces/<id>/ai-docs/<subdir>/<filename>
  ▼
文件系统写入
  │  将消息内容写入对应路径
  ▼
SQLite ai_artifacts 表 INSERT
  │  { file_path, conversation_id, message_id, created_at }
  ▼
emit("artifact_saved", { file_path, subdir })
  │
  ▼
前端 workspace store 更新文件列表
  │  WorkspaceFiles 页面刷新，ai-docs/ 节点高亮新文件
  ▼
消息气泡中「💾 保存」按钮变为「✅ 已保存」，显示目标路径
```

文件写入和数据库插入在同一 tokio 任务中顺序执行，任一失败均回滚（删除已写文件或跳过插入），前端通过 Toast 提示错误。

## 8. 对话分享与导出数据流

```text
用户点击对话操作菜单「分享」
  │
  ▼
前端展示 ShareRangeSelector 弹窗
  │  选项：全部消息 / 最近 N 条 / 手动勾选
  │  开关：是否包含 Tool 调用详情
  │  用户确认后调用 invoke
  ▼
invoke("share_conversation", { conversation_id, message_ids, include_tools })
  │
  ▼
Tauri Command → SharePackager
  │
  ▼
SharePackager 媒体检测
  │  扫描所选消息中的媒体附件：
  │  ├── 无媒体 / 仅图片          → 策略 A：单文件 HTML
  │  ├── 含音频且 < 10MB          → 策略 A：单文件 HTML（base64 内嵌）
  │  ├── 含音频 ≥ 10MB 或任意视频  → 策略 B：ZIP 包
  │  └── （P2）云端分享            → 策略 C：上传 + 短链
  │
  ├─► 策略 A：生成自包含 HTML
  │     │  媒体文件 base64 内嵌，CSS/JS 内联
  │     │  输出：chat-<date>-<title>.html（临时目录）
  │     ▼
  └─► 策略 B：生成 ZIP 包
        │  生成 index.html（媒体用相对路径引用）
        │  复制媒体文件到 media/ 目录
        │  生成 README.txt（解压说明）
        │  打包为 chat-<date>-<title>.zip（临时目录）
        ▼
emit("share_ready", { file_path, strategy })
  │
  ▼
前端收到事件 → 调用 @tauri-apps/plugin-share
  │  share({ files: [file_path] })
  │  macOS → 唤起系统 Share Sheet
  │  Windows → 唤起系统分享菜单
  ▼
用户选择分享目标（AirDrop / 微信 / 钉钉 / 存储到文件 等）
  │
  ▼
分享完成后临时文件保留（用户可通过「另存为」永久保存）
  │  或点击「在浏览器中预览」验证效果
```

ZIP 打包使用 `zip` crate 在后台线程执行，不阻塞主 tokio 运行时；媒体文件按原始格式复制，不重新编码。

## 9. 多媒体生成数据流

多媒体生成分三种模式，由 `ProviderRegistry` 按请求类型路由。

### 9a. TTS 流式语音合成

```text
用户发出 TTS 请求（文本 + 音色 + 情感标签）
  │  invoke("text_to_speech_stream", { text, voice_id, model })
  ▼
Tauri Command Layer
  │  spawn tokio task
  ▼
ProviderRegistry → MiniMaxClient（speech-2.8-hd）/ GoogleTtsClient（Chirp3-HD）
  │  POST /v1/t2a_v2（MiniMax）或 Cloud TTS API（Google）
  │  stream=true
  ▼
Provider API（HTTP chunked 流）
  │  每个 audio chunk：hex 编码字节（MiniMax）/ PCM bytes（Google）
  ▼
StreamDecoder
  │  MiniMax：hex 解码 → Bytes；status=1 继续，status=2 结束
  │  Google：PCM → mp3 转码
  ▼
Tauri Event Bus
  │  emit("tts_audio_chunk", { data: Vec<u8>, is_last: bool })
  ▼
React 前端（Audio worklet）
  │  边接收边写入 AudioBuffer → 实时播放，无感知延迟
  ▼
全部 chunk 接收后：本地缓存完整 mp3 / 供用户下载
```

### 9b. 图像生成（同步请求，多张并行）

```text
用户发出图像生成请求（prompt + 宽高比 + 数量）
  │  invoke("generate_image", { prompt, model, n, aspect_ratio })
  ▼
ProviderRegistry → GoogleImageClient（Imagen 3）/ MiniMaxImageClient（image-01）
  │
  ├─► Google Imagen 3：POST generateContent（图像输出模式）
  │     响应：base64 图像数组，同步返回
  │
  └─► MiniMax image-01：POST /v1/image_generation
        响应：{ data.image_urls[], metadata.success_count, metadata.failed_count }
        image_urls 有效期 24h → 立即下载缓存到本地
  ▼
图像文件写入 workspaces/<id>/ai-docs/code/（或 other/，按 MIME 归类）
  │
  ▼
emit("image_ready", { file_paths: Vec<String>, failed_count: u32 })
  │
  ▼
React 前端（MediaPreview 组件）
  │  渲染缩略图网格；failed_count > 0 时展示内容安全过滤提示
```

### 9c. 视频 / 音乐生成（异步任务 + 轮询）

```text
用户发出视频/音乐生成请求
  │  invoke("generate_video" / "generate_music", { prompt, model, ... })
  ▼
ProviderRegistry → GoogleVideoClient（Veo 3.1）/ MiniMaxVideoClient / MiniMaxMusicClient
  │
  ├─► Google Veo 3.1：POST models/veo-3.1-generate-preview:predictLongRunning
  │     响应：{ name: "operations/<id>" }（LongRunning Operation）
  │
  ├─► Google Lyria 3（音乐）：POST interactions.create（via Interactions API）
  │     响应同步，含 output_audio（base64 mp3）+ output_text（歌词）
  │
  └─► MiniMax video-01 / music-3.0：
        视频：POST /v1/video_generation → { task_id }
        音乐：POST /v1/music_generation（可选 stream=true）
  │
  ▼
TaskPoller（tokio 后台任务，每 10 秒轮询）
  │  Google：GET operations/<id> → { done: bool, response }
  │  MiniMax：GET /v1/query/video_generation?task_id=<id>
  │  done=false → 继续等待；done=true → 提取下载链接
  │
  ├── 轮询期间：emit("task_progress", { task_id, status, progress })
  │   前端显示进度条（Pending → Processing xx% → Done）
  │
  └── 完成：下载媒体文件到本地缓存目录
  ▼
emit("media_ready", { task_id, file_path, duration_secs })
  │
  ▼
React 前端（MediaPreview 组件）
  │  视频：内联 <video> 播放器
  │  音乐：wavesurfer.js 波形 + 播放控件 + 歌词展示（若有）
  │  提供「保存到 ai-docs/」按钮 → 复用 AI 产物归档数据流（第 7 节）
```

三种模式对比：

| 能力 | 模式 | 延迟特征 | 前端体验 |
| ---- | ---- | -------- | -------- |
| TTS | 流式 SSE | 首字节 < 500ms，边播边收 | 实时音频播放 |
| 图像生成 | 同步请求 | 5~30s，一次性返回 | 加载动画 → 网格展示 |
| 视频 / 音乐 | 异步轮询 | 30s~数分钟 | 进度条 → 完成通知 |
