## 一、后端语言选型：Rust vs 其他

### 对比矩阵

| 维度 | Rust | Go | Java/Kotlin | Python | C++ |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 内存安全 | ✅ 编译期保证 | ✅ GC 保证 | ✅ GC 保证 | ✅ GC 保证 | ❌ 手动管理 |
| 运行时性能 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| 启动速度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 内存占用 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| 开发效率 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| 并发模型 | async/await + 无 GC | goroutine | 线程/协程 | asyncio/线程 | 线程 |
| 桌面框架集成 | ✅ Tauri 原生 | ❌ 无成熟方案 | ⚠️ 较重 | ❌ 无成熟方案 | ✅ Qt |
| WASM 支持 | ✅ 一流 | ⚠️ 有限 | ⚠️ 实验性 | ❌ 不适合 | ✅ 良好 |
| 生态（AI/HTTP） | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| 学习曲线 | 陡峭 | 平缓 | 中等 | 平缓 | 极陡峭 |

### 选择 Rust 的理由

1. **Tauri 生态**：Tauri 本身用 Rust 编写，选择 Rust 可以无缝集成，共享类型定义，避免跨语言序列化开销
2. **桌面应用资源占用**：Rust 二进制无需 GC，内存占用和启动速度远优于 JVM 系语言，符合桌面应用体验要求
3. **WASM 沙箱**：Rust 编译 WASM 是一流支持，Skills 系统的 WASM 沙箱执行需要这一能力
4. **长期维护性**：内存安全保证减少运行时崩溃，适合长期演进的 Agent 框架
5. **并发性能**：Agent 同时处理多个工具调用、子 Agent、流式响应，tokio 的零成本异步适合此场景

### 主要劣势及应对

| 劣势 | 应对措施 |
| ---- | ---- |
| 开发效率低于 Go/Python | 统一错误处理（anyhow），充分利用 derive macro |
| 学习曲线陡 | 核心 trait 设计期邀请 Rust 专家 Review，使用成熟模式 |
| 编译时间长 | 拆分 workspace crate，使用 sccache 缓存，CI 开启增量编译 |
| AI 生态不如 Python 丰富 | 通过 HTTP 调用 Provider REST API，不依赖 Python SDK |

**结论：选择 Rust ✅**

## 四、向量存储选型：sqlite-vec vs qdrant vs pgvector

| 维度 | sqlite-vec | qdrant（本地） | pgvector |
| ---- | ---- | ---- | ---- |
| 部署方式 | 嵌入式（无服务进程） | 独立进程 | PostgreSQL 扩展 |
| 依赖复杂度 | 极低（SQLite 扩展） | 中（需启动进程） | 高（需 PostgreSQL） |
| 桌面应用适配 | ✅ 最佳 | ⚠️ 需管理子进程 | ❌ 不适合桌面 |
| 性能（10 万块） | 待 POC 验证 | ✅ 优秀 | ✅ 良好 |
| 与现有 SQLite 集成 | ✅ 同一数据库文件 | ❌ 独立存储 | ❌ 独立存储 |
| 数据加密 | ✅ SQLCipher 一并加密 | ⚠️ 需单独加密 | ⚠️ 需单独加密 |
| 成熟度 | 较新（2024） | ✅ 生产级 | ✅ 生产级 |

**结论：首选 sqlite-vec，POC 验证性能后决定，备选 qdrant 本地模式 ✅**

## 五、动态脚本选型：Rhai vs Lua vs JS（deno_core）vs WASM

| 维度 | Rhai | Lua | deno_core（JS） | WASM |
| ---- | ---- | ---- | ---- | ---- |
| Rust 集成 | ✅ 原生 Rust 库 | ⚠️ 需 FFI | ⚠️ 较重 | ✅ wasmtime |
