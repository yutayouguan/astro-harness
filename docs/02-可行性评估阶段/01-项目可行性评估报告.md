### 2.3 关键技术风险

**风险 1：Rust 开发效率**

Rust 学习曲线陡峭，生命周期和借用检查器对新手有较高心智负担，可能影响开发速度。

缓解措施：
- 使用 `anyhow` + `thiserror` 简化错误处理
- 核心 trait 设计阶段邀请 Rust 专家 Review
- 前期允许使用 `Arc<Mutex<T>>` 等简单模式，后期优化

**风险 2：多 Provider API 兼容性**

各 Provider API 格式不完全统一，特别是多模态（图像、音频）接口差异大。

缓解措施：
- 设计统一 Trait 抽象层，各 Provider 各自实现
- 每个 Provider 单独维护适配器，隔离变更影响

**风险 3：Tauri 跨平台兼容性**

macOS / Windows / Linux 在系统通知、文件路径、原生菜单上存在差异。

缓解措施：
- 优先支持 macOS 和 Windows，Linux 社区版次优先
- 使用 Tauri 官方 API，不直接调用平台特定系统 API

**风险 4：sqlite-vec 向量检索性能**

sqlite-vec 是较新的向量扩展，在大规模文档（> 10 万块）下性能未经验证。

缓解措施：
- POC 阶段验证 10 万块场景下检索延迟
- 如性能不达标，切换至 qdrant（本地模式）

#### 风险 5：大量工具时的 Token 消耗（Tool Search 机制）

当用户挂载多个 MCP Server 或加载大量 Skills 时，所有工具 JSON Schema 一次性注入上下文，Token 消耗随工具数量线性增长。挂载 10 个 MCP Server（每 Server 30 个工具）即可消耗数万 Token，严重压缩对话可用空间。

参考 Hermes Agent Tool Search 设计，需实现按需披露（Progressive Disclosure）机制：

- 三桥接工具（`tool_search` / `tool_describe` / `tool_call`）替代全量 Schema 注入
- BM25 检索（工具名 + 描述 + 参数名分词），零分时降级为子串匹配
- 分级策略：Eager → Lazy+Listing → 裸桥接，每轮根据 Token 预算动态决定
- 目录无状态，每次从当前注册表重建，避免缓存与实际工具脱同

缓解措施：

- POC 阶段实现 BM25 检索原型，验证在 100+ 工具场景下首次调用延迟 < 2 次模型往返
- 提供配置项（`threshold_pct`、`listing_max_tokens`）允许用户调整预算阈值
- 注意不可消除的权衡：冷工具首次调用有额外往返；延迟 Schema 无法享受 Prompt Cache 前缀优化

**结论：技术可行性 ✅（存在中等风险，可控）**

| 角色 | 人数 | 职责 |
| ---- | ---- | ---- |
| Rust 后端工程师 | 2 | agent-core、agent-providers、agent-runtime |

### 3.3 关键路径

```text
agent-providers（Provider 抽象）
    ↓

    ↓
```

**结论：工期可行性 ✅（标准团队下 5 个月可交付 v0.3）**

## 四、运维风险评估

| 风险 | 概率 | 影响 | 应对 |
| ---- | ---- | ---- | ---- |
| Provider API 服务中断 | 中 | 高 | Fallback Chain + 离线模式 |
| 本地数据库损坏 | 低 | 高 | 定时备份 + WAL 模式 |
| 版本更新导致配置不兼容 | 中 | 中 | SQLite Migration + 向后兼容配置格式 |
| 第三方 MCP Server 恶意行为 | 低 | 高 | 权限沙箱 + 用户审批 |
| API Key 泄露 | 低 | 极高 | SQLCipher 加密 + 不上传 Key 到任何服务器 |
