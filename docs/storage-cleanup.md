# 安全清理：确认单与恢复区

入口：偏好设置 → 诊断 → 存储与配置 → 清理预览 → **生成清理确认单**。
检查、预览和生成确认单不写配置、不移动文件；移动必须单独确认。

## 用户流程

1. 后端重新检查当前配置和文件，生成最多 20 项的精确清单，不直接执行旧预览样本。
2. 对话框显示数据根、完整相对路径、逐项大小、总量及未覆盖范围。
3. 默认不勾选同意。核对后勾选，再明确点击“确认移入恢复区”。
4. 后端验证一次性 token、确认标志和 5 分钟有效期，重新检查所有条目后再移动。
5. 返回逐项结果及恢复位置。失败或未尝试的条目不会被静默删除。

确认框禁用通用 Enter 快捷确认；Enter 在“取消”按钮上会取消，Escape 也会取消。
Tab 焦点限制在确认框内。取消、切换页面/数据根会丢弃待确认 token，旧异步回调不能继续提交。
已确认且开始执行的操作由后端完成，关闭页面不破坏中途恢复记录。

## 范围与限制

- 只处理当前全局策略认可、封装校验通过且过期的模型/MCP 缓存，以及日期和修改时间
  都超过 30 天的标准 `agent.log.YYYY-MM-DD` / `errors.log.YYYY-MM-DD` 运行日志。
- 数据库、rollout、会话、凭证、工作区、技能、UI 资源、浏览器资料、安全审计和已有备份
  不在范围内。外部、越界、重叠缓存目录不作为来源。
- 文件系统根、用户主目录以及带 `.git` 的仓库根拒绝作为清理数据根，避免误把项目或主目录
  当成 Astro 数据目录。使用 Git 管理整个 Astro home 时也需手动处理，不绕过这个保护。
- 每批最多 20 项；缓存单文件最多 512 KiB，日志最多 8 MiB，文件总量最多 32 MiB。
  候选扫描和执行中的各轮读取分别受预算约束；执行会重复校验，不是只读取一次。
  生成清单最多检查 8192 个直接目录项，采用约 5 秒的条目间预算，不强行中断系统 I/O。
- 生成确认单会读取候选内容以计算 SHA-256，但不回传正文。无法验证或超预算的文件
  不会自动纳入，未列出的文件不会处理；操作后可重新检查下一批。
- 最多保留 2 张未使用确认单。token 仅在当前进程内存中存在，使用一次即消耗，重启后失效。
  同时检查单调时间和墙钟时间，休眠或时钟调整不能无限延长旧确认。

## 文件系统与并发边界

核心为 `home::storage_cleanup`，UI 命令位于 `commands/workspace/storage_cleanup.rs`。
执行 RPC 只接受 token 和确认标志，不接受客户端指定的源路径或目标目录。

规划与执行通过固定目录句柄逐层打开，不跟随中间或末尾软链接。重命名相对于已固定的
目录句柄执行；目录在校验后被替换为外部软链接，不能重定向移动。
快照包含文件句柄身份、长度、修改时间和 SHA-256；第一项移动前整体检查，逐项移动前
再次检查。配置内容、数据根或文件变化，以及迁移中断，都会使旧确认失效。
Unix 打开文件时使用非阻塞标志并验证普通文件类型，避免 FIFO 替换卡住执行线程。

执行使用与设置写入共用的配置锁，以及与缓存写入/容量淘汰共用的缓存锁；取锁失败立即
停止。对不遵守锁的并发修改，移动后再次校验身份：若在最后校验与重命名之间被替换，
文件保留在恢复区并标记 `changed_in_recovery`，不删除，也不盲目覆盖原位置的新文件。

## 恢复区与失败语义

文件进入 `backups/storage-cleanup/<batch-uuid>/`，Unix 上批次目录权限为 0700。
第一项移动前写入完整 `manifest.json`，记录原相对路径、对应 `NN.data`、预计大小、
SHA-256 和状态，随后逐项原子更新。同步文件，并在支持的平台同步目录。

状态包括 `pending`、`moved`、`changed_not_moved`、`move_failed`、`changed_in_recovery`；
结果中的 `not_attempted` 表示后续未尝试项。中断时初始清单及已经移动的文件仍保留。
跨文件系统重命名等失败不退化成“复制后删除”。I/O 错误时保留已有源/目标，不自动重试，
实际位置需对照清单检查原位和恢复区。清单更新失败后停止后续
移动，返回 `manifestComplete=false`，不承诺跨文件事务回滚。

**恢复区不是系统废纸篓，移动不会立即释放磁盘空间。** 恢复区受备份保护，不会被下一次
清理再次选中。这一版不提供永久删除或自动覆盖式恢复。

手动恢复步骤：

1. 停止 Astro 和相关写入进程，打开该批次的 `manifest.json`。
2. 核对实际存在的 `NN.data` 与 SHA-256；中断和变更条目必须人工检查。
3. 原路径没有新文件时才恢复对应文件，不能覆盖已重建的缓存或新日志。
4. 验证成功后是否移除该批次，由用户另行决定，不能直接清空整个备份目录。

旧日志若被不遵守锁的外部进程持有，可能在移动后继续追加到恢复文件；摘要因此可能变化，
但内容仍保留，应停机核对。清理不是对所有进程进行强制冻结。

## 验证

```sh
cargo test -p home --lib storage_cleanup
cargo test -p astro-agent --lib native_cleanup_requires_confirmation
cd apps/desktop
node --test src/lib/settings/storageCleanup.test.ts
npx playwright test storage-cleanup.spec.ts storage-diagnostics.spec.ts
```

实际移动测试只使用专属临时目录，不操作真实用户数据。浏览器交互测试 mock IPC，
验证未勾选、Enter、取消、Escape、过期和重复事件不会意外执行，不调用真实清理。
