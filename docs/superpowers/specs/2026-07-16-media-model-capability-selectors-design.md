# 媒体模型能力选择器设计

## 背景

供应商详情的「媒体」页目前用自由文本配置生图、生视频、语音合成和视觉模型。模型列表已经携带能力元数据，但界面没有复用这些数据，用户可能填入不支持对应任务的模型。

现有 Google `music_gen` 工具已支持 Lyria 3，本次只补充模型能力、供应商配置和界面接入，不新增音乐生成工具。

## 目标

- 将媒体模型文本框改为按能力过滤的选择器。
- 未知能力或能力不匹配的模型不出现在选择器中。
- 增加独立的 `music_gen` 能力和「音乐生成模型」配置。
- 无有效选择时统一回退各媒体工具的内置默认模型。
- 保留 `music_gen` 工具参数 `clip` / `pro` 的单次调用覆盖能力。

## 非目标

- 不根据模型名称在前端猜测能力。
- 不新增媒体模型列表后端接口。
- 不改变本地音乐播放工具 `music`。
- 不扩大支持媒体配置的供应商范围；仍为 Google 和 OpenAI，音乐生成仅 Google。

## 数据模型

`ModelCapabilities` 在 Rust 与 TypeScript 两侧增加 `music_gen: bool`。能力继续由供应商 API 提示与 LiteLLM 元数据合并产生；LiteLLM 条目的 `mode` 含 `music` 时标记 `music_gen`。没有可靠元数据的模型保持 `false`。

供应商配置链路增加可选字符串 `music_model`：

- 前端 `ProviderDto` 与编辑草稿
- Tauri provider DTO、保存输入及 `providers.json`
- Agent 启动时构造的媒体凭证 / 工具上下文

空字符串表示使用内置默认 `lyria-3-clip-preview`，与现有媒体模型字段语义一致。

## 界面

媒体页使用现有 `SelectMenu` 展示五类模型：

| 字段 | 必需能力 | 支持供应商 |
| --- | --- | --- |
| 生图模型 | `image_gen` | Google、OpenAI |
| 生视频模型 | `video_gen` | Google |
| 语音合成模型 | `audio_gen` | Google、OpenAI |
| 音乐生成模型 | `music_gen` | Google |
| 视觉模型 | `vision` | Google、OpenAI |

每个选择器第一项为「内置默认（模型 ID）」，实际值为空。其余选项来自当前供应商已缓存或在线拉取的模型列表，并严格按对应能力过滤。模型列表为空或没有匹配项时，仍保留内置默认项。

已保存值若不在当前能力过滤结果中，草稿自动清空；下一次保存后配置回退内置默认。未知值不作为兼容选项重新插入。

## 音乐模型优先级

现有 `music_gen` 工具继续接受 `model=clip|pro`：

1. 显式 `clip` 映射到 `lyria-3-clip-preview`。
2. 显式 `pro` 映射到 `lyria-3-pro-preview`。
3. 未传 `model` 时使用供应商 `music_model`。
4. `music_model` 为空时使用 `lyria-3-clip-preview`。

这使供应商配置成为默认值，同时保留 Agent 对单次任务的显式覆盖。

## 数据流与状态

进入供应商详情后继续复用现有模型缓存和自动刷新流程。模型列表到达或更新时，媒体选择器重新计算候选项并校验五个草稿值。校验只影响能力不匹配的媒体字段，不修改聊天默认模型。

保存仍由现有供应商保存按钮一次提交全部草稿字段。工具运行时只读取已保存配置，未保存的界面选择不会影响正在运行的 Agent。

## 错误与兼容

- LiteLLM 元数据不可用时不猜测能力，只显示内置默认。
- 在线刷新失败时使用缓存；缓存也为空时仍可保存默认值。
- 旧配置缺少 `music_model` 或模型能力缺少 `music_gen` 时通过 serde / TypeScript 默认值兼容。
- 旧媒体模型值若不再被能力元数据认可，将按用户确认的规则清空并回退默认。

## 测试

- Rust：`music_gen` 能力默认值、序列化兼容、LiteLLM `mode=music_generation` 映射。
- 前端纯函数：按五种能力过滤、未知模型隐藏、无效已保存值清空、默认项始终存在。
- `music_gen`：未指定模型时读取供应商配置；显式 `clip/pro` 优先；空配置回退 clip。
- 现有模型元数据、供应商保存和媒体工具测试保持通过。
