## 目标

1. 在会话侧栏完成单会话的重命名、重新生成标题、归档、取消归档和永久删除。
2. 首轮助手回复完成后异步生成短标题，不阻塞当前对话。
3. 为标题生成、上下文压缩、智能审批、入梦、记忆审查提供统一的辅助模型设置。
4. 复用现有 SessionStore、Provider、Keyring 和 `auxiliary` 配置体系，不引入新的配置数据库。

## 非目标

- 回收站、软删除恢复和批量删除。
- 为不调用 LLM 的网页抓取、技能搜索或 MCP 增加无效模型配置。
- 按 Agent 或按会话覆盖辅助模型。
- 级联删除会话关联的用户产物。
- 重做 Provider、模型缓存或主模型选择体系。

## 决策摘要

| 项目 | 决策 |
|------|------|
| 删除 | 二次确认后永久删除，不提供恢复 |
| 归档 | 独立“已归档”列表，可查看、继续对话并取消归档 |
| 标题触发 | 首轮助手回复完成后异步生成 |
| 标题操作 | 支持手动重命名和主动重新生成 |

| 降级 | 指定辅助模型不可用或调用失败时回退当前主模型 |
| 配置位置 | 扩展现有 `config.yaml` 的 `auxiliary.*` |

## 1. 架构与职责

### 会话管理

沿用现有三层调用链：

```text
React 会话列表 / hooks
  → Tauri commands
  → SessionStore
  → SQLite state.db
```

- `SessionStore` 负责归档字段、列表过滤、标题条件更新和事务性删除。
- Tauri commands 提供重命名、重新生成、归档、取消归档和删除入口。
- React 负责菜单、确认弹窗、列表页签、乐观状态与失败回滚。
- SQLite 仍是会话权威数据源；localStorage 只缓存当前会话。

### 辅助模型

扩展现有 `AuxiliaryConfig` 和 `resolve_auxiliary`，统一解析五类任务：

```text
辅助任务
  → 读取 auxiliary.<task>
  → auto：当前主模型
  → explicit：指定 Provider/Model
  → 显式模型不可用或调用失败：当前主模型
```

Provider 凭据继续保存在现有 Provider 配置与 Keyring 中。辅助配置仅保存 Provider ID 和 Model ID。

## 2. 数据模型

### 会话归档

在 `sessions` 表新增可空字段：

```text
archived_at TEXT NULL
```

- `NULL` 表示普通会话。
- 非空表示归档时间。
- 归档不修改 `ended_at` 或 `end_reason`，不改变会话可写性。
- 普通列表默认排除归档；归档列表只查询 `archived_at IS NOT NULL`。
- 归档与压实是两个正交状态：压实描述生命周期，归档描述用户整理行为。

本次 schema 升级必须使用非破坏性迁移：检测旧表缺少 `archived_at` 时执行
`ALTER TABLE sessions ADD COLUMN archived_at TEXT` 并更新 schema version。不得沿用删库重建路径，
因为会话管理功能不能以丢失已有会话为升级代价。

### 标题

继续使用现有 `sessions.title`：

- 自动生成仅在标题为空时写入。
- 手动重命名可覆盖现有标题。
- “重新生成标题”是用户显式操作，可以覆盖现有标题。
- 标题写入继续遵守现有唯一性后缀策略。

### 辅助模型配置

配置形状：

```yaml
auxiliary:
  title_generation: { provider: auto, model: auto }
  compaction: { provider: auto, model: auto }
  smart_approval: { provider: auto, model: auto }
  dreaming: { provider: auto, model: auto }
  background_review: { provider: auto, model: auto }
  background_review_enabled: false
```

配置写回必须保留 `config.yaml` 中 memory、hooks、delegation 等其它键。

## 3. 会话操作

### 重命名

会话卡片菜单提供“重命名”。提交非空标题后调用 Store 的标题写入能力，成功后原位刷新列表。空白标题不提交。

### 重新生成标题

用户点击“重新生成标题”后，读取会话中最早一轮用户与助手文本，调用标题辅助模型并覆盖现有标题。没有完整首轮时禁用该操作。

### 归档与取消归档

归档只设置 `archived_at`。当前会话归档后仍保持当前聊天界面，不强制切走；它从普通列表移到“已归档”列表。取消归档清空 `archived_at`。

### 永久删除

删除前弹出二次确认，显示会话标题并明确提示不可恢复。确认后：

1. 释放该会话对应的活跃 AgentLoop。
2. 在数据库事务中删除会话消息、搜索索引和会话记录。
3. 不修改或删除关联产物及其文件；它们继续通过文件空间访问，会话关联仅作为历史元数据保留。
4. 若删除当前会话，清理 localStorage、pending interrupts 和当前 UI 状态，进入空白新会话。

删除失败时不修改前端状态，并显示非阻塞错误提示。

## 4. 自动标题流程

首轮完整回复的 `Done` 事件到达后触发 fire-and-forget 标题任务：

1. 确认当前会话标题仍为空。
2. 读取首轮用户与助手的纯文本内容；忽略 tool、reasoning 和空消息。
3. 通过 `title_generation` 路由选择辅助模型。
4. 要求模型只返回简短标题，不返回引号、Markdown 或解释。
5. 清理空白、换行和包裹符号，并按固定长度上限截断。
6. 使用“仅标题仍为空时更新”的条件写入，避免覆盖并发手动重命名。
7. 发出会话元数据变更事件，让侧栏原位更新。

生成期间继续显示首条用户消息摘要。两次模型调用均失败时保留摘要并记录日志，不弹阻塞错误。

## 5. 辅助模型路由

五类任务都使用统一接口，调用方提供当前主模型作为降级目标：

| 任务 | 行为 |
|------|------|
| 标题生成 | 首轮后异步调用；失败不影响对话 |
| 上下文压缩 | 替换当前直接使用激活主模型的路径 |
| 智能审批 | 替换当前复用会话主模型的路径 |
| 入梦 | 迁移到统一解析与降级逻辑 |
| 记忆审查 | 迁移到统一解析与降级逻辑 |

降级规则：

1. `auto/auto` 直接使用当前主模型。
2. 显式 Provider/Model 先验证 Provider 已启用且凭据可用。
3. 显式模型解析失败或调用失败时尝试当前主模型一次。
4. 后台任务最终失败只记录日志或事件。
5. 压实和智能审批属于前台流程，最终失败时向用户报告，并保持原状态。

## 6. 界面设计

### 会话侧栏

- 会话卡片悬停显示 `⋯` 菜单。
- 普通会话菜单：重命名、重新生成标题、归档、永久删除。
- 归档会话菜单：重命名、重新生成标题、取消归档、永久删除。
- 列表顶部提供“会话 / 已归档”切换。
- 搜索仅过滤当前页签。
- 当前选中态、玻璃效果和卡片密度延续现有视觉语言。

永久删除使用确认弹窗，不提供批量入口。

### 辅助模型设置

设置页增加“辅助模型”面板，参考所给截图的纵向任务列表：

- 每行包含任务名、简短说明和当前 Provider/Model。
- 操作包含“设为主模型”和“更改”。
- “更改”复用现有 Provider 分组模型选择器。
- 顶部提供“全部重置为主模型”。
- 显式模型当前不可用时显示警告，但保留配置；运行时自动降级。

## 7. 并发、错误与一致性

- 自动标题使用条件更新，防止覆盖手动重命名。
- 会话操作成功后再提交前端最终状态；失败保留原列表。
- 删除时先释放运行时会话，避免数据库删除后 AgentLoop 再次写回。
- 删除当前会话时同步清理 localStorage，避免刷新后恢复幽灵会话。
- 列表操作完成及标题更新后统一触发会话列表失效或元数据事件。
- 辅助模型配置写入使用现有串行/合并模式，避免覆盖其它 YAML 配置。

## 9. 验收标准

1. 会话可以重命名、重新生成标题、归档、取消归档和永久删除。
2. 普通列表默认不显示归档会话，归档列表可独立搜索和恢复。
3. 升级数据库 schema 不会删除已有会话或消息。
4. 删除当前会话后不会在 localStorage 或数据库中重新出现。
5. 新会话首轮完成后自动生成标题，且不会覆盖用户并发手动标题。
6. 五类辅助任务均可选择自动或指定模型。
7. 指定辅助模型不可用时回退主模型，且后台失败不打断聊天。
8. 网页抓取、技能搜索和 MCP 不出现无效模型配置项。
9. 设置页与现有 Provider 选择器、会话侧栏视觉保持一致。
