## 一、数据目录与路径

| 术语 | 统一值 | 说明 |
| ---- | ---- | ---- |
| 应用数据根目录 | `~/.astro/` | 不使用 `~/.astro-agent/` |
| 数据库文件 | `~/.astro/agent.db` | 单一全局数据库，通过 `workspace_id` 隔离 |
| 审计日志 | `~/.astro/audit.jsonl` | 不使用 `~/.astro-agent/audit.jsonl` |
| 工作区目录 | `~/.astro/workspaces/<id>/` | 每个工作区独立物理目录 |
| Secrets 目录 | `~/.astro/secrets/` | API Key 加密文件存储（Keychain 不可用时的回退） |

## 二、API Key 存储方案

统一为**两层方案**：

| 层级 | 机制 | 适用场景 |
| ---- | ---- | ---- |
| 优先 | 系统 Keychain（macOS Keychain / Windows Credential Manager / Linux Secret Service） | 主方案，通过 `keyring` crate 访问 |
| 回退 | `~/.astro/secrets/<provider_id>.key` 加密文件（AES-256-GCM，密钥由主密码派生） | Keychain 不可用时（如无桌面环境的 Linux） |

- ~~SQLCipher 数据库内存储~~

## 三、核心数据结构

### 3.1 Message 结构

统一为多模态版本：

```rust
pub struct Message {
    pub id: Uuid,
    pub role: MessageRole,
    pub content: Vec<ContentPart>,  // 统一为多模态，不使用 String
    pub name: Option<String>,
    pub reasoning_content: Option<String>,
    pub token_count: u32,
    pub is_pinned: bool,
    pub slot: ContextSlot,
    pub created_at: i64,
}
```

不使用 `content: String` 的纯文本版本。

### 3.2 RiskLevel 枚举

```rust
pub enum RiskLevel {
    Low,      // 对应 L1：自动执行，无需审批
    Medium,   // 对应 L2：弹窗确认，30s 超时自动拒绝
    High,     // 对应 L3：强制手动确认，无超时
    Critical, // 对应极高风险：强制任务暂停
}
```

映射关系：

| 代码枚举 | 文档标签 | 行为 |
| ---- | ---- | ---- |
| `Low` | L1 | 自动执行 |
| `Medium` | L2 | 弹窗，30s 超时自动**拒绝** |
| `High` | L3 | 弹窗，**无超时**，必须人工 |
| `Critical` | 极高 | 强制暂停任务 |

不使用 `Safe`、`L1/L2/L3` 作为代码枚举值。

### 3.3 Skill 状态枚举

以 `01-Skills系统详细设计.md` 为权威定义：

### 3.4 MemoryEntry 分类

统一使用业务分类（Schema 为权威来源），DTO 层使用相同值：

```rust
pub enum MemoryCategory {
    DailyEvent,   // 日常事件
    CaseLesson,   // 案例教训
    WorkPattern,  // 工作模式
    CoreInsight,  // 核心洞察
    General,      // 通用（默认值）
}
```

不使用认知科学分类（~~`Episodic/Semantic/Procedural/Working`~~），该分类仅作为架构文档中的概念说明，不进入代码。

### 3.5 ErrorCategory 枚举

错误恢复策略分类（见 `06-安全与基础设施/06-错误处理详细设计.md`）：

```rust
pub enum ErrorCategory {
    Retryable,    // 可自动重试（网络超时、429 限流、5xx 服务端错误）
    UserFixable,  // 用户可修复（API Key 无效、配额耗尽、参数错误）
    SystemFatal,  // 系统致命错误（数据库损坏、磁盘空间不足）
    Transient,    // 瞬时错误（DNS 解析失败、连接重置）
}
```

每个 `AstroError` 实例必须携带 `ErrorCategory`，用于决定重试策略和用户提示。

### 3.6 GuardState 枚举

HumanGuard 状态机状态（见 `06-安全与基础设施/02-人工接管与授权详细设计.md`）：

```rust
pub enum GuardState {
    Running,   // Agent 正常运行，自动审批 L1 操作
    Pending,   // 等待用户对 L2/L3 操作的审批决定
    Paused,    // 用户主动暂停 Agent 执行
    Takeover,  // 完全接管模式，Agent 仅观察，人工直接操作
}
```

状态转移：`Running` -> `Pending`（触发审批）-> `Running`（批准/拒绝后）；`Running` -> `Paused`（用户暂停）-> `Running`（用户恢复）；`Running` -> `Takeover`（用户接管）-> `Running`（drain-on-release 释放）。

### 3.7 CheckpointType 枚举

检查点类型（见 `01-核心引擎层/10-Checkpoint与状态快照详细设计.md`）：

```rust
pub enum CheckpointType {
    Auto,      // 自动检查点：每轮工具执行完成后自动创建
    Manual,    // 手动检查点：用户通过 /checkpoint 命令显式创建
    Workflow,  // 工作流检查点：DAG 节点执行完成时创建，用于断点续传
}
```

## 五、Agent 生命周期与运行时

### 5.1 AgentInstance

Agent 实例模型（见 `01-核心引擎层/07-Agent生命周期详细设计.md`）：

```rust
pub struct AgentInstance {
    pub id: Uuid,
    pub session_id: Uuid,
    pub workspace_id: String,
    pub state: AgentState,           // 7 阶段状态机
    pub config: AgentConfig,
    pub created_at: i64,
}
```

每个 `AgentInstance` 对应一次完整的 Agent 会话生命周期（初始化 -> 就绪 -> 运行 -> 暂停/等待 -> 完成/失败/取消）。

### 5.2 AgentLifecycle

Agent 生命周期的 7 个阶段：`Initializing` -> `Ready` -> `Running` -> `WaitingForApproval` / `Paused` -> `Completed` / `Failed` / `Cancelled`。

### 5.3 AgentSessionManager

管理多个 `AgentInstance` 的并发会话，负责会话创建、恢复、切换、持久化。持有所有活跃 Agent 实例的注册表，支持崩溃恢复时自动扫描 `status = 'running'` 的中断会话。

## 六、Hooks 系统

### 6.1 HookEvent

Hooks 系统的生命周期事件类型（见 `01-核心引擎层/08-Hooks系统详细设计.md`）：

~~以下旧枚举已废弃，不再使用：~~

~~`AgentStart`、`AgentStop`、`ConversationStart`、`ConversationEnd`、`MessagePreSend`、`MessagePostReceive`、`ToolPreExecute`、`ToolPostExecute`、`ApprovalRequest`、`ApprovalResponse`、`MemoryWrite`、`MemoryRead`、`SkillPreExecute`、`SkillPostExecute`、`ErrorOccurred`、`SubAgentSpawn`、`SubAgentComplete`、`ContextCompress`~~

Hook 事件已对齐 Codex V2 canonical 名称（PascalCase 字符串精确匹配），分两组：

**Codex 公开事件（11 个）：**

| Canonical 名称 | 含义 |
| ---- | ---- |
| `PreToolUse` | 工具使用前 |
| `PermissionRequest` | 权限请求 |
| `PostToolUse` | 工具使用后 |
| `PreCompact` | 上下文压缩前 |
| `PostCompact` | 上下文压缩后 |
| `SessionStart` | 会话开始 |
| `SessionEnd` | 会话结束 |
| `UserPromptSubmit` | 用户 prompt 提交 |
| `SubagentStart` | Agent Thread 启动 |
| `SubagentStop` | Agent Thread 关闭 |
| `Stop` | Agent 准备停止 |

**Astro 扩展事件：**

`PreLlmCall`、`PreApiRequest`、`PostApiRequest`、`TransformTerminalOutput`、`TransformToolResult`、`TransformLlmOutput`、`PostLlmCall`、`PostApprovalResponse`、`PreGatewayDispatch`、`SessionReset`、`SessionFinalize`、`GatewayStartup`、`AgentEnd`、`CommandNewChat`

权威定义见 [`docs/hooks.md`](../hooks.md)。

### 6.2 HookPipeline

Hook 执行管道，按注册顺序串行执行所有匹配的 Hook。支持中断（Hook 返回 `HookResult::Abort` 时终止管道并阻止被 Hook 的操作）。

### 6.3 HookRegistry

全局 Hook 注册表，管理所有已注册的 Hook 实例。支持按 `HookEvent` 类型索引，支持动态注册/注销。从 `hooks.toml` 配置文件加载用户自定义 Hook（Shell 脚本或 WASM 模块）。

### 6.4 HookContext

传递给每个 Hook 的执行上下文，包含当前事件类型、触发事件的数据载荷、Agent 状态引用等。Hook 可通过 `HookContext` 读取上下文信息或修改载荷（如消息过滤）。

### 6.5 内置 Hook 类型

| Hook | 说明 |
| ---- | ---- |
| ObservabilityHook | 自动记录结构化日志和 SpanTree 追踪数据，监听所有事件类型 |
| SecurityCheckHook | 在 `ToolPreExecute` 时执行安全检查（PermissionSet 验证、风险等级评估） |
| PrivacyFilterHook | 在 `MessagePreSend` 时执行 PII 过滤（SensitiveFilter），阻止敏感数据发送到 Provider |

## 七、自主决策与行为进化

### 7.1 BehaviorEngine

行为策略引擎（见 `01-核心引擎层/11-自主决策与行为进化详细设计.md`），根据历史行为模式和用户反馈动态调整 Agent 的决策策略。管理工具选择偏好、回复风格、主动决策阈值等行为参数。

### 7.2 FeedbackCollector

反馈信号收集器，从多种来源捕获用户反馈：显式反馈（点赞/点踩/文字评价）、隐式反馈（采纳/重试/编辑/忽略）、行为信号（会话时长/消息数/工具调用成功率）。收集的信号归一化后输入 `PreferenceLearner`。

### 7.3 PreferenceLearner

用户偏好学习模型，基于 `FeedbackCollector` 收集的信号进行在线学习。维护用户画像（工具偏好、回复长度偏好、主动性阈值等），周期性将学习结果写入 `USER.md` 快照。

## 八、Checkpoint 与状态快照

### 8.1 Checkpoint

检查点快照（见 `01-核心引擎层/10-Checkpoint与状态快照详细设计.md`），记录某一时刻的完整 Agent 状态，用于状态恢复和断点续传。

```rust
pub struct Checkpoint {
    pub id: Uuid,
    pub conversation_id: Uuid,
    pub checkpoint_type: CheckpointType,   // Auto / Manual / Workflow
    pub round_number: u32,
    pub state_snapshot: Vec<u8>,           // 序列化的 Agent 状态
    pub created_at: i64,
}
```

自动检查点在每轮工具执行完成后创建；手动检查点由用户通过 `/checkpoint` 命令创建；工作流检查点在 DAG 节点完成时创建。恢复时支持覆盖当前状态或创建分支。

## 九、存储层

### 9.1 StorageManager

统一存储管理器（见 `06-安全与基础设施/09-存储层详细设计.md`），管理 `~/.astro/` 目录下的所有文件存储操作。职责包括：目录结构初始化、路径解析、存储配额管理、临时文件清理。

### 9.2 BlobStore

内容寻址的二进制对象存储，用于存储文件附件、媒体内容、导出包等大对象。使用 SHA-256 作为内容地址，自动去重。存储路径：`~/.astro/blobs/<sha256_prefix>/<sha256>`。

### 9.3 CacheManager

多级缓存管理器，管理内存 LRU 缓存和磁盘缓存。缓存对象包括：LLM 响应缓存、Tantivy 索引缓存、MCP 工具 Schema 缓存、嵌入向量缓存。支持按 TTL 或容量上限自动淘汰。

## 十、安全边界

### 10.1 SecurityPolicy

安全策略聚合（见 `06-安全与基础设施/04-安全边界详细设计.md`），持有所有 Guard 实例，提供统一的安全检查入口。

### 10.2 PathGuard

文件路径访问控制器，限制 Agent 的文件读写范围。默认白名单：工作区目录 + `~/.astro/` + `/tmp/`。阻止访问：`~/.ssh/`、`~/.gnupg/`、系统目录等敏感路径。支持用户自定义白名单/黑名单规则。

### 10.3 DomainGuard

网络域名访问控制器，限制 Agent 可访问的外部域名。用于 MCP Server 的网络请求审查和 Web 工具的域名白名单。

### 10.4 ShellGuard

Shell 命令执行控制器，拦截高危命令（`rm -rf /`、`sudo`、`chmod 777` 等）。对所有 Shell 执行进行风险评估并分配 RiskLevel。

### 10.5 PromptGuard

提示注入防御器，对外部输入（MCP 返回、用户上传文件、工具输出）进行注入检测。四层防御：Input Sanitization（正则过滤） + System Prompt Hardening（随机分隔符） + Output Monitoring（行为异常检测） + Canary Token Detection（金丝雀令牌检测）。

## 十一、成本与预算

### 11.1 BudgetManager

三级预算管理器（见 `01-核心引擎层/05-成本预算控制详细设计.md`）：

| 级别 | 作用域 | 说明 |
| ---- | ---- | ---- |
| 全局预算 | 整个应用 | 月度/日度总额上限 |
| 工作区预算 | 单个工作区 | 工作区级别的费用隔离 |
| 任务预算 | 单次任务/对话 | 单次对话的 Token 上限 |

超支时触发渐进降级：警告 -> 降级到廉价模型 -> YOLO 强制关闭 -> 任务暂停。

### 11.2 CostEstimator

费用预估器，在 LLM 调用前根据当前 Token 数和模型单价预估本次调用费用。用于 `check_before_call` 拦截和预算预警。

### 11.3 DegradationManager

渐进降级管理器，当预算接近上限或 Provider 不可用时，自动执行降级策略：切换到更廉价的模型、减少上下文窗口、关闭 YOLO 模式、暂停非关键后台任务。

## 十二、知识库与检索

### 12.1 KnowledgeService

知识库服务（见 `03-记忆与上下文/04-知识库RAG详细设计.md`），统一管理文档导入、分块、向量化、检索的完整管道。对外提供 `knowledge_manage` 工具接口。

### 12.2 HybridRetriever

混合检索器，融合 BM25（tantivy）和向量检索（sqlite-vec）两路结果，使用 RRF（Reciprocal Rank Fusion）进行排序融合。

```rust
pub struct HybridRetriever {
    pub bm25_weight: f64,      // 默认 0.4
    pub vector_weight: f64,    // 默认 0.6
    pub top_k: usize,          // 默认 10
    pub rrf_k: f64,            // RRF 常数，默认 60.0
}
```

### 12.3 RecursiveChunker

递归分块器，根据文档类型自动选择分块策略：

| 文档类型 | 分块策略 | 说明 |
| ---- | ---- | ---- |
| Markdown | ByParagraph + ParentChild | 按段落分块，保留父子层级关系 |
| 源代码 | tree-sitter | 按 AST 节点（函数/类/模块）分块 |
| PDF/纯文本 | SlidingWindow | 滑动窗口分块（默认 512 token，128 token 重叠） |

## 十三、工作流系统

### 13.1 WorkflowExecutor

工作流 DAG 执行引擎（见 `04-工具与扩展生态/05-工作流DAG执行引擎设计.md`），使用 Kahn 算法进行拓扑排序和并发调度。支持节点类型：LLM 调用、工具执行、条件分支、循环、子工作流、人工审批。

### 13.2 TriggerManager

工作流触发器管理器（见 `04-工具与扩展生态/07-工作流触发器详细设计.md`），管理所有触发器的生命周期（注册/启用/禁用/删除）。触发器类型：

| 类型 | 说明 |
| ---- | ---- |
| CronTrigger | 基于 cron 表达式的定时触发 |
| WebhookTrigger | HTTP 端点触发（本地监听） |
| EventTrigger | 事件驱动触发（文件变更、Agent 事件等） |
| ChainTrigger | 链式触发（工作流完成后触发另一个工作流） |

### 13.3 DAGEngine

DAG 编译与验证引擎，负责将工作流编辑器的可视化节点图编译为可执行的 DAG。执行环形依赖检测、节点类型验证、变量模板解析。

## 十四、Skills 系统扩展

### 14.1 SkillCompiler

Skill 编译器，将工作流 DAG 编译为独立 Skill（SKILL.md 格式）。编译过程：DAG 验证 -> 参数提取 -> 模板生成 -> 测试用例生成。

### 14.2 SkillOverrides

Skill 配置覆盖机制，允许用户在工作区级别覆盖全局 Skill 的配置（如默认参数、执行模型、超时时间）。工作区级覆盖优先于全局默认。

### 14.3 动态上下文注入

Skills 系统支持两种动态内容机制：

| 语法 | 名称 | 说明 |
| ---- | ---- | ---- |
| `` !`cmd` `` | 命令注入 | 执行 Shell 命令，将 stdout 注入 Skill 上下文（如 `` !`git diff --cached` ``） |
| `$ARGUMENTS` | 参数替换 | 将用户调用 Skill 时传入的参数替换到 Skill 内容中 |

命令注入在 Skill 被选中后、发送给 LLM 前执行，结果缓存 60 秒。

## 十九、agent-core crate 职责

agent-core 包含：
1. **核心 trait 定义**（Tool、Skill、TextClient 等）
2. **多模态类型定义**（Message、ContentPart、MediaContent 等）
3. **内置工具实现**（`tools/builtin/` 目录下的 22 个工具）

agent-core **不是**"纯 trait 定义层"，它包含具体实现。trait 定义在 `traits/` 目录，具体实现在 `tools/builtin/` 目录，两者物理分离。
