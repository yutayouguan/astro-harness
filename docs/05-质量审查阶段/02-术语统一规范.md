# 术语统一规范

> 文档状态：持续同步
>
> 阶段：质量审查
>
> 更新日期：2026-09-04

本文是 Astro 正式设计文档的权威术语表。类型、枚举、路径或协议字段发生变更时，当前源码和迁移测试优先于本文。

## 1. Agent Harness

### 1.1 核心定义

> **Agent = Model + Harness**

| 术语 | 统一定义 | 不应混用为 |
| --- | --- | --- |
| Model | 负责推理、决策、文本和工具调用意图 | 真实工具执行器 |
| Agent Harness | 包裹 Model，负责多步循环、上下文、工具、安全、恢复、观测和运行环境的工程系统 | 单一 prompt、SDK 或 crate |
| Scaffold | 模型在当前 step 看到的基础指令、动态上下文、工具 schema 和输出契约 | 完整 Harness |
| Framework | 用于构建 Agent 的组件和 API 集 | 生产级 Harness 的全部能力 |
| Orchestrator | 多 Agent/多任务的协调层 | 单 Agent 内层 sampling loop |
| Gateway | 模型或工具流量的鉴权、路由和边界 | 业务状态机 |

标准执行循环写作 **Reason → Act → Observe → Reason**。

### 1.2 运行层级

| 术语 | 统一含义 | 当前类型 |
| --- | --- | --- |
| Thread | 长生命周期会话 actor | `AstroThread` |
| Session | 会话共享状态和服务 | `Session`；`AgentLoop` 仅是兼容别名 |
| Task | 可取消的一次会话工作 | `SessionTask`、`RegularTask` |
| Turn | 一条用户意图从提交到终态的执行 | `TurnContext` |
| Step | 一次模型 sampling 和其生成的工具执行 | `StepContext` |
| Attempt | 一次真实工具/子进程执行尝试 | `SandboxPolicy`/network lease 的归属单元 |

## 2. Prompt 与 Provider

| 术语 | 统一用法 |
| --- | --- |
| `PromptContract` | 类型化 scaffold：`base_instructions`、角色化 `context`、`context_sections`、`usage` |
| base instructions | 稳定基础指令，不与工具 schema 拼接 |
| dynamic context | 带来源/角色/预算的 AGENTS、TOOLS、Memory、Skill、模式等上下文 |
| `ResponsesRequest.tools` | Agent Responses 原生工具输入，不是 system prompt 文本 |
| `ModelTarget` | 一个 Provider/model 调用目标；Session 可持有 primary + fallback 链；名称不暗示 Chat Completions |
| `AuxiliaryTask` | Compaction、Dreaming、SmartApproval、TitleGen 等非主回答模型任务 |
| `StreamChunk` | 跨 Provider 统一的 text/reasoning/tool/usage/error 流事件 |
| turn aggregate usage | 当前用户 turn 内多次 sampling 用量之和，用于计费与 `TokenCount` |
| latest sampling usage | 最近一次 Provider sampling 的 usage，用于上下文占用校准 |
| provider reported | Provider 原始 `total_tokens`存在，top-line 直接使用该值 |
| provider recomputed | Provider 有分项但无 total，由规范化分项重算 |
| local estimate | Provider usage 不可用时，按 prompt/history/tool schema 字符数估算 |
| `TokenUsageRecord` | rollout 中的 durable usage checkpoint；同时保存 latest、cumulative 与可选 compaction response id |
| `persistent` reasoning | OpenAI 模型目录门控的本地 effort；wire 值为 `disabled`，其他 Provider 不透传 |

`reasoning_tokens` 一律是 `output_tokens` 子集；`cache_read_tokens`/`cache_write_tokens` 是 input 明细。子集用于解释和差异化计价，不重复加入 total。

## 3. 工具

### 3.1 原生定义

| 术语 | wire type | 语义 |
| --- | --- | --- |
| Function | `function` | JSON Schema 结构化参数 |
| Freeform | `custom` | 原始文本 + grammar |
| Namespace | `namespace` | 具有稳定域名的子工具集 |
| ToolSearch | `tool_search` | 客户端搜索并激活 Deferred tools |
| WebSearch | `web_search` | Provider-hosted 搜索；与 Astro 本地 `web_search` Function 区分 |

### 3.2 暴露和授权

| 术语 | 含义 |
| --- | --- |
| Direct | 直接进入当前模型工具 schema |
| Deferred | 只能被 `tool_search` 发现，激活后在下一 step 可见 |
| Hidden | 不向模型或 `tool_search` 暴露 |
| ModelOnly | 可向模型暴露，不在用户工具 UI 展示 |

**Deferred 是可见性，不是授权。** 工具是否可执行仍由 StepContext、interaction mode、approval、sandbox、hooks 和当前 attempt 决定。

### 3.3 工具命名

- 内置工具使用 canonical registered name。
- Namespace 的 Responses 规范身份是分离的 `(namespace, name)`，例如 `namespace = cron` + `name = add`；`cron.add` 只是人类可读投影。
- 默认 Function / Custom 命名空间为 `functions`；`None`、空字符串与 `functions` 在路由时等价。
- MCP 模型身份使用 `namespace = mcp__{server_id}` + `name = {tool_name}`；`mcp__{server_id}__{tool_name}` 仅是 `McpHub` 内部执行键。
- Namespace 不降级为 Function-only Provider 的展平名；`namespace.child` 和 `namespace__child` 均不能作为模型顶层直调别名。
- Code Mode 可在当前 Step 快照内临时生成 JavaScript 标识符，但不改写 Responses 历史中的 namespace 和 child name。

## 4. 协议与事件

| 术语 | 统一含义 |
| --- | --- |
| `Op` | 向 Thread 提交的控制或输入操作 |
| `Submission` | 带稳定 submission id 的 `Op` |
| `EventMsg` | Harness 向外发布的统一事件 |
| `TurnItem` | 可持久化/投影的结构化 turn 项 |
| rollout | append-only 执行事件事实源 |
| projection | 从 rollout/event 构建的 SessionStore、gRPC 或 UI 查询视图 |
| live boundary | 历史 snapshot 与实时事件之间的去重/接续边界 |
| `ThreadSettingsApplied` | provider/backend/model/reasoning 的 durable 设置快照，供冷/热 Thread 恢复 |
| `ExtensionSnapshot` | 单个 turn 冻结的扩展/MCP/Skills/Hooks/toolsets 视图 |
| extension reconcile | 比较快照并把变更排到下一 turn，不替换 active snapshot |
| MCP event-stream manager | process-owned 订阅生命周期基础；具体 Server opener/UI 尚未接线 |

Core EventBus、SessionEventHub 和单独的 `multi_turn_to_chat_event` 不得再作为现行权威架构术语。

## 5. 子 Agent 与编排

| 术语 | 统一用法 |
| --- | --- |
| Agent Thread | 拥有真实 Session 时间线的子 Agent 任务 |
| Agent Graph | 从 root 开始的父子任务拓扑 |
| mailbox | Agent 间持久消息队列 |
| `send_message` | 只入队，不启动新 turn |
| `followup_task` | 入队并启动/恢复目标 turn |
| worktree | 显式桌面多任务隔离能力，不是 subagent 默认行为 |

`delegate_task`、`delegate_async`、`Supervisor`、`DelegateRunner`、`agent_spawn` 均不再是现行模型工具或运行时契约。

## 6. 安全与控制

| 术语 | 统一含义 |
| --- | --- |
| `HitlGate` | 将需要用户回答的工具执行 park 在 oneshot 上 |
| `PauseControl` | 流式/turn 暂停与取消传播 |
| `SessionApprovalCache` | 当会话审批决策缓存 |
| `SandboxPolicy` | 一次子进程 attempt 的文件系统/网络边界 |
| managed network lease | 仅归属当前 attempt 和精确 loopback port 的代理能力 |
| policy denial | 带结构化决策来源的拒绝，不是普通 I/O 错误 |

`RiskLevel` 和 `GuardState` 不再是当前全局统一枚举；设计文档应引用具体工具的 approval requirement、MCP approval、interaction mode 和实际控制类型。

## 7. Responses 历史与 UI 投影

| 术语 | 统一用法 |
| --- | --- |
| `ResponseItem` | Agent sampling、rollout、SessionStore 和 Desktop history RPC 共享的 canonical item |
| `StoredResponseItem` | SessionStore 中的 item + 索引元数据；不是另一份消息模型 |
| `ConversationEntry` | React 渲染边界从 `ResponseItem` 临时投影的展示条目；不持久化、不回传 Agent |
| `ChatCompletionMessage` | 仅属于非 Agent Chat Completions/Anthropic/Gemini 兼容入口 |

禁止定义或恢复泛化 `Message`、`Role`、`MessageContent` 作为 Agent history。压缩、spill 和搜索索引都只产生 `ResponseItem` 的可重建视图，不替换原生 item。

### 7.1 命名规则

- 协议与存储文件按原生对象命名：`response_item.rs`、`response_items.rs`、`response_input.rs`。
- Agent 执行周期使用 `turn` / `step`，不用 `chat` / `message` 代指协议对象。
- 非 Agent 兼容层必须显式带 `chat_completion` / `ChatCompletion` 前缀。
- UI 可使用产品词 `ChatView`；但数据类型使用 `ConversationEntry`，投影函数使用 `projectResponseItemsToEntries`。

## 8. 数据路径

| 术语 | 统一路径/规则 |
| --- | --- |
| 运行数据根 | `$ASTRO_MEMORY_DIR` 或 `~/.astro` |
| canonical 数据库目录 | `{base}/data/`；统一由 `agent-home` 路径 resolver 生成 |
| 旧路径兼容 | 仅由 workspace 启动迁移读取；生产 store 不得再直接打开旧路径；双库并存时 fail closed |
| rollout 目录 | `{base}/sessions/rollouts/` |
| 记忆子系统 | `{base}/memory/` |
| Agent 配置 | `{base}/agents/default/` 或其他 Agent 目录 |
| 默认工作区 | `{base}/workspace` |
| 其他 Agent 工作区 | `{base}/workspace-{agent_id}` |

核心数据库职责：

- `state.db`：Session/message/billing/FTS 投影；
- `subagents-v2.db`：Agent Graph/mailbox/status；
- `usage.db`：用量与成本事件；
- `artifacts.db`：文件空间索引；
- `knowledge.db`：知识内容 FTS；
- `cron_v1.db`：定时任务运行记录。

上述六个 SQLite 职责库均位于 `{base}/data/`；rollout 事件文件仍位于 `{base}/sessions/rollouts/`，不与 Session SQLite 投影混为一谈。

不再使用“单一 `agent.db` 是所有 Agent 状态事实源”的表述。

## 9. 状态标记

设计文档必须显式使用以下标记：

- **已实现**：当前源码及测试可证明；
- **部分实现**：主链存在，但协议分支或 UI 投影不完整；
- **目标设计**：尚无可执行路径；
- **历史参考**：仅说明决策演进。

`docs/superpowers/plans/`、`docs/superpowers/specs/` 和 `_v0.3规划/` 默认是时点记录，不作为当前实现契约。
