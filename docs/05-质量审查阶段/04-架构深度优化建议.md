## 高优先级（编码初期解决）

### H1. Prompt 注入分层防御

当前 `PromptGuard::scan()` 仅 3 条启发式规则，在真实对抗中近乎无效。

**三层防御体系**：

1. **结构化隔离（加强）**：所有外部数据（MCP 返回、用户上传文件内容）必须通过 `ContentPart::ToolResult { is_external: true }` 注入，所有 Provider 实现必须将其映射为 tool role message 而非拼接到 user message
2. **LLM 二次检测**：高风险工具返回的大段文本，用轻量 LLM（Haiku）做"是否包含操纵指令"的二分类，成本约 $0.001/次
3. **行为异常检测**：Agent 处理工具结果后突然要求执行未计划的高风险操作时，自动触发暂停

### H2. 冷启动分级加载

将启动分为三阶段：

| 阶段 | 时间目标 | 加载内容 |
| ---- | ---- | ---- |
| Phase 1 | < 500ms | UI 渲染 + 基础配置 + SQLite 连接池 |
| Phase 2 | < 2s | 内置工具注册 + 记忆快照加载 |
| Phase 3 | 后台 | Tantivy 索引（从磁盘恢复，非重建） + MCP 懒连接 + WASM AOT 缓存 |

关键优化：Tantivy 索引持久化到磁盘 + MCP Server 首次调用时才建连 + WASM 预编译为 `.cwasm`

### H3. 文件级乐观锁（多子 Agent 并发安全）

多子 Agent 并发 `file_write` 同一文件时可能静默覆盖。

```rust
pub async fn file_write_safe(path: &Path, content: &str, expected_hash: Option<&str>) -> Result<()> {
    if let Some(hash) = expected_hash {
        let current = sha256(fs::read(path).await?);
        if current != hash {
            return Err(ToolError::ConcurrencyConflict(
                "文件已被其他 Agent 修改，请重新读取后重试".into()
            ));
        }
    }
    fs::write(path, content).await?;
    Ok(())
}
```

### H4. 成本归因系统

每轮 LLM 调用后记录 `CostItem`，子 Agent 完成时上报明细到父 Agent。前端展示成本饼图/时间线。

```rust
pub struct CostAttribution {
    pub task_id: Uuid,
    pub total_cost_usd: f64,
    pub breakdown: Vec<CostItem>,
}

pub struct CostItem {
    pub step_index: u32,
    pub description: String,
    pub agent_id: Uuid,
    pub model: String,
    pub input_tokens: u64,
    pub output_tokens: u64,
    pub cost_usd: f64,
}
```

## 中优先级（v0.2 阶段）

### M1. 进化验证多维标准 + 上线后持续监控

A/B 验证增加用户反馈信号和成本/延迟不退化检查。上线后为每个 Skill 维护滑动窗口指标，低于基线自动触发回滚。

### M2. 多 Agent 水平协作（AgentBus）

在 Supervisor 中增加 `AgentBus`（broadcast channel），兄弟 Agent 可订阅 `FileChanged`/`DiscoveryShared`/`IntermediateResult` 事件。不改变现有父子架构，仅增加横向通信能力。

### M3. delegate_task 结构化输出 Schema

支持父 Agent 在 `delegate_task` 中指定 `output_schema: Option<Value>`（JSON Schema），引导子 Agent 返回可结构化合并的结果。

### M4. 流式响应背压

`EventEmitter::emit_token()` 改用有界 channel（buffer=256），当 buffer 满时自然阻塞 LLM 流式消费，通过 TCP 背压传导减缓 LLM 输出速度。

### M5. 第三方 Provider 热注册

`providers.toml` 支持 `type = "openai-compat"` 的自定义条目，用户通过 `base_url` + `api_key_env` 注册私有 LLM（vLLM/Azure/企业网关），无需重新编译。

### M6. MCP 连接池优化

懒连接 + 工具 Schema 缓存（SQLite，TTL 1h）+ 5 分钟闲置自动断连回收。

## 低优先级（v0.3+ 阶段）

### L1. 进化谱系可视化与因果追溯

`evolution_log` 增加 `evidence_trace_ids` 字段，记录触发进化的具体 TaskTrace。前端展示 Skill 版本树。

### L2. WASM ABI 版本协商

`PluginPool::instantiate()` 增加 `abi_version` 兼容性检查和 `MIN_SUPPORTED_ABI_VERSION` 门控。

### L3. TestBuilder 模式

提供 `AgentExecutor::test()` 构建器一站式构建全部 Mock 依赖，降低集成测试的编写成本。

### L4. 进化系统混沌测试

注入恶意 TaskTrace（含 prompt injection 的 reasoning），验证进化引擎不会将恶意内容固化为 Skill。

### L5. Agent 决策可解释性

`TaskTrace.steps[]` 增加 `DecisionPoint { alternatives_considered, chosen, rationale }`，前端工具调用卡片增加"推理过程"折叠面板。

### L6. 子 Agent 摘要安全扫描

子 Agent 结构化摘要返回父 Agent 前，强制经过 `PromptGuard::scan()`，检测到风险时在摘要中标注安全提醒。
