# Codex 生命周期对齐更新说明

> 日期：2026-09-01
> 状态：已落地基线
> 范围：Realtime、`ResolveElicitation`、`TurnSettings`、Guardian assessment/retry、独立用户 Shell

## 更新摘要

本次将 Codex 风格的交互控制操作纳入 Astro 统一 Thread/Session 生命周期。桌面端和外部客户端经 Tauri/gRPC 提交 typed `Op`，由 `Session::submission_loop` 串行处理，结果以 typed reply 和 `EventMsg` 返回。这些能力不引入第二套任务或事件模型。

| 能力 | 用户可见行为 | 关键保证 |
| --- | --- | --- |
| Realtime | 通过 WebSocket、WebRTC 或 ExistingCall 开启 V2/V3 会话，并可将任务 handoff 给 Codex | transport readiness 边界、连接 target 隔离、typed event、可恢复 transcript |
| `ResolveElicitation` | 接受、拒绝或取消 MCP server 的表单/信息请求 | 以 server + request id 精确关联，单次解决，有界存储 |
| `TurnSettings` | 在 Agent 运行中调整模型、推理等级/摘要和 service tier | 必须命中 active turn，原子替换，仅对下一 sampling step 生效 |
| Guardian retry | 用户可对一次被 Guardian 拒绝的精确操作授权单次重试 | 内容摘要绑定、单次消费、重复操作 FIFO、有界队列 |
| 独立用户 Shell | 用户在任务中或空闲时直接运行 shell 命令 | 与模型工具隔离，参与 task 取消，stdout/stderr 分别限制 1 MiB |

## Realtime

> 命名说明：本文的 V2/V3 是 Astro Realtime wire 协议代号，不是 `gpt-realtime`
> 等模型的版本，也不是 OpenAI Realtime 产品的 GA/Beta 代际。V2 对应公开
> OpenAI/Azure GA `/v1/realtime` 事件族；V3 对应显式、Codex 专用的 `/live` 协议。

### 生命周期

```text
start request
  -> Thread submission queue
  -> build optional startup context
  -> agent-realtime transport negotiation
  -> provider handshake / unified SDP / sideband attach
  -> start reply + RealtimeConversationStarted
  -> versioned typed events + optional Codex handoff/BEM
  -> RealtimeHistory reducer -> RolloutItem::RealtimeItem
  -> close/error
  -> RealtimeConversationClosed
```

- `include_startup_context` 在缺省时为 `true`，会合并受限的 system prompt 与最近 user/assistant 文本历史。
- start RPC/Tauri command 等待 transport-specific readiness：WebSocket 等待 session handshake，WebRTC 等待 call 创建与 SDP answer，ExistingCall 启动 sideband 生命周期；不再只确认 submission queue 已接收。
- 每次 Realtime 连接持有自己的 `ModelTarget`、API key、base URL 和 model，不改写 Thread 的普通 Responses target 链。
- transport 包含 WebSocket、创建 call 的 WebRTC unified SDP，以及只附加 server sideband 的 ExistingCall。ExistingCall 不修改已建立的 session 配置，前端也不重复创建本地麦克风采集链。
- Astro V2 是 OpenAI/Azure GA 默认 wire 映射，使用 `session.update`、conversation item
  和 `response.create`；Astro V3 是显式选择、仅用于 Codex 的 frameless/live 协议。
- V3 server sideband 断开后使用有界指数退避重连；V2 选择关闭，不自动重放可能非幂等的音频和 response request。
- typed `HandoffRequested` 可启动或 steer 普通 Agent turn，再按 `thinking`、`commentary` 或 `bem_tags` 模式把 assistant delta 回传到 call。BEM 可识别标准和自定义通道前缀。
- `RealtimeHistory` 只将 session started、完整 transcript、BEM item promotion 和 session closed outcome 写为 `RolloutItem::RealtimeItem`；原始 delta 和音频不落盘。
- 输入、输出和 frame 大小采用有界通道/上限；失败通过 error 和 closed 事件明确收敛。

## `ResolveElicitation`

MCP server 发起 `elicitation/create` 后，broker 以 `(server_name, request_id)` 保存 oneshot responder，并向桌面端发送请求。用户回复经 `ResolveElicitation` 回到原 MCP future。

- 操作为 `accept` / `decline` / `cancel`，各层保持一一映射。
- 只有 `accept` 携带 content；拒绝或取消不伪造空表单提交。
- 最多 128 个 pending request；重复 key、队列已满或 UI channel 关闭时明确失败。
- 请求的取消/销毁 cleanup 带唯一 token，不会误删之后复用同一 key 的请求。
- 并行任务 UI 与主会话 UI 都只移除已解决的 pending item，其他 elicitation 保留。

## `TurnSettings`

`TurnSettings` 是 turn-scoped 热更新，而非 Thread 默认配置修改。

- 可更新 `model`、`reasoning_effort`、`reasoning_summary` 和 `service_tier`。
- 嵌套 optional 字段区分“未提供”与“显式清空”。
- 空更新、空 model、不可用 target、非法 provider params 或非 active turn 会被拒绝。
- 新值先在副本上完整校验，再递增 generation 并一次性替换；失败不会留下部分修改。
- 正在飞行的 Provider 请求保持原快照，下一个 sampling step 才读取新设置。

## Guardian assessment / retry

Guardian assessment 事件包含 assessment id、工具调用和 `in_progress` / `approved` / `denied` / `aborted` 状态。被拒绝的操作不会因 UI 点击直接重放；用户授权只是为下一次内容完全相同的调用准备一枚一次性 token。

```text
tool call denied
  -> record assessment_id + canonical action digest
  -> user approves assessment_id
  -> enqueue one exact retry authorization
  -> identical tool call arrives
  -> consume one token and continue
```

- canonical action 覆盖 tool name 和序列化 arguments，防止授权被不同命令复用。
- 相同 action 可对应多个独立 assessment；授权按 FIFO 消费，不会相互覆盖。
- denied map 和 authorized queue 都限制为 128 项，避免长驻 Session 无界增长。
- 后端、gRPC 和 Tauri command 已接线。产品界面必须继续保持“拒绝”与“用户显式授权”的可见区分。

## 独立用户 Shell

该能力面向用户终端交互，不是 Agent 可调用的 terminal tool。

- 命令由用户显式提交，用 login shell 执行，并在事件中标记 `origin=user` 和 `sandbox=disabled`。
- 当 Agent turn 活跃时，命令作为该 turn 的 child 运行；空闲时创建独立 `UserShellTask`。
- 两种形态都输出 `ItemStarted`、stdout/stderr delta 和 `ItemCompleted`，因此 UI 不需要第二套终端历史协议。
- 取消 turn 会终止子进程并收敛事件；stdout 和 stderr 分别最多捕获 1 MiB，截断信息在 delta 和最终结果中可见。

## 兼容性与安全边界

- 新控制面不改变 Responses-only canonical history；仅符合持久化策略的 typed event 进入 rollout。
- Realtime 凭据、Guardian retry token、MCP pending responder 为运行时内存状态，不写入模型历史；Realtime 仅持久化 reducer 产生的完整语义项。
- User Shell 绕过 Agent sandbox 是明确产品语义，不能从模型生成的 tool call 自动转入该路径。
- 所有异步 pending 状态都需要容量上限、取消收敛和明确错误，避免慢消费者或断开连接导致常驻泄漏。
