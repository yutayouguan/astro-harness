## 1. 结构化异步用户输入

### 工具契约

```json
{
  "name": "request_user_input_async",
  "arguments": {
    "questions": [
      {
        "title": "需要用户回答的完整问题",
        "options": ["建议答案 A", "建议答案 B"]
      }
    ]
  }
}
```

- 问题数组不能为空，`title` 不能是空白文本。
- `options` 可省略；Desktop 始终允许自由文本。
- 工具立即返回 `{"accepted":true}`，不结束、不 park 当前 turn。
- 可读 fallback text 与结构化 `questions` 一起进入 `AgentMessageItem`。
- `ItemStarted` / `ItemCompleted` 共用稳定 ID，rollout 恢复和 Desktop 投影按 ID 去重。
- 仅最新、尚未被后续 user input 回答的问题组保持交互性。

`send_user_message_async` 已从 handler、工具注册、Plan 模式白名单和工具开关迁移中移除。
持久化的旧调用如果被重放，会按未知工具明确失败，不再静默改写。

## 2. Thread Snapshot 模型设置

`ThreadSnapshot` 新增：

```proto
optional string model = 8;
optional string reasoning_effort = 9;
```

listener 仍只负责 Turn/Item 历史。`ResumeThread` 获得 listener snapshot 后，从
`ManagedThread.runtime.session()` 读取当前 primary target 和 provider options 补全字段。
这保证模型热更新和后续重连看到当前状态；冷恢复仅返回 Session 已重建的
设置，空 Thread 使用 `null`。

## 3. Managed worktree

`agent-delegate` 恢复为独立 workspace crate，不再把 Git 检出逻辑放在 `agent-core`。

```text
source cwd
  -> canonical repository root + nested cwd
  -> verify HEAD/explicit base commit
  -> allocate managed bucket
  -> git worktree add --detach --no-checkout
  -> reset --hard with hooks/fsmonitor/filters disabled
  -> validate destination cwd
  -> ManagedWorktree
```

安全边界：

- 清除继承的 Git repository selectors，防止命令被父进程环境重定向。
- 不执行仓库 hooks、filesystem monitor 和 clean/smudge/process filters。
- 目标 cwd 必须解析到 managed root 内的真实目录。
- 失败时回滚不完整 worktree 和 allocation bucket。
- 脏 worktree 不自动删除。
- Desktop cleanup 会重新解析 repo root，且只允许删除
  `.worktrees/<bucket>/<repo>` 下的 Astro 管理检出。
- Git 命令强制 `safe.bareRepository=explicit`，避免隐式 bare repository 选择。
- `.worktreeinclude` 兼容入口只复制普通文件/目录，跳过绝对路径、`..` 和符号链接。

## 4. Realtime 跨 session 恢复

`RealtimeHistory::start` 在已有 active session 时使用下列顺序收敛：

1. 封口旧 session 未完成的 user/assistant transcript；
2. 追加旧 session closed outcome；
3. 追加新 session started。

`agent_rollout::realtime_history()` 只筛选 durable `RealtimeItem`，但保持追加顺序，
因此连续会话恢复时不会合并或重排 session boundary。

## 5. 已有能力的验收结论

以下 Codex 变化在 Astro 已有等价语义，本轮只做源码/测试确认：

- User / AutoReview / Full Access 三维权限路由，以及 hardline deny 优先级。
- 本地 Extension 每 turn 重新发现，`ExtensionSnapshot` 在 turn 内冻结。
- `McpHub::reload_with_configs` 保留未变连接，重连变更项，移除已删除/禁用项。
- MCP `tools/list_changed` 自动更新工具快照，elicitation 使用有界 broker。

Codex 的远程 Plugin Marketplace reconcile、原生 Voice helper 和 `persistent` reasoning 没有
直接移植：前两者在 Astro 尚无对应产品入口；`persistent` 必须同时获得模型目录
`persistent_instructions` 才能暴露，否则仅将 wire effort 改成 `disabled` 会产生虚假功能。

## 6. Responses 原生工具命名空间

- `ToolName` 作为 `ToolRouter.routes` / `model_routes` 的结构化键；默认
  `functions` namespace 与无 namespace 等价。
- `ResponseItem::FunctionCall` 中的 `namespace` 和 `name` 直接进入当前
  StepContext 校验，不先展平成 `namespace.child` 或 `namespace__child`。
- MCP 模型可见形态为 `namespace=mcp__{server}` + 原生子工具；展平
  `mcp__{server}__{tool}` 仅作为 Hub 内部执行键。
- `tool_search` 会合并同 namespace 命中项，并由 durable `ToolSearchOutput`
  在下一 Step 重建可路由 `ToolName` 集合。
- Function-only 非 Agent adapter 不再把 Namespace 降级为伪 Function 名。
