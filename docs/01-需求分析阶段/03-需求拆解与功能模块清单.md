> 文档状态：草稿 | 阶段：需求分析 | 属性：必出

## 一、模块拆分总览

```text
Astro Agent
├── agent-core              # Agent 主循环、Planner、Tool/Skill 调度
├── agent-providers         # 多模态 Provider 抽象与实现
├── agent-runtime           # 执行循环、HumanGuard、Supervisor
├── agent-mcp-server        # 暴露为 MCP Server
├── agent-evals             # 评估套件
└── desktop                 # Tauri 桌面端
    ├── src-tauri           # Tauri Rust 层（Commands、Events）
    └── src                 # 前端 React + TypeScript
        ├── 对话模块
        ├── Skills 模块
        ├── 工作流模块
        ├── 知识库模块
        ├── 工作区模块
        ├── 设置模块
        └── 进化监控模块
```

> **目标平台**：macOS (v0.1) + Windows (v0.1) + Linux (v0.2)。Desktop Only，不计划移动端和 Web 版。

### M-07 记忆系统（五层架构）

参考 Hermes Agent 记忆设计，明确五层记忆体系（在四层基础上拆分持久记忆层，与 Hermes Agent 对齐），增加用户建模层：

```text
┌──────────────────────────────────────────────────────────┐
│  层级          实现                        注入方式        │
│  情节记忆      SQLite 对话表 + FTS5        session_search  │
│  语义记忆      sqlite-vec + FTS5 混合      @ 引用按需检索  │
│  持久记忆      MEMORY.md + USER.md         会话开始冻结注入│
│  程序性记忆    Skills 目录系统              渐进式披露      │
│  用户建模      LLM 推断 + USER.md          冻结快照        │
└──────────────────────────────────────────────────────────┘
```

**冻结快照注入机制：** 会话开始时将 MEMORY.md 和 USER.md 以快照形式一次性注入 system prompt（格式示例：`MEMORY [67% — 1,474/2,200 chars]`），会话中途不更新，以保留 LLM Prompt 前缀缓存性能；写磁盘后下次会话才生效。

### M-08 工作流模块

工作流编辑器基于 React Flow（`@xyflow/react`）提供可视化 DAG 任务编排，支持 AI 节点、工具节点、控制流节点的拖拽连线，并具备完整的节点配置、实时运行状态和日志追踪能力。

**节点类型分类：**

| 分类 | 节点 |
| ---- | ---- |
| 触发器 | 手动触发、⏰ 定时任务（cron）、🌐 Webhook |
| AI 节点 | LLM 调用（含 Provider/模型/Prompt/Temperature 配置）、Skill 节点、子 Agent（spawn_agent） |
| 工具节点 | HTTP 请求、文件操作、数据库查询 |
| 控制流 | 条件分支（◆）、循环（🔁）、合并（⬡） |

| 功能点 | 描述 | 优先级 | 版本 |
| ---- | ---- | ---- | ---- |
| React Flow 节点画布 | 无限画布，支持缩放/拖拽/多选；节点与连线的增删改 | P2 | v0.3 |
| 节点面板（左侧） | 四类节点按分类展示，支持拖入画布；含节点名称搜索 | P2 | v0.3 |
| 节点配置面板（右侧） | 选中节点展开属性面板；LLM 节点含 Provider / 模型 / System Prompt / User Prompt（支持 `{{变量}}` 占位符）/ Temperature / Max Tokens / 输出变量名 | P2 | v0.3 |
| 工作流执行引擎 | 按 DAG 拓扑顺序执行，并行分支并发处理 | P2 | v0.3 |

### M-11 工作空间文件管理模块

工作区内文件独立存储，AI 生成内容通过**手动一键保存**归档到 `ai-docs/` 目录，按内容类型自动分入子目录，数据库记录来源会话元数据，任意文件可作为对话上下文。

```text
workspace/<工作区名>/
  files/               # 用户自行管理的文件
  ai-docs/             # AI 产物归档根目录（工作区物理隔离）
    code/              # 代码文件（.py .rs .ts .sh 等）
    reports/           # 报告、分析、总结
    articles/          # 文章、文案、文档
    data/              # 数据文件（.json .csv .yaml 等）
    other/             # 无法自动归类的产物
  knowledge/           # 知识库原始文档
```

**归档机制说明：**

- **触发**：手动一键，消息中文档/代码块显示「💾 保存」按钮，点击弹确认框后才写入文件系统
- **分类**：按文件扩展名和内容特征自动路由子目录，用户可在确认框修改
- **命名**：默认 `YYYY-MM-DD_<AI推断标题>.<ext>`，用户可在确认框修改
- **关联**：`ai_artifacts` 表记录 `file_path + conversation_id + message_id`，文件管理页可跳转来源对话
- **隔离**：`ai-docs/` 随工作区 `root_path` 物理隔离，跨工作区不可见
