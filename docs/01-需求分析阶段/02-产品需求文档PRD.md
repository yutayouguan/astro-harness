## 一、业务背景

### 1.1 项目定位

Astro Agent 是一款**本地优先的多模态 AI Agent 桌面应用**，基于 Rust + Tauri v2 构建。目标是为重度 AI 用户提供统一的多模态交互入口，支持 Skills 编排、子 Agent 派生、自我进化和可视化工作流，同时保证数据本地可控、执行过程透明。

### 1.2 目标用户

| 用户类型 | 描述 | 核心诉求 |
| ---- | ---- | ---- |
| 开发者 | 日常使用 AI 辅助编码、调研 | 可扩展、MCP 集成、执行透明 |
| 内容创作者 | 文案、图像、音频生产 | 多模态统一、Skills 复用 |
| 研究人员 | 文献整理、知识管理 | RAG 知识库、长上下文 |
| 企业用户 | 内部自动化流程 | 安全合规、工作流编排、审计日志 |

### 1.3 成功指标

| 指标 | 目标值 |
| ---- | ---- |
| 首次响应时间 | < 500ms（本地模型 < 2s） |
| 冷启动时间 | < 3s |
| Skills 执行成功率 | > 95% |
| 月活跃用户留存 | > 60% |
| 崩溃率 | < 0.1% |

### 1.4 目标平台

| 平台 | 支持状态 | 版本 |
|------|---------|------|
| macOS (Apple Silicon + Intel) | ✅ v0.1 首发 | macOS 12+ |
| Windows (x64) | ✅ v0.1 首发 | Windows 10+ |
| Linux (x64, AppImage) | ✅ v0.2 | Ubuntu 22.04+ |
| iOS / Android | ❌ 不在计划内 | — |
| Web 版 | ❌ 不在计划内 | — |

> **设计原则：Desktop Only。** UI 布局按 ≥960px 宽度设计，不考虑移动端适配。响应式断点仅用于处理窗口缩小（最小宽度 800px），非移动端兼容。`03-系统设计阶段/07-UI设计/01-主界面设计.md` 中 <600px 单栏模式定义为窄窗口模式，非移动端模式。

#### F-10 工作空间文件管理

用户可在工作区内管理本地文件，AI 生成的文档通过**手动一键保存**归档到 `ai-docs/` 目录，按内容类型自动分入子目录，同时在数据库记录来源会话元数据；工作区之间完全物理隔离。

**`ai-docs/` 目录结构：**

```text
workspace/<工作区名>/
  files/               # 用户自行管理的文件
  ai-docs/             # AI 产物归档根目录（工作区隔离）
    code/              # 代码文件（.py .rs .ts .sh 等）
    reports/           # 报告、分析、总结（.md .pdf 等）
    articles/          # 文章、文案、文档（.md .txt 等）
    data/              # 数据文件（.json .csv .yaml 等）
    other/             # 无法自动归类的产物
  knowledge/           # 知识库原始文档
```

**AI 文档归档机制：**

- **触发方式**：手动一键保存。AI 回复中的文档/代码块出现「💾 保存」按钮，用户主动点击才触发归档，不自动保存。
- **自动分类**：系统根据文件扩展名和内容特征推断类型，路由到对应子目录；用户可在确认弹窗中修改目标路径。
- **自动命名**：默认命名格式为 `YYYY-MM-DD_<AI推断标题>.<ext>`，用户可在确认弹窗中修改。
- **会话关联**：保存时在数据库 `ai_artifacts` 表记录 `file_path + conversation_id + message_id + created_at`，文件管理页可查看「来源对话」并跳转。
- **工作区隔离**：`ai-docs/` 目录随工作区 `root_path` 物理隔离，不同工作区的产物互不可见。

| 功能点 | 描述 | 优先级 |
| ---- | ---- | ---- |
| 文件浏览器 | 树形 / 列表 / 网格三种视图，展示工作区文件结构 | P1 |
| 文件操作 | 新建、重命名、移动、删除文件/文件夹 | P1 |
| 文件预览 | 内联预览 Markdown、图片、音频、视频、PDF | P1 |

| 自动类型分类 | 按文件类型自动路由到 `ai-docs/code/`、`reports/`、`articles/`、`data/`、`other/` | P0 |

#### F-33 记忆系统分层架构

明确五层记忆体系（在四层基础上拆分持久记忆层，与 Hermes Agent 对齐）：

| 层级 | 说明 | 实现 | 注入方式 | 优先级 |
| ---- | ---- | ---- | ---- | ---- |
| 情节记忆 | 对话历史，按时间/全文检索 | SQLite 对话表 + FTS5 | `session_search` 工具按需 | P0 |
| 语义记忆 | 知识库文档，按内容检索 | sqlite-vec 向量 + FTS5 全文 | @ 引用按需检索 | P1 |
| 持久记忆 | Agent 笔记 + 用户档案，跨会话常驻 | MEMORY.md（≤ 2200字符）+ USER.md（≤ 1375字符） | 会话开始冻结注入 | P1 |
| 程序性记忆 | Skills 系统，可复用的执行能力 | SKILL.md 目录结构 | 渐进式披露 | P0 |
| 用户建模 | 用户画像推断，辩证式更新 | LLM 推断 → USER.md | 随持久记忆冻结注入 | P1 |

持久记忆由 `MEMORY.md`（Agent 笔记）和 `USER.md`（用户档案）两个文件构成，会话开始时以冻结快照形式一次性注入 system prompt，Agent 通过 `memory` 工具主动管理记忆条目。记忆系统的技术实现细节详见[系统设计阶段 01-持久化层.md](../03-系统设计阶段/03-基础设施/01-持久化层.md)。

| 功能点 | 描述 | 优先级 |
| ---- | ---- | ---- |
| **MEMORY.md / USER.md 双文件持久化** | Agent 笔记与用户档案明确分离，各有独立字符上限 | P1 |
| **冻结快照注入** | 会话开始注入，中途不更新，保留 Prompt 前缀缓存 | P1 |
| **memory 工具（add/replace/remove）** | Agent 主动写入、修改、删除记忆条目 | P1 |
| **容量限制与整合策略** | 字符上限硬执行；超 80% 主动整合；满载时返回错误附条目列表 | P1 |
| **使用率可视化** | 注入时显示占比，UI 展示容量进度条 | P1 |
| **重复防护** | 完全重复条目自动拒绝写入 | P1 |
| **记忆安全扫描** | 写入前扫描 Prompt 注入、凭据外泄、不可见 Unicode 隐写 | P1 |

#### F-39 交互执行模式

| 功能点 | 描述 | 优先级 |
| ---- | ---- | ---- |
| Agent 模式（自适应） | LLM 自判断任务复杂度：预计超过 3 步工具调用或涉及不可逆操作时，自动先生成执行计划等待用户确认，简单任务直接执行；L1/L2/L3 风险门控全程生效 | P0 |
| 运行中追加消息 | Agent 运行期间用户发送的消息进入 pending 队列；当前轮次（LLM 回复 + 所有工具调用）完成后自动注入下一轮 context | P0 |
| Pending 状态展示 | pending 消息在输入框下方显示"等待执行中..."标识；轮次完成后标识消失，消息正式入队 | P1 |
| MultiTask 并发 | 不同工作区的 Agent 任务可并行执行，互不干扰；侧边栏展示各任务执行状态 | P1 |
| YOLO 开关 | 临时跳过 L2/L3 审批弹窗；首次启用需勾选免责确认；费用预算超限时强制关闭；不跨会话持久化 | P2 |

## 三、操作流程

### 3.1 基础对话流程

```text
用户输入（文本/图片/语音）
    ↓
消息预处理（格式化、Token 估算）
    ↓
选择模型（用户指定 or 自动路由）
    ↓
调用 Provider API（流式）
    ↓
工具调用处理（如有 ToolCall）
    ↓
结果渲染（Markdown / 图片 / 音频）
    ↓
写入对话历史（SQLite）
    ↓
更新费用统计
```

### 3.2 Skill 调用流程

```text
用户触发 Skill（命令面板 / @ 语法 / 工具栏）
    ↓
加载 Skill 定义（SKILL.md 目录结构）
    ↓
注入上下文变量
    ↓
执行 Skill（可能包含多个 Tool 调用）
    ↓
返回结果 → 插入对话
    ↓
记录执行轨迹（TaskTrace）
```

### 3.3 自我进化流程

```text
任务完成后 → TaskTrace 写入
    ↓
定时触发 ReflectionEngine
    ↓
分析成功/失败模式
    ↓
生成改进提案（新 Skill / 优化 Prompt）
    ↓
用户审批界面展示
    ↓
用户批准 → 合并到 Skill 库 / Prompt 库
```

## 四、异常分支与处理规则

| 场景 | 处理方式 |
| ---- | ---- |
| API 建连失败（DNS/TCP/TLS） | 请求层有限重试后进入等待网络状态；前台持续重连且不切换模型，后台任务按有界策略失败 |
| API 调用超时或 5xx | 请求层按配置指数退避；仍失败时进入有界 stream retry，5xx 可按用户显式配置的 fallback 链切换 |
| Token 超出上下文限制 | 自动压缩历史消息，保留最近 N 轮 |
| Provider 不可用 | 自动切换备用 Provider（Fallback Chain） |
| 费用超出预算 | 暂停请求，弹窗提示用户确认或调整预算 |
| Skill 执行失败 | 捕获异常，展示错误详情，记录到 TaskTrace |
| 子 Agent 超时 | 主动终止，返回已完成部分结果 |
| 文件上传过大 | 前端限制（图片 < 20MB，文档 < 50MB），超出提示压缩 |
| 本地数据库损坏 | 从最近备份恢复，提示用户 |
| 用户点击暂停 | 立即中止 LLM 流式输出（watch 信号广播），前端清空 streaming buffer，Agent 进入 Paused 状态等待恢复 |
| 前台持续断网 | 保持当前 Turn active，以单条非终态状态展示等待网络；恢复后自动继续，只有用户中断才结束等待 |
| 后台任务持续断网 | 达到有界重试上限后写入明确错误并结束 Turn，不永久占用 Cron/自动化 worker |
| L2 审批超时未操作 | 30s 后按"自动拒绝"处理，跳过该工具调用，Agent 记录跳过原因后继续执行；L3 无超时，必须人工响应 |
| 用户释放 L3 接管 | 被阻塞的工具调用批量注入"已取消"结果，LLM 获取完整历史（含用户手动操作记录）重新规划 |
| 应用崩溃重启 | 扫描 task_traces 中 status='running' 的任务，读取 messages 表实际状态，仅补全未完成步骤，已完成工具调用不重跑；**Pending 队列内存丢失**（见下行） |
| 崩溃时 Pending 消息丢失 | Pending 队列为纯内存存储，崩溃后不可恢复；重启界面顶部显示 Banner："您在上次崩溃前有待发送的消息，请重新输入"；已记入 messages 表的正式消息不受影响 |
| 运行中追加消息 | 消息进入 pending 队列，当前轮次结束后注入下一轮 context；输入框显示"等待执行中..."标识 |
| Agent 自动生成计划被拒绝 | 用户可修改计划内容后确认，或直接取消任务 |

## 五、交互规则

### 5.1 消息渲染规则

- 流式输出：AI 回复逐字渲染，支持中途打断
- Markdown：完整支持 GFM（表格、代码块、LaTeX 公式）
- 代码块：Shiki 语法高亮，一键复制
- 工具调用：折叠卡片展示，可展开查看参数和结果
- 图片：内联渲染，点击放大
- 音频：内联波形播放器（wavesurfer.js）

### 5.2 快捷键规则

| 快捷键 | 功能 |
| ---- | ---- |
| `Cmd/Ctrl + K` | 打开命令面板 |
| `Cmd/Ctrl + Enter` | 发送消息 |
| `Cmd/Ctrl + N` | 新建对话 |
| `Cmd/Ctrl + /` | 切换 Skill |
| `Esc` | 中断 AI 输出 |

### 5.3 斜杠命令（/ 命令）规则

用户在对话框输入 `/` 即触发命令选择器，统一入口调用 Skills、Tools、工作区操作等所有能力。

**触发与交互：**

- 输入 `/` 立即弹出命令浮层，展示所有可用命令
- 继续输入字符进行模糊搜索过滤（如 `/trans` 匹配"翻译"）
- 键盘 `↑` `↓` 切换选项，`Enter` 确认，`Esc` 关闭
- 命令浮层显示：命令名称、描述、来源类型（Skill / Tool / 系统）

**命令分类：**

| 前缀示例 | 类型 | 示例 |
| ---- | ---- | ---- |
| `/translate` | Skill | 调用翻译 Skill |
| `/code-review` | Skill | 调用代码审查 Skill |
| `/summarize` | Skill | 调用摘要 Skill |
| `/search` | Tool | 调用网络搜索工具 |
| `/read-file` | Tool | 读取指定文件 |
| `/new-chat` | 系统命令 | 新建对话 |
| `/clear` | 系统命令 | 清空当前对话 |
| `/model` | 系统命令 | 切换当前使用的模型 |
| `/workspace` | 系统命令 | 切换工作区 |
| `/save` | 系统命令 | 保存当前 AI 输出到工作区 |

**其他输入触发符：**

- `@文件名` — 引用工作区文件内容作为上下文
- `@知识库` — 触发知识库检索
- `#` — 引用历史对话
- `[[` — 引用工作区内另一份文档（双链语法）
