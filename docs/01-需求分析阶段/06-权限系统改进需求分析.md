# 权限系统改进需求分析

> 阶段：需求分析 | 状态：已实现 | 日期：2026-08-28

## 1. 背景与动机

### 1.1 对标分析

与 Codex 权限系统对比后发现以下改进机会：

| 维度 | Codex | Astro（改进前） | 差距 |
|---|---|---|---|
| 会话缓存 | `ApprovalStore` 按命令 key 缓存 | 无缓存，每次重新弹窗 | 用户体验痛点 |
| Smart Approval 上下文 | Guardian 发送对话上下文 | 仅发送孤立 PermissionRequest JSON | 判断准确度不足 |
| 配置粒度 | `GranularApprovalConfig` 统一配置 | 策略分散在多个配置域 | 配置体验差 |
| 子 Agent 继承 | 无显式缓存继承 | 无审批缓存可继承 | subagent 场景重复审批 |
| 决策可解释性 | 内存级缓存 | 审计不含决策理由 | 审计追溯不完整 |

### 1.2 核心问题

1. **重复弹窗**：同一会话中 `cargo test` 被批准后，下次运行仍弹窗
2. **盲判**：Smart Approval 辅模型看不到对话语境，误判率高
3. **配置碎片化**：Terminal/MCP/Network 审批策略分散在不同文件
4. **subagent 孤岛**：每个子 agent 审批独立，父级已批准的命令仍需重新审批
5. **审计不透明**：事后无法回溯「为什么这个命令被自动放行了」

## 2. 需求列表

### P0: 会话级审批缓存（体验直接提升）

**用户故事**：作为开发者，我希望同一会话中批准过 `cargo test` 后，后续运行相同类型命令不再弹窗，以保持工作流连贯。

**验收标准**：
- 用户批准 `cargo test -p agent` 后，`cargo test -p tools` 自动放行（命令前缀泛化）
- 不同工具名（`exec_command` vs `code_exec`）的缓存互不影响
- 会话结束时缓存自动清空
- `allow_always` 路径同时写入持久白名单和会话缓存

### P1: Smart Approval 注入对话上下文（准确度提升）

**用户故事**：作为开发者，我希望 Smart Approval 辅模型在判断命令是否安全时，能看到当前对话语境（如「用户让 agent 跑测试」），避免对合理命令误拒。

**验收标准**：
- 辅模型 prompt 中包含最近 5 轮对话摘要
- 敏感信息（API_KEY、TOKEN 等）自动脱敏
- 每条消息预览不超过 200 字符
- 不传上下文时行为与改进前一致（向后兼容）

### P2: 统一审批粒度配置面（配置简化）

**用户故事**：作为管理员，我希望在 `config.yaml` 的一个 `approval:` 段中集中配置 Terminal/策略/审查者，不必翻找多个位置。

**验收标准**：
- `config.yaml` 支持 `approval:` 段，含 `terminal`、`policy`、`reviewer` 子字段
- 各域独立配置字段优先级高于统一配置（向后兼容）
- 未设置的字段使用各域默认值

### P3: 子 Agent 审批缓存继承（subagent 体验提升）

**用户故事**：作为开发者使用子 agent 批量执行任务时，我希望子 agent 能继承父级已批准的命令模式，减少重复审批。

**验收标准**：
- 子 agent 可读取父级缓存（只读继承）
- 子 agent 的新审批写入自己的缓存，不影响父级
- 子 agent 结束时其缓存自动丢弃

### P4: 审批决策回溯与可解释性（安全审计）

**用户故事**：作为安全审计人员，我希望审计日志中包含每次审批的决策理由（辅模型判断、用户手动、缓存命中等），以便事后审查。

**验收标准**：
- `PermissionAuditEvent` 包含 `reasoning` 字段
- Smart Approval 路径记录辅模型返回文本
- 旧格式 JSONL 向后兼容（`reasoning` 反序列化为 `None`）

### P5: 渐进式信任模型（长期体验优化）

**用户故事**：作为长期使用的开发者，我希望频繁被批准的命令类型自动降低审批频率，而不需要手动配置白名单。

**验收标准**：
- 连续 5 次批准 → 从 AlwaysAsk 升级到 SmartReview
- 连续 10 次批准 → 从 SmartReview 升级到 AutoApprove
- 任何 1 次拒绝 → 立即回退到 AlwaysAsk
- 信任分数仅 session 内有效，不跨会话
- hardline 命令不受信任模型影响

## 3. 非功能需求

- **安全**：fail-closed 原则——缓存未命中、辅模型超时均回退到最保守策略
- **性能**：缓存查询 O(1)，不增加工具执行延迟
- **兼容**：所有改进向后兼容，不改变已有配置文件格式语义
