## 一、业务背景与痛点

### 1.1 当前痛点

#### 痛点 1：多工具割裂，缺乏统一 AI 助手

用户在日常工作中需要切换多个 AI 工具（ChatGPT、Claude、Midjourney 等），无法在同一界面完成文本生成、图像生成、语音转写等多模态任务，上下文频繁丢失。

#### 痛点 2：AI 能力无法编排与复用

用户发现某个 Prompt 或操作组合效果好，但无法将其保存为可复用的"技能"，每次都要重新输入，效率低下。

#### 痛点 3：Agent 执行过程不透明

市面上的 AI Agent 产品执行过程如黑盒，用户不知道 Agent 在做什么、调用了哪些工具、花费了多少 Token 和费用。

#### 痛点 4：无法离线使用

强依赖云端 API，网络不稳定或无网络时完全不可用，影响隐私场景下的使用。

#### 痛点 5：数据无法掌控

对话记录、知识库数据存储在第三方云端，存在隐私泄露风险，且无法跨工具迁移。

#### 痛点 6：视频内容无法与 AI 交互

用户想让 AI 理解视频内容（分析讲解视频、提取字幕、总结要点），但现有工具要么不支持视频输入，要么只能处理极短片段，且无法在同一界面完成视频生成任务。

#### 痛点 7：音乐创作门槛高，AI 工具分散

音乐创作者需要在多个专业软件之间切换（DAW、AI 生成工具、音频编辑器），无法用自然语言描述直接生成或分析音乐，且现有工具对音乐内容的理解（曲风识别、情绪分析、节拍检测）能力弱。

## 二、原始诉求整理

### 2.1 核心诉求

| 编号 | 原始表述 | 整理后需求 | 优先级 |
| ---- | ------------------------------ | ---------- | --- |
| R-01 | "希望一个工具能搞定文字、图片、语音、视频、音乐、简单编程" | 多模态统一入口 | P0 |
| R-02 | "想把常用操作存下来，下次一键调用" | Skills 系统 | P0 |
| R-03 | "想看到 AI 每步在做什么" | 执行轨迹可视化 | P1 |
| R-04 | "希望没网也能用基础功能" | 离线模式（本地模型） | P1 |
| R-05 | "数据要放在自己电脑上" | 本地优先存储 | P0 |
| R-06 | "能接入我们自己的 MCP 服务" | MCP 客户端支持 | P1 |
| R-07 | "Agent 能自动学习改进" | 自我进化能力 | P2 |
| R-08 | "想用工作流搭建自动化流程" | 可视化工作流编辑器 | P2 |
| R-09 | "能让 AI 看懂我的视频，帮我剪辑或总结" | 视频理解与生成 | P1 |
| R-10 | "直接用文字描述就能生成一段音乐" | 音乐理解与生成 | P2 |

### 2.2 隐性需求（访谈中发现）

- 用户对 Token 费用敏感，需要明确的费用展示与预算控制
- 开发者用户希望能扩展自定义工具和插件
- 企业用户关注数据加密和审计日志

## 三、竞品使用反馈

| 竞品 | 优点 | 不足 |
| --------------- | ---------- | --------------------- |
| ChatGPT Desktop | 界面简洁，响应快 | 不支持本地存储，无 Skills，无工作流 |
| Claude.ai | 长上下文强，思维链好 | 无多模态编排，无离线能力 |
| Dify | 工作流强大 | 部署复杂，桌面体验差，无原生多模态 |
| Cursor | 代码场景极致 | 仅限代码，不通用 |

---

## 四、调研结论

1. 核心差异化方向：**多模态统一 + 本地优先 + 可进化 Skills**
2. 目标用户：重度 AI 用户（开发者、内容创作者、研究人员）
3. 最小可行产品（MVP）聚焦：文本对话 + Skills 系统 + 执行轨迹 + 本地存储
