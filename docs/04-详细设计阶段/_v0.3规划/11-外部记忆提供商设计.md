# 外部记忆提供商集成设计

> v0.3.2 规划 | 状态：规划中 | 覆盖：Mem0、Honcho 等外部记忆服务集成

---

## 1. 概述

Astro Agent 内置四层记忆系统（L1 工作记忆 → L2 短期记忆 → L3 长期记忆 → L4 知识图谱）。外部记忆提供商作为**补充来源**，扩展以下能力：

- **语义搜索增强**：利用外部服务的向量索引，扩大可召回的知识范围
- **跨设备记忆**：通过云端记忆服务实现多设备间记忆同步
- **知识图谱补充**：对接外部知识图谱服务，丰富实体关系

**核心原则**：内置记忆系统始终是主记忆源，外部提供商是可选补充，禁用外部提供商不影响任何核心功能。

## 2. MemoryProvider Trait

### 2.1 接口定义

```rust
use async_trait::async_trait;

/// 外部记忆提供商接口
#[async_trait]
pub trait MemoryProvider: Send + Sync {
    /// 语义搜索记忆
    async fn search(
        &self,
        query: &str,
        top_k: usize,
        filters: Option<SearchFilters>,
    ) -> Result<Vec<MemoryEntry>>;

    /// 添加记忆条目
    async fn add(&self, entry: MemoryEntry) -> Result<String>;  // 返回 entry_id

    /// 删除记忆条目
    async fn delete(&self, entry_id: &str) -> Result<()>;

    /// 提供商名称
    fn provider_name(&self) -> &str;

    /// 健康检查
    async fn health_check(&self) -> Result<bool>;
}

/// 搜索过滤条件
pub struct SearchFilters {
    pub user_id: Option<String>,
    pub session_id: Option<String>,
    pub created_after: Option<DateTime<Utc>>,
    pub metadata: Option<HashMap<String, String>>,
}

/// 统一的记忆条目格式
pub struct MemoryEntry {
    pub id: String,
    pub content: String,
    pub relevance_score: f32,          // 0.0 - 1.0
    pub source: MemorySource,
    pub created_at: DateTime<Utc>,
    pub metadata: HashMap<String, String>,
}

pub enum MemorySource {
    Internal(InternalLevel),           // L1 / L2 / L3 / L4
    External(String),                  // 提供商名称
}
```

### 2.2 设计说明

- `search` 返回的 `MemoryEntry` 必须包含 `relevance_score`，用于跨来源排序
- `add` 用于将本地记忆同步到外部服务（可选功能，用户控制）
- `health_check` 用于启动时检测外部服务可用性，不可用时静默降级

## 3. 支持的提供商

### 3.1 Mem0

[mem0.ai](https://mem0.ai) — AI 记忆层服务，支持用户级和会话级记忆管理。

```rust
pub struct Mem0Provider {
    api_key: String,
    base_url: String,       // 默认 https://api.mem0.ai/v1
    user_id: String,        // Astro 用户标识
    http_client: reqwest::Client,
}

#[async_trait]
impl MemoryProvider for Mem0Provider {
    async fn search(
        &self,
        query: &str,
        top_k: usize,
        filters: Option<SearchFilters>,
    ) -> Result<Vec<MemoryEntry>> {
        let resp = self.http_client
            .post(format!("{}/memories/search/", self.base_url))
            .header("Authorization", format!("Token {}", self.api_key))
            .json(&json!({
                "query": query,
                "user_id": self.user_id,
                "limit": top_k,
            }))
            .send()
            .await?;

        let results: Vec<Mem0Memory> = resp.json().await?;
        Ok(results.into_iter().map(|m| m.into_memory_entry()).collect())
    }

    async fn add(&self, entry: MemoryEntry) -> Result<String> {
        let resp = self.http_client
            .post(format!("{}/memories/", self.base_url))
            .header("Authorization", format!("Token {}", self.api_key))
            .json(&json!({
                "messages": [{"role": "user", "content": entry.content}],
                "user_id": self.user_id,
            }))
            .send()
            .await?;

        let result: Mem0AddResponse = resp.json().await?;
        Ok(result.id)
    }

    fn provider_name(&self) -> &str { "mem0" }

    async fn health_check(&self) -> Result<bool> {
        let resp = self.http_client
            .get(format!("{}/memories/", self.base_url))
            .header("Authorization", format!("Token {}", self.api_key))
            .query(&[("user_id", &self.user_id), ("limit", &"1".to_string())])
            .send()
            .await?;
        Ok(resp.status().is_success())
    }
}
```

### 3.2 Honcho

[honcho.dev](https://honcho.dev) — Session-based 记忆管理，适合对话式 AI。

```rust
pub struct HonchoProvider {
    api_key: String,
    base_url: String,       // 默认 https://api.honcho.dev/v1
    app_id: String,
    user_id: String,
    http_client: reqwest::Client,
}
```

Honcho 的核心概念映射：

| Honcho 概念 | Astro 映射 |
|------------|-----------|
| App | Astro Agent 实例 |
| User | Astro 用户 |
| Session | Astro 对话（conversation） |
| Metamessage | 记忆条目标注 |

### 3.3 自定义提供商

任何实现 `MemoryProvider` trait 的 HTTP 服务均可接入：

```yaml
# ~/.astro/config.yaml
memory_providers:
  - name: "my-memory"
    type: "custom"
    endpoint: "http://localhost:8000/memory"
    api_key: "custom_key_123"
```

自定义提供商需实现以下 REST 端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/search` | POST | 语义搜索 |
| `/add` | POST | 添加记忆 |
| `/delete/{id}` | DELETE | 删除记忆 |
| `/health` | GET | 健康检查 |

## 4. 集成架构

### 4.1 MemoryAggregator

```rust
pub struct MemoryAggregator {
    internal: Arc<InternalMemory>,                     // 内置 L1-L4
    providers: Vec<Arc<dyn MemoryProvider>>,            // 外部提供商
    dedup_threshold: f32,                               // 去重相似度阈值
}

impl MemoryAggregator {
    /// 合并搜索：内置 + 所有外部提供商
    pub async fn search(&self, query: &str, top_k: usize) -> Vec<MemoryEntry> {
        // 1. 并发搜索所有来源
        let mut futures = vec![];

        // 内置记忆搜索
        futures.push(self.internal.search(query, top_k));

        // 外部提供商搜索（带超时）
        for provider in &self.providers {
            let p = provider.clone();
            let q = query.to_string();
            futures.push(tokio::spawn(async move {
                tokio::time::timeout(
                    Duration::from_secs(3),
                    p.search(&q, top_k, None),
                ).await
                .unwrap_or(Ok(vec![]))
                .unwrap_or_default()
            }));
        }

        let results = futures::future::join_all(futures).await;

        // 2. 合并所有结果
        let mut all_entries: Vec<MemoryEntry> = results
            .into_iter()
            .flatten()
            .collect();

        // 3. 去重（相同内容保留分数最高的）
        self.dedup(&mut all_entries);

        // 4. 按 relevance_score 降序排序
        all_entries.sort_by(|a, b| b.relevance_score.partial_cmp(&a.relevance_score).unwrap());

        // 5. 取 top_k
        all_entries.truncate(top_k);

        all_entries
    }

    /// 去重：内容相似度 > threshold 的条目只保留分数最高的
    fn dedup(&self, entries: &mut Vec<MemoryEntry>) {
        let mut seen: Vec<String> = vec![];
        entries.retain(|entry| {
            for s in &seen {
                if text_similarity(&entry.content, s) > self.dedup_threshold {
                    return false;
                }
            }
            seen.push(entry.content.clone());
            true
        });
    }
}
```

搜索结果通过 `Slot[5]`（记忆注入槽）注入到 LLM prompt：

```

[内置/L3] 用户偏好使用 pnpm 而非 npm（score: 0.92）
```

每条记忆标注来源（内置层级或外部提供商名称），方便用户和 Agent 判断可信度。

`~/.astro/config.yaml` 中的记忆提供商配置：

```yaml
memory:
  # 内置记忆（始终启用）
  internal:
    enabled: true

  # 外部提供商
  providers:
    - name: "mem0"
      type: "mem0"
      api_key: "${MEM0_API_KEY}"      # 支持环境变量引用
      user_id: "astro_user_001"
      enabled: true

    - name: "honcho"
      type: "honcho"
      api_key: "${HONCHO_API_KEY}"
      app_id: "astro_app"
      user_id: "astro_user_001"
      enabled: false                  # 默认关闭

  # 聚合设置
  aggregator:
    dedup_threshold: 0.85             # 去重相似度阈值
    external_timeout_ms: 3000         # 外部查询超时
    max_external_results: 10          # 每个外部提供商最多返回条数
```

## 6. 数据同步策略

### 6.1 单向读取（默认）

默认模式下，外部提供商仅作为搜索来源，Agent 不向外部写入数据：

- `search()` — 使用
- `add()` — 不使用

### 6.2 双向同步（可选）

用户可开启"同步记忆到外部服务"：

```yaml
memory:
  providers:
    - name: "mem0"
      sync_mode: "bidirectional"      # read_only（默认） | bidirectional
      sync_levels: ["L3"]             # 仅同步指定层级
```

- 只同步 L3（长期记忆），不同步 L1（工作记忆）和 L2（短期记忆）
- L4（知识图谱）的同步需要额外的图结构映射，v0.3 暂不支持
- 同步频率：记忆条目创建/更新时异步推送，不阻塞主流程

### 6.3 冲突处理

外部和内置记忆冲突时的处理规则：

| 场景 | 处理 |
|------|------|
| 相同内容不同分数 | 保留分数较高的来源 |
| 外部服务不可用 | 静默降级，仅使用内置记忆 |
| 外部返回超时 | 3 秒超时，跳过该提供商 |

### 7.2 数据过滤

向外部服务发送数据前的过滤规则：

- 自动移除包含 API Key、Token、密码等敏感模式的记忆条目
- 敏感模式检测复用工具风险评估模块的正则规则
- 用户可配置额外的排除关键词列表

```yaml
memory:
  privacy:
    exclude_patterns:
      - "password"
      - "secret"
      - "api_key"
      - "token"
    exclude_tags:
      - "sensitive"
      - "private"
```

### 7.3 API Key 安全

- 外部提供商的 API Key 支持环境变量引用（`${ENV_VAR}`），避免明文存储
- 配置文件权限 `600`
- 设置页显示 Key 时默认遮罩，需点击"显示"

## 10. 风险与约束

- **延迟**：外部 API 调用增加 100-500ms 延迟，通过并发查询 + 3 秒超时控制上限
- **成本**：外部记忆服务可能按调用次数收费，需在文档中提醒用户
- **一致性**：双向同步时可能出现数据不一致，MVP 阶段通过仅支持单向读取规避
- **依赖风险**：外部服务 API 变更可能导致集成失效，需关注上游 changelog
