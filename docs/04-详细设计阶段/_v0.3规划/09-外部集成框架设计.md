# 外部集成框架设计

> v0.3.1 规划 | 状态：规划中 | 覆盖：Telegram Bot、Slack Bot、渠道管理

---

## 1. 概述

Astro Agent 当前仅支持桌面端 UI 交互。v0.3.1 引入外部集成框架，允许通过 Telegram、Slack 等渠道与 Agent 交互，实现跨平台访问。

**设计目标**：

- 统一的渠道抽象层，新增渠道只需实现一个 trait
- 所有渠道共享同一工作区的记忆、Skills 和工具
- 外部渠道默认高安全等级，防止远程误操作

---

## 2. 集成架构

### 2.1 ChannelAdapter Trait

```rust
use async_trait::async_trait;

/// 渠道适配器 - 每个外部渠道实现此 trait
#[async_trait]
pub trait ChannelAdapter: Send + Sync + 'static {
    /// 渠道名称标识
    fn channel_name(&self) -> &str;

    /// 启动渠道监听（长驻任务）
    async fn start(&self, sender: mpsc::Sender<IncomingMessage>) -> Result<()>;

    /// 发送响应到渠道
    async fn send(&self, response: AgentResponse) -> Result<()>;

    /// 停止渠道
    async fn stop(&self) -> Result<()>;
}

/// 来自外部渠道的消息
pub struct IncomingMessage {
    pub channel: String,           // "telegram" | "slack"
    pub user_id: String,           // 渠道内用户标识
    pub conversation_id: String,   // 对话/线程 ID
    pub content: MessageContent,   // 文本 / 图片 / 文件
    pub timestamp: DateTime<Utc>,
}

pub enum MessageContent {
    Text(String),
    Image { url: String, caption: Option<String> },
    File { url: String, filename: String },
}
```

### 2.2 渠道管理器

```rust
pub struct ChannelManager {
    adapters: Vec<Box<dyn ChannelAdapter>>,
    agent_core: Arc<AgentCore>,
    incoming_rx: mpsc::Receiver<IncomingMessage>,
    incoming_tx: mpsc::Sender<IncomingMessage>,
}

impl ChannelManager {
    /// 注册渠道适配器
    pub fn register(&mut self, adapter: Box<dyn ChannelAdapter>) {
        self.adapters.push(adapter);
    }

    /// 启动所有渠道，统一消费消息队列
    pub async fn run(&self) -> Result<()> {
        // 启动每个渠道的监听
        for adapter in &self.adapters {
            let tx = self.incoming_tx.clone();
            tokio::spawn(adapter.start(tx));
        }

        // 统一消费消息 → 路由到 AgentCore
        while let Some(msg) = self.incoming_rx.recv().await {
            let response = self.agent_core.process(msg).await?;
            self.route_response(response).await?;
        }
        Ok(())
    }
}
```

## 3. Telegram Bot

### 3.1 技术选型

使用 `teloxide` crate（Rust 原生 Telegram Bot 框架），长轮询模式，无需公网 URL。

### 3.2 配置

`~/.astro/integrations/telegram.yaml`：

```yaml
enabled: true
bot_token: "123456:ABC-DEF..."       # 从 @BotFather 获取
allowed_users:                        # 白名单，空则拒绝所有
  - 12345678
  - 87654321
max_message_length: 4096              # Telegram 消息长度限制
```

### 3.3 功能映射

| Telegram 操作 | Agent 行为 |
|--------------|-----------|
| 发送文本消息 | 进入 Agent 对话，流式返回文本 |
| 发送图片 | 作为多模态输入，附加到对话 |
| 发送文件 | 下载到临时目录，作为上下文 |
| `/skill deploy-k8s` | 触发指定 Skill 执行 |
| `/skills` | 列出可用 Skills |
| `/cancel` | 取消当前执行中的任务 |
| `/status` | 查看 Agent 状态 |

### 3.4 消息处理

- 长文本回复自动分段（每段 ≤ 4096 字符）
- 代码块使用 Telegram Markdown 格式
- 执行中的任务显示 "typing..." 状态
- 超时 5 分钟无响应自动取消任务

## 4. Slack Bot

### 4.1 技术选型

使用 Slack Events API 的 **Socket Mode**，无需公网 URL，适合本地部署。

依赖 crate：`slack-morphism`（Rust Slack SDK）。

### 4.2 配置

`~/.astro/integrations/slack.yaml`：

```yaml
enabled: true
app_token: "xapp-1-..."             # Socket Mode App Token
bot_token: "xoxb-..."               # Bot User OAuth Token
allowed_channels:                    # 允许交互的频道
  - "C01234ABCDE"
allowed_users: []                    # 空 = 频道内所有人可用
```

### 4.3 功能映射

| Slack 操作 | Agent 行为 |
|-----------|-----------|
| @mention Bot | 触发 Agent 对话 |
| Thread reply | 在同一对话上下文中继续 |
| 上传文件 | 下载并作为上下文输入 |
| `/astro skill_name` | Slash command 触发 Skill |
| Emoji reaction 👍 | 标记任务结果为正向反馈 |

### 4.4 Thread 对话管理

- 每个 Slack thread 映射为一个 Agent conversation
- Thread ID 作为 `conversation_id`，复用记忆上下文
- 非 thread 的 @mention 创建新对话
- 对话 idle 超过 30 分钟后自动归档

## 5. 渠道共享记忆

### 5.1 统一记忆空间

所有渠道共享同一工作区的记忆系统（L1-L4），不按渠道隔离：

```rust
pub struct IncomingMessage {
    pub channel: String,          // 来源渠道标记
    // ...
}

// 记忆存储时标记来源
pub struct MemoryEntry {
    pub content: String,
    pub source_channel: String,   // "desktop" | "telegram" | "slack"
    pub created_at: DateTime<Utc>,
    // ...
}
```

### 5.2 跨渠道上下文

- 在 Telegram 中建立的对话记忆，可在桌面端或 Slack 中被召回
- 记忆搜索结果包含 `source_channel` 标记，方便用户溯源
- 对话历史（L1 工作记忆）按 `conversation_id` 隔离，不跨渠道混合

### 5.3 Skills 共享

- 所有渠道可触发相同的 Skills
- Skill 执行结果通过触发渠道返回
- 需审批的 Skill 操作在触发渠道内弹出确认消息

## 6. 权限控制

### 6.1 渠道风险等级

| 渠道 | 默认风险等级 | 说明 |
|------|-------------|------|
| Desktop | L1（低） | 本地操作，用户在场 |
| Telegram | L2（中） | 远程操作，需审批确认 |
| Slack | L2（中） | 远程操作，需审批确认 |

### 6.2 工具白名单

每个渠道独立配置允许使用的工具：

```yaml
# telegram.yaml
tool_whitelist:
  - "file_read"
  - "web_search"
  - "skill_execute"
  # 默认不包含 shell_execute / file_write 等高风险工具

tool_blacklist:
  - "shell_execute"     # 明确禁止
```

白名单为空时，使用全局默认工具集（排除高风险工具）。

### 6.3 审批机制

外部渠道触发高风险操作时的审批流程：

1. Agent 识别操作风险等级 > 渠道允许等级
2. 在触发渠道发送审批请求："操作 `rm -rf build/` 需要确认，回复 Y 执行 / N 取消"
3. 用户回复 Y → 执行；回复 N 或 60 秒超时 → 取消
4. 审批记录写入操作日志

### 6.4 认证安全

- Bot Token 存储在 `~/.astro/integrations/` 下，文件权限 `600`
- `allowed_users` / `allowed_channels` 白名单必须配置，空白名单 = 拒绝所有
- 非白名单用户的消息直接忽略，不返回任何响应

## 8. 风险与约束

- **网络依赖**：Telegram / Slack 渠道依赖网络连接，Agent 本身仍为本地运行
- **消息格式**：不同渠道的 Markdown 语法不同，需在 `send()` 中做格式转换
- **并发**：多渠道同时触发任务时，AgentCore 需支持并发任务队列（复用 v0.2 的任务管理器）
- **隐私**：消息经过第三方平台传输，敏感信息应在发送前过滤或加密
