# 加密备份与恢复

> v0.3 精简版 | 状态：规划中 | 原零知识同步方案已简化为本地加密备份
> 原文档：540 行（三级密钥层次、XChaCha20 加密块、多设备 X25519 密钥交换、零知识服务器 API），已归档精简

## 设计原则

- **本地优先**：备份文件存储在用户指定目录
- **用户自选同步**：用户可将备份目录放在 iCloud/Dropbox 自行同步
- **无自建服务器**：不构建云端基础设施
- **密码保护**：备份文件使用 SQLCipher 加密，用户设置备份密码

## 1. 核心结构

```rust
// crates/agent-runtime/src/backup/manager.rs

pub struct BackupManager {
    db_pool: SqlitePool,
    backup_dir: PathBuf,          // 用户选择的备份目录
    passphrase: Option<String>,   // 备份密码（运行时持有，不持久化明文）
}

impl BackupManager {
    /// 创建加密备份到指定目录
    pub async fn backup_to_directory(&self, target_dir: &Path) -> anyhow::Result<BackupResult> {
        // 1. SQLite WAL checkpoint（确保所有写入刷到主文件）
        sqlx::query("PRAGMA wal_checkpoint(TRUNCATE)")
            .execute(&self.db_pool).await?;

        // 2. 使用 SQLCipher 的 sqlcipher_export 创建加密副本
        let backup_path = target_dir.join(format!(
            "astro-backup-{}.db",
            chrono::Utc::now().format("%Y%m%d-%H%M%S")
        ));
        sqlx::query(&format!(
            "ATTACH DATABASE '{}' AS backup KEY '{}'",
            backup_path.display(),
            self.passphrase.as_deref().unwrap_or("")
        )).execute(&self.db_pool).await?;

        sqlx::query("SELECT sqlcipher_export('backup')")
            .execute(&self.db_pool).await?;
        sqlx::query("DETACH DATABASE backup")
            .execute(&self.db_pool).await?;

        // 3. 写入元数据文件（版本、时间戳、校验和）
        let meta = BackupMeta {
            version: env!("CARGO_PKG_VERSION").to_string(),
            created_at: chrono::Utc::now(),
            checksum: sha256_file(&backup_path)?,
            is_incremental: false,
        };
        let meta_path = backup_path.with_extension("meta.json");
        std::fs::write(&meta_path, serde_json::to_string_pretty(&meta)?)?;

        Ok(BackupResult { path: backup_path, meta })
    }

    /// 从加密备份恢复
    pub async fn restore_from_backup(
        &self,
        backup_path: &Path,
        passphrase: &str,
    ) -> anyhow::Result<()> {
        // 1. 验证 meta.json 中的 checksum
        let meta_path = backup_path.with_extension("meta.json");
        let meta: BackupMeta = serde_json::from_str(&std::fs::read_to_string(&meta_path)?)?;
        let actual_checksum = sha256_file(backup_path)?;
        if actual_checksum != meta.checksum {
            return Err(anyhow::anyhow!("备份文件校验失败，可能已损坏"));
        }

        // 2. 用 passphrase 打开加密备份并导入
        sqlx::query(&format!(
            "ATTACH DATABASE '{}' AS restore KEY '{}'",
            backup_path.display(), passphrase
        )).execute(&self.db_pool).await?;

        sqlx::query("SELECT sqlcipher_export('main', 'restore')")
            .execute(&self.db_pool).await?;
        sqlx::query("DETACH DATABASE restore")
            .execute(&self.db_pool).await?;

        Ok(())
    }
}
```

## 2. 增量备份

基于 SQLite WAL（Write-Ahead Log）实现轻量增量备份：

```rust
pub async fn incremental_backup(&self, target_dir: &Path) -> anyhow::Result<BackupResult> {
    let latest = find_latest_backup(target_dir)?;

    match latest {
        Some(base) => {
            // WAL checkpoint 后比较文件修改时间
            // 如果距上次备份无写入 → 跳过
            let db_modified = std::fs::metadata(&self.db_path)?.modified()?;
            if db_modified <= base.meta.created_at.into() {
                return Ok(BackupResult::skipped());
            }
            // 有变更 → 全量加密备份（SQLCipher 不支持页级增量）
            self.backup_to_directory(target_dir).await
        }
        None => self.backup_to_directory(target_dir).await, // 首次 → 全量
    }
}
```

**说明**：SQLCipher 加密后无法做页级 diff，因此"增量"策略为：检测到数据变更时才执行全量备份，无变更则跳过。备份目录保留最近 N 份（默认 5），自动清理旧备份。

## 3. UI 设计

**位置**：Settings > Data > Backup

| 控件 | 说明 |
|------|------|
| 备份目录 | 目录选择器，显示当前路径（如 `~/Library/CloudStorage/iCloud/AstroBackup`） |
| 备份密码 | 密码输入框 + 确认框（首次设置或修改时） |
| 自动备份 | 开关 + 频率选择（每日/每周/手动） |
| 立即备份 | 按钮，点击执行一次备份 |
| 恢复备份 | 文件选择器，选择 `.db` 文件 → 输入密码 → 确认恢复 |
| 备份历史 | 列表：文件名、时间、大小，支持删除旧备份 |

## 4. 与现有加密层的关系

| 层 | 作用 | 密钥来源 |
|----|------|---------|
| SQLCipher（本地 .db） | 防止磁盘被盗时数据泄露 | OS Keychain |
| 备份加密（本文档） | 保护备份文件安全 | 用户设置的备份密码 |

两层独立，互不依赖。
