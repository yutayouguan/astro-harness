# 全局搜索系统设计

> 版本：v1.0 | 日期：2026-08-07 | 状态：草稿
> 对应需求：F-17 全局搜索、M-19 全局搜索模块

> **当前 Harness 基线（2026-08-29）**：`session_search` 是 Harness 工具能力，受当前 StepContext、工具暴露和授权约束；桌面全局搜索是 UI/索引投影。两者不得与 Provider `WebSearch` 或本地 HTTP `web_search` Function 混用。

全局搜索提供跨对话、跨文件、跨知识库、跨 Skills 的统一检索入口（`Cmd+Shift+F`），以及 Agent 内部可调用的 `session_search` 工具（FTS5 历史对话检索）。

---

## 1. 搜索源与索引策略

| 搜索源 | 索引类型 | 索引位置 | 优先级 |
| ------ | -------- | -------- | ------ |
| **对话消息**（messages） | FTS5 虚拟表 `messages_fts` | state.db | P1 |
| **知识库文档块**（knowledge chunks） | FTS5 `chunks_fts` + sqlite-vec 向量 | state.db | P1 |
| **工作区文件** | 实时 grep（ripgrep/Rust walkdir） | 文件系统 | P1 |
| **Skills** | FTS5 `skills_fts`（name + content） | state.db | P1 |
| **记忆条目**（memory_entries） | FTS5 `memory_entries_fts` | state.db | P2 |

### 1.1 messages_fts 表结构（已有 Schema）

```sql
-- 完整 DDL 见数据库设计/01-Schema设计.md §14
CREATE VIRTUAL TABLE IF NOT EXISTS messages_fts USING fts5(
    content,               -- 消息正文（与 messages.content 同步）
    conversation_title,    -- 会话标题（冗余，避免 JOIN）
    content='messages',
    content_rowid='rowid',
    tokenize='unicode61'   -- 支持中英文混合分词
);
```

触发器（`messages_fts_insert / _delete / _update`）保持索引与 `messages` 表实时同步，无需手动维护。

### 1.2 工作区文件搜索策略

文件系统搜索不建索引，使用 `ripgrep` 等价的 Rust 实现（`grep` crate + `walkdir`）在搜索时实时扫描：

- 扫描路径：当前工作区目录（`workspace.root_dir`）
- 文件过滤：按 `.gitignore` 规则 + 常见二进制文件排除（图片/视频/编译产物）
- 超时保护：文件搜索硬性超时 2s，超时返回已找到的部分结果

## 2. 搜索引擎架构

```text
GlobalSearchEngine
    │
    ├── MessageSearch    (FTS5 messages_fts)
    ├── KnowledgeSearch  (FTS5 chunks_fts + 可选向量 rerank)
    ├── FileSearch       (walkdir + regex scan)
    └── SkillSearch      (FTS5 skills_fts)
```

所有搜索源实现同一 trait：

```rust
// crates/agent-core/src/search/mod.rs

#[async_trait]
pub trait SearchSource: Send + Sync {
    async fn search(
        &self,
        query: &str,
        workspace_id: &str,
        limit: usize,
    ) -> anyhow::Result<Vec<SearchResult>>;
}

#[derive(Debug, Serialize)]
pub struct SearchResult {
    pub source: SearchSourceType,
    pub id: String,             // conversation_id / chunk_id / 文件路径 / skill_id
    pub title: String,
    pub snippet: String,        // 高亮片段（≤ 200 字符）
    pub score: f64,             // 归一化 BM25 分（0.0–1.0）
    pub metadata: SearchMeta,   // 来源附加信息
}

#[derive(Debug, Serialize)]
#[serde(rename_all = "camelCase")]
pub enum SearchSourceType { Message, Knowledge, File, Skill, Memory }

#[derive(Debug, Serialize)]
#[serde(untagged)]
pub enum SearchMeta {
    Message  { conversation_id: String; workspace_id: String; created_at: i64 },
    Knowledge { chunk_index: u32; doc_title: String },
    File     { path: String; line_number: u32 },
    Skill    { version: String },
    Memory   { key: String },
}
```

## 3. Rust 实现

### 3.1 GlobalSearchEngine

```rust
// crates/agent-core/src/search/engine.rs

pub struct GlobalSearchEngine {
    pool: SqlitePool,
    workspace_root: PathBuf,
}

impl GlobalSearchEngine {
    /// 并发查询所有搜索源，合并排序结果
    pub async fn search(
        &self,
        query: &str,
        workspace_id: &str,
        options: &SearchOptions,
    ) -> anyhow::Result<SearchResponse> {
        // 各搜索源并发执行，互不阻塞
        let (messages, knowledge, files, skills) = tokio::join!(
            MessageSearch::new(&self.pool).search(query, workspace_id, 20),
            KnowledgeSearch::new(&self.pool).search(query, workspace_id, 10),
            FileSearch::new(&self.workspace_root).search(query, workspace_id, 10),
            SkillSearch::new(&self.pool).search(query, workspace_id, 10),
        );

        let mut results: Vec<SearchResult> = [
            messages.unwrap_or_default(),
            knowledge.unwrap_or_default(),
            files.unwrap_or_default(),
            skills.unwrap_or_default(),
        ].concat();

        // 按 score 降序，同类型内保持相对顺序
        results.sort_by(|a, b| b.score.partial_cmp(&a.score).unwrap_or(Ordering::Equal));

        Ok(SearchResponse {
            query: query.to_string(),
            total: results.len(),
            results,
        })
    }
}
```

### 3.2 MessageSearch（FTS5）

```rust
// crates/agent-core/src/search/message_search.rs

impl SearchSource for MessageSearch {
    async fn search(&self, query: &str, workspace_id: &str, limit: usize) -> anyhow::Result<Vec<SearchResult>> {
        let rows = sqlx::query!(
            r#"SELECT
                 m.id,
                 m.conversation_id,
                 m.created_at,
                 f.conversation_title,
                 snippet(messages_fts, 0, '<mark>', '</mark>', '...', 20) AS snippet,
                 bm25(messages_fts) AS rank
               FROM messages_fts f
               JOIN messages m ON m.rowid = f.rowid
               JOIN conversations c ON c.id = m.conversation_id
               WHERE messages_fts MATCH ?
                 AND c.workspace_id = ?
               ORDER BY rank
               LIMIT ?"#,
            query, workspace_id, limit as i64
        )
        .fetch_all(&self.pool)
        .await?;

        Ok(rows.into_iter().map(|r| SearchResult {
            source: SearchSourceType::Message,
            id: r.id,
            title: r.conversation_title.unwrap_or_default(),
            snippet: r.snippet.unwrap_or_default(),
            score: normalize_bm25(r.rank.unwrap_or(0.0)),
            metadata: SearchMeta::Message {
                conversation_id: r.conversation_id,
                workspace_id: workspace_id.to_string(),
                created_at: r.created_at,
            },
        }).collect())
    }
}

/// BM25 得分为负值（越负越相关），归一化到 [0, 1]
fn normalize_bm25(rank: f64) -> f64 {
    1.0 / (1.0 + rank.abs())
}
```

### 3.3 FileSearch（实时扫描）

```rust
// crates/agent-core/src/search/file_search.rs

impl SearchSource for FileSearch {
    async fn search(&self, query: &str, _workspace_id: &str, limit: usize) -> anyhow::Result<Vec<SearchResult>> {
        let root = self.workspace_root.clone();
        let query = query.to_string();

        // 文件 IO 在独立线程执行，避免阻塞 tokio 运行时
        let results = tokio::task::spawn_blocking(move || {
            search_files_sync(&root, &query, limit)
        })
        .await??;

        Ok(results)
    }
}

fn search_files_sync(root: &Path, query: &str, limit: usize) -> anyhow::Result<Vec<SearchResult>> {
    let re = regex::Regex::new(&regex::escape(query))?;
    let mut results = Vec::new();

    for entry in walkdir::WalkDir::new(root)
        .follow_links(false)
        .into_iter()
        .filter_entry(|e| !is_excluded(e))
        .filter_map(|e| e.ok())
        .filter(|e| e.file_type().is_file())
    {
        if results.len() >= limit { break; }

        let Ok(text) = std::fs::read_to_string(entry.path()) else { continue };
        for (line_no, line) in text.lines().enumerate() {
            if re.is_match(line) {
                let snippet = line.trim().chars().take(200).collect::<String>();
                results.push(SearchResult {
                    source: SearchSourceType::File,
                    id: entry.path().to_string_lossy().into_owned(),
                    title: entry.file_name().to_string_lossy().into_owned(),
                    snippet,
                    score: 0.5,  // 文件搜索无 BM25，固定中等分值
                    metadata: SearchMeta::File {
                        path: entry.path().to_string_lossy().into_owned(),
                        line_number: (line_no + 1) as u32,
                    },
                });
                if results.len() >= limit { break; }
            }
        }
    }
    Ok(results)
}
```

## 5. Tauri Command

```rust
// apps/desktop/src-tauri/src/commands/search.rs

#[tauri::command]
pub async fn global_search(
    query: String,
    workspace_id: String,
    state: State<'_, AppState>,
) -> Result<SearchResponse, String> {
    if query.trim().is_empty() {
        return Ok(SearchResponse::empty());
    }

    state
        .search_engine
        .search(&query, &workspace_id, &SearchOptions::default())
        .await
        .map_err(|e| e.to_string())
}
```

### 6.3 SearchModal 组件

```typescript
// apps/desktop/src/components/search/SearchModal.tsx

interface SearchModalProps {
  open: boolean;
  onClose: () => void;
  workspaceId: string;
}

export function SearchModal({ open, onClose, workspaceId }: SearchModalProps) {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<SearchResponse | null>(null);
  const [selected, setSelected] = useState<SearchResult | null>(null);

  // 防抖搜索
  useEffect(() => {
    if (!query.trim()) { setResults(null); return; }
    const timer = setTimeout(async () => {
      const res = await invoke<SearchResponse>("global_search", { query, workspaceId });
      setResults(res);
      setSelected(res.results[0] ?? null);
    }, 300);
    return () => clearTimeout(timer);
  }, [query, workspaceId]);

  const grouped = useMemo(() => groupBySource(results?.results ?? []), [results]);

  return (
    <Dialog open={open} onOpenChange={onClose}>
      <DialogContent className="search-modal">
        <SearchInput value={query} onChange={setQuery} />
        <div className="search-body">
          <SearchResultList groups={grouped} selected={selected} onSelect={setSelected} />
          <SearchPreview result={selected} onNavigate={onClose} />
        </div>
      </DialogContent>
    </Dialog>
  );
}
```

## 7. 性能目标

| 场景 | 目标延迟 | 实现手段 |
| ---- | -------- | -------- |
| 消息 FTS5 搜索（100 万条） | < 20ms | BM25 内置索引，unicode61 分词 |
| 知识库全文搜索（10 万 chunk） | < 30ms | 独立 `chunks_fts` 虚拟表 |
| 工作区文件扫描（1 万文件） | < 2s | spawn_blocking + 超时保护 |
| 整体搜索响应（含 UI 防抖） | < 350ms | 并发查询 + 300ms 防抖 |

## 8. 设计约束

- **跨工作区隔离**：所有 DB 搜索 SQL 必须携带 `workspace_id` 条件，文件搜索限定在当前工作区 `root_dir`
- **内容安全**：搜索结果中的 `snippet` 使用 SQLite `snippet()` 函数生成，标记词通过 `<mark>` 包裹后在前端渲染（不直接 innerHTML）
- **`session_search` 与 UI 搜索共享实现**：底层 `SearchSource` trait 实现复用，避免逻辑分叉
- **结果不截断**：`session_search` 工具返回完整 `content`（不做截断），保证 Agent 能读到完整历史；UI 搜索只显示 snippet
