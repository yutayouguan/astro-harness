# 桌面宠物详细设计

## 目标与范围

桌面宠物是 Astro 的本地透明悬浮窗口。它同时支持：

- 单张 PNG/JPEG/WebP 静态桌宠，作为快速生成和降级路径。
- Codex-compatible v2 动画桌宠，使用 `8x11` atlas 与 `spriteVersionNumber: 2`。

自动生成完整 v2 atlas 属于后续的后台孵化流水线；当前运行时提供严格导入、播放和 Agent 状态投影。

## 持久化协议

`~/.astro/ui/desktop-pet/state.json` 是桌宠当前状态的唯一事实源，由 `agent-types::DesktopPetState` 定义。Agent Tool 和 Tauri 命令必须通过共享文件锁读写，不得维护独立副本。

每次成功写入在同一文件锁内递增 `revision`；旧文件从版本 0 读取。临时文件通过原子替换提交，Windows 不先删除旧状态。非法缩放、未知动画版本或损坏 JSON 返回错误，不静默恢复默认设置。前端共用 `useDesktopPetState`，先订阅事件再读取快照，并拒绝旧版本回包；设置命令串行执行。

动画宠物包从用户显式选择的 `pet.json` 导入，再复制到：

```text
~/.astro/ui/desktop-pet/pets/<id>-<nonce>/
├── pet.json
└── spritesheet.png | spritesheet.webp
```

Astro 不自动扫描 `.codex/pets` 作为配置输入；用户可通过设置页显式导入兼容包。

## 宠物场景与 AI 壁纸联动

场景是可复用的桌宠身份快照与可选壁纸的配对。同一宠物可收藏多套场景；壁纸仍使用 `agent-types::UiStyleManifest`，不引入另一套主题格式，也不修改操作系统桌面壁纸。

- `DesktopPetState.scenes` 保存最多 100 个场景，包含 `id/name/pet/style/wallpaperSourcePath`；整个状态上限 1 MiB，图片仍为受控本地文件。
- `pet` 快照保留照片来源、静态图片或 v2 atlas、显示名与实际模型。场景切换不改变全局缩放和置顶设置。
- `style` 使用现有主题协议；壁纸与主题副本在 `ui/style/themes/<scene-id>/`，激活后进入既有 `active.json`、主题色适配和刷新链路。
- `followWallpaper` 默认关闭。整套应用开启；“仅桌宠”关闭；“仅壁纸”显式保留当前宠物，即使已有联动也不会立即切换。
- `lastWallpaperPath` 消除重复同步。未绑定壁纸保留桌宠，普通壁纸切换保留其显示/隐藏状态。同一原始壁纸被多次绑定时，以最近一次显式绑定为准。

### 生成与失败处理

设置页先上传照片，输入场景名，可勾选“同时生成配套壁纸”（默认关闭，额外一次图片请求）。先生成并收藏桌宠，再以该桌宠为参考生成环境壁纸；可另选包含宠物肖像。v2 宠物只取首个 idle 帧作为参考，避免将整张动画网格发给模型。

生成和关联仅保存预览，不替换当前场景。壁纸失败时保留已收藏桌宠，可按“生成 / 重试壁纸”单独补齐；也可选择最近使用的壁纸或本地图片。慢请求以场景快照校验，不能覆盖生成期间的新绑定。所有图片均校验实际格式、尺寸、解码内存和读取上限。

### 切换与恢复

`apply_pet_scene` / `desktop_pet action=apply_scene` 共用 `types::pet_scene::apply_scene`，模式为 `all/pet/wallpaper/linked`。选择与待发布主题一起写入桌宠状态；`pendingSceneStyle` 是持久化待办，后续读取会幂等发布主题并清除。单个文件原子替换；这不是跨文件同时可见的事务，但进程中断后可重放完成，发布失败明确报告“已保存，待恢复”。

前端 `useWallpaper` 收到现有 `ui-style-changed` 后将场景壁纸加入最近列表并停止跟随系统背景；手动选择、轮换、系统背景跟随均调用共享同步入口。请求串行并合并中间选择；后台在桌宠锁内重读实际激活主题，拒绝迟到的旧壁纸关联。`useActiveUiStyle` 同时拒绝过期读取回包。桌宠配置损坏不阻断独立壁纸读取。

聊天入口仍为 Deferred `desktop_pet`：`save_scene` 可将 `image_gen` 的 `imagePath` 保存为新预览，或通过 `sceneId + wallpaperPath` 为已收藏场景补壁纸；`status` 返回收藏；`configure followWallpaper` 控制联动。内置 `desktop-pet-creator` Skill 先询问/遵循用户的配套壁纸选择，不默认增加费用。

交互验收样例：Storybook `Settings/PetSceneStudio`。样例复用概念图并模拟壁纸失败，不调用模型或修改真实桌宠；原生窗口联动与 Azure 实际出图需在重启后的 Desktop 上验收。

## V2 Atlas 契约

| 项目 | 值 |
| --- | --- |
| 图集尺寸 | `1536x2288` |
| 单元格 | `192x208` |
| 网格 | `8` 列 x `11` 行 |
| 标准动作 | 行 `0-8` |
| 16 向注视 | 行 `9-10` |
| 透明度 | 所有未使用单元格必须全透明 |

导入时必须校验 manifest 版本、路径越界、图片真实格式、图集尺寸、已用格非空和未用格全透明。失败时不替换当前桌宠。

## 动画与状态投影

Canvas 播放器按 v2 的逐帧时长播放，切换动作时复用已解码的 atlas，不重新加载图片。

| Astro 运行状态 | 动画行 |
| --- | --- |
| 无活动 | `idle` |
| Turn / Tool 执行 | `running` |
| 审批或等待用户输入 | `waiting` |
| review / inspect / audit 工具 | `review` |
| 首次显示或更换动画宠物 | `waving` |
| Turn 成功 | `jumping` 短暂播放后回到聚合状态 |
| Turn 失败 | `failed` 短暂播放后回到聚合状态 |
| 向左/右拖动 | `running-left` / `running-right` |
| 空闲时鼠标靠近 | 行 `9-10` 的 16 向注视 |

`session_status_changed` 提供运行/等待的权威状态；`desktop_pet_activity_changed` 仅由已接纳的 live 事件产生，补充 review 与明确的成功/失败/中断结果，历史快照不触发情绪动画。两条通道共用单调事件时钟。前端按 Session 拒绝过期事件和重复结果；多会话等待状态优先，其他任务结束不会清除等待。

## 可访问性与性能

- `prefers-reduced-motion` 下每个状态只显示首帧，禁用注视跟随和拖动动作切换。
- atlas 每次路径变化只解码一次，动作切换仅重置时间轴。
- Canvas 按设备像素比绘制，但最高使用 `2x`，防止高 DPI 窗口过度消耗。
- 动作切换不锁定指针输入；窗口拖动仍由 Tauri 原生机制接管。
- 左右移动由原生 `onMoved` 位移决定，不按按下位置猜测。动画图片加载失败会清空旧帧并显示错误；切换 reduced-motion 后不会停留在方向帧。
- 创建 WebView 的命令为异步；外部状态刷新运行在工作线程，避免 Windows WebView2 的同步命令死锁。窗口更新串行执行并重新读取最新状态。

## 信任边界

- 仅导入用户显式选择的 manifest。
- `spritesheetPath` 必须是包内相对路径，canonicalize 后不得越出 manifest 父目录。
- 只接受 PNG/WebP，atlas 最大 50 MB，manifest 最大 64 KiB。
- 文件读取先校验已打开文件的类型/大小，同时限制实际读取字节数；解码也有尺寸与内存限额。
- 导入、校验或状态写入失败时，保留当前桌宠并清理未完成的临时包。
- 静态图片统一经过同一 PNG 规范化器：只剔除与外边界连通的纯色背景，保留角色内部相似颜色与已有 alpha，所有返回分支都编码为真实 PNG。
