# 首次启动与首任务引导

## 用户路径

欢迎动画 → 个性化与可选使用偏好 → 真实连接验证（不可跳过） → 工作空间/权限 → 设置摘要 → 聊天中的初次见面，或首任务草稿。

引导页不收集用户称呼、职业或背景；这些信息在真实聊天中自然了解，不是进入应用或开始任务的门槛。

初始化必须完成真实模型验证，不能跳过。已完成初始化的用户后续失去模型凭证时，聊天中的“连接模型”进入现有模型服务设置。普通发送与并行任务发送共用 `providerIsReady` 配置检查，后端凭证检查仍是执行边界。

## 持久化与恢复

`home::onboarding_path`（默认 `~/.astro/ui/onboarding.json`）由 Tauri 管理。检查入口位于 `ActiveAgentProvider` 之前。默认配置文件、空数据库和后台 rollout 不作为老用户证据；已有会话或 completed 标记会跳过初始化。Provider 配置沿用全局 TOML `desktop.providers`，不回退或双写旧 JSON。

`save_onboarding_progress(step, draft)` 保存有界、非机密草稿：

- Agent 名称、Provider ID、模型、服务地址；
- 工作空间路径、权限预设。
- 可选的桌宠选择 `pet_enabled`；未操作时为 null，表示保留已有设置。

语言和主题继续使用现有偏好持久化。API Key 仅经 `set_provider_api_key` 交给现有凭证存储，不进入草稿。含用户名、密码或凭证查询参数的 URL 不保存。后端拒绝草稿中的未知字段，避免误传 apiKey。

客户端串行执行进度写入和完成操作；完成前等待保存结果。后端写入有互斥锁，使用同目录临时文件、sync_all 和 rename 替换；晚到的进度写入不能重新打开已完成状态。只有“关于 → 重新运行”可以重置。读写失败在 UI 中显示重试入口，不静默宣称完成。

字段编辑采用 700ms 合并保存，服务地址失焦及步骤切换立即保存。草稿文件操作通过异步命令转入阻塞线程池，避免文件锁与 `fsync` 占用原生界面线程；品牌装饰和提供商选项保持稳定，避免输入时重复构建无关内容。地址标签只显示“服务地址”，关闭输入自动纠正与首字母大写，保留正常光标及选区行为。

地址编辑回归覆盖 Azure 长地址中间选区替换、连续输入期间不逐字保存、删除/插入后的光标与值、失焦落盘；已在隔离原生 WebView 中核对占位符替换、中间编辑和最终草稿内容，不以浏览器测试单独判定原生输入体验。

模型配置页不再对整块表单卡片应用实时 backdrop blur，保留原底色、边框和阴影；输入框焦点反馈不做过渡动画。点击/拖选回归使用 Chromium 与 WebKit，并断言输入控件祖先无实时 backdrop filter、字段不属于原生拖拽区域。可用 `ASTRO_FOCUS_BENCH=1 npx playwright test -c playwright.onboarding-input.config.ts` 做可逆 A/B 诊断：记录 pointerdown 到两次 requestAnimationFrame 的间隔，不把它解释为端到端输入延迟。首次运行需 `npx playwright install chromium webkit`。

2026-09-09 诊断：关闭入场动效后，Chromium 旧卡片点击指标约 53ms，移除整卡模糊后约 14ms，恢复旧模糊后约 52ms；WebKit 同项约 27ms，未复现同等差距。这证明了可复现的 Chromium 重绘开销，但不单独证明所有原生卡顿均已消除。

## 可选使用偏好

个性化页提供桌面宠物、任务通知和登录时启动，均不是新的必经步骤。新安装默认为关闭；读取既有状态时不写回默认值。通知与登录启动即时保存，桌宠只保存到引导草稿，完成模型及目录验证后才应用。

- 桌宠复用 `types::update_desktop_pet_state` 事务。有既有素材时沿用，不覆盖照片、名称、缩放或场景。没有素材且用户选择开启时，安装随包内置的静态 SVG 小伙伴，不调用图像模型。未完成/重新运行引导时原生桌宠窗口保持隐藏；重新引导不改原本的 enabled 设置，完成后恢复显示。
- 任务通知复用全局 TOML `desktop.notifications.enabled`，只改该字段，保留其他段、同段未知字段和注释。启动时不申请权限；用户开启时才申请，拒绝授权或保存失败会显示错误并重新读取真实状态。仅接受已去重的 live 回合完成/失败/等待确认以及 Cron 完成/失败；历史快照、token、手动中断和内部入梦不触发。系统通知只用固定状态文案，不带任务标题、正文、工具参数或错误详情。
- 登录启动使用 Tauri autostart 的真实系统状态，不另建 TOML 镜像。引导与设置页共用读写命令，设置后核验实际状态；失败尝试回滚并提示，避免只把开关画成成功。

通知和登录启动在“设置 → 通用”可再次修改；桌宠的详细配置保留在桌宠设置。Storybook 只改变演示状态，不请求系统权限、不创建登录项、不保存或生成宠物。

2026-09-09 使用偏好验收：自动化覆盖默认关闭、已有设置不写回、授权/系统设置失败回读、缺失旧桌宠不被内置素材替换，以及未验证时不得安装/显示桌宠。原生隔离测试包中核对了内置预览、返回页面后保留开启状态、完成前仅存草稿，以及完成后真实桌宠窗口显示 SVG 小伙伴。未执行系统注销/登录，不把开关开启等同于实际登录启动验收；系统通知权限拒绝与回滚采用测试传输覆盖。

QA 包若开启登录启动会创建独立的系统登录项，目标仍是测试包路径；验收结束后应让用户决定是否关闭，不能擅自清除用户选择，也不能把临时数据根当成系统登录时自动继承的环境。

## 工作空间路径确认

工作空间卡片直接显示实际路径；标准默认目录为 `~/.astro/workspace`，使用 `ASTRO_MEMORY_DIR` 时显示对应根目录下的 `workspace`。运行时读取 `get_config.default_workspace_dir` 与 `default_workspace_display_path`，后者由后端按当前用户主目录缩写；前端不猜测用户名或写死默认路径。

用户确认路径后点击“完成设置”，也可选其他目录或恢复默认。默认路径读取失败时提供重试，不允许以未知路径完成；完成摘要保留路径，并将实际使用该根目录的项目设为当前项目。普通 Storybook 预览中的默认路径是明确标注的演示值。

进入工作空间步骤或更换目录后，通过 `check_onboarding_workspace` 检查目录存在、可列出、可写。写入检查只创建一个随机命名的 `.astro-write-check-*` 小文件，写入同步后删除，不创建不存在的目录、不改现有文件。失败提供“重新检查”与更换目录。完成前前端再次检查，后端 `complete_onboarding` 也检查已保存草稿对应的目录；最终保存期间锁定目录与权限选择。

## 模型连接

先填写 API Key（或使用已保存的密钥），点击“保存密钥并获取模型”，再从共享 SelectMenu 中主动选择默认聊天模型。列表来自所选服务的模型接口，不预选硬编码默认值；非聊天模型和重复项会过滤。获取列表不发起聊天生成，但也不代表连接验证通过。修改密钥、服务地址或提供商会清空列表与验证结果；重新拉取强制绕过旧列表缓存，空列表和失败均需重试。

已添加账户会复用保存的地址、密钥和模型，配置未改变时不重复写 Provider；已有模型也必须在新获取的列表中才能继续测试。获取成功自动打开搜索菜单；选择后突出并聚焦测试按钮，测试成功突出并聚焦“继续”，不自动生成或自动跳过步骤。余额/限流错误可打开后端提供的 HTTPS 官方控制台，密钥与地址错误继续直接定位对应字段。

复用现有 Provider 保存、密钥保存、测试及激活命令。初始化通过 `verify_onboarding_provider` 包装 canonical `test_provider`：只有真实测试成功才返回不落盘的随机验证凭据。`complete_onboarding(verificationToken)` 在后端核验当前激活 Provider、backend、模型、服务地址及凭证与测试快照完全一致，且验证未超过 15 分钟；成功完成后消费凭据。

应用重启或恢复未完成的工作空间步骤时，先返回模型页重新验证。配置变化、凭据丢失或过期都会拒绝完成。读取初始化状态失败时仅可重试，不提供绕过入口。连接测试由用户点击触发，旁边明确提示短生成请求可能产生少量费用。客户端为测试及相关请求设置 20 秒等待上限。

“取消等待”会作废当前请求序号，迟到的测试响应不得继续激活模型。它们不撤销已经完成的配置保存，也不承诺取消服务端已收到的生成请求。

失败分类：密钥/权限、余额/配额、模型/部署不存在、超时、网络、限流及未知错误。仅显示静态处理建议，不回显可能含凭证的供应商原始错误。

正式完成摘要只能以本次已验证连接为前提；演示数据明确标识，不作为完成凭据。沙箱不可用/未确认时展示提示，不统一显示绿色通过。

## 已添加提供商与模板

Provider 配置持久化 `added` 标记；`get_providers_state.providers` 只返回已添加账户，未添加内置项放在独立的 `provider_templates`，仅供初始化选择。设置页首次为空，用户通过“添加提供商”添加后立即显示，即使尚未填写密钥。保存初始化配置/密钥同样会将选中的模板转为已添加账户。可以删除最后一个账户，重启不会再显示未添加模板。

旧配置缺少 `added` 时做一次性分类：有真实凭证、改过名称/地址/模型/能力配置、自定义/TOML 项或同类重复账户会保留为已添加；原样内置默认项隐藏但不删除。旧格式无法精确还原“手工添加后完全未修改”的历史，隐藏项仍可重新添加，原有数据和密钥不做清理。

## 首任务

完成页提供实用任务示例，包括查看桌面文件并建议至少五个协作方向。示例可直接填入新对话编辑。

任务示例只创建可编辑草稿，不自动调用模型。内容只有用户在聊天中点击发送后才交给所选模型；查看文件类任务按其授权范围和正常工具权限执行，选择示例本身不触发文件扫描。

草稿通过一次性 sessionStorage 交接，内存缓冲用于存储不可用时的同页面降级。App 接收后打开新对话并预填，输入框保持可编辑。

## 在聊天中初次见面

“进入 Astro，认识一下”在主界面入场结束、模型配置就绪且聊天为空时，使用普通 `useSend → start_chat` 路径发送一次 `/first-meeting` 开场。它不是新的资料弹窗，也不另建模型调用通道。完成页说明接下来会开始认识对话；使用已连接模型，正常产生模型用量。

内置 `first-meeting` Skill 随应用播种，通过现有 composer Skill 解析加载。先自我介绍，再用 `request_user_input_async` 每次问一个有推荐选项的问题；用户可填写昵称，也可直接开始具体任务。技能未安装、禁用或读取失败时不提交开场，也不消费邀请。

`ui/onboarding.json.first_meeting` 记录 `pending/deferred/started` 与会话 ID，不存称呼、问答或密钥。只有本次完成必要配置才创建 pending；旧安装没有该字段时不会被重新引导。发送前 `resolve_first_meeting(sessionId)` 在同一状态锁下领取邀请并原子落盘；StrictMode、重挂载和重启不重复自动发送。领取后提交失败仍保留会话身份，重试由用户操作；领取后崩溃且无历史时只准备重试草稿，不自动重发。started 表示交接过会话，不表示档案已补全。

用户先选任务示例或开始编辑时不覆盖草稿、不把开场排进其任务队列。“先做任务”将未开始的邀请设为 deferred，后续可从邀请入口或 `/first-meeting` 继续；当前会话的认识过程保留在正常聊天历史里。认识会话期间不自动弹出界面导览。

Skill 要求 AI 从明确回答提炼建议，先展示拟记住的摘要，允许修改、删除和暂不保存。确认后使用现有文件编辑工具局部更新 `USER.md`；只有用户明确确认的长期职责或表达偏好才补充 `IDENTITY.md`、`SOUL.md`，保留原身份、安全范围和人格原则。未知字段留空，已有内容不整篇重写。写入遵守普通工具审批，Skill 的确认要求是对话约束，不是额外的跨文件事务或强制授权机制。当前会话已有确认过的对话上下文；新会话读取文件，不宣称刷新其他运行中的会话。

开发验证使用临时目录与模拟传输，不修改真实用户的三份档案，也不调用真实计费模型。真实模型是否逐步遵循问答、摘要确认及局部写入，需要单独的端到端验收。

## 连续动效

`OnboardingBrandMotion` 维护一个固定定位 Logo，根据 intro、header、App 品牌锚点的实际位置更新几何信息。新页面出现时复用同一视觉元素，不逐页重新生成 Logo。进入 App 后卸载装饰层和观察器；目标缺失或系统未派发动画事件时有有界退场。

遵循 reduced-motion、reduced-transparency 和高对比偏好。减少动态效果时取消空间移动，仅使用短淡入淡出/静态切换。等待/装饰动画不决定功能操作能否完成。

## 测试

前端纯逻辑测试覆盖错误分类、草稿过滤、有界任务内容、一次性草稿交接及异步写入顺序。Rust 测试覆盖首次判断、恢复、完成保护与机密字段拒绝。

浏览器测试使用生产 Gate、生产 App 和模拟的 Tauri transport；测试 Provider 是本机拦截路由，外部 HTTP 请求全部阻断，不使用真实密钥或计费服务。

```sh
cd apps/desktop
node --test src/lib/ui/onboarding.test.ts src/lib/ui/onboardingIntegration.test.mjs
npx playwright test visual-tests/onboarding.spec.ts
```

Storybook 的普通演示场景明确标注模拟结果，且不将演示草稿交给生产 App；`App/Onboarding runtime` 用于原生传输契约测试。
