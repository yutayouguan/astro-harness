### ConversationView — 流式渲染

流式 token 通过 `listen<TokenChunkEvent>` 接收，写入 `useRef` 缓冲区，由 `requestAnimationFrame` 批量刷新到 React state，避免每 token 触发一次 re-render：

```typescript
const pendingChunks = useRef<string[]>([]);
const rafId = useRef<number>(0);

useEffect(() => {
  const unlistenToken = listen<TokenChunkEvent>('token_chunk', ({ payload }) => {
    if (payload.convId !== conversationId) return;
    pendingChunks.current.push(payload.delta);
    cancelAnimationFrame(rafId.current);
    rafId.current = requestAnimationFrame(() => {
      setMessages(prev => appendChunk(prev, pendingChunks.current.join('')));
      pendingChunks.current = [];
    });
  });

  // thinking_delta：DeepSeek / MiniMax 思考过程（折叠展示）
  const unlistenThinking = listen<ThinkingDeltaEvent>('thinking_delta', ({ payload }) => {
    if (payload.convId !== conversationId) return;
    setThinkingBuffer(prev => prev + payload.delta);
  });

  return () => {
    unlistenToken.then(f => f());
    unlistenThinking.then(f => f());
    cancelAnimationFrame(rafId.current);
  };
}, [conversationId]);
```

工具调用卡片采用受控展开/收起，`collapsed` 状态存储在 Zustand `toolCallSlice`，默认运行中展开、完成后收起。Markdown 渲染使用 `react-markdown` + `rehype-highlight`，代码块懒加载高亮。

### 代码 Diff 对比视图

#### 触发条件

当 AI 回复中的代码块与同一对话上文中的代码块有以下关系时自动启用：

- 相同文件名（代码块语言标识后的文件名，如 `` ```rust:src/main.rs ``）
- 内容相似度 > 60%（基于行级 LCS）

#### 视图模式

| 模式 | 说明 |
|------|------|
| 原始 | 完整代码块（默认） |
| Diff | 红绿行级差异，左旧右新 |
| 仅变更 | 只显示变更行 ± 3 行上下文 |

右上角切换按钮组：[原始] [Diff] [仅变更]

#### 实现

- diff 算法：使用 `diff` npm 包的 `diffLines()`
- 渲染：基于 `react-diff-viewer-continued`
- 文件名匹配：从 `` ``` `` 后的 `:filename` 提取，或从 AI 文字"修改 xxx 文件"中推断
- 无匹配时不显示 Diff 按钮

#### 组件

`CodeDiffView.tsx`：props 为 `oldCode`、`newCode`、`language`、`fileName`。

### ModelSwitcher — 会话中模型切换 UX

#### 切换到更大模型（上下文窗口足够）

- 无确认弹窗，直接切换
- 对话区插入系统消息："已切换到 {model_name}"（灰色小字）
- 后续消息使用新模型

#### 切换到更小模型（上下文窗口不足）

弹出确认对话框：

```typescript
interface ModelSwitchConfirmProps {
  currentTokens: number;
  newModel: string;
  newLimit: number;
  keepCount: number;
  totalCount: number;
  onConfirm: () => void;
  onCancel: () => void;
}
```

对话框内容：

- **标题**：切换模型需要压缩历史
- **内容**：当前对话使用了 `{current_tokens}` tokens，`{new_model}` 的上下文窗口为 `{new_limit}` tokens。切换后将自动压缩历史消息（保留最近 `{keep_count}` 条）。
- **压缩预览**：
  - 保留消息数：`{keep_count}` / `{total_count}`
  - 压缩方式：LLM 摘要
- **按钮**：[确认切换] [取消]

#### 切换后反馈

- 对话区插入系统消息："已切换到 {model_name}，{compressed_count} 条消息已压缩为摘要"
- 压缩的消息区域显示折叠块："{count} 条消息已压缩 [展开摘要]"

#### 消息级模型标识

- 每条 AI 消息底部小字显示模型名称（仅在会话使用过多个模型时显示）
- 格式：`Claude Sonnet 4 · 234 tokens · 1.2s`

```typescript

  <span className="message-model-tag">
    {message.modelName} · {message.tokenCount} tokens · {message.latencyFormatted}
```

#### 消息级信息显示

消息底部信息栏根据场景分层展示，避免信息过载：

**常态显示**

- AI 消息底部小字显示模型名 + 响应延迟：`Claude Sonnet 4 · 1.2s`
- **单模型会话**：隐藏模型名，仅显示延迟 `1.2s`
- **多模型会话**：始终显示模型名，便于区分不同模型的回复

**Hover 详情（Tooltip）**

### ApprovalDialog — HumanGuard 弹层

接收 `ApprovalRequestEvent`（含 `risk_level: L1|L2|L3`）后根据风险等级决定行为：

- **L1 (Low)** — 自动执行，无弹窗。前端收到事件后直接调用 `onApprove()`，不渲染 Dialog。
- **L2 (Medium)** — 弹窗确认，30s 超时自动拒绝。倒计时条使用 `setInterval(100ms)` 更新进度。
- **L3 (High)** — 弹窗确认，无超时，必须人工操作。

通过 Portal 挂载到 `document.body`：

```typescript
const [remaining, setRemaining] = useState(timeoutMs);

useEffect(() => {
  // L1：自动执行，不弹窗
  if (riskLevel === 'L1') {
    onApprove();
    return;
  }
  // L2：30s 超时自动拒绝
  if (riskLevel === 'L2' && timeoutMs > 0) {
    const id = setInterval(() => setRemaining(r => {
      if (r <= 100) { onReject(); clearInterval(id); return 0; }
      return r - 100;
    }), 100);
    return () => clearInterval(id);
  }
  // L3：无超时，等待人工操作
}, [riskLevel, timeoutMs]);
```

风险色彩：L2 用 `--color-warning` 橙色进度条，L3 全屏红色遮罩并锁定页面滚动（`document.body.style.overflow = 'hidden'`）。

### MemoryInspector — 记忆版本可视化

展示当前工作区的记忆条目，支持查看版本历史和 Weibull 衰减分数：

```typescript
interface MemoryEntryView {
  id: string;
  category: string;
  key: string;
  value: string;
  halfLifeDays: number;
  retrievalCount: number;
  validFrom: number;
  validTo: number | null;      // null = 当前活跃版本
  weibullScore: number;        // 前端计算，实时显示
}

// Weibull 分数前端计算（与 Rust 实现保持一致）
function weibullScore(entry: MemoryEntryView): number {
  const ageDays = (Date.now() - entry.validFrom) / 86_400_000;
  const effectiveHalfLife = entry.halfLifeDays
    * Math.min(3, 1 + Math.log(entry.retrievalCount + 1) / 3);
  return Math.exp(-Math.pow(ageDays / effectiveHalfLife, 1.5));
}
```

记忆卡片颜色渐变：score > 0.7 绿色，0.3~0.7 黄色，< 0.3 红色（接近遗忘阈值）。点击卡片展开版本历史（`valid_to IS NOT NULL` 的历史版本）。

### PlanConfirmationCard — 执行计划确认卡片

Agent 自适应规划触发时，`plan_confirmation_required` 事件写入 `agentSlice.pendingPlan`，对话流末尾渲染此卡片：

```typescript
interface PlanConfirmationCardProps {
  requestId: string;
  planMarkdown: string;
}

function PlanConfirmationCard({ requestId, planMarkdown }: PlanConfirmationCardProps) {
  const [edited, setEdited] = useState(planMarkdown);

  const onConfirm = async () => {
    await invoke('confirm_plan', { requestId, editedPlan: edited });
    useAgentStore.getState().setPendingPlan(null);
  };

  const onCancel = async () => {
    await invoke('cancel_plan', { requestId });
    useAgentStore.getState().setPendingPlan(null);
  };

  return (
    <div className="plan-card">
      <div className="plan-card__header">执行计划 · 请确认后继续</div>
      <textarea
        className="plan-card__editor"
        value={edited}
        onChange={e => setEdited(e.target.value)}
      />
      <div className="plan-card__actions">
        <button onClick={onCancel}>取消</button>
        <button onClick={onConfirm} className="primary">确认执行</button>
      </div>
    </div>
  );
}
```

卡片可编辑区域支持 Markdown 语法，用户修改后的内容在确认时完整发回后端注入下一轮 context。计划卡片展示期间输入框保持可用，用户新发的消息进入 pending 队列。

### InputBar — 文件上传交互设计

#### 触发方式（三种）

1. **点击 📎 图标** — 打开系统原生文件选择器（`<input type="file" multiple accept="..." />`，隐藏后由图标按钮代理点击）。
2. **拖拽文件到对话区域** — 整个 `ConversationView` 注册 `dragenter`/`dragover`/`drop` 事件，拖入时显示 Drop Zone 高亮叠加层。
3. **Ctrl/Cmd+V 粘贴剪贴板图片** — 监听 `paste` 事件，从 `ClipboardEvent.clipboardData.files` 提取图片文件。

#### 文件类型与限制

| 类型 | 接受格式 | 大小限制 |
| --- | --- | --- |
| 图片 | png, jpg, gif, webp, svg | 20MB |
| 文档 | pdf, txt, md, csv | 50MB |
| 代码 | js, ts, py, rs, go, java, c, cpp, h 等常见扩展名 | 50MB |

不在白名单内的扩展名拒绝添加，toast 提示"不支持的文件类型：.xxx"。

#### 上传预览区

输入框上方渲染缩略图条（`AttachmentBar` 组件）：

- **图片**：64×64 缩略图（`URL.createObjectURL`）+ 文件名 + 文件大小 + ✕ 删除按钮。
- **文档/代码**：文件类型图标 + 文件名 + 文件大小 + ✕ 删除按钮。
- 多文件横向滚动（`overflow-x: auto`），**最多 10 个附件**。
- 超出大小限制：toast 提示"文件大小超过 {limit}MB 限制"，文件不添加。
- 超出数量限制：toast 提示"最多添加 10 个文件"。

#### Drop Zone 设计

- **拖入时**：对话区覆盖半透明蓝色叠加层（`rgba(59,130,246,0.1)`）+ 2px 虚线边框 + 居中文字"拖放文件到此处"。
- **不支持的文件类型**：叠加层变为红色 + 文字"不支持的文件类型"。
- **释放后**：叠加层消失，合法文件添加到预览区。
- 嵌套元素的 `dragenter`/`dragleave` 通过引用计数避免闪烁。

#### 剪贴板粘贴行为

| 粘贴内容 | 行为 |
| --- | --- |
| 图片文件 | 自动添加到 `AttachmentBar` 预览区 |
| 纯文本 | 插入输入框光标位置（现有行为不变） |
| HTML | 转为纯文本后插入输入框 |

#### 富文本粘贴处理

不同粘贴内容类型的精细化处理，确保输入内容格式正确且不触发误操作：

| 粘贴内容 | 处理方式 |
| --- | --- |
| HTML 富文本 | 剥离所有标签，通过 `event.clipboardData.getData('text/plain')` 取纯文本插入 |
| 表格数据（Excel/Sheets） | 检测 TSV 格式，自动转换为 Markdown 表格（`\| col1 \| col2 \|` 形式） |
| 多行代码 | 保留原始缩进，自动包裹 `` ``` `` 代码围栏；单行代码不包裹 |
| 大段文本（>10,000 字符） | 弹出确认框："粘贴内容较长（{n} 字符），确认粘贴？"，用户确认后插入 |

**触发字符安全**

粘贴文本中包含 `@`、`#`、`[[` 等触发字符时，**不触发**对应的 Popover（提及、标签、双链）。仅键盘逐字输入才触发 Popover：

```typescript
// InputBar onInput 事件中区分输入来源
const handleInput = (e: React.FormEvent<HTMLTextAreaElement>) => {
  const inputEvent = e.nativeEvent as InputEvent;
  // 粘贴 / 拖入 / IME 组合输入期间不触发 popover
  if (inputEvent.inputType === 'insertFromPaste'
    || inputEvent.inputType === 'insertFromDrop'
    || inputEvent.isComposing) {
    return;
  }
  checkTriggerCharacters(inputEvent.data);
};
```

`AttachedFile[]` 转换为 Tauri Command 参数 `MediaInput[]`：

- **图片 < 5MB**：读取为 Base64 字符串，inline 传入。
- **图片 >= 5MB 或文档/代码**：传递本地文件绝对路径（通过 `window.__TAURI__.path` 或 `webkitRelativePath` 获取），后端按路径读取。
- 发送完成后释放所有 blob URL（`URL.revokeObjectURL`），清空 `AttachmentBar`。

#### 跨面板拖放交互

## 3. 流式数据接收策略

`useConversationEvents` hook 统一注册所有会话级事件，各自写入 Zustand 对应 slice：

| 事件名 | 触发条件 | 目标 Slice |
| --- | --- | --- |
| `token_chunk` | LLM 正文增量 | `conversationSlice.streamBuffers` |
| `thinking_delta` | 思考内容增量（DeepSeek/MiniMax） | `conversationSlice.thinkingBuffers` |
| `tool_call` | 工具调用开始 | `toolCallSlice.active` |
| `tool_result` | 工具执行完成 | `toolCallSlice.results` |
| `approval_required` | 需要人工审批 | `agentSlice.pendingApprovals` |
| `plan_confirmation_required` | 需要确认执行计划 | `agentSlice.pendingPlan` |
| `tts_chunk` | TTS 音频块 | 直接写入 `AudioContext`（不过 Zustand） |
| `media_task_update` | 媒体任务状态变更 | `mediaSlice.tasks` |
| `message_done` | 本轮结束 | `conversationSlice`（提交最终消息） |
| `message_error` | 不可恢复错误 | `agentSlice.lastError` |

React 18 自动批量更新（Automatic Batching）保证同一微任务内的多次 `setState` 只触发一次渲染。

### 流式响应错误恢复 UX

#### 错误状态分类与 UI 映射

| 后端事件 | 前端显示 | 用户可用操作 |
| --- | --- | --- |
| `RetryNotice { attempt: 2, max: 3 }` | 消息气泡底部灰色横条："重试中 (2/3)..." + 旋转图标 | 等待 / 点击"取消" |
| `RetryNotice { attempt: 3, max: 3 }` | 同上，文案变为"最后一次重试..." | 等待 |
| `stream_error { recoverable: true }` | 消息气泡内容区替换为黄色错误卡片：错误信息 + \[重试\] \[换模型重试\] 按钮 | 点击重试或切换模型 |
| `stream_error { recoverable: false }` | 红色错误卡片：错误信息 + \[复制错误信息\] 按钮 | 查看并复制错误详情 |
| 网络断开（`navigator.onLine === false`） | 对话区顶部固定横幅："网络已断开，等待重连..." + 已接收部分内容保留显示（灰色字体） | 等待自动重连 / 切换离线模型 |

#### 部分内容保留策略

流中断时，已接收的 token **不丢弃**：

- 已有内容以灰色斜体渲染，底部标注"（生成中断，内容不完整）"。
- 重试成功后，新的完整响应**替换**中断内容。
- 用户可点击"保留当前内容"按钮放弃重试，将不完整内容作为最终响应保留。
- 中断内容存入 `conversationSlice.partialContent[convId]`，重试或保留后清除。

#### 前端状态机

```text
StreamState:
  Idle → Streaming → Complete
                   → RetryPending → Streaming (重试成功)
                                  → ErrorRecoverable (重试耗尽)
                   → ErrorRecoverable (可恢复错误)
                   → ErrorFatal (不可恢复错误)
```

状态存储在 `agentSlice.streamState`，由 `useConversationEvents` hook 内的事件监听器驱动转换。

#### 错误恢复组件

- **RetryBanner**：内嵌在 `MessageBubble` 底部，显示当前重试次数和旋转加载图标，点击"取消"调用 `invoke('cancel_stream')`。
- **ErrorCard**：替换 `MessageBubble` 的内容区域，包含错误描述文本和操作按钮。可恢复错误显示"重试"和"换模型重试"；不可恢复错误仅显示"复制错误信息"。
- **OfflineBanner**：固定在 `ConversationView` 顶部（`position: sticky`），监听 `window.addEventListener('online'/'offline')` 自动显隐，重连后触发未完成流的自动恢复。

### 限流与重试反馈 UX

当 LLM Provider 返回限流（429）时，后端触发自动重试并发送 `RetryNotice` 事件，前端提供细粒度的等待反馈：

#### 等待倒计时

订阅 `RetryNotice { attempt, max_attempts, wait_ms }` 事件后，在当前消息气泡底部渲染内联进度条：

```typescript
interface RetryWaitBarProps {
  waitMs: number;
  attempt: number;
  maxAttempts: number;
  onCancel: () => void;
}

function RetryWaitBar({ waitMs, attempt, maxAttempts, onCancel }: RetryWaitBarProps) {
  const [elapsed, setElapsed] = useState(0);

  useEffect(() => {
    const id = setInterval(() => setElapsed(e => Math.min(e + 100, waitMs)), 100);
    return () => clearInterval(id);
  }, [waitMs]);

  const remainingSec = Math.ceil((waitMs - elapsed) / 1000);

  return (
    <div className="retry-wait-bar">
      <progress value={elapsed} max={waitMs} />
      <span>限流等待中 {remainingSec}s... ({attempt}/{maxAttempts})</span>
      <button onClick={onCancel} className="retry-cancel">取消</button>
    </div>
  );
}
```

#### 重试耗尽

所有重试失败后，进度条过渡为 `ErrorCard`（已有设计），显示"已达最大重试次数"和操作按钮。

#### Provider 状态指示器

TopBar 的模型名称旁显示小圆点，实时反映当前 Provider 的健康状态：

| 颜色 | 含义 | 数据来源 |
| --- | --- | --- |
| 🟢 绿色 | 正常 | `provider_status.status === 'ok'` |
| 🟡 黄色 | 限流中 | `provider_status.status === 'throttled'` |
| 🔴 红色 | 服务不可用 | `provider_status.status === 'down'` |

状态通过 `provider_status` 事件更新，存入 `agentSlice.providerHealth`，TopBar 组件订阅渲染。连续 3 次限流自动切换为黄色状态，30s 内无新限流事件恢复绿色。

## 5. Zustand Store 设计

按关注点切分为五个 store，通过 `immer` middleware 支持可变写法：

```typescript
// conversationStore：会话列表 + 流式消息缓冲
interface ConversationStore {
  conversations: ConversationMeta[];
  activeId: string | null;
  streamBuffers: Record<string, string>;    // conv_id → 累积 delta
  thinkingBuffers: Record<string, string>;  // conv_id → thinking 内容
  actions: { selectConv; appendDelta; appendThinking; commitMessage; };
}

// agentStore：执行状态 + 审批队列 + 计划确认 + pending 消息
interface AgentStore {
  status: 'idle' | 'running' | 'paused' | 'takeover';
  pendingApprovals: ApprovalRequest[];
  pendingPlan: PlanConfirmationEvent | null;   // 非 null 时展示计划确认卡片
  pendingUserMessages: PendingUserMessage[];    // 运行中已入队但未注入的消息
  lastError: string | null;
}

interface PendingUserMessage {
  content: string;
  queuedAt: number;   // ms timestamp，用于展示"等待执行中..."标识
}

// mediaStore：媒体任务状态缓存
interface MediaStore {
  tasks: Record<string, MediaTaskEvent>;
  actions: { updateTask; clearCompleted; };
}

// costStore：Token 消耗与成本统计
// settingsStore：Provider 配置、主题、快捷键
```

`conversationStore.appendDelta` 由 `token_chunk` 监听器驱动，React 组件用 `useShallow` 订阅 `streamBuffers[activeId]` 实现高性能流式渲染，避免全量 diff。

## 8. 主题切换实现

CSS 变量定义在 `:root` 与 `[data-theme="dark"]` 两个选择器下，覆盖所有语义色板（`--color-bg`/`--color-surface`/`--color-primary` 等）：

```typescript
const applyTheme = (theme: 'light' | 'dark' | 'system') => {
  const resolved = theme === 'system'
    ? (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light')
    : theme;
  document.documentElement.dataset.theme = resolved;
  localStorage.setItem('theme', theme);
};

// 监听系统主题变化
window.matchMedia('(prefers-color-scheme: dark)')
  .addEventListener('change', () => {
    if (localStorage.getItem('theme') === 'system') applyTheme('system');
  });
```

`ThemeProvider` 在应用启动时从 `localStorage` 读取偏好并立即应用，避免首屏主题闪烁（FOUC）。shadcn/ui 组件通过 `data-theme` 属性自动适配，无需额外覆盖样式。

## 9. 无障碍（Accessibility）规范

### ARIA 角色标注

关键组件必须标注语义化 ARIA 角色，确保屏幕阅读器正确识别：

| 组件 | ARIA 属性 | 说明 |
| --- | --- | --- |
| `Sidebar` | `role="navigation"` `aria-label="会话导航"` | 标识为导航地标 |
| `MessageList` | `role="log"` `aria-live="polite"` | 标识为日志区域，新消息到达时通知 |
| `InputBar` | `role="textbox"` `aria-multiline="true"` `aria-label="消息输入"` | 多行文本输入 |
| `ApprovalDialog` | `role="alertdialog"` `aria-modal="true"` | 模态警告对话框 |
| `CommandPalette` | `role="combobox"` `aria-expanded` | 命令面板搜索框 |
| `ToolCallCard` | `role="status"` | 工具调用实时状态 |

### Tab 焦点顺序

全局 Tab 顺序：`Sidebar` → `InputBar` → `MessageList` → `RightPanel`。页面顶部提供 Skip Navigation 隐藏链接（获焦时可见），允许键盘用户跳过导航直达主内容区：

```html
<a href="#main-content" className="skip-nav">跳转到主内容</a>
```

### 焦点陷阱

以下组件激活时捕获焦点，Tab 循环限制在组件内部，按 `Esc` 关闭并还原焦点到触发元素：

- `ApprovalDialog`（审批弹层）
- `CommandPalette`（命令面板）
- 所有模态对话框（通过 `FocusTrap` 高阶组件统一实现）

### 流式内容播报

流式消息气泡设置 `aria-live="polite"`，但逐 token 更新会导致屏幕阅读器频繁播报。采用 500ms 节流批量通知：

```typescript
// 流式消息的 aria-live 更新节流
const announceRef = useRef<string>('');
useEffect(() => {
  const id = setInterval(() => {
    if (announceRef.current !== streamContent) {
      announceRef.current = streamContent;
      // aria-live 区域内容变更触发播报
    }
  }, 500);
  return () => clearInterval(id);
}, [streamContent]);
```

流式完成后，播报完整消息的前 100 字 + "消息结束"。

### 减弱动画（`prefers-reduced-motion`）

当用户系统开启减弱动画时，禁用以下效果：

- 流式光标闪烁动画
- 面板滑入/滑出过渡（改为瞬时切换）
- 工具调用卡片翻转动画
- 消息气泡淡入动画
- 所有 `transition-duration` 归零

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```
