# 对话分支系统设计

> 版本：v1.0 | 日期：2026-08-07 | 状态：草稿

对话分支允许用户在任意历史消息处创建"替代对话线"，在不丢失原对话的前提下探索不同的回复路径，类似 Git 分支。

---

## 1. 数据模型

分支关系通过 `conversations` 表的两个字段实现（完整 DDL 见 [数据库设计/01-Schema设计.md](../../03-系统设计阶段/04-数据库设计/01-Schema设计.md)）：

```sql
conversations (
    id                      TEXT PRIMARY KEY,
    workspace_id            TEXT NOT NULL,
    parent_conversation_id  TEXT REFERENCES conversations(id),   -- NULL = 根对话
    branch_point_message_id TEXT REFERENCES messages(id),        -- 从哪条消息分叉
    title                   TEXT,
    ...
)
```

### 分支拓扑示例

```text
conv-root  (parent = NULL, branch_point = NULL)
    │
    ├─ [msg-1] 用户："帮我写一首诗"
    ├─ [msg-2] AI：诗歌 A
    │
    ├─── 用户在 msg-2 处创建分支 ────────────────────┐
    │                                                │
    ├─ [msg-3] 用户："继续"             conv-branch-1 (parent=conv-root, branch_point=msg-2)
    ├─ [msg-4] AI：后续 A                  ├─ [msg-5] 用户："换一首风格不同的"
                                           └─ [msg-6] AI：诗歌 B
```

## 2. 核心操作

### 2.1 创建分支

```rust
// crates/agent-core/src/storage/conversations.rs

pub async fn create_branch(
    &self,
    source_conversation_id: &str,
    branch_point_message_id: &str,
    new_title: Option<&str>,
) -> anyhow::Result<String> {
    let new_id = Uuid::new_v4().to_string();

    // 1. 创建新对话记录
    sqlx::query!(
        r#"INSERT INTO conversations (id, workspace_id, parent_conversation_id,
           branch_point_message_id, title, model, created_at, updated_at)
           SELECT ?, workspace_id, ?, ?, COALESCE(?, title || ' (分支)'),
                  model, unixepoch('now','subsec')*1000, unixepoch('now','subsec')*1000
           FROM conversations WHERE id = ?"#,
        new_id, source_conversation_id, branch_point_message_id,
        new_title, source_conversation_id,
    )
    .execute(&self.pool)
    .await?;

    // 2. 复制分支点之前的消息历史（不含分支点后的消息）
    sqlx::query!(
        r#"INSERT INTO messages (id, conversation_id, role, content, reasoning_content,
           tool_call_id, tool_name, token_count, latency_ms, is_pinned, created_at)
           SELECT lower(hex(randomblob(16))), ?, role, content, reasoning_content,
                  tool_call_id, tool_name, token_count, latency_ms, is_pinned, created_at
           FROM messages
           WHERE conversation_id = ?
             AND created_at <= (SELECT created_at FROM messages WHERE id = ?)
           ORDER BY created_at"#,
        new_id, source_conversation_id, branch_point_message_id,
    )
    .execute(&self.pool)
    .await?;

    Ok(new_id)
}
```

### 2.2 切换分支（前端）

切换分支只是切换当前活跃的 `conversation_id`，加载对应消息列表，无需后端特殊操作。前端 Zustand store 维护 `activeConversationId`。

### 2.3 查询分支树

```rust
pub async fn get_branch_tree(
    &self,
    root_conversation_id: &str,
) -> anyhow::Result<Vec<ConversationBranchNode>> {
    // 递归 CTE 查询所有后代分支
    let rows = sqlx::query!(
        r#"WITH RECURSIVE branch_tree AS (
            SELECT id, parent_conversation_id, branch_point_message_id, title, 0 as depth
            FROM conversations WHERE id = ?
            UNION ALL
            SELECT c.id, c.parent_conversation_id, c.branch_point_message_id, c.title, bt.depth + 1
            FROM conversations c
            JOIN branch_tree bt ON c.parent_conversation_id = bt.id
        )
        SELECT * FROM branch_tree ORDER BY depth, id"#,
        root_conversation_id
    )
    .fetch_all(&self.pool)
    .await?;

    Ok(rows.into_iter().map(ConversationBranchNode::from).collect())
}
```

## 3. 前端 UI 设计

### 3.1 消息气泡上下文菜单

用户右键/长按任意 AI 消息时，上下文菜单显示"从此处创建分支"选项。

```text
┌─────────────────────────────────────┐
│  AI 的回复内容...                    │
│                      [·] ▾          │  ← 三点菜单
└─────────────────────────────────────┘
         ┌──────────────────────┐
         │  📌 固定此消息       │
         │  🌿 从此处创建分支   │  ← 点击创建分支
         │  📋 复制内容         │
         │  🗑️ 删除消息         │
         └──────────────────────┘
```

### 3.2 分支选择器

当对话有分支时，分支点消息旁显示分支指示器：

```text
[msg-2] AI：诗歌 A
             ├─ 当前分支（主线）  ●
             └─ conv-branch-1    ○  [切换]
```

### 3.3 分支树可视化（侧边栏）

在侧边栏对话列表中，带分支的对话折叠展示分支节点，缩进表示层级：

```text
📂 诗歌创作对话          ←── 根对话
   └─ 🌿 换一首风格不同的  ←── 子分支（branch_point 摘要）
```

## 5. 设计约束

- **分支深度无硬性上限**，但 UI 超过 3 层嵌套时折叠展示，避免界面混乱
- **消息不跨分支共享**（复制而非引用），简化删除和修改操作的影响范围
- **分支不继承 YOLO 状态**：切换到子分支时 YOLO 始终为 OFF
- **分支计入工作区对话数量限制**（如有），避免无限制创建分支消耗存储

## 6. 分支可视化

### 6.1 入口

对话标题旁显示分支图标（仅当对话有分支时出现）
- 点击 → 切换到聊天右侧面板（`ChatRightPanel`）的 `branches` tab（3 tab 之一：summary / context / branches）

### 6.2 分支树渲染

使用竖向树形图，类似 git log --graph：

```
● 主线 "分析需求文档"          ← 当前
│
├─● 分支1 "改用 Python 方案"    12:30
│  │
│  └─● 分支1.1 "添加测试"      12:45
│
├─● 分支2 "性能优化版本"        12:35
│
● [消息编辑点]
│
● 开始
```

### 6.3 节点信息
每个节点显示：
- 分支标题（自动生成或用户重命名）
- 创建时间
- 消息数量（小数字）
- 当前分支高亮（accent color 圆点）

### 6.4 交互
- 点击节点 → 切换到该分支
- 右键节点 → 重命名 / 删除分支
- 拖动节点 → 不支持（只读视图）
- 节点间的连线显示分支点消息的前 30 字符

### 6.5 实现
- 使用递归 CTE 查询分支树（已有 SQL）
- 前端用 SVG 绘制树形图（无需第三方库）
- 节点位置算法：深度优先遍历，每层缩进 24px

### 6.6 组件
BranchGraphPanel.tsx:
- conversationId: string
- onSwitchBranch: (branchId: string) => void
BranchNode.tsx: 单个节点渲染
