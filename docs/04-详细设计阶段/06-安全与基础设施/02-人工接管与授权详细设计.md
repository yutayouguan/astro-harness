# 人工接管与授权详细设计

> **Harness 当前基线（2026-08-29）**：授权与暂停是两条协作的控制链：`HitlGate` 承载需要答复的决策，`PauseControl`/取消信号管理活跃 turn，`SessionApprovalCache` 保存会话级决策。工具、MCP、Browser 和 sandbox escalation 各自产生可审计请求。

> 阶段：详细设计 | 状态：草稿 | 说明：Permission enum、HumanGuard 状态机、白名单、审计日志

## 1. 系统定位

本模块分布于两个 crate：

- **`crates/agent-core/src/security/`**：Permission 枚举、PermissionSet、RiskLevel、白名单规则——纯类型，无 Tauri 依赖
- **`crates/agent-runtime/src/guard/`**：HumanGuard 状态机——持有 `AppHandle` 和 `SqlitePool`，只能在 agent-runtime 中实现

本模块负责：

- **权限声明与强制检查**：每个工具/Skill 声明最小权限集，执行前拦截验证
- **HumanGuard 状态机**：L1 单次审批 / L2 暂停 / L3 完全接管三级介入
- **白名单快速放行**：命中规则的操作绕过审批直接执行
- **审计日志**：所有审批决定写入不可篡改的 `audit_logs` 表
- **提示注入防御**：工具输出隔离包装 + 启发式扫描

> **风险等级映射**：`RiskLevel` 枚举（工具系统）与 HumanGuard 介入等级的对应关系：
>
> - `Low` → L1 自动执行，无需审批
> - `Medium` → L2 弹窗确认，30s 超时自动通过
> - `High` → L3 强制手动确认，无超时
> - `Critical` → 强制暂停（`force_pause_above`），即使 YOLO 模式也不可跳过

## 3. 权限声明模型

### 3.1 Permission 枚举

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq, Hash)]
pub enum Permission {
    ReadFile,
    WriteFile,
    DeleteFile,
    NetworkRead,
    NetworkWrite,
    ExecuteBash,
    ExecuteRhai,
    ExecuteWasm,
    ReadEnv,              // 读取环境变量
    WriteEnv,             // 修改环境变量
    BrowserControl,       // 浏览器自动化
    SpawnAgent,
    SpawnAgentWithTools(Vec<String>),
    UseMcp(String),       // 指定 MCP server 名称
    UseProvider(String),  // 指定 Provider（如 "minimax/speech-2.8-hd"）
}

pub struct PermissionSet(HashSet<Permission>);

impl PermissionSet {
    pub fn check(&self, required: &Permission) -> Result<(), SecurityError> {
        if self.0.contains(required) {
            Ok(())
        } else {
            Err(SecurityError::PermissionDenied(format!("{:?}", required)))
        }
    }

    /// 从 Skill manifest 的 permissions 字段解析
    pub fn from_manifest_list(list: &[String]) -> anyhow::Result<Self> {
        let perms = list.iter().map(|s| parse_permission(s)).collect::<Result<_, _>>()?;
        Ok(Self(perms))
    }
}
```

### 3.2 工具执行前检查

`ToolRegistry::execute_checked` 是所有工具调用的唯一入口，在此强制校验调用方权限：

```rust
impl ToolRegistry {
    pub async fn execute_checked(
        &self,
        tool_name: &str,
        input: ToolInput,
        caller_permissions: &PermissionSet,
        guard: &HumanGuard,
    ) -> Result<ToolOutput, ToolError> {
        let tool = self.get(tool_name).ok_or(ToolError::NotFound(tool_name.into()))?;

        // 1. 静态权限检查（调用方 manifest 是否声明了此工具对应的权限）
        caller_permissions.check(&tool.required_permission())
            .map_err(|e| ToolError::PermissionDenied(e.to_string()))?;

        // 2. HumanGuard 动态审批（白名单放行 / 弹窗等待）
        let outcome = guard.check(tool.as_ref(), &input).await?;

        // 3. ModifiedAndApproved：用户修改了参数，用修改后的参数执行
        let actual_input = match outcome {
            ApprovalOutcome::ModifiedAndApproved(modified) => {
                validate_against_schema(&modified, &tool.input_schema())?;
                ToolInput { parameters: modified, ..input }
            }
            _ => input,
        };

        tool.execute(actual_input).await
    }
}
```

### 4.4 check() 实现

```rust
impl HumanGuard {
    pub async fn check(
        &self,
        tool: &dyn Tool,
        input: &ToolInput,
    ) -> Result<ApprovalOutcome, GuardError> {
        // 1. 全局开关关闭时直接放行（仅开发模式）
        if !self.config.enabled {
            return Ok(ApprovalOutcome::Approved);
        }

        // 2. L2/L3 状态下阻塞等待，不执行任何工具
        loop {
            let state = self.state.read().await.clone();
            match state {
                GuardState::Paused | GuardState::Takeover => {
                    // 每 200ms 轮询一次状态变更（或改用 Notify）
                    tokio::time::sleep(Duration::from_millis(200)).await;
                    continue;
                }
                _ => break,
            }
        }

        let risk = tool.risk_level();

        // 3. force_pause_above：高于阈值的直接进 L2 而非 L1 弹窗
        if risk >= self.config.risk_thresholds.force_pause_above {
            self.set_state(GuardState::Paused).await;
            self.app.emit("agent_paused", AgentPausedPayload {
                reason: "guard",
                tool_name: tool.name().into(),
                risk_level: format!("{:?}", risk),
            }).ok();
            return Err(GuardError::ForcePaused);
        }

        // 4. Low 风险 + 白名单命中 → 静默放行
        if risk <= self.config.risk_thresholds.auto_approve_below
            && self.whitelist.matches(tool.name(), &input.parameters)
        {
            self.audit(tool, input, ApprovalOutcome::Approved, "whitelist").await;
            return Ok(ApprovalOutcome::Approved);
        }

        // 5. Low 风险（未命中白名单）也放行，不弹窗
        if risk == RiskLevel::Low {
            self.audit(tool, input, ApprovalOutcome::Approved, "auto_low").await;
            return Ok(ApprovalOutcome::Approved);
        }

        // 6. Medium / High → L1 弹窗审批
        let request_id = Uuid::new_v4();
        let timeout_ms = self.config.timeout_secs as u64 * 1000;
        let default_outcome = if risk >= RiskLevel::High {
            ApprovalOutcome::Rejected   // 高风险超时默认拒绝
        } else {
            self.config.default_on_timeout.clone()
        };

        let (tx, rx) = oneshot::channel::<ApprovalResponse>();
        self.pending_decisions.insert(request_id, tx);

        // 推送审批请求到前端
        self.app.emit("approval_required", ApprovalRequiredPayload {
            request_id: request_id.to_string(),
            tool_name: tool.name().into(),
            action_summary: format!("{} — {}", tool.name(), input.parameters.get("path")
                .or(input.parameters.get("command")).and_then(|v| v.as_str()).unwrap_or("")),
            action_detail: input.parameters.clone(),
            risk_level: risk.as_str(),
            timeout_ms,
            default_on_timeout: default_outcome.as_str(),
        }).ok();

        // 等待用户决定（超时注入默认结果）
        let resp = match tokio::time::timeout(Duration::from_millis(timeout_ms), rx).await {
            Ok(Ok(resp)) => resp,
            _ => ApprovalResponse {
                request_id,
                outcome: default_outcome,
                modified_args: None,
            },
        };
        self.pending_decisions.remove(&request_id);

        self.audit(tool, input, resp.outcome.clone(), "user").await;
        Ok(resp.outcome)
    }
}
```

### 4.5 resolve() — 接收前端决定

```rust
impl HumanGuard {
    /// Tauri Command approve_action / reject_action 调用此方法
    pub fn resolve(&self, request_id: Uuid, outcome: ApprovalOutcome, modified_args: Option<Value>) {
        if let Some((_, tx)) = self.pending_decisions.remove(&request_id) {
            let _ = tx.send(ApprovalResponse { request_id, outcome, modified_args });
        }
    }
}
```

## 5. Tauri Commands — 全部接管控制接口

```rust
/// 批准单个操作（可携带修改后的参数）
#[tauri::command]
pub async fn approve_action(
    state: State<'_, AppState>,
    request_id: String,
    modified_args: Option<Value>,
) -> Result<(), AppError> {
    let id = Uuid::parse_str(&request_id)?;
    state.human_guard.resolve(
        id,
        if modified_args.is_some() { ApprovalOutcome::ModifiedAndApproved(modified_args.unwrap()) }
        else { ApprovalOutcome::Approved },
        None,
    );
    Ok(())
}

/// 拒绝单个操作
#[tauri::command]
pub async fn reject_action(
    state: State<'_, AppState>,
    request_id: String,
) -> Result<(), AppError> {
    let id = Uuid::parse_str(&request_id)?;
    state.human_guard.resolve(id, ApprovalOutcome::Rejected, None);
    Ok(())
}

/// L2 暂停（Agent 完成当前原子操作后挂起）
#[tauri::command]
pub async fn pause_agent(state: State<'_, AppState>, app: AppHandle) -> Result<(), AppError> {
    state.human_guard.set_state(GuardState::Paused).await;
    app.emit("agent_paused", AgentPausedPayload { reason: "user_command" }).ok();
    Ok(())
}

/// 恢复 L2 暂停
#[tauri::command]
pub async fn resume_agent(state: State<'_, AppState>, app: AppHandle) -> Result<(), AppError> {
    state.human_guard.set_state(GuardState::Running).await;
    app.emit("agent_resumed", ()).ok();
    Ok(())
}

/// L3 完全接管（立即生效，Agent 停止所有待执行操作）
#[tauri::command]
pub async fn takeover(state: State<'_, AppState>, app: AppHandle) -> Result<(), AppError> {
    state.human_guard.set_state(GuardState::Takeover).await;
    // 取消当前所有 pending_decisions（以 Rejected 结束）
    state.human_guard.drain_pending_with_rejected();
    app.emit("agent_takeover", AgentTakeoverPayload { triggered_by: "user" }).ok();
    Ok(())
}

/// 释放 L3 接管，Agent 恢复自主运行
#[tauri::command]
pub async fn release_control(state: State<'_, AppState>, app: AppHandle) -> Result<(), AppError> {
    state.human_guard.set_state(GuardState::Running).await;
    app.emit("agent_released", ()).ok();
    Ok(())
}
```

## 6. 白名单规则

### 6.1 规则结构

```rust
pub struct WhitelistRule {
    pub tool_name: String,                   // 精确匹配工具名
    pub args_pattern: Option<Regex>,         // 可选：参数 JSON 字符串正则匹配
}

pub struct Whitelist(Vec<WhitelistRule>);

impl Whitelist {
    pub fn matches(&self, tool_name: &str, args: &Value) -> bool {
        let args_str = args.to_string();
        self.0.iter().any(|rule| {
            rule.tool_name == tool_name
                && rule.args_pattern.as_ref().map_or(true, |p| p.is_match(&args_str))
        })
    }
}
```

## 7. L3 完全接管模式——前端手动工具调用面板

L3 接管时，前端展示 `TakeoverPanel`，让用户手动发起工具调用：

```typescript

interface TakeoverPanelProps {
  availableTools: ToolDefinition[];
  onExecute: (toolName: string, args: unknown) => Promise<ToolOutput>;
  onRelease: () => void;

function TakeoverPanel({ availableTools, onExecute, onRelease }: TakeoverPanelProps) {
  const [selectedTool, setSelectedTool] = useState<ToolDefinition | null>(null);
  const [argsJson, setArgsJson] = useState('{}');

      </header>
      <ToolSelector tools={availableTools} onSelect={setSelectedTool} />
      <JsonEditor value={argsJson} schema={selectedTool?.input_schema} onChange={setArgsJson} />

  );
```

对应 Tauri Command：

```rust
#[tauri::command]
pub async fn manual_tool_call(
    state: State<'_, AppState>,
    tool_name: String,
    args: Value,
) -> Result<ToolOutput, AppError> {
    // L3 接管时才允许手动调用；Running 状态下拒绝（避免冲突）
    if *state.human_guard.state.read().await != GuardState::Takeover {
        return Err(AppError::Validation("非接管模式不允许手动工具调用".into()));
    }
    let input = ToolInput { tool_name: tool_name.clone(), parameters: args, .. };
    // 接管模式下跳过 HumanGuard，直接执行（用户就是操作者）
    let tool = state.tool_registry.read().await
        .get(&tool_name).ok_or(AppError::NotFound(tool_name))?;
    tool.execute(input).await.map_err(|e| AppError::Tool(e.to_string()))
}
```

## 8. 审批决定写入审计日志

每次 `check()` 返回前，异步写入 `audit_logs`（不阻塞主流程）：

```rust
async fn audit(&self, tool: &dyn Tool, input: &ToolInput, outcome: ApprovalOutcome, decided_by: &str) {
    let log = AuditLog {
        id: uuid(),
        workspace_id: input.workspace_id.clone(),
        session_id: Some(input.caller_agent_id.clone()),
        actor: "agent".into(),
        action: "tool_call".into(),
        tool_name: Some(tool.name().into()),
        tool_source: Some(classify_source(tool.name())),
        risk_level: Some(format!("{:?}", tool.risk_level())),
        params_digest: sha256_hex(&input.parameters.to_string()),
        status: outcome.as_audit_status(),
        approved_by: Some(decided_by.into()),
        duration_ms: None,
        detail_json: serde_json::json!({
            "outcome": format!("{:?}", outcome),
            "decided_by": decided_by,
        }).to_string(),
        created_at: now_ms(),
    };
    tokio::spawn(async move {
        AuditLogRepo::new(&self.pool).insert(log).await.ok();
    });
}
```

## 9. 提示注入防御

工具输出回填到 `message_history` 前，先经过 `PromptGuard` 处理：

```rust
pub struct PromptGuard;

impl PromptGuard {
    /// 将工具结果包装为明确标记的 ToolResult，LLM 不会误解为系统指令
    pub fn wrap(tool_name: &str, output: &ToolOutput) -> Message {
        Message {
            role: Role::Tool,
            content: vec![ContentPart::Text(
                serde_json::to_string(&output.content).unwrap_or_default()
            )],
            tool_call_id: None,
            tool_name: Some(tool_name.to_string()),
            reasoning_content: None,
            ..Default::default()
        }
    }

    /// 启发式扫描，检测可疑注入模式
    pub fn scan(content: &str) -> Vec<InjectionWarning> {
        const PATTERNS: &[(&str, &str)] = &[
            (r"(?i)ignore (previous|above|all) instructions", "角色覆盖指令"),
            (r"<\|(?:system|user|assistant)\|>",              "特殊 token 注入"),
            (r"(?i)you are now",                              "身份替换"),
            (r"(?i)disregard your",                           "规则绕过"),
        ];
        PATTERNS.iter().filter_map(|(pat, label)| {
            Regex::new(pat).ok()?.find(content).map(|m| InjectionWarning {
                pattern: label.to_string(),
                excerpt: content[m.start()..m.end().min(m.start()+80)].to_string(),
            })
        }).collect()
    }
}
```

扫描到注入模式时，在 `audit_logs` 记录 `action = "injection_warning"`，并向前端推送 `injection_warning` 事件（前端显示黄色警示条，不阻断执行）。

## 10. 子 Agent 权限继承规则

父 Agent spawn 子 Agent 时，子 Agent 的权限集不能超过父 Agent：

```rust
pub fn spawn_child_permissions(
    parent: &PermissionSet,
    requested: &PermissionSet,
) -> Result<PermissionSet, SecurityError> {
    let intersection: HashSet<_> = parent.0.intersection(&requested.0).cloned().collect();
    if intersection.len() < requested.0.len() {
        let excess: Vec<_> = requested.0.difference(&parent.0).collect();
        return Err(SecurityError::PermissionEscalation(format!("{:?}", excess)));
    }
    Ok(PermissionSet(intersection))
}
```

子 Agent 递归深度上限（`depth ≤ 8`，即 depth=0 主 Agent 到 depth=8 共 9 层）在 `SessionManager::new_session` 时检查，超限返回 `GuardError::DepthExceeded`，不 spawn。

## 11. 恢复执行设计

### 11.1 三种场景的性质差异

| 场景 | 底层状态 | 需要 checkpoint？ | 恢复策略 |
| --- | --- | --- | --- |
| L2 暂停后 resume | Rust async task 在 `sleep` 轮询处挂起，栈帧完整 | **不需要** | 轮询检测到 Running，自然退出循环，工具调用继续 |
| L3 接管后 release | `drain_pending_with_rejected()` 已把当前 L1 审批队列清空，新 check() 阻塞在 Takeover 轮询里 | **不需要快照，需要"释放排水"** | release 时将仍在轮询的工具调用批量注入 Rejected，LLM 凭完整历史重建意图 |
| 进程崩溃后重启 | task 栈全部消失，只有 SQLite 持久化数据 | **需要显式 checkpoint** | 每轮完成后写 checkpoint 到 `task_traces`；重启时扫描未完成任务，重建 AgentContext 继续 |

---

### 11.2 L2 暂停恢复（无需任何附加机制）

`guard.check()` 内的轮询循环：

```rust
loop {
    match *self.state.read().await {
        GuardState::Paused | GuardState::Takeover => {
            tokio::time::sleep(Duration::from_millis(200)).await;
        }
        _ => break,  // Running → 退出，继续正常审批流程
    }
}
```

`resume_agent` 将 state 切为 Running，200ms 内轮询必然检测到变化，退出后走正常风险评估。整个 `run_agent_turn` 的调用栈、局部变量、正在处理的 tool_call 列表都没有改变，无缝衔接。

### 11.3 L3 接管释放——"释放排水（drain-on-release）"

**问题**：L3 期间，新的 `guard.check()` 调用阻塞在 Takeover 轮询里。用户手动操作（`manual_tool_call`）会向 `message_history` 追加记录。L3 释放时，那些阻塞中的工具调用应该如何处理？

**不能直接继续执行**：用户已手动完成了部分工作，重复执行会造成副作用。

#### 方案：drain-on-release

```rust
impl HumanGuard {
    pub async fn release_control(&self, app: &AppHandle) {
        // 1. 对仍在 pending_decisions 中等待 L1 审批的请求，注入 Rejected
        self.drain_pending_with_rejected();

        // 2. 设置一个"释放排水"标志，通知正在 Takeover 轮询的 check() 以 Rejected 返回
        self.drain_on_next_check.store(true, Ordering::Release);

        // 3. 切回 Running
        *self.state.write().await = GuardState::Running;

        app.emit("agent_released", ()).ok();
    }
}
```

`check()` 中检测此标志：

```rust
loop {
    match *self.state.read().await {
        GuardState::Takeover => {
            if self.drain_on_next_check.swap(false, Ordering::AcqRel) {
                // 以"用户接管期间已取消"为由注入 Rejected 结果
                self.audit(tool, input, ApprovalOutcome::Rejected, "takeover_drain").await;
                return Ok(ApprovalOutcome::Rejected);
            }
            tokio::time::sleep(Duration::from_millis(200)).await;
        }
        _ => break,
    }
}
```

**结果**：所有在 L3 期间阻塞的工具调用都以 `Rejected` 结束，`run_agent_turn` 把这些 Rejected 结果写入 `message_history`，然后重新调用 LLM。LLM 看到的完整历史是：

```text
[assistant]  tool_calls: [file_write, shell_exec]          ← 原意图
[tool]       file_write: 操作已被用户接管取消              ← drain 注入
[tool]       shell_exec: 操作已被用户接管取消              ← drain 注入
[tool]       manual/file_write: 用户手动写入成功 …         ← 用户手动操作
[tool]       manual/shell_exec: 用户手动执行成功 …         ← 用户手动操作
```

LLM 理解"用户已手动完成了这些步骤"，判断接下来还需要做什么，不会重复执行。

### 11.4 进程崩溃恢复——显式 Checkpoint

#### Checkpoint 数据结构

`task_traces` 表（迁移 0006）新增 `checkpoint_json` 列，仅存储轮次编号：

```rust
#[derive(Serialize, Deserialize, Default)]
struct AgentCheckpoint {
    round: u32,   // 已完成的轮次计数，仅用于日志，不参与恢复截断逻辑
}
```

`messages` 表本身就是追加写的执行日志，是恢复的权威数据来源。checkpoint 的职责只有两个：标记任务处于 running 状态、记录已完成轮次数（调试用）。

写入时机：每轮所有工具结果落盘后、下一次 LLM 调用之前：

```rust
trace_repo.write_checkpoint(&trace_id, &AgentCheckpoint { round }).await.ok();
```

#### 悬空状态修复

崩溃时已完成的工具结果已写入 `messages` 表，恢复时读取完整历史，找出最后一条 assistant 消息中缺少 tool result 的 tool_call_id，仅对这些补注入占位——**已完成的工具不会重跑**：

```rust
pub fn repair_dangling_tool_calls(mut messages: Vec<Message>) -> Vec<Message> {
    let completed: HashSet<String> = messages.iter()
        .filter(|m| m.role == "tool")
        .filter_map(|m| m.tool_call_id.clone())
        .collect();

    let dangling: Vec<String> = messages.iter().rev()
        .find(|m| m.role == "assistant" && m.tool_calls.is_some())
        .into_iter()
        .flat_map(|m| m.tool_calls.as_deref().unwrap_or_default().iter()
            .filter(|tc| !completed.contains(&tc.id))
            .map(|tc| tc.id.clone()))
        .collect();

    for tool_id in dangling {
        messages.push(Message::synthetic_tool_result(
            &tool_id,
            "进程意外重启，操作未完成，请重新规划",
        ));
    }
    messages
}
```

#### 重启恢复流程

```rust
pub async fn resume_incomplete_tasks(pool: &SqlitePool, registry: Arc<ProviderRegistry>) {
    let repo = TaskTraceRepo::new(pool);
    let incomplete = repo.scan_incomplete().await.unwrap_or_default();

    // 只恢复根任务（depth=0），子任务由父任务编排逻辑重新 spawn
    for task in incomplete.iter().filter(|t| t.parent_id.is_none()) {
        // messages 表为权威：读取完整实际状态
        let all_messages = MessageRepo::new(pool)
            .list_by_conversation(&task.conversation_id).await
            .unwrap_or_default();

        // 仅对未完成的 tool_call 注入占位，已完成的不重跑
        let repaired = repair_dangling_tool_calls(all_messages);

        let ctx = AgentContext::resume(task.conversation_id.clone(), repaired, registry.clone());
        SessionManager::global().resume_task(task.id.clone(), ctx).await;
    }
}
```

#### 崩溃恢复后 LLM 视角

崩溃发生在 Round 2 执行 step3 时（step1、step2 已完成）：

```text
[user]       原始任务描述
[assistant]  tool_calls: [step1, step2, step3]
[tool]       step1: 成功                        ← messages 表已有，不重跑
[tool]       step2: 成功                        ← messages 表已有，不重跑
[tool]       step3: 进程意外重启，操作未完成    ← repair 注入
```

LLM 只重新规划 step3 及后续步骤。

### 11.5 Checkpoint 粒度选择

恢复精度由 `messages` 表保证，不依赖 checkpoint 截断。因此 checkpoint 写入频率只影响"能否识别任务曾在运行"，不影响恢复质量：

| 粒度 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **每条工具调用后** | 轮次计数最精确 | 写入频繁，意义不大（恢复不用它） | ✗ 不选 |
| **每轮 LLM 调用后（推荐）** | 写入少，任务状态标记及时 | 无明显缺点 | ✓ **选此方案** |
| **每次会话开始/结束** | 写入极少 | 任务首轮内崩溃无 checkpoint，`scan_incomplete` 找不到它 | ✗ 不选 |

恢复精度由 `repair_dangling_tool_calls` 保证：无论崩溃在哪一轮的哪一步，只有真正未完成的 tool_call 需要重新处理，已完成的一律不重跑。

## 12. 运行中追加消息与计划确认

### 12.1 pending 消息队列与暂停的交互

用户在 Agent 运行期间发送消息时，消息进入 `SessionHandle.pending_user_messages` 队列（详见 agent-runtime 设计第 8.2 节）。此队列与暂停机制存在以下交互：

| 触发动作 | pending 队列行为 |
| --- | --- |
| 用户发消息，Agent 正常运行中 | 入队，等待当前轮次结束后注入下一轮 context |
| 用户点击"暂停" | 队列**立即**注入当前 context，不等轮次结束；Agent 暂停后 LLM 下次调用时可感知追加内容 |
| 用户点击"恢复" | 队列此时已清空（暂停时已注入），正常继续执行 |
| L3 接管期间用户发消息 | 消息入队；释放接管时与 drain-on-release 一同处理，注入 LLM 重新规划的 context |
| 应用崩溃重启 | 内存队列丢失；若有 pending 消息未注入，用户需在恢复后重新发送 |

### 12.2 计划确认与人工接管的关系

计划确认（`plan_confirmation_required` 事件）与 L3 接管共用同一套"阻塞等待用户响应"的模式，但作用域不同：

| 维度 | 计划确认 | L3 接管 |
| --- | --- | --- |
| 触发时机 | LLM 输出 `<agent_plan>` 块后 | 用户主动点击"接管" |
| 等待内容 | 用户确认或编辑执行计划 | 用户手动执行工具调用 |
| 恢复方式 | 用户点击"确认执行"或"取消" | 用户点击"释放接管" |
| 暂停信号响应 | 监听 `pause_rx`，暂停信号到达时取消等待并切换 Paused 状态 | 同左 |
| context 写入 | 将用户确认的计划文本注入下一轮 user 消息 | 将用户手动工具调用结果追加到 message_history |

计划确认期间，`HumanGuard` 状态保持 `Running`（不切换为 `Paused`），但 round_loop 挂起在 `oneshot::channel` 等待处，效果上等同于暂停。若此时用户点击"暂停"按钮，`pause_rx` 变更触发 `select!` 分支，计划等待取消，Agent 切换为 `Paused` 状态。
