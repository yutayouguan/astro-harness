# 数据库访问层详细设计

> **Harness 当前基线（2026-09-08）**：`agent-rollout` 是执行事件事实源，`agent-session` schema v23 直接保存 `response_items.item_json`，不存储 `Message` 投影。v22 → v23 只增量添加线程检查点表，保留既有数据；更早的旧 messages schema 仍沿用重建策略。本文后续 `MessageRepo` 伪代码仅是历史草案，不是当前 API。

> 阶段：详细设计 | 状态：草稿 | 说明：Repository 模式、每表专属 struct、软替换、Weibull 扫描

## 1. 总体架构

数据库访问层采用 **Repository 模式**，每张业务表对应一个专属 Repository struct，封装所有 CRUD 操作。上层（AgentExecutor、Tool 实现、后台任务）只通过 Repository API 访问数据，不直接持有 sqlx 连接。

```text
Agent 编排层
    │
    ├── ConversationRepo
    ├── MessageRepo
    ├── MemoryRepo          ← 含软替换、版本查询、Weibull 扫描
    ├── SkillRepo
    ├── MediaTaskRepo
    ├── AiArtifactRepo
    ├── CostRepo
    └── AuditLogRepo        ← 只有 INSERT，不允许 UPDATE/DELETE
         │
    SqlitePool（共享，Arc<SqlitePool> 传递）
         │
    SQLite（WAL + SQLCipher + sqlite-vec 扩展）
```

## 2. 连接池初始化

```rust
// crates/agent-core/src/storage/mod.rs
use sqlx::sqlite::{SqliteConnectOptions, SqliteJournalMode, SqlitePoolOptions};
use sqlite_vec::sqlite3_vec_init;

pub async fn open(path: &Path, passphrase: &str) -> anyhow::Result<SqlitePool> {
    let options = SqliteConnectOptions::new()
        .filename(path)
        .create_if_missing(true)
        .journal_mode(SqliteJournalMode::Wal)
        .foreign_keys(true)
        // SQLCipher：密钥必须在任何 SQL 执行前设置
        .pragma("key", passphrase)
        .pragma("cipher_page_size", "4096");

    let pool = SqlitePoolOptions::new()
        .max_connections(5)
        .acquire_timeout(Duration::from_secs(10))
        .before_acquire(|conn, _| Box::pin(async move {
            // sqlite-vec C 扩展：每条连接加载一次
            unsafe { sqlite3_vec_init(conn.as_raw_handle().as_ptr()); }
            Ok(true)
        }))
        .connect_with(options)
        .await?;

    // 编译期内嵌 migrations/ 目录，sqlx 自动按版本升序执行
    sqlx::migrate!("./migrations").run(&pool).await?;

    Ok(pool)
}
```

**SQLCipher 密钥管理**：密钥从系统密钥链（`keyring` crate）读取，首次启动自动生成并存储。passphrase 只在 Rust 进程内存中存在，不写入配置文件，不序列化到前端。

### 3.3 MemoryRepo（核心）

```rust
pub struct MemoryRepo(SqlitePool);

impl MemoryRepo {
    /// 写入新记忆；若同 workspace+category+key 已有活跃版本，自动软替换
    pub async fn upsert(&self, entry: &NewMemoryEntry) -> anyhow::Result<String> {
        let mut tx = self.0.begin().await?;
        let new_id = uuid();
        let now_ms = now_ms();

        // 查找当前活跃版本
        let existing = sqlx::query!(
            "SELECT id FROM memory_entries
             WHERE workspace_id = ? AND category = ? AND key = ? AND valid_to IS NULL",
            entry.workspace_id, entry.category, entry.key
        ).fetch_optional(&mut *tx).await?;

        if let Some(old) = existing {
            // 软替换：设置旧版本失效时间和 superseded_by
            sqlx::query!(
                "UPDATE memory_entries SET valid_to = ?, superseded_by = ? WHERE id = ?",
                now_ms, new_id, old.id
            ).execute(&mut *tx).await?;
        }

        // 插入新版本
        sqlx::query!(
            "INSERT INTO memory_entries
             (id, workspace_id, category, key, value, source, importance,
              half_life_days, valid_from, expires_at)
             VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
            new_id, entry.workspace_id, entry.category, entry.key, entry.value,
            entry.source, entry.importance, entry.half_life_days, now_ms, entry.expires_at
        ).execute(&mut *tx).await?;

        tx.commit().await?;
        Ok(new_id)
    }

    /// 软删除（设 valid_to = now()，不物理删除，历史可追溯）
    pub async fn soft_expire(&self, id: &str) -> anyhow::Result<()> {
        sqlx::query!(
            "UPDATE memory_entries SET valid_to = ? WHERE id = ?",
            now_ms(), id
        ).execute(&self.0).await?;
        Ok(())
    }

    /// 按 key 软删除活跃版本
    pub async fn soft_expire_by_key(
        &self, workspace_id: &str, key: &str, category: Option<&str>,
    ) -> anyhow::Result<()> {
        if let Some(cat) = category {
            sqlx::query!(
                "UPDATE memory_entries SET valid_to = ?
                 WHERE workspace_id = ? AND key = ? AND category = ? AND valid_to IS NULL",
                now_ms(), workspace_id, key, cat
            ).execute(&self.0).await?;
        } else {
            sqlx::query!(
                "UPDATE memory_entries SET valid_to = ?
                 WHERE workspace_id = ? AND key = ? AND valid_to IS NULL",
                now_ms(), workspace_id, key
            ).execute(&self.0).await?;
        }
        Ok(())
    }

    /// 更新检索统计（异步后台，不影响主流程）
    pub async fn update_retrieval_stats(&self, id: &str) {
        let _ = sqlx::query!(
            "UPDATE memory_entries
             SET retrieval_count = retrieval_count + 1,
                 last_retrieved_at = ?
             WHERE id = ?",
            now_ms(), id
        ).execute(&self.0).await;
    }

    /// 扫描所有工作区中 Weibull 分数低于阈值的活跃条目（遗忘调度器使用）
    pub async fn scan_for_forgetting_all(&self, _threshold: f64) -> anyhow::Result<Vec<MemoryEntry>> {
        // 查出所有活跃条目（过滤逻辑在调用方用 weibull_score() 完成）
        Ok(sqlx::query_as!(
            MemoryEntry,
            "SELECT * FROM memory_entries
             WHERE valid_to IS NULL
             ORDER BY workspace_id, category, retrieval_count ASC, created_at ASC"
        ).fetch_all(&self.0).await?)
    }
}
```

## 4. 事务管理规范

批量操作统一使用显式事务，确保原子性：

```rust
pub async fn batch_memory_upsert(
    pool: &SqlitePool,
    entries: Vec<NewMemoryEntry>,
) -> anyhow::Result<()> {
    let mut tx = pool.begin().await?;
    let repo = MemoryRepo(pool.clone());
    for entry in &entries {
        repo.upsert_in_tx(&entry, &mut tx).await?;
    }
    tx.commit().await?;
    Ok(())
}
```

**事务粒度原则**：

- 记忆软替换（旧版本 UPDATE + 新版本 INSERT）：必须同一事务
- 批量工具操作（`ops` 数组）：整批包在一个事务
- 单条记录的简单读写：不开事务，直接 execute

## 5. 向量检索（sqlite-vec）

```rust
pub async fn knn_search(
    pool: &SqlitePool,
    workspace_id: &str,
    query_embedding: &[f32],
    top_k: usize,
) -> anyhow::Result<Vec<KnnResult>> {
    // 将 f32 切片序列化为 JSON 数组绑定
    let embedding_json = serde_json::to_string(query_embedding)?;

    let rows = sqlx::query!(
        "SELECT e.source_id, e.source_type, e.distance
         FROM embeddings e
         WHERE e.embedding MATCH ?       -- KNN 查询向量
           AND e.workspace_id = ?
           AND k = ?",
        embedding_json, workspace_id, top_k as i64
    ).fetch_all(pool).await?;

    Ok(rows.into_iter().map(|r| KnnResult {
        source_id: r.source_id,
        source_type: r.source_type,
        distance: r.distance,
    }).collect())
}
```

KNN 查询后，通过 `source_id` 关联 `memory_entries`，并额外过滤 `valid_to IS NULL`，确保只返回活跃版本记忆。

```sql
CREATE TABLE IF NOT EXISTS task_traces (
    id              TEXT    PRIMARY KEY,
    conversation_id TEXT    NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    workspace_id    TEXT    NOT NULL,
    parent_id       TEXT    REFERENCES task_traces(id),  -- 子 Agent 挂在父任务下
    depth           INTEGER NOT NULL DEFAULT 0,          -- 递归深度，≤ 3
    status          TEXT    NOT NULL DEFAULT 'pending'    -- pending / running / done / failed / cancelled
                    CHECK(status IN ('pending','running','done','failed','cancelled')),
    input_json      TEXT,                                -- 原始任务描述（序列化 Message）
    checkpoint_json TEXT,                                -- 最新 checkpoint，覆盖写
    created_at      INTEGER NOT NULL DEFAULT (CAST(unixepoch('now','subsec') * 1000 AS INTEGER)),
    updated_at      INTEGER NOT NULL DEFAULT (CAST(unixepoch('now','subsec') * 1000 AS INTEGER)),
    finished_at     INTEGER
);

CREATE INDEX IF NOT EXISTS idx_task_traces_status
    ON task_traces(status)
    WHERE status = 'running';

CREATE INDEX IF NOT EXISTS idx_task_traces_conversation
    ON task_traces(conversation_id);
```

`checkpoint_json` 存储 `AgentCheckpoint` 结构体的 JSON 序列化结果，每轮工具调用全部完成后覆盖写入一次。恢复时以 `messages` 表为权威日志，`checkpoint` 只做任务标记，不参与精确截断：

### 8.2 TaskTraceRepo

```rust
pub struct TaskTraceRepo(SqlitePool);

impl TaskTraceRepo {
    pub fn new(pool: &SqlitePool) -> Self {
        Self(pool.clone())
    }

    /// 创建新任务记录，返回 trace_id
    pub async fn create(&self, trace: &NewTaskTrace) -> anyhow::Result<String> {
        let id = uuid();
        let now = now_ms();
        sqlx::query!(
            "INSERT INTO task_traces
             (id, conversation_id, workspace_id, parent_id, depth, status, input_json,
              created_at, updated_at)
             VALUES (?, ?, ?, ?, ?, 'running', ?, ?, ?)",
            id,
            trace.conversation_id,
            trace.workspace_id,
            trace.parent_id,
            trace.depth,
            trace.input_json,
            now,
            now,
        )
        .execute(&self.0)
        .await?;
        Ok(id)
    }

    /// 每轮工具调用全部完成后覆盖写入 checkpoint
    pub async fn write_checkpoint(
        &self,
        trace_id: &str,
        cp: &AgentCheckpoint,
    ) -> anyhow::Result<()> {
        let json = serde_json::to_string(cp)?;
        sqlx::query!(
            "UPDATE task_traces
             SET checkpoint_json = ?, updated_at = ?
             WHERE id = ?",
            json,
            now_ms(),
            trace_id,
        )
        .execute(&self.0)
        .await?;
        Ok(())
    }

    /// 标记任务完成或失败，清空 checkpoint（已完成无需恢复）
    pub async fn finish(
        &self,
        trace_id: &str,
        success: bool,
    ) -> anyhow::Result<()> {
        let status = if success { "done" } else { "failed" };
        let now = now_ms();
        sqlx::query!(
            "UPDATE task_traces
             SET status = ?, checkpoint_json = NULL,
                 finished_at = ?, updated_at = ?
             WHERE id = ?",
            status,
            now,
            now,
            trace_id,
        )
        .execute(&self.0)
        .await?;
        Ok(())
    }

    /// 启动时扫描所有未完成任务（status='running' 且有 checkpoint）
    pub async fn scan_incomplete(&self) -> anyhow::Result<Vec<IncompleteTask>> {
        Ok(sqlx::query_as!(
            IncompleteTask,
            "SELECT id, conversation_id, workspace_id, parent_id, depth, checkpoint_json
             FROM task_traces
             WHERE status = 'running'
               AND checkpoint_json IS NOT NULL
             ORDER BY created_at ASC"
        )
        .fetch_all(&self.0)
        .await?)
    }
}

#[derive(Debug)]
pub struct IncompleteTask {
    pub id: String,
    pub conversation_id: String,
    pub workspace_id: String,
    pub parent_id: Option<String>,
    pub depth: i64,
    pub checkpoint_json: Option<String>,
}

impl IncompleteTask {
    /// 解析 checkpoint，返回 None 表示数据损坏（按首轮处理）
    pub fn checkpoint(&self) -> Option<AgentCheckpoint> {
        self.checkpoint_json
            .as_deref()
            .and_then(|s| serde_json::from_str(s).ok())
    }
}
```

### 8.3 悬空状态修复

`messages` 表是追加写的执行日志，崩溃时已完成的工具调用结果已落盘。恢复时读取完整历史，找出最后一条 assistant 消息中缺少对应 tool result 的 tool_call_id，仅对这些补注入占位，已完成的工具**不会重复执行**：

```rust
/// 修复 messages 历史中的悬空 tool_call（有 tool_call 但缺 tool result）
pub fn repair_dangling_tool_calls(mut messages: Vec<Message>) -> Vec<Message> {
    // 收集所有已有 tool result 的 tool_call_id
    let completed: HashSet<String> = messages.iter()
        .filter(|m| m.role == "tool")
        .filter_map(|m| m.tool_call_id.clone())
        .collect();

    // 找最后一条含 tool_calls 的 assistant 消息
    let dangling: Vec<String> = messages.iter().rev()
        .find(|m| m.role == "assistant" && m.tool_calls.is_some())
        .into_iter()
        .flat_map(|m| m.tool_calls.as_deref().unwrap_or_default().iter()
            .filter(|tc| !completed.contains(&tc.id))
            .map(|tc| tc.id.clone()))
        .collect();

    // 对缺失的 tool_call_id 补注入崩溃占位结果
    for tool_id in dangling {
        messages.push(Message::synthetic_tool_result(
            &tool_id,
            "进程意外重启，操作未完成，请重新规划",
        ));
    }

    messages
}
```

### 8.4 在 agent 主循环中的调用位置

```rust
// agent/loop.rs — run_agent_turn 主循环
pub async fn run_agent_turn(ctx: AgentContext, trace_repo: &TaskTraceRepo) {
    let trace_id = trace_repo.create(&NewTaskTrace {
        conversation_id: ctx.conversation_id.clone(),
        workspace_id: ctx.workspace_id.clone(),
        parent_id: ctx.parent_trace_id.clone(),
        depth: ctx.depth,
        input_json: serde_json::to_string(&ctx.initial_message).ok(),
    })
    .await
    .unwrap_or_default();

    let mut round: u32 = 0;

    loop {
        // 1. 调用 LLM，获取 tool_calls 列表
        let response = call_llm(&ctx).await?;
        let tool_calls = response.tool_calls;

        // 2. 执行本轮所有工具调用，结果逐条写入 messages 表
        let results = execute_tool_calls(&tool_calls, &ctx).await;
        append_tool_results(&ctx, &results).await;

        // 3. 写 checkpoint（在下一次 LLM 调用之前，仅记录轮次编号）
        trace_repo.write_checkpoint(&trace_id, &AgentCheckpoint { round }).await.ok();
        round += 1;

        if response.stop_reason == StopReason::EndTurn {
            break;
        }
    }

    trace_repo.finish(&trace_id, true).await.ok();
}
```

### 8.5 启动时恢复流程

```rust
// src-tauri/src/startup.rs
pub async fn resume_incomplete_tasks(
    pool: &SqlitePool,
    session_manager: Arc<SessionManager>,
) {
    let repo = TaskTraceRepo::new(pool);
    // 按 depth ASC 排序：先恢复根任务，子任务由根任务编排逻辑重新 spawn
    let incomplete = repo.scan_incomplete().await.unwrap_or_default();

    for task in incomplete.iter().filter(|t| t.parent_id.is_none()) {
        // 读取 messages 表完整实际状态（权威日志）
        let all_messages = MessageRepo::new(pool)
            .list_by_conversation(&task.conversation_id)
            .await
            .unwrap_or_default();

        // 仅对崩溃时未完成的 tool_call 注入占位，已完成的不重跑
        let repaired = repair_dangling_tool_calls(all_messages);

        let ctx = AgentContext::resume(
            task.conversation_id.clone(),
            task.workspace_id.clone(),
            None,  // 根任务无 parent
            task.depth as u8,
            repaired,
        );
        session_manager.resume_task(task.id.clone(), ctx).await;
    }
}
```

子任务（`parent_id IS NOT NULL`）不独立恢复，由父任务重新 spawn 管理；`scan_incomplete` 返回结果已按 `depth ASC` 排序，确保父任务先于子任务处理。
