# 权限系统改进详细设计

> **Harness 当前基线（2026-08-29）**：权限以“模型可见性 ≠ 可执行授权”为核心原则。工具暴露、StepContext 路由、interaction mode、approval cache、HITL、workspace grant、SandboxPolicy 和 network decision 需逐层同时成立；Deferred 激活不产生授权。

> 阶段：详细设计 | 状态：已实现 | 日期：2026-08-28
> 需求来源：`docs/01-需求分析阶段/06-权限系统改进需求分析.md`
> 实施计划：`docs/plans/2026-08-28-permission-system-improvements.md`

## 1. 架构概览

改进集中在 `agent-core/src/control/` 模块，不改变 HitlGate/Interrupt 核心协议。在审批管线上叠加三层增强：

```
工具调用 → classify_dangerous_command → approval_route
                                            ↓
                                    ┌─ SessionApprovalCache (P0)
                                    │   命中 → Allowlist 路径
                                    │   未命中 ↓
                                    ├─ SmartApprovalContext (P1)
                                    │   注入对话上下文 → 辅模型判断
                                    │   未命中 ↓
                                    ├─ park_confirm (HITL)
                                    │   用户批准 → 写入缓存 + 可选持久白名单
                                    │   用户拒绝 → TrustEvaluator.record_denial (P5)
                                    └─ TrustEvaluator (P5)
                                        根据信任等级动态调整 approval_route
```

## 2. 模块设计

### 2.1 SessionApprovalCache（P0+P3）

**文件**：`crates/agent-core/src/control/approval_cache.rs`

```rust
pub struct SessionApprovalCache {
    session_id: String,
    entries: Mutex<HashMap<ApprovalCacheKey, CachedApproval>>,
    parent: Option<Arc<SessionApprovalCache>>,  // P3: 父级只读视图
}
```

**缓存 key 设计**：
- `ApprovalCacheKey { tool_name, command_prefix }` — 按命令前 2 个 token 索引
- `cargo test -p agent` 和 `cargo test -p tools` 共享 key `("exec_command", "cargo test")`

**生命周期**：
- 创建：`ThreadControls` 初始化时随 `HitlGate` 一起创建
- 读写：`execute_tools_serial_inner` 中 `approval_route` 返回 `Smart|Manual` 前查询；`park_confirm` 批准后写入
- 销毁：`ThreadControls` 被 drop 时自动清空

**父子继承（P3）**：
- `derive_child_cache(child_session_id)` 返回新缓存，持有父级 `Arc` 只读引用
- `lookup` 先查自身 → 未命中再递归查父级（`Box::pin` 解决递归 async）
- `insert` / `invalidate` / `clear` 只作用于自身，不影响父级

### 2.2 SmartApprovalContext（P1）

**文件**：`crates/agent-core/src/control/smart_approval.rs`

```rust
pub struct SmartApprovalContext {
    pub recent_turns: Vec<TurnSummary>,
    pub current_task_description: Option<String>,
    pub tool_call_chain: Vec<String>,
}
```

**上下文采集**：
- 从 `Session::clone_history()` 取最近 5 条非空消息
- 每条消息截断到 200 字符，总上下文约 1000 字符
- 通过 `redact_sensitive()` 脱敏（正则匹配 `API_KEY|TOKEN|SECRET|PASSWORD|BEARER|CREDENTIAL|AUTH_KEY` 模式）

**集成点**：
- `build_smart_approval_context(session)` 在 `tools_exec.rs` 中 Smart 路径调用
- `maybe_smart_downgrade_ask(request, targets, context)` 第三参数传入上下文
- `build_prompt(request, context)` 在 prompt 中附加 `Conversation context (redacted)` JSON 段

### 2.4 PermissionAuditEvent.reasoning（P4）

**文件**：`crates/agent-memory/src/permission_audit.rs`

```rust
pub struct PermissionAuditEvent {
    // ... 已有字段 ...
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub reasoning: Option<String>,  // 新增：最长 500 字符
}
```

**填充场景**：
- Smart Approval 自动放行：辅模型返回的 JSON 文本（截断）
- 用户手动审批：`"user_manual_approval"`
- 缓存命中：`"session_cache_hit: {command_prefix}"`
- 信任模型升级：`"trust_upgrade: {old_level} -> {new_level}"`

### 2.5 TrustEvaluator（P5）

**文件**：`crates/agent-core/src/control/trust_model.rs`

```rust
pub enum TrustLevel { AlwaysAsk, SmartReview, AutoApprove }

pub struct TrustEvaluator {
    scores: Mutex<HashMap<String, TrustScore>>,
}
```

**升降级规则**：
- 连续 5 次批准：`AlwaysAsk → SmartReview`
- 连续 10 次批准：`SmartReview → AutoApprove`
- 1 次拒绝：立即回退 `→ AlwaysAsk`
- session 结束自动清零

**安全护栏**：
- `hardline_blocked` 命令不受信任模型影响
- `ExternalSideEffect` 能力不参与信任升级

## 3. 数据流

### 3.1 审批管线完整流程

```
exec_command 调用
  → classify_dangerous_command
  → ApprovalAction::Ask
  → approval_route(cmd, permissions, allowlist)
    → Deny: 拒绝（hardline）
    → Allowlist: 放行（白名单）
    → Off: 放行（policy=Never）
    → Smart/Manual:
        → SessionApprovalCache.lookup(key)
          → 命中: 路由改为 Allowlist，记录 reasoning="session_cache_hit"
          → 未命中:
            → Smart: build_smart_approval_context → maybe_smart_downgrade_ask
              → Auto: 放行，记录 reasoning=辅模型文本
              → Ask: 拒绝（Auto-review 模式下不弹卡）
            → Manual: park_confirm (HITL 弹卡)
              → 批准: 写入 SessionApprovalCache + TrustEvaluator.record_approval
                → confirm.always → 同时写入持久白名单
              → 拒绝: TrustEvaluator.record_denial
```

### 3.2 子 Agent 缓存继承

```
spawn_agent
  → parent.ensure_thread_controls().approval_cache
  → approval_cache.derive_child_cache(child_session_id)
  → child 获得 ReadOnlyView(parent) + 自身可写缓存
  → child.lookup(key): 自身 → 父级 → None
  → child.insert(key): 仅写自身
  → child 结束: Arc drop，缓存自然清空
```
