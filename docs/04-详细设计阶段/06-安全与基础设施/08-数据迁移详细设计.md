## 1. 迁移系统架构

### 1.1 设计目标

数据迁移系统需要满足以下核心需求：

- **零外部依赖**：迁移 SQL 在编译期内嵌到二进制中（`sqlx::migrate!` 宏），发布产物自包含，用户无需管理外部迁移文件
- **确定性执行**：相同版本的二进制在任意环境下执行相同迁移序列，结果一致
- **安全回退**：每次迁移前自动备份数据库文件，失败时可秒级恢复
- **大表友好**：百万行级表的结构/数据变更不阻塞用户操作
- **加密兼容**：全流程兼容 SQLCipher 加密数据库，备份文件同样加密

### 1.2 架构总览

```text
应用启动
  │
  ▼
┌─────────────────────────────────────────────────────┐
│  MigrationRunner                                     │
│  ┌───────────┐  ┌──────────────┐  ┌───────────────┐ │
│  │ Backup    │→ │ SqlxMigrator  │→ │ DataMigrator  │ │
│  │ Manager   │  │ (SQL 迁移)    │  │ (Rust 迁移)   │ │
│  └───────────┘  └──────────────┘  └───────────────┘ │
│       │               │                  │           │
│       ▼               ▼                  ▼           │
│  agent.db.bak    _sqlx_migrations   data_migrations │
│  (备份文件)      (版本追踪表)       (Rust 迁移追踪) │
└─────────────────────────────────────────────────────┘
         │
         ▼
    SqlitePool（就绪，交付 Repository 层使用）
```

系统分为三个协作组件：

| 组件 | 职责 | 触发时机 |
|------|------|----------|
| **BackupManager** | 迁移前自动备份数据库文件，管理备份保留策略 | 检测到待执行迁移时 |
| **SqlxMigrator** | 执行 SQL DDL 迁移（建表、加列、建索引等），由 sqlx 内置引擎驱动 | 每次启动 |
| **DataMigrator** | 执行 Rust 编写的数据转换迁移（重新嵌入、格式变更、加密密钥轮换等） | SQL 迁移完成后 |

## 2. schema_versions 表

### 2.1 sqlx 内置表 `_sqlx_migrations`

项目使用 sqlx 作为 SQL 迁移引擎，其内置的 `_sqlx_migrations` 表负责追踪所有 SQL 迁移的执行状态：

```sql
-- 此表由 sqlx 自动创建和维护，不需手动管理
CREATE TABLE IF NOT EXISTS _sqlx_migrations (
    version        BIGINT   PRIMARY KEY,       -- 迁移版本号（从文件名解析）
    description    TEXT     NOT NULL,           -- 迁移描述（从文件名解析）
    installed_on   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,  -- 执行时间
    success        BOOLEAN  NOT NULL,           -- 是否成功
    checksum       BLOB     NOT NULL,           -- SQL 内容的 SHA-384 哈希
    execution_time BIGINT   NOT NULL            -- 执行耗时（纳秒）
);
```

sqlx 在每次启动时自动：
1. 比对编译期内嵌的迁移列表与 `_sqlx_migrations` 表中已执行的版本
2. 校验已执行迁移的 checksum 是否与内嵌版本一致（防篡改）
3. 按版本号升序执行所有待执行迁移
4. 任一迁移失败则回滚当前事务并抛出错误

### 2.2 data_migrations 扩展表

对于 Rust 编写的数据转换迁移（非 SQL DDL），需要独立的追踪表：

```sql
-- migrations/0007_data_migrations.sql
CREATE TABLE IF NOT EXISTS data_migrations (
    id              TEXT    PRIMARY KEY,        -- 迁移唯一标识，如 "dm_001_reembed_memories"
    description     TEXT    NOT NULL,           -- 人类可读描述
    applied_at      INTEGER NOT NULL DEFAULT (CAST(unixepoch('now','subsec') * 1000 AS INTEGER)),
    checksum        TEXT    NOT NULL,           -- Rust 迁移代码的版本哈希
    success         BOOLEAN NOT NULL DEFAULT 0, -- 执行是否成功
    duration_ms     INTEGER,                    -- 执行耗时
    rows_affected   INTEGER DEFAULT 0,          -- 影响行数
    error_message   TEXT,                       -- 失败时的错误信息
    -- 大表在线迁移的进度追踪
    total_rows      INTEGER,                    -- 总行数（在线迁移用）
    processed_rows  INTEGER DEFAULT 0,          -- 已处理行数
    is_resumable    BOOLEAN NOT NULL DEFAULT 0  -- 是否支持断点续传
);
```

两张表的分工明确：`_sqlx_migrations` 追踪 DDL 结构变更，`data_migrations` 追踪 Rust 数据转换。两类迁移之间通过版本号隐式排序——Rust 数据迁移可以声明对特定 SQL 迁移版本的依赖。

### 2.3 migration_backups 备份记录表

```sql
-- migrations/0007_data_migrations.sql（同一迁移文件中）
CREATE TABLE IF NOT EXISTS migration_backups (
    id              TEXT    PRIMARY KEY,
    backup_path     TEXT    NOT NULL,           -- 备份文件的绝对路径
    db_size_bytes   INTEGER NOT NULL,           -- 备份时数据库大小
    schema_version  INTEGER NOT NULL,           -- 备份时的最高 SQL 迁移版本
    created_at      INTEGER NOT NULL DEFAULT (CAST(unixepoch('now','subsec') * 1000 AS INTEGER)),
    retained        BOOLEAN NOT NULL DEFAULT 1  -- 是否保留（0=已清理）
);
```

## 3. 迁移文件格式

### 3.1 SQL 迁移文件命名

迁移文件统一放在 `crates/agent-core/migrations/` 目录，命名格式遵循 sqlx 约定：

```text
{4位版本号}_{snake_case描述}.sql

示例：
0001_init.sql                     # 基础表结构
0002_vec_tables.sql               # sqlite-vec 虚拟表
0003_media_artifacts.sql          # 媒体任务与 AI 制品表
0004_memory_versioning.sql        # 记忆版本化字段
0005_fts.sql                      # FTS5 全文检索
0006_task_traces.sql              # 任务追踪表
0007_data_migrations.sql          # 数据迁移追踪表
0008_add_conversation_tags.sql    # 会话标签功能
```

**规则约束**：

- 版本号为 4 位递增整数（0001-9999），严格递增，不允许跳号
- 已执行迁移的文件内容**禁止修改**——sqlx 通过 checksum 校验检测篡改
- 每次只允许追加新迁移文件，不允许删除或重排已有迁移
- 描述部分使用 snake_case，简明表达迁移内容

### 3.2 SQL 迁移文件结构

sqlx 的 SQL 迁移只支持前向执行（up），不内置 down 回滚语法。项目通过备份机制实现回退，而非 down 迁移：

```sql
-- 0008_add_conversation_tags.sql
-- 迁移描述：为会话增加标签支持
-- 依赖版本：0001_init.sql (conversations 表)

-- 新建标签表
CREATE TABLE IF NOT EXISTS conversation_tags (
    id              TEXT PRIMARY KEY,
    conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    tag_name        TEXT NOT NULL,
    created_at      INTEGER NOT NULL DEFAULT (CAST(unixepoch('now','subsec') * 1000 AS INTEGER)),
    UNIQUE(conversation_id, tag_name)
);

CREATE INDEX IF NOT EXISTS idx_conv_tags_name
    ON conversation_tags(tag_name);

-- 为 conversations 表增加置顶字段
ALTER TABLE conversations ADD COLUMN pinned BOOLEAN NOT NULL DEFAULT 0;
```

**编写规范**：

1. 文件头部用 SQL 注释说明迁移目的和依赖的前置版本
2. 所有 `CREATE TABLE` 使用 `IF NOT EXISTS`，增强幂等性
3. 所有 `CREATE INDEX` 使用 `IF NOT EXISTS`
4. `ALTER TABLE ADD COLUMN` 前无需检查列是否存在——sqlx 保证每个版本只执行一次
5. SQLite 的 `ALTER TABLE` 限制：不支持 `DROP COLUMN`（3.35.0 之前）、不支持 `MODIFY COLUMN`；需要结构变更时使用影子表模式

### 3.3 编译期内嵌

sqlx 的 `migrate!` 宏在编译期将 `migrations/` 目录下所有 `.sql` 文件内嵌到二进制中：

```rust
// crates/agent-core/src/storage/mod.rs
use sqlx::migrate::Migrator;

/// 编译期内嵌的迁移集合（静态常量，随二进制发布）
static MIGRATOR: Migrator = sqlx::migrate!("./migrations");

pub async fn open(path: &Path, passphrase: &str) -> anyhow::Result<SqlitePool> {
    let pool = create_pool(path, passphrase).await?;

    // MigrationRunner 统一编排备份 + SQL 迁移 + 数据迁移
    MigrationRunner::new(&pool, path)
        .run(&MIGRATOR)
        .await?;

    Ok(pool)
}
```

编译期内嵌的优势：
- 发布包自包含，不依赖外部文件系统
- 编译期即检测 SQL 语法错误（配合 `sqlx::query!` 宏的编译期校验）
- checksum 在编译期计算，运行时仅比对，无文件 I/O 开销

## 4. MigrationRunner 实现

### 4.1 核心结构

```rust
// crates/agent-core/src/storage/migration/mod.rs

use sqlx::migrate::Migrator;
use sqlx::SqlitePool;
use std::path::{Path, PathBuf};

pub struct MigrationRunner {
    pool: SqlitePool,
    db_path: PathBuf,
    backup_manager: BackupManager,
    data_migrator: DataMigrator,
}

impl MigrationRunner {
    pub fn new(pool: &SqlitePool, db_path: &Path) -> Self {
        Self {
            pool: pool.clone(),
            db_path: db_path.to_path_buf(),
            backup_manager: BackupManager::new(db_path),
            data_migrator: DataMigrator::new(pool.clone()),
        }
    }

    /// 完整迁移流程：检测 → 备份 → SQL 迁移 → 数据迁移
    pub async fn run(&self, migrator: &Migrator) -> anyhow::Result<MigrationReport> {
        let mut report = MigrationReport::default();

        // 1. 检测是否有待执行的 SQL 迁移
        let pending = self.detect_pending_sql_migrations(migrator).await?;
        let has_pending_data = self.data_migrator.has_pending().await?;

        if pending.is_empty() && !has_pending_data {
            tracing::info!("数据库 schema 已是最新，无需迁移");
            return Ok(report);
        }

        // 2. 版本兼容性检查
        self.check_version_compatibility(migrator).await?;

        // 3. 迁移前备份
        if !pending.is_empty() || has_pending_data {
            let backup_path = self.backup_manager
                .create_backup(&self.pool)
                .await?;
            report.backup_path = Some(backup_path);
            tracing::info!(
                "迁移前备份完成：{}",
                report.backup_path.as_ref().unwrap().display()
            );
        }

        // 4. 执行 SQL 迁移（sqlx 引擎）
        if !pending.is_empty() {
            tracing::info!("检测到 {} 个待执行 SQL 迁移", pending.len());
            match migrator.run(&self.pool).await {
                Ok(()) => {
                    report.sql_migrations_applied = pending.len();
                    tracing::info!("SQL 迁移全部执行成功");
                }
                Err(e) => {
                    tracing::error!("SQL 迁移失败：{e}");
                    // sqlx 已自动回滚当前失败事务
                    // 提示用户可从备份恢复
                    return Err(anyhow::anyhow!(
                        "数据库迁移失败：{e}。\n\
                         可从备份文件恢复：{path}",
                        path = report.backup_path
                            .as_ref()
                            .map(|p| p.display().to_string())
                            .unwrap_or_default()
                    ));
                }
            }
        }

        // 5. 执行 Rust 数据迁移
        if has_pending_data {
            let data_report = self.data_migrator.run_pending().await?;
            report.data_migrations_applied = data_report.applied;
            report.rows_transformed = data_report.total_rows_affected;
        }

        // 6. 清理过期备份
        self.backup_manager.cleanup_old_backups().await?;

        Ok(report)
    }

    /// 检测待执行的 SQL 迁移列表
    async fn detect_pending_sql_migrations(
        &self,
        migrator: &Migrator,
    ) -> anyhow::Result<Vec<PendingMigration>> {
        // 查询已执行的迁移版本
        let applied: Vec<i64> = sqlx::query_scalar(
            "SELECT version FROM _sqlx_migrations WHERE success = 1"
        )
        .fetch_all(&self.pool)
        .await
        .unwrap_or_default();

        let pending: Vec<PendingMigration> = migrator
            .iter()
            .filter(|m| !applied.contains(&m.version))
            .map(|m| PendingMigration {
                version: m.version,
                description: m.description.to_string(),
            })
            .collect();

        // checksum 校验：已执行迁移的内容不应被篡改
        for migration in migrator.iter() {
            if applied.contains(&migration.version) {
                self.verify_checksum(migration).await?;
            }
        }

        Ok(pending)
    }

    /// 校验已执行迁移的 checksum
    async fn verify_checksum(
        &self,
        migration: &sqlx::migrate::Migration,
    ) -> anyhow::Result<()> {
        let stored_checksum: Option<Vec<u8>> = sqlx::query_scalar(
            "SELECT checksum FROM _sqlx_migrations WHERE version = ?"
        )
        .bind(migration.version)
        .fetch_optional(&self.pool)
        .await?;

        if let Some(stored) = stored_checksum {
            if stored != migration.checksum.as_bytes() {
                return Err(anyhow::anyhow!(
                    "迁移 {} ({}) 的 checksum 不匹配！\n\
                     已执行版本的 SQL 内容可能被篡改，拒绝启动。\n\
                     存储: {:x?}\n期望: {:x?}",
                    migration.version,
                    migration.description,
                    stored,
                    migration.checksum.as_bytes()
                ));
            }
        }
        Ok(())
    }
}
```

### 4.3 错误处理与自动回滚

迁移执行采用分层错误处理策略：

```rust
/// 迁移错误类型
#[derive(Debug, thiserror::Error)]
pub enum MigrationError {
    #[error("checksum 校验失败：版本 {version} 的迁移内容已被篡改")]
    ChecksumMismatch { version: i64 },

    #[error("SQL 迁移执行失败：{source}")]
    SqlMigrationFailed {
        #[source]
        source: sqlx::migrate::MigrateError,
    },

    #[error("数据迁移执行失败：{migration_id} — {message}")]
    DataMigrationFailed {
        migration_id: String,
        message: String,
    },

    #[error("备份创建失败：{0}")]
    BackupFailed(#[from] std::io::Error),

    #[error("版本不兼容：当前 schema {current}，应用要求最低 {minimum}")]
    IncompatibleVersion { current: i64, minimum: i64 },
}
```

**回滚策略总结**：

| 失败场景 | 回滚机制 | 自动/手动 |
|----------|----------|-----------|
| 单条 SQL 迁移执行失败 | sqlx 自动回滚该迁移的事务，已完成的迁移保留 | 自动 |
| checksum 不匹配 | 拒绝启动，不执行任何迁移 | 自动 |
| 数据迁移执行失败 | 依赖备份恢复（SQL DDL 已变更，无法部分回退） | 手动 |
| 大表在线迁移中断 | 支持断点续传，从已处理位置继续 | 自动 |

## 5. 在线迁移（大表）

### 5.1 适用场景

当表行数超过 100K 时，直接执行 `ALTER TABLE` 或全表 `UPDATE` 会导致长时间持锁，阻塞 WAL 写入，影响用户体验。以下操作必须使用在线迁移：

- 全表数据回填（如给新列设置非常量默认值）
- 批量数据格式转换
- 影子表结构变更（添加/移除约束、修改列类型）

### 5.2 批处理迁移器

```rust
// crates/agent-core/src/storage/migration/online.rs

use sqlx::SqlitePool;
use tokio::sync::watch;

/// 在线迁移配置
pub struct OnlineMigrationConfig {
    /// 每批处理的行数
    pub batch_size: u32,
    /// 批次间的休眠时间（让出锁，允许其他操作）
    pub batch_delay: Duration,
    /// 进度回调频率（每 N 批回调一次）
    pub progress_interval: u32,
}

impl Default for OnlineMigrationConfig {
    fn default() -> Self {
        Self {
            batch_size: 5000,
            batch_delay: Duration::from_millis(50),
            progress_interval: 10,
        }
    }
}

/// 在线迁移执行器
pub struct OnlineMigrator {
    pool: SqlitePool,
    config: OnlineMigrationConfig,
    /// 暂停/恢复信号
    pause_signal: watch::Receiver<bool>,
}

impl OnlineMigrator {
    pub fn new(
        pool: SqlitePool,
        config: OnlineMigrationConfig,
        pause_signal: watch::Receiver<bool>,
    ) -> Self {
        Self { pool, config, pause_signal }
    }

    /// 分批执行 UPDATE 操作
    ///
    /// `update_sql` 必须包含 `LIMIT ?` 占位符，由执行器填充 batch_size。
    /// 返回总影响行数。
    pub async fn batch_update(
        &self,
        migration_id: &str,
        count_sql: &str,
        update_sql: &str,
    ) -> anyhow::Result<BatchResult> {
        // 获取总行数用于进度追踪
        let total_rows: i64 = sqlx::query_scalar(count_sql)
            .fetch_one(&self.pool)
            .await?;

        let mut processed: i64 = 0;
        let mut batch_count: u32 = 0;

        // 尝试从上次中断位置恢复
        let resume_offset = self.load_progress(migration_id).await?;
        if resume_offset > 0 {
            processed = resume_offset;
            tracing::info!(
                "[{migration_id}] 从断点恢复，已处理 {processed}/{total_rows} 行"
            );
        }

        loop {
            // 检查暂停信号
            while *self.pause_signal.borrow() {
                tracing::info!("[{migration_id}] 迁移已暂停，等待恢复信号...");
                self.pause_signal.changed().await?;
            }

            // 执行一批
            let affected = sqlx::query(update_sql)
                .bind(self.config.batch_size as i64)
                .execute(&self.pool)
                .await?
                .rows_affected() as i64;

            if affected == 0 {
                break;
            }

            processed += affected;
            batch_count += 1;

            // 定期保存进度（支持断点续传）
            if batch_count % self.config.progress_interval == 0 {
                self.save_progress(migration_id, processed, total_rows).await?;
                let pct = (processed as f64 / total_rows as f64 * 100.0) as u32;
                tracing::info!(
                    "[{migration_id}] 进度 {pct}% ({processed}/{total_rows})"
                );
            }

            // 批次间短暂休眠，让出 WAL 锁
            tokio::time::sleep(self.config.batch_delay).await;
        }

        // 标记完成
        self.mark_completed(migration_id, processed).await?;

        Ok(BatchResult {
            total_rows,
            processed_rows: processed,
            batch_count,
        })
    }

    /// 保存迁移进度到 data_migrations 表
    async fn save_progress(
        &self,
        migration_id: &str,
        processed: i64,
        total: i64,
    ) -> anyhow::Result<()> {
        sqlx::query(
            "UPDATE data_migrations
             SET processed_rows = ?, total_rows = ?
             WHERE id = ?"
        )
        .bind(processed)
        .bind(total)
        .bind(migration_id)
        .execute(&self.pool)
        .await?;
        Ok(())
    }

    /// 从 data_migrations 表加载上次进度
    async fn load_progress(&self, migration_id: &str) -> anyhow::Result<i64> {
        let row: Option<i64> = sqlx::query_scalar(
            "SELECT processed_rows FROM data_migrations
             WHERE id = ? AND is_resumable = 1 AND success = 0"
        )
        .bind(migration_id)
        .fetch_optional(&self.pool)
        .await?;

        Ok(row.unwrap_or(0))
    }

    /// 标记迁移完成
    async fn mark_completed(
        &self,
        migration_id: &str,
        rows_affected: i64,
    ) -> anyhow::Result<()> {
        sqlx::query(
            "UPDATE data_migrations
             SET success = 1, rows_affected = ?, processed_rows = total_rows
             WHERE id = ?"
        )
        .bind(rows_affected)
        .bind(migration_id)
        .execute(&self.pool)
        .await?;
        Ok(())
    }
}

#[derive(Debug)]
pub struct BatchResult {
    pub total_rows: i64,
    pub processed_rows: i64,
    pub batch_count: u32,
}
```

### 5.3 影子表模式（Zero-Downtime 结构变更）

SQLite 不支持 `ALTER TABLE DROP COLUMN`（3.35.0 之前）或 `ALTER TABLE MODIFY COLUMN`。当需要移除列、修改列类型或添加复杂约束时，使用影子表模式：

```rust
/// 影子表迁移步骤
pub struct ShadowTableMigration {
    pool: SqlitePool,
    config: OnlineMigrationConfig,
}

impl ShadowTableMigration {
    /// 执行影子表迁移
    ///
    /// 步骤：
    /// 1. 创建具有新结构的影子表
    /// 2. 分批从源表复制数据到影子表
    /// 3. 原子性重命名（旧表 → _old，影子表 → 原名）
    /// 4. 删除旧表
    /// 5. 重建索引和触发器
    pub async fn execute(
        &self,
        source_table: &str,
        create_shadow_sql: &str,
        copy_sql: &str,
        post_rename_sql: &str,
    ) -> anyhow::Result<()> {
        let shadow_table = format!("{source_table}_shadow");
        let old_table = format!("{source_table}_old");

        // 1. 创建影子表
        sqlx::query(create_shadow_sql)
            .execute(&self.pool)
            .await?;

        // 2. 分批复制数据
        let batch_size = self.config.batch_size as i64;
        let mut offset: i64 = 0;
        loop {
            let copy_batch = format!(
                "{copy_sql} LIMIT {batch_size} OFFSET {offset}"
            );
            let affected = sqlx::query(&copy_batch)
                .execute(&self.pool)
                .await?
                .rows_affected();

            if affected == 0 {
                break;
            }
            offset += batch_size;

            // 批次间让出锁
            tokio::time::sleep(self.config.batch_delay).await;
        }

        // 3. 原子性重命名（在事务中）
        let mut tx = self.pool.begin().await?;

        sqlx::query(&format!(
            "ALTER TABLE {source_table} RENAME TO {old_table}"
        ))
        .execute(&mut *tx)
        .await?;

        sqlx::query(&format!(
            "ALTER TABLE {shadow_table} RENAME TO {source_table}"
        ))
        .execute(&mut *tx)
        .await?;

        tx.commit().await?;

        // 4. 删除旧表
        sqlx::query(&format!("DROP TABLE IF EXISTS {old_table}"))
            .execute(&self.pool)
            .await?;

        // 5. 重建索引和触发器
        if !post_rename_sql.is_empty() {
            sqlx::query(post_rename_sql)
                .execute(&self.pool)
                .await?;
        }

        Ok(())
    }
}
```

### 6.1 设计动机

部分迁移无法用纯 SQL 表达，需要 Rust 逻辑介入：

| 场景 | 为何需要 Rust |
|------|---------------|
| 重新生成嵌入向量 | 需要调用嵌入模型 API |
| 数据格式变更 | 需要反序列化旧格式 → 转换 → 序列化新格式 |
| 加密密钥轮换 | 需要解密旧数据 → 重新加密 |

### 6.2 DataMigrator 注册表

```rust
// crates/agent-core/src/storage/migration/data_migrator.rs

use std::future::Future;
use std::pin::Pin;
use sqlx::SqlitePool;

/// 数据迁移 trait
#[async_trait::async_trait]
pub trait DataMigration: Send + Sync {
    /// 迁移唯一标识
    fn id(&self) -> &str;
    /// 人类可读描述
    fn description(&self) -> &str;
    /// 代码版本哈希（用于检测代码变更）
    fn checksum(&self) -> &str;
    /// 依赖的最低 SQL 迁移版本（确保表结构就绪）
    fn requires_sql_version(&self) -> i64;
    /// 是否支持断点续传
    fn is_resumable(&self) -> bool { false }
    /// 执行迁移
    async fn execute(&self, pool: &SqlitePool) -> anyhow::Result<u64>;
}

/// 数据迁移注册与执行器
pub struct DataMigrator {
    pool: SqlitePool,
    /// 按依赖顺序排列的迁移列表（编译期注册）
    migrations: Vec<Box<dyn DataMigration>>,
}

impl DataMigrator {
    pub fn new(pool: SqlitePool) -> Self {
        Self {
            pool,
            migrations: Self::register_all(),
        }
    }

    /// 编译期注册所有数据迁移
    fn register_all() -> Vec<Box<dyn DataMigration>> {
        vec![
            Box::new(ReembedMemoriesMigration),
            Box::new(EncryptionKeyRotation),
            // 新增数据迁移在此追加
        ]
    }

    /// 检测是否有待执行的数据迁移
    pub async fn has_pending(&self) -> anyhow::Result<bool> {
        for migration in &self.migrations {
            if !self.is_applied(migration.id()).await? {
                return Ok(true);
            }
        }
        Ok(false)
    }

    /// 执行所有待执行的数据迁移
    pub async fn run_pending(&self) -> anyhow::Result<DataMigrationReport> {
        let mut report = DataMigrationReport::default();

        for migration in &self.migrations {
            if self.is_applied(migration.id()).await? {
                continue;
            }

            // 确保依赖的 SQL 迁移已执行
            let current_sql_version = self.current_sql_version().await?;
            if current_sql_version < migration.requires_sql_version() {
                tracing::warn!(
                    "数据迁移 {} 依赖 SQL 版本 {}，当前版本 {}，跳过",
                    migration.id(),
                    migration.requires_sql_version(),
                    current_sql_version
                );
                continue;
            }

            // 记录迁移开始
            self.record_start(migration.as_ref()).await?;

            let start = std::time::Instant::now();
            match migration.execute(&self.pool).await {
                Ok(rows_affected) => {
                    let duration = start.elapsed();
                    self.record_success(
                        migration.id(),
                        rows_affected,
                        duration,
                    ).await?;
                    report.applied += 1;
                    report.total_rows_affected += rows_affected;
                    tracing::info!(
                        "数据迁移 {} 完成：影响 {} 行，耗时 {:?}",
                        migration.id(), rows_affected, duration
                    );
                }
                Err(e) => {
                    self.record_failure(migration.id(), &e.to_string()).await?;
                    return Err(anyhow::anyhow!(
                        "数据迁移 {} 失败：{e}", migration.id()
                    ));
                }
            }
        }

        Ok(report)
    }

    async fn is_applied(&self, id: &str) -> anyhow::Result<bool> {
        let exists: bool = sqlx::query_scalar(
            "SELECT EXISTS(SELECT 1 FROM data_migrations WHERE id = ? AND success = 1)"
        )
        .bind(id)
        .fetch_one(&self.pool)
        .await?;
        Ok(exists)
    }

    async fn current_sql_version(&self) -> anyhow::Result<i64> {
        let version: Option<i64> = sqlx::query_scalar(
            "SELECT MAX(version) FROM _sqlx_migrations WHERE success = 1"
        )
        .fetch_optional(&self.pool)
        .await?;
        Ok(version.unwrap_or(0))
    }

    async fn record_start(&self, migration: &dyn DataMigration) -> anyhow::Result<()> {
        sqlx::query(
            "INSERT OR REPLACE INTO data_migrations
             (id, description, checksum, is_resumable, success)
             VALUES (?, ?, ?, ?, 0)"
        )
        .bind(migration.id())
        .bind(migration.description())
        .bind(migration.checksum())
        .bind(migration.is_resumable())
        .execute(&self.pool)
        .await?;
        Ok(())
    }

    async fn record_success(
        &self,
        id: &str,
        rows_affected: u64,
        duration: Duration,
    ) -> anyhow::Result<()> {
        sqlx::query(
            "UPDATE data_migrations
             SET success = 1, rows_affected = ?, duration_ms = ?
             WHERE id = ?"
        )
        .bind(rows_affected as i64)
        .bind(duration.as_millis() as i64)
        .bind(id)
        .execute(&self.pool)
        .await?;
        Ok(())
    }

    async fn record_failure(&self, id: &str, error: &str) -> anyhow::Result<()> {
        sqlx::query(
            "UPDATE data_migrations
             SET success = 0, error_message = ?
             WHERE id = ?"
        )
        .bind(error)
        .bind(id)
        .execute(&self.pool)
        .await?;
        Ok(())
    }
}

#[derive(Debug, Default)]
pub struct DataMigrationReport {
    pub applied: usize,
    pub total_rows_affected: u64,
}
```

#### 6.3.1 重新生成嵌入向量

当嵌入模型升级（如从 text-embedding-ada-002 切换到 text-embedding-3-small）时，需要为所有记忆条目重新生成向量：

```rust
pub struct ReembedMemoriesMigration;

#[async_trait::async_trait]
impl DataMigration for ReembedMemoriesMigration {
    fn id(&self) -> &str { "dm_001_reembed_memories_v3small" }
    fn description(&self) -> &str { "将记忆嵌入向量从 ada-002 升级到 text-embedding-3-small" }
    fn checksum(&self) -> &str { "a1b2c3d4" }  // 代码变更时手动更新
    fn requires_sql_version(&self) -> i64 { 4 }  // 需要 0004 之后的表结构
    fn is_resumable(&self) -> bool { true }

    async fn execute(&self, pool: &SqlitePool) -> anyhow::Result<u64> {
        let (pause_tx, pause_rx) = tokio::sync::watch::channel(false);
        let migrator = OnlineMigrator::new(
            pool.clone(),
            OnlineMigrationConfig {
                batch_size: 100,  // 嵌入 API 限制
                batch_delay: Duration::from_millis(200),  // 避免 API 限流
                ..Default::default()
            },
            pause_rx,
        );

        // 获取所有需要重新嵌入的记忆条目
        let entries: Vec<(String, String)> = sqlx::query_as(
            "SELECT m.id, m.value FROM memory_entries m
             LEFT JOIN embeddings e ON e.source_id = m.id
             WHERE m.valid_to IS NULL
             ORDER BY m.created_at ASC"
        )
        .fetch_all(pool)
        .await?;

        let total = entries.len() as u64;
        let mut processed: u64 = 0;

        for chunk in entries.chunks(100) {
            // 批量调用嵌入 API
            let texts: Vec<&str> = chunk.iter().map(|(_, v)| v.as_str()).collect();
            let embeddings = embed_batch(&texts).await?;

            // 批量更新 embeddings 表
            let mut tx = pool.begin().await?;
            for ((id, _), embedding) in chunk.iter().zip(embeddings.iter()) {
                let embedding_json = serde_json::to_string(embedding)?;
                sqlx::query(
                    "INSERT OR REPLACE INTO embeddings (source_id, source_type, embedding, workspace_id)
                     SELECT ?, 'memory', ?, workspace_id FROM memory_entries WHERE id = ?"
                )
                .bind(id)
                .bind(&embedding_json)
                .bind(id)
                .execute(&mut *tx)
                .await?;
            }
            tx.commit().await?;

            processed += chunk.len() as u64;
            tokio::time::sleep(Duration::from_millis(200)).await;
        }

        Ok(processed)
    }
}
```

```rust
pub struct MessageContentFormatMigration;

impl DataMigration for MessageContentFormatMigration {
    fn id(&self) -> &str { "dm_003_message_content_to_parts" }
    fn description(&self) -> &str { "将 messages.content 从纯文本转换为 JSON ContentPart 数组" }

                    .bind(&parts)
                    .bind(id)
                    .execute(&mut *tx)
                    .await?;
            }
            tx.commit().await?;

            total_affected += rows.len() as u64;
            tokio::time::sleep(Duration::from_millis(50)).await;
        }
```

## 7. 备份策略

### 7.1 BackupManager 实现

```rust
// crates/agent-core/src/storage/migration/backup.rs

use std::path::{Path, PathBuf};
use sqlx::SqlitePool;
use tokio::fs;

/// 备份保留策略
const MAX_BACKUPS: usize = 3;

pub struct BackupManager {
    db_path: PathBuf,
}

impl BackupManager {
    pub fn new(db_path: &Path) -> Self {
        Self {
            db_path: db_path.to_path_buf(),
        }
    }

    /// 创建迁移前备份
    ///
    /// 使用 SQLite 的 VACUUM INTO 命令创建一致性备份。
    /// 相比文件复制，VACUUM INTO 确保：
    /// - WAL 日志已合并到主文件
    /// - 备份文件是完整、自洽的数据库
    /// - 备份过程中不会阻塞并发读写（WAL 模式下）
    pub async fn create_backup(
        &self,
        pool: &SqlitePool,
    ) -> anyhow::Result<PathBuf> {
        let timestamp = chrono::Utc::now().format("%Y%m%d_%H%M%S");
        let backup_path = self.backup_dir().join(
            format!("agent.db.bak-{timestamp}")
        );

        // 确保备份目录存在
        fs::create_dir_all(self.backup_dir()).await?;

        // 使用 VACUUM INTO 创建一致性备份
        let backup_path_str = backup_path.to_string_lossy().to_string();
        sqlx::query(&format!("VACUUM INTO '{backup_path_str}'"))
            .execute(pool)
            .await
            .map_err(|e| anyhow::anyhow!(
                "数据库备份失败（VACUUM INTO）：{e}"
            ))?;

        // 记录备份元信息
        let db_size = fs::metadata(&self.db_path).await?.len();
        let current_version = self.current_schema_version(pool).await?;

        sqlx::query(
            "INSERT INTO migration_backups (id, backup_path, db_size_bytes, schema_version)
             VALUES (?, ?, ?, ?)"
        )
        .bind(uuid::Uuid::new_v4().to_string())
        .bind(&backup_path_str)
        .bind(db_size as i64)
        .bind(current_version)
        .execute(pool)
        .await?;

        tracing::info!(
            "数据库备份完成：{backup_path_str}（{size} 字节）",
            size = db_size
        );

        Ok(backup_path)
    }

    /// 清理过期备份，仅保留最近 MAX_BACKUPS 份
    pub async fn cleanup_old_backups(&self) -> anyhow::Result<()> {
        let backup_dir = self.backup_dir();

        if !backup_dir.exists() {
            return Ok(());
        }

        // 读取所有备份文件，按修改时间降序排列
        let mut backups: Vec<(PathBuf, std::time::SystemTime)> = Vec::new();

        let mut entries = fs::read_dir(&backup_dir).await?;
        while let Some(entry) = entries.next_entry().await? {
            let path = entry.path();
            if path.file_name()
                .and_then(|n| n.to_str())
                .map(|n| n.starts_with("agent.db.bak-"))
                .unwrap_or(false)
            {
                if let Ok(meta) = fs::metadata(&path).await {
                    if let Ok(modified) = meta.modified() {
                        backups.push((path, modified));
                    }
                }
            }
        }

        backups.sort_by(|a, b| b.1.cmp(&a.1));

        // 删除超出保留数量的旧备份
        for (path, _) in backups.iter().skip(MAX_BACKUPS) {
            if let Err(e) = fs::remove_file(path).await {
                tracing::warn!(
                    "清理旧备份失败：{} — {e}",
                    path.display()
                );
            } else {
                tracing::info!("已清理旧备份：{}", path.display());
            }
        }

        Ok(())
    }

    /// 从备份恢复数据库
    pub async fn restore_from_backup(
        &self,
        backup_path: &Path,
    ) -> anyhow::Result<()> {
        // 验证备份文件存在且是有效的 SQLite 数据库
        if !backup_path.exists() {
            return Err(anyhow::anyhow!(
                "备份文件不存在：{}", backup_path.display()
            ));
        }

        // 验证 SQLite 文件头魔数
        let header = fs::read(backup_path).await?;
        if header.len() < 16 || &header[..16] != b"SQLite format 3\0" {
            // 注：SQLCipher 加密数据库的文件头不是标准 SQLite 格式
            // 如果使用 SQLCipher，跳过此检查
            tracing::warn!("备份文件头非标准 SQLite 格式（可能是 SQLCipher 加密数据库）");
        }

        // 关闭所有现有连接后替换数据库文件
        // 注：此操作需要在应用停止后手动执行，或通过 CLI 工具执行
        let wal_path = self.db_path.with_extension("db-wal");
        let shm_path = self.db_path.with_extension("db-shm");

        // 删除 WAL 和 SHM 文件（避免旧日志干扰恢复后的数据库）
        let _ = fs::remove_file(&wal_path).await;
        let _ = fs::remove_file(&shm_path).await;

        // 覆盖主数据库文件
        fs::copy(backup_path, &self.db_path).await?;

        tracing::info!(
            "数据库已从备份恢复：{} → {}",
            backup_path.display(),
            self.db_path.display()
        );

        Ok(())
    }

    /// 列出可用备份
    pub async fn list_backups(&self) -> anyhow::Result<Vec<BackupInfo>> {
        let backup_dir = self.backup_dir();
        let mut backups = Vec::new();

        if !backup_dir.exists() {
            return Ok(backups);
        }

        let mut entries = fs::read_dir(&backup_dir).await?;
        while let Some(entry) = entries.next_entry().await? {
            let path = entry.path();
            if let Ok(meta) = fs::metadata(&path).await {
                backups.push(BackupInfo {
                    path: path.clone(),
                    size_bytes: meta.len(),
                    created_at: meta.modified().ok(),
                });
            }
        }

        backups.sort_by(|a, b| b.created_at.cmp(&a.created_at));
        Ok(backups)
    }

    fn backup_dir(&self) -> PathBuf {
        self.db_path.parent().unwrap().join("backups")
    }

    async fn current_schema_version(&self, pool: &SqlitePool) -> anyhow::Result<i64> {
        let version: Option<i64> = sqlx::query_scalar(
            "SELECT MAX(version) FROM _sqlx_migrations WHERE success = 1"
        )
        .fetch_optional(pool)
        .await?;
        Ok(version.unwrap_or(0))
    }
}

#[derive(Debug)]
pub struct BackupInfo {
    pub path: PathBuf,
    pub size_bytes: u64,
    pub created_at: Option<std::time::SystemTime>,
}
```

### 7.2 备份时机与保留策略

| 时机 | 触发条件 | 保留策略 |
|------|----------|----------|
| 迁移前 | 检测到待执行的 SQL 迁移或数据迁移 | 保留最近 3 份 |
| 手动备份 | 用户通过设置面板触发 | 不计入自动清理 |
| 密钥轮换前 | 执行 `PRAGMA rekey` 之前 | 保留至密钥轮换确认成功 |

```text
数据库损坏 / 迁移失败
```

## 8. 版本兼容性

### 8.1 应用版本与 Schema 版本映射

每个应用版本内嵌一组明确的 schema 版本约束：

```rust
// crates/agent-core/src/storage/migration/compat.rs

/// 应用版本对 schema 版本的要求
pub struct SchemaCompatibility {
    /// 当前应用期望的 schema 版本（等于内嵌迁移的最高版本号）
    pub expected_version: i64,
    /// 最低支持的 schema 版本（低于此版本需要先升级应用到中间版本）
    pub minimum_supported_version: i64,
}

/// 编译期常量，随应用版本更新
pub const SCHEMA_COMPAT: SchemaCompatibility = SchemaCompatibility {
    expected_version: 7,       // 0007_data_migrations.sql
    minimum_supported_version: 4,  // 低于 0004 的 schema 需要先升级到 v1.x
};

impl SchemaCompatibility {
    /// 检查当前数据库的 schema 版本是否兼容
    pub async fn check(&self, pool: &SqlitePool) -> Result<CompatResult, MigrationError> {
        let current = self.current_version(pool).await?;

        if current == 0 {
            // 全新数据库，直接执行所有迁移
            return Ok(CompatResult::FreshDatabase);
        }

        if current > self.expected_version {
            // 数据库版本高于应用版本——可能是降级安装
            return Err(MigrationError::IncompatibleVersion {
                current,
                minimum: self.expected_version,
            });
        }

        if current < self.minimum_supported_version {
            // 数据库太旧，需要先通过中间版本升级
            return Err(MigrationError::IncompatibleVersion {
                current,
                minimum: self.minimum_supported_version,
            });
        }

        if current == self.expected_version {
            Ok(CompatResult::UpToDate)
        } else {
            Ok(CompatResult::NeedsMigration {
                from: current,
                to: self.expected_version,
            })
        }
    }

    async fn current_version(&self, pool: &SqlitePool) -> Result<i64, MigrationError> {
        // _sqlx_migrations 表可能还不存在（全新数据库）
        let version: Option<i64> = sqlx::query_scalar(
            "SELECT MAX(version) FROM _sqlx_migrations WHERE success = 1"
        )
        .fetch_optional(pool)
        .await
        .unwrap_or(None);

        Ok(version.unwrap_or(0))
    }
}

#[derive(Debug)]
pub enum CompatResult {
    /// 全新数据库，无需兼容性检查
    FreshDatabase,
    /// schema 已是最新
    UpToDate,
    /// 需要从 from 迁移到 to
    NeedsMigration { from: i64, to: i64 },
}
```

### 8.2 前向执行策略

迁移系统严格执行前向策略，不支持回退到旧版本的 schema：

```text
                      不可逆
v0004 ──→ v0005 ──→ v0006 ──→ v0007
                                 ▲
                        当前 schema 版本
                                 │
                    ← ← ← 不支持回退 ← ← ←
                    （只能通过备份恢复）
```

**设计原因**：

1. **down 迁移不可靠**：撤销 `ALTER TABLE ADD COLUMN` 在 SQLite 中需要影子表重建，风险高于收益
2. **数据迁移不可逆**：重新嵌入向量、格式转换等操作无法机械性逆转
3. **备份恢复更安全**：SQLite 单文件特性使文件级恢复成为零成本操作

### 8.3 版本号生命周期

```text
应用 v1.0 ──→ schema 0001-0005
应用 v1.1 ──→ schema 0001-0006（新增 task_traces 表）
应用 v1.2 ──→ schema 0001-0007（新增 data_migrations/migration_backups 表）
应用 v2.0 ──→ schema 0004-0010（minimum_supported_version 提升到 0004）
```

当 `minimum_supported_version` 提升后，跳过中间版本直接从旧版本升级到新版本将被拒绝。用户需要先安装中间版本完成增量迁移，或从干净状态开始。

### 9.4 迁移 Dry-Run

提供 dry-run 模式用于在不执行迁移的情况下预览变更：

```rust
impl MigrationRunner {
    /// Dry-run：仅检测并报告待执行的迁移，不实际执行
    pub async fn dry_run(
        &self,
        migrator: &Migrator,
    ) -> anyhow::Result<DryRunReport> {
        let pending_sql = self.detect_pending_sql_migrations(migrator).await?;
        let pending_data = self.data_migrator.list_pending().await?;

        let compat = SCHEMA_COMPAT.check(&self.pool).await;

        Ok(DryRunReport {
            current_version: SCHEMA_COMPAT
                .current_version(&self.pool)
                .await
                .unwrap_or(0),
            target_version: SCHEMA_COMPAT.expected_version,
            pending_sql_migrations: pending_sql,
            pending_data_migrations: pending_data,
            compatibility: compat,
            estimated_backup_size: self.estimate_backup_size().await?,
        })
    }

    async fn estimate_backup_size(&self) -> anyhow::Result<u64> {
        let meta = tokio::fs::metadata(&self.db_path).await?;
        Ok(meta.len())
    }
}

#[derive(Debug)]
pub struct DryRunReport {
    pub current_version: i64,
    pub target_version: i64,
    pub pending_sql_migrations: Vec<PendingMigration>,
    pub pending_data_migrations: Vec<PendingDataMigration>,
    pub compatibility: Result<CompatResult, MigrationError>,
    pub estimated_backup_size: u64,
}
```

开发期间可通过 CLI 子命令调用 dry-run：

```bash

# 目标 schema 版本: 8
# 待执行 SQL 迁移:

#   0008_add_conversation_tags.sql
# 待执行数据迁移:
#   dm_001_reembed_memories_v3small — 将记忆嵌入向量升级到 text-embedding-3-small
```

### 9.5 迁移编写检查清单

新迁移提交前，需确认以下事项：

- [ ] 迁移文件版本号严格递增，无跳号
- [ ] `CREATE TABLE` / `CREATE INDEX` 均使用 `IF NOT EXISTS`
- [ ] `ALTER TABLE ADD COLUMN` 的 `DEFAULT` 值为常量（SQLite 限制）
- [ ] 不依赖 SQLite 3.35.0+ 特性（除非已确认目标平台版本）
- [ ] 包含文件头注释（目的、依赖、作者、日期）
- [ ] 已在内存数据库上通过完整迁移链路测试
- [ ] 已在包含生产数据量级的测试数据库上验证性能
- [ ] 如果影响大表（>100K 行），使用在线迁移方案
- [ ] `compat.rs` 中的 `expected_version` 已更新
