# 异步任务与通知系统设计

> **Harness 边界（2026-08-29）**：Thread 内异步任务使用 submission/event channel 和 active-task cancellation；Agent 间异步消息使用 V2 durable mailbox；Cron 使用独立 ticker/run DB。用户可见通知是 Harness 事件的投影，不是任务完成的事实源。

> 版本：v1.0 | 日期：2026-08-07 | 状态：草稿
> 对应需求：F-15 异步长任务 + 通知系统、F-24 定时任务、M-17 异步任务与通知模块

耗时任务（视频/图像/音乐生成、大文档摄入、进化反思）提交后立即返回，后台执行完成后通过桌面通知 + 应用内消息中心告知用户。

---

## 1. 任务类型全景

| 类型 | 存储表 | 典型耗时 | 触发方式 |
| ---- | ------ | -------- | -------- |
| **媒体生成**（视频/图像/音乐/ASR） | `media_tasks` | 10s – 5min | 用户请求 / Agent 工具调用 |
| **知识库文档摄入** | `task_traces`（progress 字段） | 1s – 60s | 拖拽上传 / Agent `knowledge_ingest` 工具 |
| **Agent 执行**（主循环轮次） | `task_traces` | 实时 | 用户消息 |
| **定时任务**（cron Skill） | `scheduled_tasks` | 取决于 Skill | 系统 Scheduler 触发 |
| **进化反思**（异步） | `task_traces` + `evolution_log` | 5s – 30s | 轮次完成后后台触发 |

## 2. 媒体任务状态机

```text
提交 API
    │
    ▼
[pending] ──────────────────────────────► [cancelled]（用户取消）
    │
    │  Provider 开始处理
    ▼
[processing]
    │ progress_pct: 0 → 100
    │
    ├──► [done]     → 下载文件到本地 → 推送完成通知
    └──► [failed]   → 记录 error → 推送失败通知
```

对应 `media_tasks` 表：

```sql
-- 完整 DDL 见数据库设计/01-Schema设计.md §11
CREATE TABLE IF NOT EXISTS media_tasks (
    task_id      TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    modality     TEXT NOT NULL CHECK(modality IN ('asr','image','video','music','lyrics')),
    status       TEXT NOT NULL DEFAULT 'pending'
                 CHECK(status IN ('pending','processing','done','failed','cancelled')),
    progress_pct INTEGER CHECK(progress_pct BETWEEN 0 AND 100),
    file_paths   TEXT NOT NULL DEFAULT '[]',   -- JSON 数组，本地缓存绝对路径
    error        TEXT,
    provider     TEXT NOT NULL,
    model        TEXT NOT NULL,
    created_at   INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000),
    finished_at  INTEGER
);
```

## 3. 后台轮询器

媒体生成 API（视频/图像）为异步轮询模式，应用启动时在独立 tokio 任务中运行：

```rust
// apps/desktop/src-tauri/src/tasks/media_poller.rs

pub async fn run_media_poller(state: Arc<AppState>, app: AppHandle) {
    let mut interval = tokio::time::interval(Duration::from_secs(3));
    loop {
        interval.tick().await;

        // 查询所有 pending / processing 任务
        let active = MediaTaskRepo::new(&state.db_pool)
            .list_active()
            .await
            .unwrap_or_default();

        for task in active {
            let client = match state.provider_registry.read().await
                .video_client(&task.provider)
            {
                Ok(c) => c,
                Err(_) => continue,
            };

            let result = match client.poll_task(&task.task_id).await {
                Ok(r) => r,
                Err(_) => continue,
            };

            // 更新 DB
            MediaTaskRepo::new(&state.db_pool)
                .update_status(&task.task_id, &result)
                .await
                .ok();

            // 内存缓存更新
            state.media_tasks.write().await
                .insert(task.task_id.clone(), result.status.clone());

            // 推送前端事件
            app.emit("media_task_update", MediaTaskEvent {
                task_id: task.task_id.clone(),
                status: result.status.clone(),
                progress_pct: result.progress_pct,
                file_paths: result.output_paths.clone(),
            }).ok();

            // 任务终态：推送应用内通知 + 桌面通知
            if matches!(result.status, MediaTaskStatus::Done | MediaTaskStatus::Failed) {
                NotificationService::new(&state.db_pool, &app)
                    .emit_task_done(&task, &result)
                    .await
                    .ok();
            }
        }
    }
}
```

`run_media_poller` 在 `tauri::Builder::setup()` 中通过 `tokio::spawn` 启动，持续运行直到应用退出。

## 4. 通知类型与发送策略

### 4.1 通知类型

| 通知类型 | 触发时机 | 应用内 | 桌面系统通知 |
| -------- | -------- | ------ | ------------ |
| `media_done` | 媒体任务完成 | ✅ | ✅（应用最小化时） |
| `media_failed` | 媒体任务失败 | ✅ | ✅（应用最小化时） |
| `ingest_done` | 知识库文档摄入完成 | ✅ | 否 |
| `evolution_proposal` | 进化引擎产生提案待审批 | ✅ | ✅（仅 P1 等级） |
| `budget_alert` | 费用达预算百分比阈值 | ✅ | ✅ |
| `scheduled_task_done` | 定时任务执行完成 | ✅ | ✅ |
| `scheduled_task_failed` | 定时任务失败 | ✅ | ✅ |
| `system` | 更新提醒、权限变更等 | ✅ | 否 |

### 4.2 桌面通知条件

只在以下条件同时满足时发送桌面通知，避免打扰：
1. 应用窗口**未处于前台聚焦**（`app.get_focused_window().is_none()`）
2. 通知类型在上表中标记了"✅"

```rust
// crates/agent-core/src/notification/service.rs

pub struct NotificationService<'a> {
    pool: &'a SqlitePool,
    app: &'a AppHandle,
}

impl<'a> NotificationService<'a> {
    pub async fn emit_task_done(
        &self,
        task: &MediaTask,
        result: &VideoGenStatus,
    ) -> anyhow::Result<()> {
        let title = match result.status {
            MediaTaskStatus::Done   => format!("✅ {} 生成完成", task.modality_display()),
            MediaTaskStatus::Failed => format!("❌ {} 生成失败", task.modality_display()),
            _ => return Ok(()),
        };
        let body = match result.status {
            MediaTaskStatus::Done   => format!("文件已保存到 {}", result.output_paths.first().unwrap_or(&"本地".into())),
            MediaTaskStatus::Failed => result.error.clone().unwrap_or_else(|| "未知错误".into()),
            _ => return Ok(()),
        };

        // 1. 持久化到应用内通知历史
        self.persist(AppNotification {
            kind: "media_task".into(),
            title: title.clone(),
            body: body.clone(),
            action_url: Some(format!("/tasks/{}", task.task_id)),
            read: false,
        }).await?;

        // 2. 推送前端铃铛更新
        self.app.emit("notification_added", UnreadCountPayload {
            count: self.unread_count().await?,
        }).ok();

        // 3. 桌面系统通知（仅非前台时）
        if self.app.get_focused_window().is_none() {
            use tauri_plugin_notification::NotificationExt;
            self.app
                .notification()
                .builder()
                .title(&title)
                .body(&body)
                .show()?;
        }

        Ok(())
    }
}
```

## 5. 定时任务（Scheduler）

### 5.1 数据模型

```sql

CREATE TABLE IF NOT EXISTS scheduled_tasks (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,
    skill_name   TEXT NOT NULL,
    skill_input  TEXT NOT NULL DEFAULT '{}',
    cron_expr    TEXT NOT NULL,           -- 标准 5 段 cron："0 9 * * 1-5"
    is_enabled   INTEGER NOT NULL DEFAULT 1,
    last_run_at  INTEGER,
    next_run_at  INTEGER,
    last_status  TEXT CHECK(last_status IN ('success','failed','running',NULL)),
    last_error   TEXT,
    created_at   INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000)
);
```

### 5.2 Scheduler 实现

```rust
// apps/desktop/src-tauri/src/tasks/scheduler.rs

pub async fn run_scheduler(state: Arc<AppState>, app: AppHandle) {
    let mut interval = tokio::time::interval(Duration::from_secs(60)); // 每分钟检查一次
    loop {
        interval.tick().await;
        let now_ms = now_unix_ms();

        let due = ScheduledTaskRepo::new(&state.db_pool)
            .list_due(now_ms)    // WHERE is_enabled=1 AND next_run_at <= now_ms
            .await
            .unwrap_or_default();

        for task in due {
            // 立即更新 next_run_at，防止重复执行
            let next = compute_next_run(&task.cron_expr, now_ms);
            ScheduledTaskRepo::new(&state.db_pool)
                .mark_running(&task.id, next)
                .await
                .ok();

            let state2 = state.clone();
            let app2   = app.clone();
            let task2  = task.clone();

            tokio::spawn(async move {
                let result = execute_skill(&state2, &task2.workspace_id,
                                           &task2.skill_name, &task2.skill_input).await;
                let (status, error) = match &result {
                    Ok(_)  => ("success", None),
                    Err(e) => ("failed",  Some(e.to_string())),
                };

                ScheduledTaskRepo::new(&state2.db_pool)
                    .mark_done(&task2.id, status, error.as_deref())
                    .await.ok();

                NotificationService::new(&state2.db_pool, &app2)
                    .emit_scheduled_done(&task2, status, error.as_deref())
                    .await.ok();
            });
        }
    }
}

/// 基于 cron_expr 计算下次执行时间（使用 `cron` crate）
fn compute_next_run(expr: &str, now_ms: i64) -> i64 {
    use cron::Schedule;
    use std::str::FromStr;
    let schedule = Schedule::from_str(expr).expect("invalid cron");
    let now = chrono::DateTime::from_timestamp_millis(now_ms).unwrap();
    schedule.after(&now).next()
        .map(|t| t.timestamp_millis())
        .unwrap_or(i64::MAX)
}
```

### 5.3 自然语言 cron 辅助

前端提供自然语言 → cron 表达式转换（本地映射，不调 LLM）：

| 自然语言 | cron 表达式 |
| -------- | ----------- |
| "每天早上 9 点" | `0 9 * * *` |
| "每周一到周五早上 9 点" | `0 9 * * 1-5` |
| "每隔 30 分钟" | `*/30 * * * *` |
| "每月 1 日午夜" | `0 0 1 * *` |

## 8. 任务取消实现

```rust
// apps/desktop/src-tauri/src/commands/tasks.rs

#[tauri::command]
pub async fn cancel_media_task(
    task_id: String,
    state: State<'_, AppState>,
) -> Result<(), String> {
    // 1. 更新 DB 状态
    MediaTaskRepo::new(&state.db_pool)
        .update_status_to_cancelled(&task_id)
        .await
        .map_err(|e| e.to_string())?;

    // 2. 内存缓存同步
    state.media_tasks.write().await
        .insert(task_id.clone(), MediaTaskStatus::Cancelled);

    // 3. 部分 Provider 支持远程取消（最佳努力，失败不阻塞 UI）
    if let Ok(client) = state.provider_registry.read().await
        .find_task_client(&task_id)
    {
        let _ = client.cancel_task(&task_id).await;
    }

    Ok(())
}
```

## 9. 设计约束

- **轮询间隔分层**：媒体任务 3s 轮询，定时任务 60s 检查，不同频率避免 Provider 限流
- **任务不跨工作区**：`media_tasks` 和 `scheduled_tasks` 均包含 `workspace_id`，前端查询必须携带
- **桌面通知频率保护**：同一任务的通知只发一次（终态才通知），中间进度更新只更新应用内 UI
- **Scheduler 幂等性**：`mark_running` 同时更新 `next_run_at`，防止同一 cron 在 60s 窗口内重复触发
- **应用内通知不落专表**：复用 `audit_logs` 中 `action='notification'` 行，不新增表，保持 Schema 精简
