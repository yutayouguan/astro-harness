# 错误处理详细设计

> **Harness 当前基线（2026-09-02）**：错误必须保留产生域和可恢复性：Provider 错误决定 fallback，tool 错误作为 observation 回灌，policy denial 终止当次 attempt，persistence 错误不能在未落盘时伪造 live 成功，cancellation 必须传播到活跃工具和子进程。

> 版本：v1.0 | 日期：2026-08-09 | 状态：草稿
> 对应需求：F-14 错误处理与容错（通用部分）
> 前置文档：[03-错误处理与容错.md](../../03-系统设计阶段/03-基础设施/03-错误处理与容错.md)（错误分类体系概述）

本文档是 F-14 错误处理与容错的**通用框架部分**，定义跨 crate 的统一错误类型层次、传播链、恢复策略、用户友好消息体系、前端展示规范、错误上报聚合、优雅降级以及 Panic 防护。Provider 相关的故障转移（熔断器、流式中断恢复、Rate Limit 专项处理等）已在 [03-Provider故障转移设计.md](../02-Provider与模型层/03-Provider故障转移设计.md) 中完整覆盖，本文不再重复。

## 1. 错误体系概述

### 1.1 设计目标

Astro Agent 的错误来源跨越 LLM 调用、工具执行、子 Agent 编排、MCP 协议、数据库操作、前端通信等多个维度。错误处理框架需要达到以下目标：

- **层次分明**：每个 crate 定义自己的领域错误枚举，通过 `From` 转换在传播链中逐层包装
- **分类可恢复**：每个错误携带 `ErrorCategory`，驱动自动恢复（重试 / 降级 / 终止）
- **用户可理解**：内部错误到用户消息的映射有独立的 `ErrorPresenter`，支持中英文和可操作建议
- **可追溯**：通过 `anyhow::Context` 在每层附加上下文，结构化日志记录完整错误链
- **不泄露**：堆栈跟踪、内部路径、密钥片段永远不暴露给前端

### 1.2 错误域划分

```text
┌─────────────────────────────────────────────────────────────────┐
│                     AppError（Tauri 层）                         │
│         统一序列化后传递给前端，按 kind 分支处理                    │
├─────────────────────────────────────────────────────────────────┤
│  CoreError       │  RuntimeError    │  ProviderError  │ ToolError│
│  (agent-core)    │  (agent-runtime) │  (agent-provs)  │ (tools)  │
│  会话/消息/记忆   │  会话/执行/超时   │  LLM调用/限流    │ 执行/权限 │
│  存储/上下文      │  调度/子Agent     │  熔断/流中断     │ 验证/超时 │
├─────────────────────────────────────────────────────────────────┤
│                   底层库错误（sqlx, reqwest, serde, ...）         │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 与 Provider 故障转移文档的关系

| 关注点 | 本文档 | 03-Provider故障转移设计 |
| --- | --- | --- |
| 错误类型层次 | CoreError / RuntimeError / ToolError / AppError 完整定义 | ProviderError 完整定义 |
| 重试策略 | 非 Provider 子系统的领域策略 | typed `ProviderError` 驱动的 request/stream retry 与网络恢复 |
| 用户消息映射 | `ErrorPresenter` 全量映射表 | 仅 Provider 切换通知 |
| 降级策略 | 各子系统降级（内存/工具/嵌入等） | 用户显式 Provider fallback；连接失败不降级 |
| 错误上报 | `error_events` 表 + 频率追踪 | `audit_logs` 中 failover 事件 |

## 2. 统一错误类型层次

### 2.1 CoreError（agent-core）

核心引擎层的领域错误，覆盖会话、消息、记忆、存储、上下文管理等。

```rust
// crates/agent-core/src/error.rs

use thiserror::Error;

#[derive(Debug, Error)]
pub enum CoreError {
    // ── 会话与消息 ──────────────────────────────
    #[error("会话 `{conversation_id}` 不存在")]
    ConversationNotFound { conversation_id: String },

    #[error("会话 `{conversation_id}` 已归档，无法继续")]
    ConversationArchived { conversation_id: String },

    #[error("消息 `{message_id}` 不存在")]
    MessageNotFound { message_id: String },

    #[error("消息格式无效: {reason}")]
    InvalidMessage { reason: String },

    // ── 上下文管理 ──────────────────────────────
    #[error("上下文溢出: 当前 {current} tokens，最大 {max} tokens")]
    ContextOverflow { current: usize, max: usize },

    #[error("上下文构建失败: {0}")]
    ContextBuildError(String),

    // ── 记忆系统 ────────────────────────────────
    #[error("记忆检索失败: {0}")]
    MemoryRetrievalError(String),

    #[error("记忆写入失败: {0}")]
    MemoryWriteError(String),

    #[error("嵌入向量计算失败: {0}")]
    EmbeddingError(String),

    // ── 存储层 ──────────────────────────────────
    #[error("数据库操作失败: {0}")]
    Database(#[from] sqlx::Error),

    #[error("序列化/反序列化失败: {0}")]
    Serialization(#[from] serde_json::Error),

    #[error("文件 I/O 错误: {path} - {source}")]
    FileIo {
        path: String,
        #[source]
        source: std::io::Error,
    },

    // ── 预算 ────────────────────────────────────
    #[error("预算超支: 已使用 ${used:.4}，预算 ${budget:.4}")]
    BudgetExceeded { used: f64, budget: f64 },

    // ── 权限 ────────────────────────────────────
    #[error("权限不足: 操作 `{action}` 需要 `{required}` 权限")]
    PermissionDenied { action: String, required: String },

    // ── 用户输入 ────────────────────────────────
    #[error("用户输入无效: {0}")]
    InvalidInput(String),

    // ── 兜底 ────────────────────────────────────
    #[error(transparent)]
    Internal(#[from] anyhow::Error),
}

pub type CoreResult<T> = Result<T, CoreError>;
```

### 2.2 RuntimeError（agent-runtime）

执行编排层的领域错误，覆盖会话管理、执行控制、子 Agent、规划、审批等。

```rust
// crates/agent-runtime/src/error.rs

use thiserror::Error;
use crate::core::CoreError;

#[derive(Debug, Error)]
pub enum RuntimeError {
    // ── 会话管理 ────────────────────────────────
    #[error("会话 `{conversation_id}` 未找到")]
    SessionNotFound { conversation_id: String },

    #[error("并发会话数超限: 当前 {current}，上限 {max}")]
    SessionLimitExceeded { current: usize, max: usize },

    // ── 执行控制 ────────────────────────────────
    #[error("工具调用轮次超限: 已达 {reached} 轮，上限 {max} 轮")]
    ToolRoundsExceeded { max: usize, reached: usize },

    #[error("执行超时: {operation} 超过 {timeout_secs}s")]
    ExecutionTimeout { operation: String, timeout_secs: u64 },

    #[error("Agent 已取消")]
    Cancelled,

    // ── 子 Agent ────────────────────────────────
    #[error("子 Agent `{agent_id}` 崩溃: {message}")]
    SubAgentCrash { agent_id: String, message: String },

    #[error("子 Agent 深度超限: 当前 {current}，最大 {max}")]
    DepthExceeded { current: u32, max: u32 },

    // ── 规划与审批 ────────────────────────────────
    #[error("用户拒绝执行计划")]
    PlanRejected,

    #[error("审批请求超时: request_id={request_id}")]
    ApprovalTimeout { request_id: String },

    #[error("用户拒绝工具调用: {tool_name}")]
    ToolRejected { tool_name: String },

    // ── 向下包装 ────────────────────────────────
    #[error(transparent)]
    Core(#[from] CoreError),

    #[error(transparent)]
    Provider(#[from] agent_providers::ProviderError),

    #[error(transparent)]
    Tool(#[from] ToolError),

    #[error(transparent)]
    Internal(#[from] anyhow::Error),
}

pub type RuntimeResult<T> = Result<T, RuntimeError>;
```

### 2.3 ToolError（工具系统）

工具执行层的领域错误，覆盖执行失败、权限拒绝、参数验证、沙箱隔离等。

```rust
// crates/agent-core/src/tools/error.rs

use thiserror::Error;

#[derive(Debug, Error)]
pub enum ToolError {
    #[error("工具 `{tool_name}` 不存在")]
    NotFound { tool_name: String },

    #[error("工具 `{tool_name}` 执行失败: {message}")]
    ExecutionFailed {
        tool_name: String,
        message: String,
        retriable: bool,
    },

    #[error("工具 `{tool_name}` 执行超时（超过 {timeout_secs}s）")]
    Timeout { tool_name: String, timeout_secs: u64 },

    #[error("工具 `{tool_name}` 参数验证失败: {reason}")]
    ValidationFailed { tool_name: String, reason: String },

    #[error("工具 `{tool_name}` 权限不足: 需要风险等级 {required_level}")]
    PermissionDenied {
        tool_name: String,
        required_level: String,
    },

    #[error("WASM 沙箱执行失败: {0}")]
    SandboxError(String),

    #[error("Shell 命令执行失败: exit_code={exit_code}, stderr={stderr}")]
    ShellError { exit_code: i32, stderr: String },

    #[error("MCP 工具调用失败: server={server}, tool={tool} - {message}")]
    McpToolError {
        server: String,
        tool: String,
        message: String,
    },
}

impl ToolError {
    pub fn is_retriable(&self) -> bool {
        match self {
            Self::Timeout { .. } => true,
            Self::ExecutionFailed { retriable, .. } => *retriable,
            Self::McpToolError { .. } => true,
            _ => false,
        }
    }
}
```

### 2.5 AppError（Tauri 层）

顶层错误枚举，将所有下层错误统一序列化后传递给前端。前端按 `kind` 字段分支处理。

```rust
// apps/desktop/src-tauri/src/error.rs

use serde::Serialize;

/// 传递给前端的统一错误类型
/// serde(tag = "kind") 保证前端 JSON 结构为 { kind: "...", message: "...", ... }
#[derive(Debug, Serialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum AppError {
    /// 数据库操作失败
    Db { message: String, code: Option<String> },
    /// Provider / LLM 调用失败
    Provider { message: String, code: Option<String>, retriable: bool },
    /// 工具执行失败
    Tool { message: String, tool_name: Option<String>, retriable: bool },
    /// 参数验证失败
    Validation { message: String, field: Option<String> },
    /// 资源不存在
    NotFound { message: String, resource: String },
    /// 权限不足
    PermissionDenied { message: String, action: String },
    /// 预算超支
    BudgetExceeded { message: String, used: f64, budget: f64 },
    /// 上下文溢出
    ContextOverflow { message: String, current: usize, max: usize },
    /// 网络错误（通用）
    Network { message: String, retriable: bool },
    /// 会话管理错误
    Session { message: String },
    /// 内部错误（兜底）
    Internal { message: String, code: Option<String> },
}

// 各层错误到 AppError 的 From 实现
impl From<CoreError> for AppError {
    fn from(e: CoreError) -> Self {
        let presenter = ErrorPresenter::default();
        presenter.to_app_error(&e)
    }
}

impl From<RuntimeError> for AppError {
    fn from(e: RuntimeError) -> Self {
        match e {
            RuntimeError::Core(ce) => ce.into(),
            RuntimeError::Provider(pe) => AppError::Provider {
                message: ErrorPresenter::default().provider_message(&pe),
                code: Some(ErrorPresenter::default().error_code(&pe)),
                retriable: pe.retryability() != Retryability::Fatal,
            },
            RuntimeError::Tool(te) => te.into(),
            RuntimeError::SessionNotFound { conversation_id } => AppError::Session {
                message: format!("会话 {} 不存在或已过期", conversation_id),
            },
            other => AppError::Internal {
                message: ErrorPresenter::default().generic_message(&other),
                code: Some(ErrorPresenter::default().error_code(&other)),
            },
        }
    }
}
```

### 2.6 类型层次关系图

```text
sqlx::Error ──┐
io::Error ────┤
serde::Error ─┤
              ▼
         CoreError ──────────┐
                             │
ProviderError ───────────────┤
                             ▼
ToolError ──────────→ RuntimeError ──────→ AppError ──→ 前端 JSON
```

## 3. 错误传播链

### 3.1 传播路径

一个典型的工具执行错误从底层传播到前端的完整路径：

```text
std::io::Error（文件读取失败）
    │
    │  ToolError::ExecutionFailed { tool_name: "file_read", message: "..." }
    ▼
ToolExecutor::execute()
    │  .with_context(|| "执行工具 file_read 时失败")
    ▼
AgentExecutor::round_loop()
    │  RuntimeError::Tool(tool_error)
    │  .with_context(|| format!("会话 {} 第 {} 轮工具执行失败", conv_id, round))
    ▼
Tauri Command (send_message)
    │  AppError::from(runtime_error)
    ▼
前端 JSON: { kind: "tool", message: "文件读取失败，请检查文件路径", tool_name: "file_read" }
```

### 3.2 上下文附加规范

每个层级在传播错误时**必须**附加本层的上下文信息，形成可追溯的错误链：

```rust
use anyhow::Context;

// 底层：存储操作
async fn load_conversation(pool: &SqlitePool, id: &str) -> CoreResult<Conversation> {
    sqlx::query_as!(Conversation, "SELECT * FROM conversations WHERE id = ?", id)
        .fetch_optional(pool)
        .await
        .context(format!("查询会话失败: id={}", id))?  // 附加 SQL 层上下文
        .ok_or(CoreError::ConversationNotFound {
            conversation_id: id.to_string(),
        })
}

// 中层：执行编排
async fn resume_session(
    session_mgr: &SessionManager,
    conv_id: &str,
) -> RuntimeResult<()> {
    let conv = load_conversation(&session_mgr.pool, conv_id)
        .await
        .context(format!("恢复会话失败: conv_id={}", conv_id))?;  // 附加业务层上下文

    if conv.status == "archived" {
        return Err(RuntimeError::Core(CoreError::ConversationArchived {
            conversation_id: conv_id.to_string(),
        }));
    }
    Ok(())
}

// 顶层：Tauri Command
#[tauri::command]
pub async fn continue_conversation(
    state: State<'_, AppState>,
    conversation_id: String,
) -> Result<(), AppError> {
    resume_session(&state.session_manager, &conversation_id)
        .await
        .map_err(AppError::from)  // 自动转换，不暴露内部细节
}
```

### 3.3 上下文附加原则

| 原则 | 说明 |
| --- | --- |
| **每层加一次** | 同一函数不要嵌套多层 `.context()`，一层加一次即可 |
| **包含定位信息** | context 字符串中必须包含能定位问题的 ID（conversation_id、tool_name、message_id 等） |
| **不包含敏感信息** | 禁止在 context 中放入 API Key、用户密码等敏感数据 |
| **用中文描述** | 上下文描述用中文，与日志保持一致；底层库错误保持英文原文 |

### 3.4 错误链日志输出

使用 `tracing` 记录完整错误链，包含所有 context 信息：

```rust
use tracing::error;

fn log_error_chain(err: &dyn std::error::Error) {
    let mut chain = vec![err.to_string()];
    let mut source = err.source();
    while let Some(s) = source {
        chain.push(s.to_string());
        source = s.source();
    }
    error!(
        error_chain = ?chain,
        "错误链: {}",
        chain.join(" → ")
    );
}

// 输出示例：
// 错误链: 恢复会话失败: conv_id=abc123 → 查询会话失败: id=abc123 → no rows returned
```

## 4. 错误分类与恢复策略

### 4.1 ErrorCategory 枚举

每个错误都归属一个 `ErrorCategory`，驱动系统的自动恢复行为：

```rust
// crates/agent-core/src/error/category.rs

/// 错误分类：决定系统的自动恢复行为
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize)]
pub enum ErrorCategory {
    /// 可自动重试（网络抖动、临时 503 等）
    Retryable,
    /// 用户可修复（API Key 错误、权限不足等）
    UserFixable,
    /// 系统致命错误（数据库损坏、配置缺失等）
    SystemFatal,
    /// 瞬时错误（可忽略并继续，如单次记忆检索失败）
    Transient,
}
```

### 4.2 各错误类型的分类映射

```rust
impl CoreError {
    pub fn category(&self) -> ErrorCategory {
        match self {
            // 可重试
            Self::Database(e) if is_transient_db_error(e) => ErrorCategory::Retryable,
            Self::EmbeddingError(_) => ErrorCategory::Retryable,
            Self::MemoryRetrievalError(_) => ErrorCategory::Transient,

            // 用户可修复
            Self::InvalidInput(_) => ErrorCategory::UserFixable,
            Self::PermissionDenied { .. } => ErrorCategory::UserFixable,
            Self::BudgetExceeded { .. } => ErrorCategory::UserFixable,
            Self::ContextOverflow { .. } => ErrorCategory::UserFixable,
            Self::ConversationNotFound { .. } => ErrorCategory::UserFixable,

            // 系统致命
            Self::Database(_) => ErrorCategory::SystemFatal,
            Self::FileIo { .. } => ErrorCategory::SystemFatal,

            // 瞬时
            Self::MemoryWriteError(_) => ErrorCategory::Transient,
            Self::ContextBuildError(_) => ErrorCategory::Retryable,

            // 其他
            _ => ErrorCategory::SystemFatal,
        }
    }
}

impl RuntimeError {
    pub fn category(&self) -> ErrorCategory {
        match self {
            Self::SubAgentCrash { .. } => ErrorCategory::Retryable,
            Self::ExecutionTimeout { .. } => ErrorCategory::Retryable,

            Self::SessionLimitExceeded { .. } => ErrorCategory::UserFixable,
            Self::ToolRejected { .. } => ErrorCategory::UserFixable,
            Self::PlanRejected => ErrorCategory::UserFixable,
            Self::Cancelled => ErrorCategory::UserFixable,
            Self::ApprovalTimeout { .. } => ErrorCategory::UserFixable,

            Self::DepthExceeded { .. } => ErrorCategory::SystemFatal,
            Self::ToolRoundsExceeded { .. } => ErrorCategory::SystemFatal,

            Self::Core(ce) => ce.category(),
            Self::Provider(pe) => match pe.retryability() {
                Retryability::Fatal => ErrorCategory::UserFixable,
                Retryability::ImmediateRetry | Retryability::BackoffRetry
                    | Retryability::StreamResume => ErrorCategory::Retryable,
                Retryability::SwitchProvider => ErrorCategory::Retryable,
            },
            Self::Tool(te) => if te.is_retriable() {
                ErrorCategory::Retryable
            } else {
                ErrorCategory::UserFixable
            },
            _ => ErrorCategory::SystemFatal,
        }
    }
}

/// 判断 SQLite 错误是否是瞬时的（如 SQLITE_BUSY）
fn is_transient_db_error(e: &sqlx::Error) -> bool {
    match e {
        sqlx::Error::Database(db_err) => {
            db_err.code().map_or(false, |c| c.as_ref() == "5")  // SQLITE_BUSY
        }
        sqlx::Error::PoolTimedOut => true,
        _ => false,
    }
}
```

### 4.3 恢复动作映射

```rust
// crates/agent-runtime/src/error/recovery.rs

pub enum RecoveryAction {
    /// 使用指数退避重试
    Retry { max_attempts: u32, initial_delay_ms: u64 },
    /// 通知用户修复后重试
    NotifyUserAndWait { user_message: String, actionable_hint: String },
    /// 跳过当前操作继续执行
    SkipAndContinue { fallback_value: Option<serde_json::Value> },
    /// 记录日志后终止
    LogAndTerminate,
    /// 静默忽略
    SilentIgnore,
}

pub fn recovery_action(category: ErrorCategory, error: &dyn std::error::Error) -> RecoveryAction {
    match category {
        ErrorCategory::Retryable => RecoveryAction::Retry {
            max_attempts: 3,
            initial_delay_ms: 1000,
        },
        ErrorCategory::UserFixable => RecoveryAction::NotifyUserAndWait {
            user_message: error.to_string(),
            actionable_hint: "请检查相关配置后重试".to_string(),
        },
        ErrorCategory::SystemFatal => RecoveryAction::LogAndTerminate,
        ErrorCategory::Transient => RecoveryAction::SkipAndContinue {
            fallback_value: None,
        },
    }
}
```

### 4.4 恢复执行器

在 `AgentExecutor` 的主循环中，恢复动作由统一的执行器驱动：

```rust
// crates/agent-runtime/src/error/recovery.rs

pub async fn execute_recovery(
    action: RecoveryAction,
    emitter: &dyn EventEmitter,
    conv_id: &str,
) -> RecoveryOutcome {
    match action {
        RecoveryAction::Retry { max_attempts, initial_delay_ms } => {
            emitter.emit("retry_notice", json!({
                "conversation_id": conv_id,
                "max_attempts": max_attempts,
            })).await.ok();
            RecoveryOutcome::ShouldRetry { max_attempts, initial_delay_ms }
        }
        RecoveryAction::NotifyUserAndWait { user_message, actionable_hint } => {
            emitter.emit("error_user_fixable", json!({
                "conversation_id": conv_id,
                "message": user_message,
                "hint": actionable_hint,
            })).await.ok();
            RecoveryOutcome::WaitForUser
        }
        RecoveryAction::SkipAndContinue { fallback_value } => {
            tracing::warn!(conv_id, "瞬时错误，跳过并继续");
            RecoveryOutcome::Continue(fallback_value)
        }
        RecoveryAction::LogAndTerminate => {
            tracing::error!(conv_id, "系统致命错误，终止执行");
            RecoveryOutcome::Terminate
        }
        RecoveryAction::SilentIgnore => RecoveryOutcome::Continue(None),
    }
}

pub enum RecoveryOutcome {
    ShouldRetry { max_attempts: u32, initial_delay_ms: u64 },
    WaitForUser,
    Continue(Option<serde_json::Value>),
    Terminate,
}
```

## 6. 前端错误展示

### 6.1 展示策略分层

不同 `ErrorCategory` 使用不同的前端展示组件：

| ErrorCategory | 展示方式 | 组件 | 持续时间 | 用户操作 |
| --- | --- | --- | --- | --- |
| `Retryable` | Toast 通知 | `ErrorToast` | 5s 自动消失 | 点击"重试" |
| `UserFixable` | 内联 Banner | `ErrorBanner` | 用户手动关闭 | 提供修复链接 |
| `SystemFatal` | 模态对话框 | `ErrorDialog` | 需手动确认 | 重启 / 反馈 |
| `Transient` | 微型提示 | `MiniToast` | 3s 自动消失 | 无 |

`StreamError` 不属于上表的终态错误分类。前台连接失败时，Server 将它投影为
`ErrorNotification { will_retry: true }`，只更新当前 Turn 的单条“正在重新连接”状态，
不展示 `ErrorToast`、不结束 Turn、不进入助手回答正文。

```tsx
  fallback?: ReactNode;

  hasError: boolean;
  error: Error | null;

export class ErrorBoundary extends Component<Props, State> {

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    // 上报到本地错误日志
    console.error('[ErrorBoundary]', error, info.componentStack);
    // 通过 Tauri invoke 写入 error_events 表
    import('@tauri-apps/api/core').then(({ invoke }) => {
      invoke('log_frontend_error', {
        error: error.message,
        stack: info.componentStack ?? '',
        component: 'ErrorBoundary',
      }).catch(() => {});
    });
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? (
        <div className="flex h-full items-center justify-center p-8">
          <div className="text-center space-y-4">
            <h2 className="text-lg font-medium">界面渲染异常</h2>

            </p>

              onClick={() => {
                this.setState({ hasError: false, error: null });
                window.location.reload();
              }}
              className="px-4 py-2 text-sm bg-primary text-primary-foreground rounded-md"
            >
              刷新页面
            </button>
          </div>
        </div>
```

### 7.3 频率追踪与周期性错误检测

系统定期扫描 `error_events` 表，发现高频重复错误时主动通知用户：

```rust
// crates/agent-runtime/src/error/frequency_tracker.rs

pub struct ErrorFrequencyTracker {
    pool: SqlitePool,
    emitter: Arc<dyn EventEmitter>,
    /// 检测窗口（默认 5 分钟）
    window_ms: i64,
    /// 触发通知阈值（同一 error_code 在窗口内出现次数）
    threshold: u32,
}

impl ErrorFrequencyTracker {
    /// 每 60 秒运行一次，检测周期性错误
    pub async fn run(self: Arc<Self>) {
        let mut interval = tokio::time::interval(Duration::from_secs(60));
        loop {
            interval.tick().await;
            if let Err(e) = self.check_recurring_errors().await {
                tracing::warn!("周期性错误检测失败: {}", e);
            }
        }
    }

    async fn check_recurring_errors(&self) -> anyhow::Result<()> {
        let cutoff = now_ms() - self.window_ms;
        let recurring = sqlx::query!(
            r#"SELECT error_code, COUNT(*) as count, MAX(message) as last_message
               FROM error_events
               WHERE created_at > ? AND resolved = 0
               GROUP BY error_code
               HAVING COUNT(*) >= ?"#,
            cutoff,
            self.threshold,
        )
        .fetch_all(&self.pool)
        .await?;

        for row in recurring {
            self.emitter.emit("recurring_error_detected", json!({
                "error_code": row.error_code,
                "count": row.count,
                "window_minutes": self.window_ms / 60_000,
                "last_message": row.last_message,
            })).await.ok();

            tracing::warn!(
                error_code = row.error_code,
                count = row.count,
                "检测到周期性错误（{} 分钟内出现 {} 次）",
                self.window_ms / 60_000,
                row.count,
            );
        }
        Ok(())
    }
}
```

```rust
        .ok();
}
```

## 8. 优雅降级策略

当子系统失败时，系统不应整体崩溃，而是降级到受限功能继续运行。每个子系统有明确的降级行为：

### 8.1 降级规则表

| 子系统 | 失败场景 | 降级行为 | 对用户的影响 |
| --- | --- | --- | --- |
| 记忆检索 | 向量搜索失败 / 嵌入服务不可用 | 跳过记忆注入，仅使用当前对话上下文 | 回复可能缺少历史背景 |
| 嵌入计算 | Embedding Provider 失败 | 将记忆条目标记为 `pending_embed`，后续补算 | 新记忆暂不可被语义搜索 |
| 工具执行 | 工具超时 / 沙箱崩溃 | 将错误信息作为 ToolResult 回填给 LLM | LLM 自行决定是否重试或换方案 |
| MCP Server | MCP 连接断开 | 从可用工具列表中移除该 Server 的工具 | 部分工具暂时不可用 |
| USER.md | 用户画像文件损坏 | 使用空白画像继续运行 | 个性化能力暂时丧失 |
| 蒸馏 | 蒸馏 LLM 调用失败 | 跳过本次蒸馏，保留原始消息 | 记忆积累延迟，不影响当前对话 |
| TTS | 语音合成失败 | 仅返回文本，不发送音频 chunk | 用户需阅读文本 |
| 进化引擎 | 反思分析失败 | 跳过本轮进化，写入 evolution_log 标记失败 | 自我改进暂停一轮 |

### 8.2 降级实现模式

```rust
// crates/agent-runtime/src/degradation.rs

use tracing::warn;

/// 记忆检索降级：失败时返回空结果，不中断主流程
pub async fn retrieve_memories_with_fallback(
    memory_repo: &MemoryRepo,
    query: &str,
    workspace_id: &str,
    reporter: &ErrorReporter,
) -> Vec<MemoryEntry> {
    match memory_repo.semantic_search(query, workspace_id, 10).await {
        Ok(entries) => entries,
        Err(e) => {
            warn!("记忆检索降级: {}", e);
            reporter.report(&CoreError::MemoryRetrievalError(e.to_string()), ErrorContext {
                source_crate: "agent-core".into(),
                workspace_id: Some(workspace_id.into()),
                extra: json!({ "query_preview": &query[..query.len().min(100)] }),
            }).await;
            vec![]  // 返回空结果，继续执行
        }
    }
}

/// 嵌入计算降级：失败时标记为待补算
pub async fn compute_embedding_with_fallback(
    embedding_client: &dyn EmbeddingClient,
    text: &str,
    entry_id: &str,
    pool: &SqlitePool,
) -> Option<Vec<f32>> {
    match embedding_client.embed(text).await {
        Ok(vec) => Some(vec),
        Err(e) => {
            warn!("嵌入计算降级，标记 pending: entry_id={}, error={}", entry_id, e);
            // 标记为待补算，后台定时任务会重试
            sqlx::query!(
                "UPDATE memory_entries SET embed_status = 'pending' WHERE id = ?",
                entry_id,
            )
            .execute(pool)
            .await
            .ok();
            None
        }
    }
}

/// 工具执行降级：将错误作为 ToolResult 回填给 LLM
pub fn tool_error_as_result(tool_call_id: &str, error: &ToolError) -> ToolResult {
    ToolResult {
        call_id: tool_call_id.to_string(),
        is_error: true,
        output: vec![ToolContent::Text(format!(
            "工具执行失败: {}。请考虑使用其他方法完成任务，或告知用户需要手动处理。",
            error
        ))],
    }
}

/// MCP Server 断连降级：从工具列表中移除
pub async fn handle_mcp_disconnect(
    mcp_manager: &McpClientManager,
    server_name: &str,
    tool_registry: &RwLock<ToolRegistry>,
    emitter: &dyn EventEmitter,
) {
    warn!("MCP Server `{}` 断开连接，移除关联工具", server_name);

    // 从工具注册表中移除该 Server 的工具
    let removed_tools = tool_registry.write().await
        .remove_by_source(&format!("mcp:{}", server_name));

    // 通知前端
    emitter.emit("mcp_server_disconnected", json!({
        "server": server_name,
        "removed_tools": removed_tools,
    })).await.ok();

    // 后台尝试重连（3 次，指数退避）
    tokio::spawn({
        let mgr = mcp_manager.clone();
        let name = server_name.to_string();
        async move {
            for attempt in 1..=3 {
                tokio::time::sleep(Duration::from_secs(2u64.pow(attempt))).await;
                if mgr.reconnect(&name).await.is_ok() {
                    tracing::info!("MCP Server `{}` 重连成功", name);
                    return;
                }
            }
            tracing::error!("MCP Server `{}` 重连失败，放弃", name);
        }
    });
}
```

## 9. Panic 防护

### 9.1 设计原则

Rust 中 panic 默认导致当前线程终止。在 Astro Agent 中，以下边界**必须**使用 `catch_unwind` 或 tokio 的 panic 捕获机制防止 panic 传播：

| 边界 | 防护方式 | 原因 |
| --- | --- | --- |
| 工具执行 | `std::panic::catch_unwind` | 第三方工具代码不可控 |
| WASM 沙箱 | `wasmtime` 内部 trap 机制 | 插件隔离执行 |
| 子 Agent 任务 | `tokio::spawn` JoinHandle panic 捕获 | 子任务不应影响父 Agent |
| 后台定时任务 | `tokio::spawn` + JoinHandle 监控 | 后台任务 panic 不应崩溃主进程 |
| Rhai 脚本执行 | `rhai::Engine` 内部错误处理 | 动态脚本不可控 |

### 9.2 工具执行 Panic 防护

```rust
// crates/agent-runtime/src/sandbox/panic_guard.rs

use std::panic::{catch_unwind, AssertUnwindSafe};

/// 在 catch_unwind 边界内执行工具，捕获任何 panic
pub async fn execute_with_panic_guard(
    tool: &dyn Tool,
    input: ToolInput,
) -> Result<ToolOutput, ToolError> {
    // 对于同步工具（如 Rhai 脚本），使用 catch_unwind
    if tool.is_sync() {
        let tool_name = tool.name().to_string();
        let result = tokio::task::spawn_blocking(move || {
            catch_unwind(AssertUnwindSafe(|| {
                // 同步工具在 blocking 线程中执行
                tool.execute_sync(input)
            }))
        })
        .await
        .map_err(|join_err| ToolError::ExecutionFailed {
            tool_name: tool_name.clone(),
            message: format!("工具线程异常: {}", join_err),
            retriable: false,
        })?;

        match result {
            Ok(Ok(output)) => Ok(output),
            Ok(Err(e)) => Err(e),
            Err(panic_info) => {
                let msg = panic_payload_to_string(&panic_info);
                tracing::error!(tool_name, "工具执行 panic: {}", msg);
                Err(ToolError::ExecutionFailed {
                    tool_name,
                    message: format!("工具内部崩溃: {}", msg),
                    retriable: false,
                })
            }
        }
    } else {
        // 异步工具：通过 tokio::spawn 隔离
        let tool_name = tool.name().to_string();
        let handle = tokio::spawn(async move {
            tool.execute(input).await
        });

        match handle.await {
            Ok(Ok(output)) => Ok(output),
            Ok(Err(e)) => Err(e),
            Err(join_err) => {
                tracing::error!(tool_name, "异步工具 panic: {}", join_err);
                Err(ToolError::ExecutionFailed {
                    tool_name,
                    message: format!("工具异步执行崩溃: {}", join_err),
                    retriable: false,
                })
            }
        }
    }
}

fn panic_payload_to_string(payload: &Box<dyn std::any::Any + Send>) -> String {
    if let Some(s) = payload.downcast_ref::<&str>() {
        s.to_string()
    } else if let Some(s) = payload.downcast_ref::<String>() {
        s.clone()
    } else {
        "未知 panic 信息".to_string()
    }
}
```

### 9.3 后台任务隔离与自动重启

后台任务（MediaPoller、MemoryDistiller、ForgetScheduler、ErrorFrequencyTracker）的 panic 不应影响主进程。使用监控器自动重启：

```rust
// crates/agent-runtime/src/background/supervisor.rs

pub struct BackgroundTaskSupervisor {
    tasks: Vec<BackgroundTask>,
}

struct BackgroundTask {
    name: String,
    factory: Box<dyn Fn() -> BoxFuture<'static, ()> + Send + Sync>,
    max_restarts: u32,
    restart_count: u32,
}

impl BackgroundTaskSupervisor {
    pub fn spawn_all(&mut self) {
        for task in &mut self.tasks {
            let name = task.name.clone();
            let future = (task.factory)();

            let handle = tokio::spawn(async move {
                future.await;
            });

            // 监控任务，panic 时自动重启
            let name_clone = name.clone();
            let max_restarts = task.max_restarts;
            tokio::spawn(async move {
                match handle.await {
                    Ok(()) => {
                        tracing::info!("后台任务 `{}` 正常退出", name_clone);
                    }
                    Err(join_err) if join_err.is_panic() => {
                        tracing::error!(
                            "后台任务 `{}` panic，准备重启: {}",
                            name_clone, join_err
                        );
                        // 重启逻辑（通过 channel 通知 supervisor）
                    }
                    Err(join_err) => {
                        tracing::error!("后台任务 `{}` 异常: {}", name_clone, join_err);
                    }
                }
            });
        }
    }
}
```

### 9.4 优雅关闭

当接收到关闭信号（Ctrl+C、窗口关闭）或检测到不可恢复的致命错误时，执行有序关闭：

```rust
// apps/desktop/src-tauri/src/shutdown.rs

pub async fn graceful_shutdown(
    state: &AppState,
    reason: ShutdownReason,
) {
    tracing::info!(?reason, "开始优雅关闭");

    // 1. 停止接收新请求
    state.accepting_requests.store(false, Ordering::SeqCst);

    // 2. 取消所有活跃会话（发送 CancellationToken）
    let sessions = state.session_manager.active_sessions().await;
    for (conv_id, _) in &sessions {
        state.session_manager.cancel(conv_id).await;
    }

    // 3. 等待正在执行的工具完成（最多 5 秒）
    let deadline = tokio::time::sleep(Duration::from_secs(5));
    tokio::select! {
        _ = state.session_manager.wait_all_idle() => {
            tracing::info!("所有会话已安全退出");
        }
        _ = deadline => {
            tracing::warn!("等待会话退出超时，强制终止");
        }
    }

    // 4. 标记未完成的会话为 interrupted
    for (conv_id, _) in &sessions {
        sqlx::query!(
            "UPDATE conversations SET status = 'interrupted' WHERE id = ? AND status = 'running'",
            conv_id,
        )
        .execute(&state.db_pool)
        .await
        .ok();
    }

    // 5. 关闭 MCP 连接
    state.mcp_manager.disconnect_all().await;

    // 6. 关闭数据库连接池
    state.db_pool.close().await;

    tracing::info!("优雅关闭完成");
}

#[derive(Debug)]
pub enum ShutdownReason {
    UserQuit,
    WindowClosed,
    CriticalError(String),
    SystemSignal,
}
```

## 10. 设计约束

### 10.1 安全约束

| 约束 | 说明 |
| --- | --- |
| **不暴露堆栈跟踪** | `AppError` 序列化时仅包含用户友好消息，Rust 侧的 backtrace 仅写入日志文件 |
| **不暴露内部路径** | 错误消息中禁止出现服务器文件路径（如 `/Users/xxx/.astro/...`），用 `~/.astro/` 替代 |
| **不暴露密钥片段** | `ProviderError::AuthenticationFailed` 的消息中不包含 API Key 的任何部分 |
| **错误日志脱敏** | `error_events` 表的 `message` 字段经过脱敏处理（正则替换 key/token 模式） |

### 10.2 i18n 准备

| 约束 | 说明 |
| --- | --- |
| **消息与代码分离** | 所有用户可见的错误消息通过 `ErrorPresenter` 查表生成，不在代码中硬编码 |
| **Locale 参数化** | `ErrorPresenter` 接受 `Locale` 参数（当前支持 `Zh` / `En`），新语言只需追加映射表 |
| **错误编码稳定** | 错误编码（如 `E1001`）一经分配不可更改，确保文档和用户反馈的可追溯性 |

### 10.3 性能约束

| 约束 | 说明 |
| --- | --- |
| **错误上报异步** | `ErrorReporter::report` 使用 `tokio::spawn` 异步写入，不阻塞主流程 |
| **频率追踪轻量** | `ErrorFrequencyTracker` 每 60 秒查询一次 SQLite，单次查询 < 1ms |
| **错误日志容量** | `error_events` 保留 30 天，预估单用户月均 < 10000 条（约 2MB） |
| **panic 捕获零开销** | `catch_unwind` 仅在 panic 发生时有性能开销，正常路径无额外成本 |

### 10.4 结构化日志规范

所有错误日志使用 `tracing` 的结构化字段，便于后续分析：

```rust
// 规范字段列表
tracing::error!(
    error_code = "E1001",
    category = "user_fixable",
    conversation_id = conv_id,
    workspace_id = workspace_id,
    tool_name = tool_name,        // 工具错误时
    provider = provider_name,     // Provider 错误时
    attempt = attempt,            // 重试时
    "错误描述: {}", error_message
);
```
