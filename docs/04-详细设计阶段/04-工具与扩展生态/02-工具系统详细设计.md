# 工具系统详细设计

> **Astro 当前基线（2026-09-04）**：工具主链是 `CoreToolRuntime / ToolExecutor -> ToolRegistry -> build_tool_router / finalize_tool_router -> ToolRouter { registry, model_visible_specs } -> StepContext -> build_prompt -> Prompt.tools -> ResponsesRequest -> ResponseItem -> ToolRouter::build_tool_call -> ToolRegistry::dispatch`。现行命名、工具数量和 schema 以 Step 冻结的 Registry/Router 快照为准。Agent 历史不写回 `Message`；Direct、Deferred 和原生 `tool_search` 见 [Responses API 原生工具协议与 Astro 工具协议](05-Responses-API原生工具协议与Astro工具协议详细设计.md)。

> 阶段：详细设计 | 状态：草稿 | 说明：名词_动词命名规范、原子批量工具、RiskLevel、ToolOutput、ToolExposure 三级暴露、BM25 工具搜索
>
> 本文档已根据实际代码库同步更新（2026-08-22）。

## 1. 设计原则

工具系统遵循以下约定：

- **命名规范**：统一使用 `名词_动词` 风格（如 `file_read`、`memory_search`），LLM 更容易理解和选择
- **原子批量**：4 个批量工具（`file_edit`、`memory_manage`、`skill_manage`、`knowledge_manage`）接受 `ops` 数组，在单次调用内完成所有操作
- **风险分级**：每个工具声明 `RiskLevel`，由 HumanGuard 决定是否需要人工审批
- **输出统一**：所有工具返回 `ToolOutput`，内含 `Vec<ToolContent>` 多态内容块

## 2. 核心数据类型

> **术语统一规范**：以下 `ToolInput`、`ToolOutput`、`ToolContent`、`ToolError`、`ToolSource` 为全系统规范定义（canonical），所有模块和文档统一引用此处。

```rust
pub struct ToolInput {
    pub tool_name: String,
    pub parameters: Value,
    pub call_id: String,
    pub context: ToolCallContext,
}

pub struct ToolCallContext {
    pub session_id: String,
    pub workspace_id: String,
    pub agent_id: Uuid,
    pub agent_depth: u8,
    pub turn_index: u32,
}

pub struct ToolOutput {
    pub call_id: String,
    pub contents: Vec<ToolContent>,
    pub truncated: bool,
    pub duration_ms: u64,
}

pub enum ToolContent {
    Text(String),
    Image { data: Vec<u8>, mime_type: String },
    Structured(Value),
    Error(String),
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RiskLevel { Low, Medium, High, Critical }

pub enum ToolSource {
    Builtin,  // priority 100, frozen=true
    Mcp,      // priority 50
    Wasm,     // priority 10
    Skill,    // priority 10 (same as Wasm, goes through SkillRegistry)
}

/// 工具三级暴露控制（对齐 Codex ToolExposure）
pub enum ToolExposure {
    /// 始终注入 LLM tools 参数列表
    Direct,
    /// 不注入 LLM；需经 tool_search 发现后可调用
    Deferred,
    /// 对 LLM 和 tool_search 均不可见，仅供内部使用
    Hidden,
}
```

## 3. CoreToolRuntime / ToolExecutor

```rust
pub trait ToolExecutor: Send + Sync + 'static {
    fn tool_name(&self) -> ToolName;
    fn spec(&self) -> ToolSpec;
    fn description(&self) -> &str;
    fn toolset(&self) -> &str;
    fn approval_requirement(&self) -> ExecApprovalRequirement;
    fn icon(&self) -> &'static str;

    fn handle<'a>(
        &'a self,
        ctx: &'a mut ToolContext<'_>,
        args: &'a serde_json::Value,
    ) -> ToolExecutorFuture<'a>;
}

pub trait CoreToolRuntime: ToolExecutor {}
```

`ToolRegistry` 持有 `Arc<dyn CoreToolRuntime>`。现有 inventory handler 由
`LegacyToolAdapter` 适配，MCP / Extension 由 `DynamicToolAdapter` 适配；Agent 主链
不再从独立的 handler table 或 MCP Hub 临时构造执行闭包。

## 4. 内置工具清单

### 4.1 文件系统（8个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `file_read` | Low | `path: string`, `encoding?: string` | 路径沙箱检查，禁止 `..` 穿越；输出超过 1MB 自动截断 |
| `file_write` | Medium | `path: string`, `content: string`, `append?: bool` | 覆盖/追加，自动创建父目录；写入前备份至 `.astro/tmp/` |
| `file_edit` | Medium | `ops: [{op, path, old_str, new_str}]` | 批量操作；`op` 枚举：`replace`/`insert`/`delete`；原子事务 |
| `file_delete` | High | `path: string`, `recursive?: bool` | `recursive=false` 只删文件；recursive 需 L3 审批 |
| `file_move` | Medium | `src: string`, `dst: string` | 移动/重命名文件；需 `Permission::WriteFile`；目标已存在时返回错误 |
| `file_stat` | Low | `path: string` | 返回文件元信息（大小/修改时间/类型）；只读，无副作用 |
| `dir_list` | Low | `path: string`, `pattern?: string` | glob 过滤，忽略 `.gitignore` 排除路径 |
| `dir_search` | Low | `path: string`, `query: string`, `type?: "content"\|"name"` | 内容搜索用 ripgrep；文件名搜索用 glob |

### 4.2 Shell（3个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `shell_exec` | High | `command: string`, `timeout_ms?: int`, `cwd?: string` | 超时后强制 kill；stdout 限 1MB，stderr 限 100KB |
| `shell_bg` | High | `command: string`, `label?: string` | 后台启动，返回 `pid`；进程句柄存入 AppState 供后续 kill |
| `process_kill` | High | `pid: int` | 发送 SIGTERM，3s 后升级 SIGKILL |

### 4.3 记忆（4个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `memory_search` | Low | `query: string`, `top_k?: int` | 触发词检测 → KNN；仅返回 `valid_to IS NULL` 活跃版本 |
| `memory_manage` | Low | `ops: [{op, key, value, category}]` | 批量 upsert/delete；upsert 自动软替换旧版本 |
| `memory_snapshot` | Low | 无 | 读取 MEMORY.md 冻结快照（纯文本） |
| `memory_purge` | Medium | `category?: string`, `before_days?: int` | 批量软删除指定范围记忆（触发 ForgetScheduler） |

### 4.4 知识库（3个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `knowledge_search` | Low | `query: string`, `top_k?: int` | sqlite-vec KNN + FTS5 混合检索 |
| `knowledge_ingest` | Low | `content: string`, `source_uri?: string` | 调用嵌入 Provider 生成向量写入 `embeddings` |
| `knowledge_manage` | Low | `ops: [{op, id, content}]` | 批量 upsert/delete 知识条目 |

### 4.5 Skills（3个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `skill_search` | Low | `query: string`, `top_k?: int` | 委托 SkillRegistry BM25，返回 name + 80 token 摘要 |
| `skill_run` | Low | `skill_name: string`, `inputs?: object` | 调用指定 Skill 执行；读取 SKILL.md 并运行 |
| `skill_manage` | Medium | `ops: [{op, id, manifest?, content?}]` | 批量 create/retire/update；写入 evolution_log |

### 4.6 网络（2个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `http_request` | Medium | `url: string`, `method?: string`, `headers?: object`, `body?: string`, `save_to?: string` | 响应体限 1MB；自动解析 HTML → 纯文本（readability）；支持 `save_to` 下载文件 |
| `web_search` | Medium | `query: string`, `engine?: string` | 通过配置的搜索 Provider（Tavily / SerpAPI）返回结构化 JSON |

> **安全说明**：`http_request` 可访问任意 URL，存在数据外泄风险（LLM 被 Prompt 注入后可能调用恶意 URL）。设为 Medium 确保每次调用都经过 HumanGuard L2 审批（30s 超时自动拒绝）。配合工作区 `network_whitelist` 域名白名单使用可进一步收窄访问范围。

> **浏览器工具架构决策**：浏览器操作（browser_goto/browser_fetch/browser_screenshot/browser_click/browser_type）通过 MCP Server（如 `mcp-server-puppeteer`）提供，而非内置工具。这样可以：（1）避免在桌面应用中捆绑 Chromium（减少包体积约 100MB）；（2）用户按需安装浏览器 MCP Server；（3）浏览器操作天然隔离在独立进程中（安全性更好）。

### 4.7 代码执行（3个）

| 工具名 | 风险 | 参数摘要 | 关键实现 |
| --- | --- | --- | --- |
| `rhai_exec` | Medium | `code: string`, `vars?: object` | Rhai 沙箱：限 100k ops，32 层调用栈；提供 `tool_call` 桥接 |
| `wasm_exec` | Medium | `wasm_base64: string`, `input?: string` | Wasmtime 沙箱：限 64MB 内存，10s epoch；仅 WASI preview2 |
| `python_exec` | Medium | `code: string`, `timeout_ms?: int` | 在指定执行后端运行 Python 脚本，支持 stdin 输入和依赖安装 |

**python_exec 详细设计**：

```rust
pub struct PythonExecTool {
    backend_registry: Arc<BackendRegistry>,
}

// 输入参数 schema
#[derive(Deserialize, JsonSchema)]
pub struct PythonExecInput {
    /// Python 脚本代码
    pub code: String,
    /// 执行超时（毫秒，默认 30000）
    pub timeout_ms: Option<u64>,
    /// 工作目录（默认当前工作区根）
    pub cwd: Option<String>,
    /// 传入 stdin 的文本
    pub stdin: Option<String>,
    /// 需要的 pip 依赖（自动安装到临时 venv）
    pub requirements: Option<Vec<String>>,
}
```

沙箱策略：通过 `BackendRegistry` 选择执行后端（LocalShell/Docker/SSH），写入临时 `.py` 文件执行，不使用 `python -c`（避免 shell 注入）。依赖管理：若 `requirements` 非空，先创建临时 venv（`python -m venv /tmp/astro_py_XXX`），`pip install` 后在 venv 内执行脚本，执行完毕清理 venv。输出截断至 `max_output_tokens`（默认 4000）。

## 5. ToolRegistry

`ToolRegistry` 位于 `crates/agent-tools/src/engine/registry.rs`，管理所有工具的注册、暴露控制和 API schema 生成。

### 核心方法

```rust
impl ToolRegistry {
    /// 返回 LLM 可见的工具 schema 列表。
    /// **仅包含 Direct 暴露的工具**，Deferred 和 Hidden 工具不会出现。
    pub fn schemas_for_api(&self) -> Vec<serde_json::Value>;

    /// 一次构建 Direct schema 和已经由 tool_search 发现的 Deferred 路由 schema。
    pub fn schemas_for_step(&self, discovered_deferred: &HashSet<String>)
        -> (Vec<serde_json::Value>, Vec<serde_json::Value>);

    /// 返回当前可用工具列表（按 toolset 过滤 + check_fn 运行时检查）。
    pub fn available_tools(&self) -> Vec<&ToolEntry>;
}
```

### ToolExposure 五级暴露控制

| 级别 | LLM 可见 | tool_search 可见 | dispatch 可调用 | 典型场景 |
|------|---------|-----------------|----------------|---------|
| Direct | 是 | 是 | 是 | 大多数内置工具 |
| Deferred | 否 | 是 | 是 | get_context_remaining、new_context_window 等低频工具 |
| Hidden | 否 | 否 | 是 | 内部控制工具 |
| DirectModelOnly | 是（仅模型） | 是 | 是 | 不需在用户工具目录展示的控制面 |
| DeferredModelOnly | 否 | 是（仅模型） | 发现后是 | 仅供模型按需加载的能力 |

`ToolExposure` 只控制披露，不是授权等级。工具即使已可见或已发现，仍需经过交互模式、approval、sandbox 和 Hook。

**延迟加载流程**：

```text
LLM 初始上下文
    → schemas_for_api() 仅含 Direct 工具 + tool_search
    → LLM 调用 tool_search(query="context remaining")
    → BM25 在当前可搜索 Deferred 工具中搜索
    → 返回匹配的 Deferred 工具描述
    → 记录原生 tool_search_output
    → 下一 Step 仅为该输出中的工具建立路由
    → LLM 正常调用 get_context_remaining
```

### Direct / CodeModeOnly 投影

Registry 是唯一工具事实源，但每个模型可以使用不同的投影方式：

| 模式 | 模型请求中的工具 | Schema 获取方式 |
| --- | --- | --- |
| Direct | Direct 工具的 `name + description + parameters/format`，另含 `tool_search` | 在 `ResponsesRequest.tools` 中直接获得；Deferred 经 `tool_search` 按需加载 |
| CodeModeOnly | 顶层仅 `exec` / `wait` | 常用工具的 TypeScript 声明放入 `exec` 描述；延迟工具从 `ALL_TOOLS[].description` 检索同形声明 |

CodeModeOnly 使用分层披露避免把所有 MCP/Skill 工具 Schema 一次性放入模型上下文：

- Direct 工具在 `exec` 描述中预置精简 TypeScript 声明，模型首次采样即可编排；
- Deferred 工具不进入初始描述，但其 `ALL_TOOLS.description` 自带相同声明；
- 若模型不知道延迟工具，先筛选并输出 description，再在下一次采样中调用。这一额外轮次是延迟披露的明确成本。

```javascript
const matches = ALL_TOOLS.filter(({ name, description }) =>
  /audio|music/i.test(`${name} ${description}`)
);
text(matches.slice(0, 5));
```

`ALL_TOOLS` 的对象形状故意保持 `{name, description}`，但 description 末尾包含 `declare const tools: ...` 调用声明。Function 参数由已清理 JSON Schema 转换，Freeform 工具声明为字符串输入。目录与 `tools.<normalized_name>()` 共享同一份 Step 快照。

### BM25 工具搜索

`tool_search` 工具使用 `bm25` crate 实现倒排索引搜索。索引覆盖工具名和描述文本。搜索结果返回匹配工具的名称、描述和参数 schema，供 LLM 决定是否调用。

### 工具命名空间

`ToolEntry.namespace` 字段用于工具分组（如 `"shell"`、`"media"`、`"mcp"`）。命名空间信息包含在 `schemas_for_api()` 输出中，帮助 LLM 理解工具的分类归属。

### 工具命名空间强制规则

1. **MCP 工具强制前缀**：`mcp__<server_name>__<tool_name>`
2. **查找顺序**：精确匹配内置工具名 → 匹配带前缀的 MCP 工具
3. **Skill soft-alias**：模型把 skill 名当工具调用时，自动改写为 `skills(action=load, skill_id=...)`

## 6. 工具执行流水线

```text
LLM 返回 tool_calls
        │
        ▼
  ToolRegistry::get(name)      ── 工具不存在 → ToolError::InvalidInput
        │
        ▼
  HumanGuard::check(risk)      ── L1 直通 / L2 等待 30s / L3 等待人工
        │
        ▼
  tool.execute(input)          ── 并发执行同批次多个工具（tokio::join_all）
        │
        ├── 超时 → kill + ToolError::Timeout
        ├── 错误 → ToolOutput { is_error: true, content: [Text(msg)] }
        └── 成功 → ToolOutput
        │
        ▼
  AuditLogRepo::insert         ── 记录 tool_name/status/duration_ms/params_digest
        │
        ▼
  matching ResponseItem output ── 按 call id 写回 canonical history
```

## 7. MCP 工具桥接

外部 MCP Server 的工具通过 `McpToolBridge` 动态注册到 `ToolRegistry`：

```rust
pub struct McpToolBridge {
    client: Arc<McpClient>,
    server_name: String,
}

#[async_trait]
impl Tool for McpToolBridge {
    fn name(&self) -> &str { &self.tool_name }              // 不使用 &'static str，避免内存泄漏
    fn description(&self) -> &str { &self.tool_description } // 来自 tools/list 的 description
    fn input_schema(&self) -> Value { self.schema.clone() }  // 来自 tools/list 的 inputSchema
    fn risk_level(&self) -> RiskLevel { RiskLevel::Medium }  // MCP 工具统一视为中风险
    fn required_permissions(&self) -> Vec<Permission> { vec![Permission::McpToolCall] }
    fn is_readonly(&self) -> bool { false }                  // MCP 工具默认非只读

    async fn execute(&self, input: ToolInput) -> Result<ToolOutput, ToolError> {
        let result = self.client
            .call_tool(&input.tool_name, input.parameters)
            .await
            .map_err(|e| ToolError::Internal(e.to_string()))?;
        Ok(ToolOutput {
            call_id: input.call_id,
            contents: result.content.into_iter().map(Into::into).collect(),
            truncated: false,
            duration_ms: 0, // 由调用方填充实际耗时
        })
    }
}
```

MCP Server 连接时，`initialize` 握手后立即调用 `tools/list`，将所有工具注册为 `McpToolBridge`（`ToolSource::Mcp`，priority = 50）。工具名自动添加 `mcp__<server_name>__` 前缀，防止与内置工具名冲突。若 MCP Server 返回的工具名与内置工具同名（无前缀），注册将被拒绝并记录安全警告。

## 8. 工具调用审计

每次工具执行（无论成功与否）写入 `audit_logs`：

```rust
AuditLogRepo::insert(AuditLog {
    workspace_id: ctx.workspace_id.clone(),
    session_id: ctx.conversation_id.clone(),
    actor: "agent".into(),
    action: "tool_call".into(),
    tool_name: Some(input.tool_name.clone()),
    tool_source: classify_source(&input.tool_name),   // builtin / mcp / skill
    risk_level: Some(format!("{:?}", tool.risk_level())),
    params_digest: sha256_hex(&input.parameters.to_string()),  // 不存原始值
    status: if output.is_error { "failed" } else { "success" }.into(),
    duration_ms: Some(elapsed.as_millis() as i64),
    ..Default::default()
}).await?;
```
