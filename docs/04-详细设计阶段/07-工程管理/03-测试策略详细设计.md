## 1. 测试架构概述

### 1.1 测试金字塔

Astro Agent 采用经典测试金字塔模型，从底层到顶层数量递减、执行时间递增：

```text
                    ┌──────────┐
                    │  E2E 测试 │   ~20 条，Tauri WebDriver
                    │   (慢)    │   验证关键用户路径
                   ┌┴──────────┴┐
                   │  集成测试    │  ~100 条，in-memory SQLite + 多 crate 组合
                   │   (中等)    │  验证模块间协作
                  ┌┴────────────┴┐
                  │  单元测试      │  ~500+ 条，纯逻辑 + Mock，毫秒级
                  │   (快)        │  验证函数/结构体正确性
                  └──────────────┘
```

### 1.2 与 Agent Eval 的分工

| 维度 | 本文档（测试策略） | Agent 评估系统 |
|------|-------------------|---------------|
| **目标** | 代码正确性、接口契约、回归防护 | 模型行为质量、任务完成率 |
| **结果** | pass/fail（二值） | 分数（0.0 ~ 1.0 连续值） |
| **触发** | 每次 git push / PR | 发布前 + 进化引擎触发 |
| **依赖** | 不依赖真实 LLM（Mock / 录制回放） | 依赖真实 LLM 调用 |
| **CI 角色** | 基本门控（必须全绿） | 质量门控（Golden Set 通过率） |
| **覆盖** | Rust crate、React 组件、Tauri 交互 | Agent 端到端任务表现 |

两者互补：本文档确保代码层面不出 bug，Eval 确保 Agent 整体输出质量不退化。

## 2. 单元测试规范

### 2.1 Rust 单元测试模式

所有 Rust crate 使用 `#[cfg(test)]` 内联模块编写单元测试，遵循以下约定：

```rust
// crates/agent-core/src/agent/helpers.rs

/// 从 LLM 响应中解析文本和工具调用
pub fn parse_response(response: ChatResponse) -> ParsedResponse {
    ParsedResponse {
        text: response.text,
        reasoning: response.reasoning_content,
        tool_calls: response.tool_calls,
        has_plan: extract_plan_block(&response.text).is_some(),
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    // 命名约定：test_<函数名>_<场景>_<预期行为>
    #[test]
    fn test_parse_response_with_text_only_returns_no_tool_calls() {
        let response = ChatResponse {
            text: Some("Hello, world!".into()),
            reasoning_content: None,
            tool_calls: vec![],
            ..Default::default()
        };

        let parsed = parse_response(response);

        assert!(parsed.text.is_some());
        assert!(parsed.tool_calls.is_empty());
        assert!(!parsed.has_plan);
    }

    #[test]
    fn test_parse_response_with_plan_block_clears_tool_calls() {
        let response = ChatResponse {
            text: Some("<agent_plan>Step 1: ...</agent_plan>".into()),
            tool_calls: vec![ToolCall::new("web_search", json!({"q": "test"}))],
            ..Default::default()
        };

        let parsed = parse_response(response);

        assert!(parsed.has_plan);
        // 互斥规则：plan 存在时清空 tool_calls
        assert!(parsed.tool_calls.is_empty());
    }

    #[test]
    fn test_parse_response_with_reasoning_preserves_thinking() {
        let response = ChatResponse {
            text: Some("Answer".into()),
            reasoning_content: Some("Let me think...".into()),
            ..Default::default()
        };

        let parsed = parse_response(response);

        assert_eq!(parsed.reasoning.unwrap(), "Let me think...");
    }
}
```

### 2.2 Mock Trait 体系

所有外部依赖通过 trait 抽象，测试时替换为 Mock 实现。Mock 组件统一放在 `agent-providers` crate 的 `mock` 模块和 `agent-test-utils` crate 中。

#### 2.2.1 MockTextClient — LLM 客户端 Mock

```rust
// crates/agent-providers/src/mock/text_client.rs

use std::collections::VecDeque;
use std::sync::Arc;
use tokio::sync::Mutex;

/// 可编程的 LLM 客户端 Mock
/// 按入队顺序依次返回预设响应，同时记录所有收到的请求
pub struct MockTextClient {
    responses: Arc<Mutex<VecDeque<TextResponse>>>,
    calls: Arc<Mutex<Vec<TextRequest>>>,
}

impl MockTextClient {
    /// 创建一个按顺序返回预设响应的 Mock
    pub fn with_responses(responses: Vec<TextResponse>) -> Self {
        Self {
            responses: Arc::new(Mutex::new(responses.into())),
            calls: Arc::new(Mutex::new(Vec::new())),
        }
    }

    /// 创建一个固定返回文本的 Mock（最常用场景）
    pub fn with_text(text: &str) -> Self {
        Self::with_responses(vec![TextResponse::text(text)])
    }

    /// 创建一个返回工具调用的 Mock
    pub fn with_tool_call(tool_name: &str, args: Value) -> Self {
        Self::with_responses(vec![TextResponse::tool_call(tool_name, args)])
    }

    /// 查询累计调用次数
    pub async fn call_count(&self) -> usize {
        self.calls.lock().await.len()
    }

    /// 获取最后一次请求
    pub async fn last_request(&self) -> Option<TextRequest> {
        self.calls.lock().await.last().cloned()
    }

    /// 获取所有请求（用于验证请求序列）
    pub async fn all_requests(&self) -> Vec<TextRequest> {
        self.calls.lock().await.clone()
    }
}

#[async_trait]
impl TextClient for MockTextClient {
    async fn complete(&self, req: TextRequest) -> Result<TextResponse> {
        self.calls.lock().await.push(req);
        self.responses
            .lock()
            .await
            .pop_front()
            .ok_or_else(|| anyhow::anyhow!("MockTextClient: no more responses queued"))
    }

    async fn stream(
        &self,
        req: TextRequest,
    ) -> Result<BoxStream<'static, Result<TextStreamEvent>>> {
        let resp = self.complete(req).await?;
        // 将完整响应拆成单字符 delta 事件流，模拟流式输出
        let events: Vec<Result<TextStreamEvent>> = resp
            .content
            .chars()
            .map(|c| Ok(TextStreamEvent::Delta { text: c.to_string() }))
            .chain(std::iter::once(Ok(TextStreamEvent::Done {
                usage: resp.usage.clone(),
            })))
            .collect();
        Ok(Box::pin(futures::stream::iter(events)))
    }

    fn capabilities(&self) -> TextCapabilities {
        TextCapabilities::full()
    }
}
```

```rust
/// 记录所有调用参数并返回固定响应的工具 Mock
pub struct SpyTool {
    name: String,
    description: String,
    fixed_response: Value,
    calls: Arc<Mutex<Vec<Value>>>,
    risk_level: RiskLevel,
}

impl SpyTool {
    pub fn new(name: &str, response: Value) -> Self {
        Self {
            name: name.to_string(),
            description: format!("Spy tool for {}", name),
            fixed_response: response,
            calls: Arc::new(Mutex::new(Vec::new())),
            risk_level: RiskLevel::Low,
        }
    }

    /// 创建一个 L2 风险的 SpyTool（测试审批流程时使用）
    pub fn with_risk(name: &str, response: Value, risk: RiskLevel) -> Self {
        let mut tool = Self::new(name, response);
        tool.risk_level = risk;
        tool
    }

    pub async fn call_count(&self) -> usize {
        self.calls.lock().await.len()
    }

    pub async fn last_input(&self) -> Option<Value> {
        self.calls.lock().await.last().cloned()
    }

    pub async fn all_inputs(&self) -> Vec<Value> {
        self.calls.lock().await.clone()
    }
}

#[async_trait]
impl Tool for SpyTool {
    fn name(&self) -> &str { &self.name }
    fn description(&self) -> &str { &self.description }
    fn input_schema(&self) -> Value { json!({}) }
    fn risk_level(&self) -> RiskLevel { self.risk_level }
    fn required_permissions(&self) -> Vec<Permission> { vec![] }
    fn is_readonly(&self) -> bool { self.risk_level == RiskLevel::Low }
    fn timeout_ms(&self) -> u64 { 30_000 }

    async fn execute(&self, input: ToolInput) -> Result<ToolOutput, ToolError> {
        self.calls.lock().await.push(input.params.clone());
        Ok(ToolOutput::json(self.fixed_response.clone()))
    }
}
```

```rust
// crates/agent-runtime/src/event_emitter.rs

/// 收集所有发送的 AgentEvent，测试结束后可检查事件序列
pub struct MockEventEmitter {
    events: Arc<Mutex<Vec<AgentEvent>>>,
}

impl MockEventEmitter {
    pub fn new() -> Self {
        Self {
            events: Arc::new(Mutex::new(Vec::new())),
        }
    }

    /// 获取所有已发送事件
    pub async fn all_events(&self) -> Vec<AgentEvent> {
        self.events.lock().await.clone()
    }

    /// 按类型过滤事件
    pub async fn events_of_type<T: AgentEventKind>(&self) -> Vec<T> {
        self.events
            .lock()
            .await
            .iter()
            .filter_map(|e| T::try_from(e).ok())
            .collect()
    }

    /// 断言事件序列中包含指定类型事件
    pub async fn assert_emitted(&self, event_kind: &str) {
        let events = self.events.lock().await;
        assert!(
            events.iter().any(|e| e.kind() == event_kind),
            "Expected event '{}' not found in: {:?}",
            event_kind,
            events.iter().map(|e| e.kind()).collect::<Vec<_>>()
        );
    }
}

#[async_trait]
impl EventEmitter for MockEventEmitter {
    async fn emit(&self, event: AgentEvent) -> Result<()> {
        self.events.lock().await.push(event);
        Ok(())
    }
}
```

```rust
// crates/agent-test-utils/src/mocks/memory.rs

/// 基于 HashMap 的内存记忆存储，无需 SQLite
pub struct MockMemoryStore {
    entries: Arc<Mutex<HashMap<String, MemoryEntry>>>,
}

impl MockMemoryStore {
    pub fn new() -> Self {
        Self {
            entries: Arc::new(Mutex::new(HashMap::new())),
        }
    }

    pub fn with_entries(entries: Vec<MemoryEntry>) -> Self {
        let map: HashMap<String, MemoryEntry> = entries
            .into_iter()
            .map(|e| (e.id.clone(), e))
            .collect();
        Self {
            entries: Arc::new(Mutex::new(map)),
        }
    }
}

#[async_trait]
impl MemoryStore for MockMemoryStore {
    async fn write(&self, entry: NewMemoryEntry) -> Result<String> {
        let id = uuid::Uuid::new_v4().to_string();
        let full = MemoryEntry::from_new(id.clone(), entry);
        self.entries.lock().await.insert(id.clone(), full);
        Ok(id)
    }

    async fn retrieve(
        &self,
        query: &str,
        workspace_id: &str,
        top_k: usize,
    ) -> Result<Vec<MemoryEntry>> {
        let entries = self.entries.lock().await;
        // 简单的关键词匹配，不做向量检索
        let results: Vec<_> = entries
            .values()
            .filter(|e| e.workspace_id == workspace_id)
            .filter(|e| e.content.contains(query))
            .take(top_k)
            .cloned()
            .collect();
        Ok(results)
    }

    async fn soft_expire(&self, id: &str) -> Result<()> {
        self.entries.lock().await.remove(id);
        Ok(())
    }
}
```

## 3. LLM 交互录制回放

### 3.1 设计目标

LLM 调用具有不确定性（相同 prompt 不同时间可能返回不同结果），且有 API 成本。录制回放机制解决两个问题：

1. **确定性**：CI 中回放录制的响应，消除 LLM 输出波动导致的测试 flake
2. **零成本**：回放模式无需 API key，无网络调用，无费用

### 3.2 RecordReplayClient 实现

```rust
// crates/agent-providers/src/recording/mod.rs

pub struct RecordReplayClient {
    inner: Option<Arc<dyn TextClient>>,  // 真实 client（仅录制模式需要）
    cassette: Arc<Mutex<Cassette>>,
    mode: RecordingMode,
}

pub enum RecordingMode {
    /// 录制模式：调用真实 LLM，保存请求-响应对到 .jsonl
    Record { output_path: PathBuf },
    /// 回放模式：按请求特征匹配，返回录制的响应
    Replay,
    /// 透传模式：不录制，直接转发（开发调试用）
    Passthrough,
}

impl RecordReplayClient {
    /// 从 cassette 文件加载（回放模式）
    pub fn replay(cassette_path: &Path) -> Result<Self> {
        let cassette = Cassette::load(cassette_path)?;
        Ok(Self {
            inner: None,
            cassette: Arc::new(Mutex::new(cassette)),
            mode: RecordingMode::Replay,
        })
    }

    /// 包装真实 client 进行录制
    pub fn record(inner: Arc<dyn TextClient>, output_path: PathBuf) -> Self {
        Self {
            inner: Some(inner),
            cassette: Arc::new(Mutex::new(Cassette::empty())),
            mode: RecordingMode::Record { output_path },
        }
    }
}

#[async_trait]
impl TextClient for RecordReplayClient {
    async fn complete(&self, req: TextRequest) -> Result<TextResponse> {
        match &self.mode {
            RecordingMode::Replay => {
                let fingerprint = RequestFingerprint::from(&req);
                let mut cassette = self.cassette.lock().await;
                cassette
                    .find_match(&fingerprint)
                    .ok_or_else(|| anyhow::anyhow!(
                        "Cassette miss: no entry matches fingerprint {:?}\n\
                         Available entries: {}",
                        fingerprint,
                        cassette.summary()
                    ))
            }
            RecordingMode::Record { ref output_path } => {
                let inner = self.inner.as_ref().unwrap();
                let resp = inner.complete(req.clone()).await?;
                let mut cassette = self.cassette.lock().await;
                cassette.append(CassetteEntry {
                    fingerprint: RequestFingerprint::from(&req),
                    request_snapshot: req.clone(),
                    response: resp.clone(),
                    recorded_at: chrono::Utc::now(),
                });
                cassette.save(output_path)?;
                Ok(resp)
            }
            RecordingMode::Passthrough => {
                self.inner.as_ref().unwrap().complete(req).await
            }
        }
    }

    async fn stream(
        &self,
        req: TextRequest,
    ) -> Result<BoxStream<'static, Result<TextStreamEvent>>> {
        // 录制/回放模式下，将 complete 结果转为模拟流
        let resp = self.complete(req).await?;
        Ok(Box::pin(simulate_stream(resp)))
    }

    fn capabilities(&self) -> TextCapabilities {
        TextCapabilities::full()
    }
}
```

### 3.3 Cassette 格式与匹配策略

```rust
// crates/agent-providers/src/recording/cassette.rs

/// Cassette 文件 = 一个 .jsonl 文件，每行一个 CassetteEntry
#[derive(Debug, Serialize, Deserialize)]
pub struct Cassette {
    pub entries: Vec<CassetteEntry>,
    /// 当前回放游标（支持顺序匹配模式）
    cursor: usize,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CassetteEntry {
    pub fingerprint: RequestFingerprint,
    pub request_snapshot: TextRequest,  // 完整请求（调试用）
    pub response: TextResponse,
    pub recorded_at: DateTime<Utc>,
}

/// 请求指纹：用于匹配录制条目
/// 采用部分匹配策略，忽略不确定字段
#[derive(Debug, Clone, Hash, PartialEq, Eq, Serialize, Deserialize)]
pub struct RequestFingerprint {
    /// 系统 prompt 的 SHA256 前 16 位
    pub system_prompt_hash: String,
    /// 最后一条用户消息的文本内容（精确匹配）
    pub last_user_message: String,
    /// 可用工具名列表的排序后拼接 hash
    pub tools_hash: String,
    /// 消息数量（粗略匹配对话上下文）
    pub message_count: usize,
}

impl RequestFingerprint {
    pub fn from(req: &TextRequest) -> Self {
        Self {
            system_prompt_hash: sha256_prefix(&req.system_prompt, 16),
            last_user_message: req
                .messages
                .iter()
                .rev()
                .find(|m| m.role == Role::User)
                .map(|m| m.text_content())
                .unwrap_or_default(),
            tools_hash: {
                let mut names: Vec<_> = req.tools.iter().map(|t| &t.name).collect();
                names.sort();
                sha256_prefix(&names.join(","), 16)
            },
            message_count: req.messages.len(),
        }
    }
}

impl Cassette {
    /// 匹配策略：
    /// 1. 优先精确匹配所有字段
    /// 2. 若无精确匹配，尝试 fuzzy 匹配（忽略 message_count 差异 <=2）
    /// 3. 若仍无匹配，按顺序返回下一个未消费的条目（顺序模式兜底）
    pub fn find_match(&mut self, fp: &RequestFingerprint) -> Option<TextResponse> {
        // 精确匹配
        if let Some(entry) = self.entries.iter().find(|e| &e.fingerprint == fp) {
            return Some(entry.response.clone());
        }

        // Fuzzy 匹配：system_prompt + last_user_message 一致即可
        if let Some(entry) = self.entries.iter().find(|e| {
            e.fingerprint.system_prompt_hash == fp.system_prompt_hash
                && e.fingerprint.last_user_message == fp.last_user_message
        }) {
            return Some(entry.response.clone());
        }

        // 顺序兜底
        if self.cursor < self.entries.len() {
            let entry = &self.entries[self.cursor];
            self.cursor += 1;
            return Some(entry.response.clone());
        }

        None
    }

    /// 从 .jsonl 文件加载
    pub fn load(path: &Path) -> Result<Self> {
        let content = std::fs::read_to_string(path)?;
        let entries: Vec<CassetteEntry> = content
            .lines()
            .filter(|line| !line.is_empty())
            .map(|line| serde_json::from_str(line))
            .collect::<Result<Vec<_>, _>>()?;
        Ok(Self { entries, cursor: 0 })
    }

    /// 追加条目并保存到 .jsonl
    pub fn append(&mut self, entry: CassetteEntry) {
        self.entries.push(entry);
    }

    pub fn save(&self, path: &Path) -> Result<()> {
        let content: String = self
            .entries
            .iter()
            .map(|e| serde_json::to_string(e).unwrap())
            .collect::<Vec<_>>()
            .join("\n");
        std::fs::write(path, content)?;
        Ok(())
    }

    pub fn summary(&self) -> String {
        self.entries
            .iter()
            .map(|e| format!("  [{}] {}", e.fingerprint.last_user_message, e.recorded_at))
            .collect::<Vec<_>>()
            .join("\n")
    }
}
```

**管理规则：**

| 规则 | 说明 |
|------|------|
| 提交到 git | cassette 文件必须跟随代码一起提交，确保 CI 行为一致 |
| 命名约定 | `<测试场景>_<子场景>.jsonl`，使用 snake_case |
| 更新时机 | 当 prompt 模板变更、工具 schema 变更时需要重新录制 |
| 大小限制 | 单个 cassette 不超过 1MB（大文件考虑拆分场景） |
| 敏感信息 | 录制前过滤 API key、用户 PII，仅保留内容和结构 |

### 4.1 设计原则

集成测试验证多个模块协同工作的正确性。与单元测试的区别：

| 维度 | 单元测试 | 集成测试 |

## 8. 覆盖率目标

### 8.1 各 Crate 覆盖率指标

| Crate | 行覆盖率目标 | 分支覆盖率目标 | 说明 |
|-------|------------|--------------|------|
| `agent`（agent-core） | **80%** | 70% | 运行时核心：Session、工具路由、审批流、状态机——基础设施代码，变更频率低但影响面大 |
| `providers`（agent-providers） | **60%** | 50% | Provider 适配层——大量 HTTP 交互逻辑通过集成测试 + cassette 覆盖 |
| `tools`（agent-tools） | **70%** | 60% | 内置工具实现、ToolRegistry——包含较多异步流控制，部分路径难以覆盖 |
| `agent-test-utils` | 不设要求 | 不设要求 | 纯测试辅助代码 |
| 前端（React） | **65%** | 60% | 组件 + Store 逻辑 |

### 8.2 覆盖率规则

- **新增代码覆盖率**：每个 PR 的新增代码行覆盖率 >= 75%（通过 CI diff coverage 检查）
- **不降低原则**：PR 不应使任何 crate 的整体覆盖率下降超过 2%
- **豁免标注**：确实无法测试的代码（如平台特定的 FFI 绑定）使用 `#[cfg(not(tarpaulin_include))]` 标注豁免

### 8.3 Rust 覆盖率工具

使用 `cargo-tarpaulin` 收集覆盖率数据：

```bash
# 本地运行覆盖率
cargo tarpaulin \
  --workspace \
  --exclude agent-test-utils \
  --out html \
  --output-dir target/coverage

# CI 中生成 LCOV 报告（用于 Codecov / Coveralls 集成）
cargo tarpaulin \
  --workspace \
  --exclude agent-test-utils \
  --out lcov \
  --output-dir target/coverage

# 仅检查特定 crate
cargo tarpaulin -p agent-core --out html
```

### 8.4 CI 覆盖率门控

```yaml
# .github/workflows/test.yml（覆盖率部分）

coverage:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4

    - name: Install Rust toolchain
      uses: dtolnay/rust-toolchain@stable

    - name: Install tarpaulin
      run: cargo install cargo-tarpaulin

    - name: Run coverage
      run: |
        cargo tarpaulin \
          --workspace \
          --exclude agent-test-utils \
          --out xml \
          --output-dir target/coverage

    - name: Check coverage thresholds
      run: |
        # 解析各 crate 覆盖率并与阈值对比
        python3 scripts/check_coverage.py \
          --report target/coverage/cobertura.xml \
          --thresholds '{
            "agent": 80,
            "tools": 70,
            "providers": 60
          }'

    - name: Upload to Codecov
      uses: codecov/codecov-action@v4
      with:
        files: target/coverage/cobertura.xml
        fail_ci_if_error: false
```


## 9. 测试命令速查

### 9.1 Rust 测试命令

```bash
# ─── 全量测试 ───
cargo test --workspace                       # 所有 crate 单元 + 集成测试

# ─── 按 crate 测试 ───
cargo test -p agent                          # 仅 agent-core（package name: agent）
cargo test -p tools                          # 仅 agent-tools（package name: tools）
cargo test -p providers                      # 仅 agent-providers（package name: providers）

# ─── 按模块/函数测试 ───
cargo test -p agent -- storage               # agent-core 中匹配 "storage" 的测试
cargo test -p agent -- memory::filter        # 记忆过滤模块测试
cargo test -p agent -- control               # 审批/HITL 相关测试
cargo test -- test_parse_response            # 按函数名匹配

# ─── 集成测试 ───
cargo test --test storage_tests              # 指定集成测试文件
cargo test --test '*' -- --test-threads=1    # 串行运行（避免 SQLite 冲突）

# ─── 录制回放 ───
RECORDING_MODE=record cargo test --features recording   # 录制模式
RECORDING_MODE=replay cargo test                         # 回放模式（CI 默认）

# ─── 覆盖率 ───
cargo tarpaulin --workspace --exclude agent-test-utils --out html

# ─── 测试输出控制 ───
cargo test -- --nocapture                    # 显示 println! 输出
cargo test -- --show-output                  # 仅显示通过测试的输出
RUST_LOG=debug cargo test                    # 启用日志输出
```

### 9.3 CI 测试矩阵

```yaml
# .github/workflows/test.yml

name: Test Suite

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  # ─── Rust 单元 + 集成测试 ───
  rust-tests:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: Run tests
        run: cargo test --workspace
        env:
          RECORDING_MODE: replay

  # ─── 前端单元测试 ───
  frontend-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: cd apps/desktop && pnpm install
      - run: cd apps/desktop && pnpm test:ci

  # ─── Rust 覆盖率 ───
  coverage:
    runs-on: ubuntu-latest
    needs: rust-tests
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo install cargo-tarpaulin
      - run: |
          cargo tarpaulin --workspace \
            --exclude agent-test-utils \
            --out xml
      - uses: codecov/codecov-action@v4

  # ─── E2E 测试（仅 main 分支）───
  e2e-tests:
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main' || github.event_name == 'pull_request'
    needs: [rust-tests, frontend-tests]
    steps:
      - uses: actions/checkout@v4
      - name: Install system deps
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev \
            libappindicator3-dev \
            xvfb
      - run: cd apps/desktop && pnpm install
      - run: cd apps/desktop && pnpm tauri build
      - run: cd apps/desktop && xvfb-run pnpm e2e
        env:
          ASTRO_TEST_MODE: 'true'
          ASTRO_MOCK_PROVIDER: 'true'

  # ─── 测试结果汇总 ───
  test-summary:
    runs-on: ubuntu-latest
    needs: [rust-tests, frontend-tests, coverage, e2e-tests]
    if: always()
    steps:
      - name: Check results
        run: |
          if [[ "${{ needs.rust-tests.result }}" != "success" ]] || \
             [[ "${{ needs.frontend-tests.result }}" != "success" ]]; then
            echo "Core tests failed"
            exit 1
          fi
```
