## 1. 环境准备

### 1.1 依赖版本要求

| 工具 | 最低版本 | 推荐安装方式 |
|------|---------|------------|
| Rust | 1.80+ | `rustup` |
| Node.js | 20 LTS | `nvm` / `fnm` |
| pnpm | 9+ | `npm i -g pnpm` |
| Tauri CLI | 2.x | `cargo install tauri-cli` |
| SQLite | 3.45+ | 随系统 / Homebrew |
| Docker（可选）| 24+ | Docker Desktop |

**macOS 额外依赖**：
```bash
xcode-select --install
brew install pkg-config openssl
```

**Windows 额外依赖**：
```powershell
# 需要 Visual Studio Build Tools（C++ 工作负载）
# 以及 WebView2（Windows 11 内置，Windows 10 需手动安装）
winget install Microsoft.VisualStudio.2022.BuildTools
```

### 1.2 一键初始化

```bash
git clone https://github.com/your-org/astro-agent.git
cd astro-agent

# 安装前端依赖
npm --prefix apps/desktop install

# 检查 Rust 工具链
rustup show

# 复制环境变量模板
cp .env.example .env.local
# 编辑 .env.local，填入至少一个 Provider 的 API Key
# ANTHROPIC_API_KEY=sk-ant-...
# OPENAI_API_KEY=sk-...
```

### 1.3 启动开发模式

```bash
# 启动 Tauri 开发模式（前端热更新 + Rust 自动重编译）
npm --prefix apps/desktop run tauri dev

# 仅启动前端（不启动 Rust 后端，用于纯 UI 开发）
npm --prefix apps/desktop run dev

# 仅编译 Rust 后端（检查错误，不启动 UI）
cargo check
```

首次启动会触发 SQLite 数据库自动迁移（migrations/ 目录下的 SQL 文件按序执行），无需手动初始化数据库。

## 3. 核心概念速查

| 概念 | 在哪里 | 一句话说明 |
|------|--------|-----------|
| `AgentExecutor` | `agent-runtime/src/executor/` | Agent 主循环，每轮：规划→选工具→执行→更新上下文 |
| `AppState` | `tauri-app/src/state.rs` | Tauri 全局共享状态（连接池、provider 注册表等）|
| `ToolContext` | `agent-core/src/tool/context.rs` | 工具执行时的上下文（pool、backend、app handle）|
| `WorkspaceContext` | `agent-runtime/src/executor/context.rs` | 会话级上下文（workspace_id、system prompt 快照）|
| `BackendRegistry` | `agent-runtime/src/execution/registry.rs` | 管理 LocalShell/Docker/SSH 执行后端 |
| Zustand stores | `apps/desktop/src/stores/` | 前端状态（chatStore、providerStore、workspaceStore）|

## 4. 常见开发任务

### 4.1 新增一个内置工具

**步骤 1**：在 `agent-core/src/tool/` 定义 trait 实现：

```rust
// crates/agent-runtime/src/tools/my_tool.rs

use agent_core::tool::{Tool, ToolContext, ToolResult};
use serde_json::{json, Value};

pub struct MyTool;

#[async_trait::async_trait]
impl Tool for MyTool {
    fn name(&self) -> &str { "my_tool" }  // 命名规范：名词_动词

    fn description(&self) -> &str {
        "一句话描述工具的功能，供 LLM 理解何时调用"
    }

    fn input_schema(&self) -> Value {
        json!({
            "type": "object",
            "properties": {
                "param_a": { "type": "string", "description": "参数说明" }
            },
            "required": ["param_a"]
        })
    }

    fn risk_level(&self) -> RiskLevel { RiskLevel::Low }  // Low / Medium / High / Critical

    async fn execute(&self, params: Value, ctx: &ToolContext) -> ToolResult {
        let param_a = params["param_a"].as_str().unwrap_or("");
        // ... 实现逻辑
        ToolResult::ok(json!({ "result": "..." }))
    }
}
```

**步骤 2**：在工具注册表中注册（`agent-runtime/src/tools/registry.rs`）：

```rust
pub fn build_tool_registry() -> ToolRegistry {
    let mut registry = ToolRegistry::new();
    // ... 已有工具 ...
    registry.register(Box::new(MyTool));
    registry
}
```

**步骤 3**：在 `接口设计/01-Tauri-Commands-API.md` 和 `05-工具系统设计.md` 中补充文档。

**步骤 4**：添加测试：

```rust
#[tokio::test]
async fn test_my_tool() {
    let ctx = ToolContext::mock();  // mock 上下文
    let tool = MyTool;
    let result = tool.execute(json!({ "param_a": "test" }), &ctx).await;
    assert!(result.is_ok());
}
```

## 6. 常见问题

### Q: `pnpm tauri dev` 启动后白屏

- 检查 Vite 开发服务器是否正常：浏览器访问 `http://localhost:1420`
- 查看 DevTools Console（开发模式 F12 可打开）是否有 JS 错误

### Q: Rust 编译时出现 `openssl` 找不到

```bash
# macOS
export PKG_CONFIG_PATH="$(brew --prefix openssl)/lib/pkgconfig"

# Windows：使用 vendored 特性（已在 Cargo.toml 配置）
```

### Q: SQLite 迁移失败

检查 `migrations/` 下的 SQL 文件是否有语法错误：

```bash
sqlite3 :memory: < migrations/0025_add_my_table.sql
```

### Q: LLM 调用返回 `base_resp` 错误（MiniMax）

MiniMax API 将错误放在响应体的 `base_resp.status_code` 中，不使用 HTTP 状态码。

### Q: 工具调用被风险门控拦截

L2 及以上的工具调用需要人工审批。开发时可临时开启 YOLO 模式跳过审批（仅本地开发，不要在生产配置中启用）：

```rust
// 仅在测试中使用
ctx.risk_gate.set_yolo(true);
```

### Q: 前端 invoke 调用没有响应

1. 确认 Command 函数已在 `generate_handler![]` 中注册
2. 检查 Rust 侧是否有 `panic`（查看终端日志）
3. 用 `tauri::command` 宏时注意参数名必须与前端 `invoke` 的 key 完全一致（camelCase ↔ snake_case 自动转换）

## 7. 开发工作流

### 7.1 典型的功能开发流程

```text
1. 阅读相关设计文档（docs/03-系统设计阶段/）
2. 在 数据库设计/01-Schema设计.md 确认是否需要新表/字段
   └── 需要 → 新建 migrations/xxxx_xxx.sql
3. 在 agent-core 定义新 trait（如有）
4. 在 agent-runtime 实现业务逻辑
5. 在 tauri-app/src/commands/ 暴露 Tauri Command
6. 在 apps/desktop 实现前端 UI
7. 编写测试（Rust 单元测试 + 前端组件测试）
8. 更新相关设计文档（如接口有变化，更新 接口设计/01-Tauri-Commands-API.md）
```

### 7.2 提交规范

```
feat(tools): add file_compress tool for ZIP archiving
fix(provider): handle MiniMax base_resp error codes correctly
docs(design): update 05-工具系统设计 with file_compress spec
test(runtime): add integration test for file_compress tool
```

格式：`type(scope): description`
- type: `feat` / `fix` / `docs` / `test` / `refactor` / `perf` / `chore`
- scope: `tools` / `provider` / `runtime` / `ui` / `db` / `sync` / `design`
