# 交互执行模式设计

> **当前基线（2026-09-07）**：`InteractionMode`（`Agent` / `Plan`）是 turn/tool 执行策略，通过 ChatRequest 下传，行为说明只进入 system guidance（不向用户消息拼接 `[Mode: ...]`）。输入在忙碌期间的 start/steer/queue 语义由 `TurnInputMode`（`StartOrSteer` / `StartIfIdle` / `Steer { expected_turn_id }`）与 Session 准入控制决定。工具审批由 `control/` 模块的 guardian、smart_approval、approval_cache 和 trust_model 实现，不再使用早期的 L1/L2/L3 + HumanGuard 分级。

> 版本：v2.0 | 日期：2026-09-07 | 状态：与源码对齐
> 对应需求：F-39 交互执行模式、M-38 自适应执行模式

---

## 1. 交互模式（InteractionMode）

### 1.1 模式枚举

定义在 `agent-types/src/interaction_mode.rs`：

```rust
#[derive(Default)]
pub enum InteractionMode {
    #[default]
    Agent,   // 正常执行模式：可调用所有工具
    Plan,    // 只读规划模式：禁止写操作，仅 web_search/todo 等只读工具
}
```

### 1.2 模式切换

- **Agent -> Plan**：模型调用 `switch_mode(to="plan", reason=...)` 自动进入
- **Plan -> Agent**：模型调用 `switch_mode(to="agent", reason=..., summary=完整计划)` 后**停止并等待用户审阅**，不得自行继续执行

### 1.3 System Guidance 注入

每种模式有对应的 `system_guidance()` 文本，在 system prompt 中注入。行为约束通过 system prompt 传达，不修改用户消息或工具定义。

**Agent 模式**：分类任务类型后决定行为 -- 纯问答直接回答；简单执行任务创建 todo；复杂/高风险任务先切换到 Plan。

**Plan 模式**：只读。可用 `web_search`、`todo` 等只读工具。禁止 terminal、code_exec、Agent Thread 工具、memory 写入。输出可审阅的具体计划。

### 1.4 只读门控

`InteractionMode::is_readonly_gate()` 在 Plan 模式返回 `true`，`ToolRouter` 构建时据此过滤写操作工具。

### 1.5 传播路径

```text
前端 ChatRequest
  → gRPC ThreadSubmitRequest.interaction_mode
  → submission_loop
  → Session::apply_thread_settings
  → SessionState.interaction_mode
  → TurnContext.mode（turn 开始时快照）
  → ToolRouter 构建（step 开始时）
  → system_guidance 注入（prompt 构建时）
```

## 2. 输入准入控制（TurnInputMode）

### 2.1 模式枚举

定义在 `agent-protocol/src/submission.rs`：

```rust
pub enum TurnInputMode {
    StartOrSteer,                        // 空闲时 start，运行中 steer
    StartIfIdle,                         // 仅空闲时 start，运行中拒绝
    Steer { expected_turn_id: String },  // 仅 steer 到指定 turn
}
```

### 2.2 提交结果

```rust
pub enum TurnInputSubmission {
    Started { turn_id: String },         // 新 turn 已启动
    Steered { turn_id: String },         // 输入已注入运行中的 turn
    NotSubmitted { reason: String },     // 拒绝（如 StartIfIdle 时正在运行）
}
```

### 2.3 Steer 语义

当 turn 正在运行时，用户新输入通过 `TurnContext` 的输入准入机制注入：

1. `TurnContext::open_input_admission()` -- turn 进入可接受输入状态
2. 用户输入到达时，如果 turn 正在运行且 admission open，输入排入 `TurnContext.input_state.pending`
3. `run_turn` 内层循环在安全采样边界调用 `take_pending_input()` 消费排队输入
4. 输入准入生命周期：`Preparing -> Accepting -> Closed`

### 2.4 前端发送模式选择器

前端提供 Queue / Steer / Interrupt 三种发送模式（见 `useSend.ts`）：

| 模式 | TurnInputMode | 行为 |
|---|---|---|
| Queue | `StartOrSteer` | 空闲时启动新 turn；运行中注入当前 turn |
| Steer | `Steer { expected_turn_id }` | 仅注入指定 turn，turn 不匹配时拒绝 |
| Interrupt | 先 interrupt 再 `StartOrSteer` | 中断当前 turn 后启动新 turn |

## 3. 工具审批体系

### 3.1 审批路由

当前工具审批不再使用早期的 L1/L2/L3 + HumanGuard 分级。审批决策由 `streaming/tools_exec.rs` 中的 `authorize_tool_call` 四阶段链完成：

```text
① workflow/browser 工具 → 特殊快速路径
② MCP 工具 → McpToolApproval 配置决定
③ 只读变异预检 → 纯读操作跳过审批
④ 危险命令分类 → Guardian 评估 → Smart Approval / 用户确认
```

### 3.2 审批路由类型

```rust
pub(crate) enum ApprovalRoute {
    Deny,          // 硬拒绝（策略禁止）
    Allowlist,     // 命令白名单自动通过
    TypeAllowlist, // 类型白名单自动通过
    Off,           // 审批关闭（权限配置允许）
    Smart,         // SmartApproval 自动评估（8s 超时）
    Manual,        // 用户手动确认（HITL park）
}
```

### 3.3 Guardian 评估

`control/guardian.rs` 提供高风险命令评估。使用辅模型在 8 秒超时内判断：

```rust
pub enum GuardianDecision {
    ApproveOnce,     // 自动通过
    Deny,            // 拒绝
    Indeterminate,   // 不确定，fallback 到用户确认
}
```

拒绝后的重试由 `GuardianRetryState` 管理（SHA256 去重，单次精确重试）。

### 3.4 渐进信任模型

`control/trust_model.rs` 实现 per-session 渐进信任：

| 连续审批次数 | 信任等级 | 行为 |
|---|---|---|
| < 5 | `AlwaysAsk` | 每次询问用户 |
| >= 5 | `SmartReview` | 先自动评估，不确定时再询问 |
| >= 10 | `AutoApprove` | 自动通过 |

任意拒绝重置为 `AlwaysAsk`。不持久化，会话结束即丢弃。

### 3.5 会话审批缓存

`control/approval_cache.rs` 实现同命令模式不重复弹窗：

- 缓存键为 `(tool_name, command_prefix)`，`command_prefix` 取命令的前 2 个 token
- 支持父子继承（`derive_child_cache`）：子缓存读取父链，写入不向上传播
- 仅缓存在内存中，会话结束即丢弃

## 4. HITL 中断机制

### 4.1 HitlGate

位于 `control/hitl.rs`。Hermes 风格阻塞闸门，工具执行路径 park，用户 resume 完成 oneshot：

```rust
pub struct HitlRequest {
    pub tool_call_id: String,
    pub reason: String,              // "confirmation" / "tool_call" / "input_required"
    pub message: String,
    pub operations: Value,           // A2UI 操作列表
    pub response_schema: Value,      // JSON Schema 校验
    pub timeout: Duration,           // 默认 600 秒
}

pub struct HitlResolution {
    pub interrupt_id: String,
    pub status: String,              // "resolved" / "cancelled" / "timeout"
    pub payload_json: String,
}
```

### 4.2 Interrupt 协议

位于 `control/interrupt.rs`。AG-UI 风格 interrupt：

- 工具执行需要用户确认时，session 发送 `InterruptAdded` 事件
- 前端渲染确认/输入 UI（通过 A2UI 模板），用户操作后发送 `ResumeItem`
- `InterruptPending::apply_resume` 校验 payload 后 resolve oneshot

### 4.3 HITL 桥接

位于 `streaming/hitl_bridge.rs`，连接工具执行与 HITL 闸门：

| 函数 | 用途 |
|---|---|
| `park_confirm` | 工具需要用户确认（执行命令、沙箱拒绝重试） |
| `park_astro_hitl` | 通用 HITL（工具返回 `astro_hitl: true` 标记） |
| `park_network_approval` | 网络主机审批（allow_once/session/always/deny） |

## 5. 网络审批

### 5.1 审批范围

位于 `control/network_approval.rs`：

```rust
pub enum ApprovalScope {
    Once,        // 单次允许
    Session,     // 会话期间允许
    Persistent,  // 持久化到磁盘（写入 sandbox config）
}
```

### 5.2 并发合并

使用 first-owner 模式：首个请求同一主机的调用方成为 `PendingHostApprovalOwner`（RAII handle），后续请求 `Join` 等待。Owner 未 resolve 即 drop 时自动 Deny。拒绝优先于允许（缓存中 deny 覆盖 allow）。

## 6. 暂停与取消

### 6.1 PauseControl

位于 `agent-providers`。`Session::ensure_thread_controls()` 返回共享的 `PauseControl`：

- `pause()` / `resume()` -- 暂停/恢复 LLM 流式调用
- `cancel()` -- 取消当前 sampling

`run_turn` 内层循环在每次迭代开始检查 pause/cancel 状态。

### 6.2 CancelSignal

位于 `prompt/hooks.rs`。可克隆的取消信号，供 streaming 和工具执行检查：

- 工具执行前后检查取消状态
- 已取消则立即中断，不进入下一轮 sampling

### 6.3 任务 Abort

`Session::abort_all_tasks(reason)` 协作式 abort：

1. 向 `RunningTask` 的 `CancellationToken` 发信号
2. 等待 `TASK_ABORT_TIMEOUT`（5s）内自然退出
3. 超时后仍清理资源，发送 `TurnAborted` 事件

## 7. 子 Agent 并发

### 7.1 资源配额

```rust
const DEFAULT_LIMITS: Limits = Limits {
    max_threads: 32,    // 单根会话可派生的线程总数（含已完成的）
    max_depth: 8,       // Agent 树最大嵌套深度
    max_running: 8,     // 同时活跃执行的子 Agent 并发数
};
```

### 7.2 隔离原则

| 资源 | 隔离方式 |
|---|---|
| Session | 每个 Agent Thread 独立 `Session` 实例 |
| IterationBudget | 每个 Agent Thread 独立预算（默认 90） |
| 工具注册表 | 共享 `ToolRegistry`，权限按 `PermissionProfile` 过滤 |
| 审批缓存 | 子继承父（`derive_child_cache`），写入不向上传播 |
| 事件 | 子 Agent 事件通过 forwarder 合并到父 event stream |

### 7.3 模型工具

6 个 V2 模型可见工具：`spawn_agent`、`list_agents`、`send_message`、`followup_task`、`wait_agent`、`interrupt_agent`。

桌面控制面额外提供：`read_subagent_thread`、`close_subagent_thread`（用户决策，非模型决策）。
