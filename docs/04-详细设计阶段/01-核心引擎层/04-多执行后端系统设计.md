# 多执行后端系统设计

> **Harness 当前基线（2026-09-07）**：当前已落地的执行环境是本地子进程（`exec_command` 工具，`crates/agent-tools/src/builtin/shell/exec_command.rs`）+ 跨平台 `agent-sandbox`（macOS seatbelt / Linux bubblewrap / Windows restricted token，`crates/agent-sandbox/`）+ 可选 `agent-network-proxy`（`crates/agent-network-proxy/`），以及任务绑定 Browser 和 MCP。模型直接使用内置工具与 `tool_search`；Node/V8 Code Mode 已下线。工具路由通过 `ToolRouter`（`crates/agent-core/src/runtime/tool_router.rs`），工具上下文为 `ToolContext`（`crates/agent-tools/src/engine/context.rs`），无 `backend` 字段，沙箱策略通过 `SandboxPolicy` 注入。配置使用 `~/.astro/config.toml`（不存在 `workspace.yaml`）。`DockerBackend/SSHBackend/BackendRegistry/ExecutionBackend` 等未有当前可执行路径的内容属于目标设计。

> 版本：v1.1 | 日期：2026-08-13 | 状态：草稿
> 对应需求：F-15 工具执行、M-08 安全边界、US-043 Docker 沙箱隔离

> v0.1 简化：仅支持 Local 和 Docker 两种后端，使用枚举分发而非 trait 抽象。SSH/E2B/WASM 后端计划在 v0.3 引入，届时可提取 trait。

---

## 1. 后端类型

| 后端 | 标识符 | 适用场景 | 隔离强度 | 实现阶段 |
|------|--------|---------|---------|---------|
| LocalShell | `local` | 默认，可信任务，快 | 无隔离 | v0.1 |
| DockerSandbox | `docker` | 不可信代码，代码生成验证 | 强（命名空间）| v0.1 |

## 2. ExecutionBackend 枚举

不使用 trait 动态分发，v0.1 以枚举静态分发覆盖两种后端：

```rust
// crates/agent-core/src/execution/backend.rs

pub enum ExecutionBackend {
    Local(LocalShellBackend),
    Docker(DockerBackend),
}

impl ExecutionBackend {
    pub async fn execute(&self, cmd: &str, timeout: Duration) -> Result<ExecOutput> {
        match self {
            Self::Local(b) => b.execute(cmd, timeout).await,
            Self::Docker(b) => b.execute(cmd, timeout).await,
        }
    }
}

pub struct ExecOutput {
    pub exit_code: i32,
    pub stdout: String,
    pub stderr: String,
    pub duration_ms: u64,
}
```

## 3. LocalShellBackend

```rust
// crates/agent-core/src/execution/local.rs（目标设计，当前不存在）

pub struct LocalShellBackend {
    workspace_root: PathBuf,
    shell: String,  // "/bin/sh" on Unix, "cmd.exe" on Windows
}

impl LocalShellBackend {
    pub async fn execute(&self, cmd: &str, timeout: Duration) -> Result<ExecOutput> {
        let start = std::time::Instant::now();

        let mut command = tokio::process::Command::new(&self.shell);
        command.arg("-c").arg(cmd)
            .current_dir(&self.workspace_root)
            .stdout(std::process::Stdio::piped())
            .stderr(std::process::Stdio::piped());

        let output = tokio::time::timeout(timeout, command.output()).await??;

        Ok(ExecOutput {
            exit_code: output.status.code().unwrap_or(-1),
            stdout: String::from_utf8_lossy(&output.stdout).into_owned(),
            stderr: String::from_utf8_lossy(&output.stderr).into_owned(),
            duration_ms: start.elapsed().as_millis() as u64,
        })
    }
}
```

## 4. DockerBackend

使用 `bollard` crate 与 Docker 守护进程通信。v0.1 仅支持在容器中执行命令，不含文件同步和健康轮询。

```rust
// crates/agent-core/src/execution/docker.rs（目标设计，当前不存在）

pub struct DockerBackend {
    docker: Docker,              // bollard::Docker
    image: String,               // e.g. "astro-sandbox:latest"
    container_id: Option<String>, // 会话期间复用同一容器
    workspace_mount: String,     // 宿主目录挂载到容器内 /workspace
}

impl DockerBackend {
    pub async fn execute(&self, cmd: &str, timeout: Duration) -> Result<ExecOutput> {
        let container_id = self.ensure_container().await?;
        let start = std::time::Instant::now();

        let exec = self.docker.create_exec(&container_id, CreateExecOptions {
            attach_stdout: Some(true),
            attach_stderr: Some(true),
            cmd: Some(vec!["sh", "-c", cmd]),
            ..Default::default()
        }).await?;

        let mut output_stream = self.docker.start_exec(&exec.id, None::<StartExecOptions>);
        let mut stdout = String::new();
        let mut stderr = String::new();

        while let Some(Ok(msg)) = output_stream.next().await {
            match msg {
                LogOutput::StdOut { message } => stdout.push_str(&String::from_utf8_lossy(&message)),
                LogOutput::StdErr { message } => stderr.push_str(&String::from_utf8_lossy(&message)),
                _ => {}
            }
        }

        let inspect = self.docker.inspect_exec(&exec.id).await?;

        Ok(ExecOutput {
            exit_code: inspect.exit_code.unwrap_or(-1) as i32,
            stdout,
            stderr,
            duration_ms: start.elapsed().as_millis() as u64,
        })
    }

    /// 延迟创建容器，同一会话复用
    async fn ensure_container(&self) -> Result<String> {
        if let Some(id) = &self.container_id {
            return Ok(id.clone());
        }
        let config = Config {
            image: Some(self.image.as_str()),
            host_config: Some(HostConfig {
                binds: Some(vec![format!("{}:/workspace:ro", self.workspace_mount)]),
                network_mode: Some("none"),
                memory: Some(512 * 1024 * 1024),
                nano_cpus: Some(1_000_000_000),
                cap_drop: Some(vec!["ALL".to_string()]),
                read_only_rootfs: Some(true),
                no_new_privileges: Some(true),
                ..Default::default()
            }),
            ..Default::default()
        };
        let container = self.docker.create_container(None::<CreateContainerOptions<&str>>, config).await?;
        self.docker.start_container(&container.id, None::<StartContainerOptions<&str>>).await?;
        Ok(container.id)
    }

    pub async fn cleanup(&self) -> Result<()> {
        if let Some(id) = &self.container_id {
            self.docker.stop_container(id, None).await.ok();
            self.docker.remove_container(id, None).await.ok();
        }
        Ok(())
    }
}
```

## 5. 配置

在 `workspace.yaml` 中通过一个字段选择后端，不使用动态注册：

```yaml
# workspace.yaml
execution_backend: "local"   # "local" | "docker"
```

初始化逻辑：

```rust
pub fn create_backend(config: &WorkspaceConfig) -> ExecutionBackend {
    match config.execution_backend.as_deref().unwrap_or("local") {
        "docker" => ExecutionBackend::Docker(DockerBackend::new(
            config.docker_image.as_deref().unwrap_or("astro-sandbox:latest"),
            &config.workspace_root,
        )),
        _ => ExecutionBackend::Local(LocalShellBackend::new(&config.workspace_root)),
    }
}
```

## 6. 工具层路由

上层工具通过 `ToolContext` 获取 `ExecutionBackend`：

```rust
// crates/agent-tools/src/builtin/shell/exec_command.rs（目标设计，当前工具无 backend 字段）

pub struct ShellExecTool;

#[async_trait]
impl Tool for ShellExecTool {
    async fn execute(&self, params: Value, ctx: &ToolContext) -> ToolResult {
        let command: String = params["command"].as_str().unwrap_or_default().into();
        let timeout = Duration::from_secs(params["timeout"].as_u64().unwrap_or(30));

        let output = ctx.backend.execute(&command, timeout).await?;

        ToolResult::ok(json!({
            "output": output.stdout,
            "exit_code": output.exit_code,
        }))
    }
}
```

## 7. 安全考量

| 后端 | 文件系统访问 | 网络访问 | 权限级别 |
|------|------------|---------|---------|
| local | 完全访问宿主机 | 完全访问 | 等同于用户进程 |
| docker | 仅挂载目录（只读）| 无（`--network none`）| 无 root，能力全部丢弃 |

- **docker 后端默认网络隔离**：如任务需要网络（如 `npm install`），在 `workspace.yaml` 中设置 `docker_network: bridge`
- **local 后端的风险门控不变**（见 [03-交互执行模式设计.md](03-交互执行模式设计.md)），切换后端不绕过风险评估
- **Docker 容器复用**：会话内复用同一容器，会话结束时 `cleanup()` 销毁

## 8. v0.3 扩展规划

以下后端计划在 v0.3 引入，届时可将 `ExecutionBackend` 枚举提取为 trait：

| 后端 | 标识符 | 适用场景 | 隔离强度 |
|------|--------|---------|---------|
| SSHRemote | `ssh:<profile>` | 远程服务器、生产环境操作 | 中（远程隔离）|
| E2BSession | `e2b` | 云端沙箱、无本地 Docker | 强（VM级）|
| WasmRuntime | `wasm` | 轻量脚本、无 IO 计算 | 极强（WASM）|

引入新后端时需要：
- 将枚举分发改为 `#[async_trait] trait ExecutionBackend`
- 添加 `BackendRegistry` 动态注册（支持 SSH profile 等运行时配置）
- 为 Docker/SSH 后端添加文件同步（`upload_file` / `download_file`）
- 添加后端健康轮询（`HealthPoller`）
