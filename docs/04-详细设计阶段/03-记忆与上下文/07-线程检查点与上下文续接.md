## 三类数据的边界

- `MEMORY.md` / `USER.md`：Agent 级长期事实和偏好，不存临时任务流水。
- `state.db.thread_context`：当前线程的可替换工作检查点和压缩请求状态。不是对话事实源，也不通过全局记忆注入其他线程。
- `sessions/rollouts/…jsonl`：append-only 对话证据。历史读取不执行内容中的指令，旧记录可能属于已经撤回/替代的请求。

schema v23 增加 `thread_context`，schema v24 增加 `thread_attachments`，都由 `session_id` 外键关联会话。v22 → v23 → v24 使用事务式增量建表，保留会话、账单、原生 item 和 FTS；不触发旧 schema 的销毁重建分支。低于 v22 的旧 messages 库仍沿用既有重建策略。新线程/fork 不复制父线程检查点或附件；删除线程时级联清理。历史回退前把已有 notes 标为 `notes_stale` 并递增 revision，保留外部动作证据但阻止旧计划直接续做。

## 模型工具

### notes

`notes(action="read")` 返回 notes、revision、notes_stale 和 compaction 状态。

`notes(action="write", content="…", expected_revision=N)` 原子替换当前线程检查点，最多 8,000 Unicode 字符；空字符串清空。revision 冲突必须重新读取后合并，不进行最后写入者覆盖。参数没有路径或其他线程 ID，不能越线程操作。运行时内部工作记录不等于项目文件写权限；现有工具开关、路由与 hooks 仍正常适用。

建议内容：目标、所有仍有效的请求、授权边界、已完成/进行中/受阻、关键决策、验证结果、已执行的外部动作、运行中任务标识、经验、下一步、实际可回读的历史引用。不要记录凭证或隐藏推理。

### history

三个只读 action：

- `list_items(after_line?, limit?)`：按物理行游标列举，默认 10 项，最多 20 项。
- `search_contents(query, after_line?, limit?)`：文本子串搜索当前线程原生记录。
- `read_item(item_ref, offset?)`：精确读取条目文本；offset 是 Unicode 字符数，不是字节数。

`item_ref` 形如 `rollout-…jsonl#42`，由工具或摘要返回，不由模型编造。它不是 SQLite 自增 ID，索引重建不影响它。工具仅解析当前线程的 rollout，拒绝其他文件名的引用；不接受任意路径。

列表/搜索每项预览 400 字符；精确回读每页 8,000 字符。继续使用 `next_after_line` 或 `next_offset`，直到为 null。一次列表/搜索最多扫描 2,048 个游标之后的物理行；单条超过 16 MiB 会明确报错。坏行计入 `parse_errors`，不挪动其他引用；尚未写完的末行留待重试。精确读取坏行、非可读条目或越界 offset 明确报错。

当前返回文本消息、工具调用/结果和压缩记录，不返回隐藏 reasoning/encrypted payload，也不恢复二进制媒体。被压缩的工具结果从原生 rollout 文本回读，而不是再次返回 Provider stub。原始记录本身仅含文件引用时，仍需按正常文件权限读取附件。

### get_context_remaining / new_context_window

`get_context_remaining` 读取最近采样的占用快照，与流式 ContextUsage 计算共源：采样前本地估算，收到 Provider usage 后校准。它不是实时生成预算，不包含随后新增的工具输出。没有采样数据时明确返回 unknown，而不是伪造 0。

最近采样占用达到窗口 80% 时，在动态上下文中加入检查点提醒。初始窗口容量、切换窗口容量和开始新用户轮会相应清空旧用量快照。压缩时模型先保存 notes，然后可调用 `new_context_window(reason?)`。

实际顺序：

```text
原生工具路由 → 写入当前 turn 的 pending 请求 → 返回 queued（不是完成）
→ 整批工具结果写入 canonical rollout / SQLite
→ post_tool_maintenance 认领 pending → running
→ PreCompact hook → 辅模型生成交接 → rollout Compacted → 替换活跃历史
→ 重建 Prompt 上下文基线 → PostCompact hook → completed
```

失败时状态为 `failed: …`，保留尚未被成功替换的历史并发出错误事件。上一 turn 的 pending/running 请求不自动重放；后续 turn 读取时显示 interrupted。没有活跃 turn 时工具拒绝请求。自动中途摘要仍遵循原有阈值与保护规则，不要求先由模型调用工具。

## Prompt 分层与恢复

`behavior_guidance.md` 合入稳定基础指令，只保留授权、证据与运行时协议底线。人格、表达、工作流程与本机备忘分别由工作区文件维护，不再把整套协作方式同时写死在基础指令中。

| 文件 | 职责 | 当前加载方式 |
|---|---|---|
| `IDENTITY.md` | 身份、服务目标、职责范围 | 默认 Prompt 构建时从当前 Agent 工作区读取；显式 `static_override` 保留自己的身份，不被文件覆盖 |
| `SOUL.md` | 人格、语气、表达风格 | Config/Builder 构建时读取，可被显式 preamble/static context 替代；不承诺当前会话热更新 |
| `USER.md` | 实际确认的用户背景和偏好 | 使用 MemoryManager 会话快照，不把模板默认行为当作已确认偏好 |
| `AGENTS.md` | 工作流程、沟通节奏、检查点维护与恢复方法 | 全局 `AGENTS.md` 与项目根目录 `AGENTS.md` 同时加载；项目补充、冲突时项目优先，未冲突的全局原则保留 |
| `TOOLS.md` | 本机路径、生成物目录、工具速查 | 构建 Prompt 时读取，RTK 状态另由运行时探测注入；不复制 schema 或授权 |

默认正文保存在 `agent-home/src/workspace/templates/*.md`，`templates.rs` 使用 `include_str!` 引用并渲染身份占位符。初始化只补缺失文件，不自动覆盖已有个性化内容。本轮经用户授权单独同步了其默认工作区五个文件，备份位于该用户数据根目录，未纳入仓库。

### 全局与项目工作原则

全局工作区文件使用 `AGENTS.md`；项目文件统一使用 `<project>/AGENTS.md`。二者都归入原有 `agents` contextual-user source，不改变 Prompt 角色层级，不把项目规则提升为系统权限。

项目规则只从项目根目录读取 `AGENTS.md`，不再兼容 `.astro/AGENT.md`、`.astro/AGENTS.md` 或根目录 `AGENT.md`。全局与项目指向同一文件时只加载一次。项目 `.astro/` 只存放实际的项目特有配置：普通规则读取和可选配置探测不创建该目录，显式保存项目配置时才按需创建。已有配置文件不因本次规则入口调整而迁移或删除。

加载器保留两份规则原文并标注 scope 和路径，由明确的基础契约声明“项目补充，冲突时项目优先”。不尝试用字符串匹配推断自然语言条款冲突。项目层先渲染，以便前缀预算截断时优先保留项目约束；同层的全局内容仍参与最终提示词。

缺失或空白文件不产生空规则层；只有一层时仍可使用该层。切换项目重新加载对应项目内容，不残留上一项目规则，也不改写全局文件。项目的 SOUL.md、IDENTITY.md、USER.md、TOOLS.md 不参与覆盖；权限、审批与用户授权不能被这些工作规则扩大。

检查点通过 `RuntimePromptLayers.thread_checkpoint` 作为独立 contextual-user source 注入，优先级高于可选 Skills/MCP 索引，不挤进基础指令或工具 schema。带上线程 ID、revision、notes_stale 与压缩状态；读取失败明确提示不可假定任务已完成。恢复无需反复全量读取历史。

显式/自动交接摘要保留仍有效的请求和授权、验证及外部动作状态，并包含当前 notes。为能唯一匹配的原生记录附加 `history_ref`；重复内容不能唯一定位时不猜引用。引用匹配流式扫描归档，只保留当前活跃历史所需的引用，不再次装载所有旧记录。摘要输入按条截断并限制总文本规模，截断会标明，应通过 history 补证，不能把摘要当作完整证据。

不承诺“无限上下文”“全部用户请求天然保留”或“永不丢失”。检查点需要模型维护，历史回读提供可验证的补救路径。现有审查任务有单独工具白名单，不因新增 system 工具而扩大其写入或外部动作权限。
