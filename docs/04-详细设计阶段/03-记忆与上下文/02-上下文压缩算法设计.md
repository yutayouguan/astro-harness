# 上下文压缩算法设计

> **Harness 当前基线（2026-09-07）**：工具上下文由 `maintain_tool_context()`（`crates/agent-core/src/runtime/context_maintenance.rs`）按 prune → `AuxiliaryTask::Compaction` LLM 摘要（最多 `MAX_LLM_TOOL_COMPRESS_PER_PASS=6` 个/轮）→ head/tail fallback 处理。`ToolCompressionManager`（`crates/agent-core/src/compression.rs`）按上下文占用率分三阶段：Soft（40%，2400 字符）、Medium（60%，1800 字符）、Hard（80%，900 字符）。`CompressionThrashingGuard` 防止连续低增益轮次。`content` 始终保留原文，`compressed_content` 是 Provider 视图。工具结果 ≥ `DEFAULT_SPILL_THRESHOLD_BYTES`（16KB）时落盘至 `tool_spills/` 目录，provider history 用 stub（`[astro:tool-spill]` / `[astro:tool-pruned]` / `[astro:llm-compressed-tool-result]` 标记）。

> 版本：v1.0 | 日期：2026-08-07 | 状态：草稿
> 对应需求：F-07 上下文管理与 Token 优化
> 补充文档：[07-上下文管理.md](../../03-系统设计阶段/02-核心功能模块/07-上下文管理.md)（Token 预算公式、优先级槽概述）

本文档专注于 09 号文档未展开的压缩算法细节：触发时机、三级压缩策略、消息重要性评分、摘要生成、Prompt Cache 保护、以及压缩后的上下文重建。

## 1. 压缩触发时机

```text
每轮对话开始时，ContextManager 检查 token 使用情况：

已用 tokens
────────────────────────────── 模型上下文窗口（如 200k）
                                │
               │ 预警阈值 75%  │
               ▼               │
        触发"轻量压缩"          │
        （滑动窗口裁剪）         │
                                │
               │ 压缩阈值 85%  │
               ▼               │
        触发"摘要压缩"          │
        （LLM 生成历史摘要）    │
                                │
               │ 硬限 95%      │
               ▼               │
        触发"紧急压缩"          │
        （丢弃非关键内容）      │
```

```rust
// crates/agent-core/src/compression.rs (目标设计；当前实现见 runtime/context_maintenance.rs)

pub struct ContextManager {
    model_window: usize,        // 模型最大 token 数（如 200_000）
    warn_ratio: f32,            // 75%
    compress_ratio: f32,        // 85%
    hard_limit_ratio: f32,      // 95%
    budget: TokenBudget,        // 各槽位 token 分配
}

pub enum CompressionLevel {
    None,
    Light,      // 75%-85%：滑动窗口
    Summary,    // 85%-95%：LLM 摘要
    Emergency,  // >95%：紧急丢弃
}

impl ContextManager {
    pub fn compression_level(&self, used_tokens: usize) -> CompressionLevel {
        let ratio = used_tokens as f32 / self.model_window as f32;
        if ratio < self.warn_ratio       { CompressionLevel::None }
        else if ratio < self.compress_ratio { CompressionLevel::Light }
        else if ratio < self.hard_limit_ratio { CompressionLevel::Summary }
        else                             { CompressionLevel::Emergency }
    }
}
```

## 2. Token 预算分配

```rust
// crates/agent-core/src/compression.rs (目标设计)

pub struct TokenBudget {
    pub total: usize,           // 模型窗口 × 0.90（留 10% 余量）
    pub system_prompt: usize,   // 固定槽（Slot 1-8），约 4000
    pub tool_definitions: usize,// 工具 Schema 注入，约 3000
    pub memory_snapshot: usize, // Slot 4 记忆，约 1200
    pub history_reserve: usize, // 为下一轮输出预留，约 4000
    // 剩余全部分配给对话历史
}

impl TokenBudget {
    pub fn history_budget(&self) -> usize {
        self.total
            .saturating_sub(self.system_prompt)
            .saturating_sub(self.tool_definitions)
            .saturating_sub(self.memory_snapshot)
            .saturating_sub(self.history_reserve)
    }

    /// 基于模型窗口大小自适应构建预算
    pub fn for_model_window(model_window: usize) -> Self {
        let total = (model_window as f32 * 0.9) as usize;  // 保留 10% 安全边际
        
        // System Prompt 各槽位实际占用（按模型窗口大小缩减）
        let (sys_prompt, tool_defs, memory) = if model_window >= 128_000 {
            // 大模型：完整预算
            (8_000, 3_000, 4_375)   // 总计 15,375
        } else if model_window >= 32_000 {
            // 中模型：压缩非核心槽位
            (4_000, 2_000, 3_000)   // 总计 9,000
        } else {
            // 小模型（Ollama 8K）：最小化 System Prompt
            (2_000, 1_000, 1_000)   // 总计 4,000
            // SOUL.md 截断到 2000 tokens
            // 工具只注入 Top-10 最相关
            // 记忆只注入 USER.md（跳过 MEMORY.md 和 L2 检索）
        };
        
        let history_reserve = total.saturating_sub(sys_prompt + tool_defs + memory + 2_000);
        // 2_000 tokens 预留给 LLM 输出
        
        Self {
            total,
            system_prompt: sys_prompt,
            tool_definitions: tool_defs,
            memory_snapshot: memory,
            history_reserve,
        }
    }
}

> **小模型适配**：当模型上下文窗口 < 32K 时，自动缩减 System Prompt 各槽位预算。SOUL.md 截断到 2,000 tokens，工具列表只保留 Top-10 最相关工具，记忆只注入 USER.md。这确保了即使在 Ollama 8K 模型上也能保留足够的对话历史空间。
```

## 3. 消息重要性评分

压缩时需要决定哪些消息保留、哪些可以丢弃或归入摘要，基于以下评分规则：

```rust
// crates/agent-core/src/compression.rs (目标设计)

pub struct MessageScorer;

impl MessageScorer {
    pub fn score(msg: &Message, position_from_end: usize) -> f32 {
        let mut score = 0.0f32;

        // 1. 位置分（越近越重要）
        score += 1.0 / (1.0 + position_from_end as f32 * 0.1);

        // 2. 角色权重
        score += match msg.role {
            Role::System  => 2.0,  // System 消息几乎不压缩
            Role::User    => 0.8,
            Role::Assistant => 0.6,
            Role::Tool    => 0.4,  // 工具结果可压缩
        };

        // 3. 内容类型权重
        if msg.has_tool_call() { score += 1.5; }       // 工具调用保留
        if msg.has_tool_result() {
            if msg.tool_result_is_large() { score += 0.3; }  // 大结果可摘要
            else                          { score += 1.2; }  // 小结果保留
        }
        if msg.content_length() < 200 { score += 0.5; }  // 短消息成本低，倾向保留
        if msg.contains_code_block()  { score += 0.8; }  // 代码块重要

        // 4. 用户明确指令检测（含关键词）
        if msg.role == Role::User && contains_instruction_keywords(&msg.content) {
            score += 1.0;
        }

        score
    }
}

fn contains_instruction_keywords(content: &str) -> bool {
    const IMPORTANCE_KEYWORDS: &[&str] = &[
        // 中文
        "重要", "关键", "必须", "目标", "结论", "决定", "注意", "错误", "问题", "解决",
        "需求", "约束", "优先", "记住", "总结",
        // English
        "important", "critical", "must", "goal", "conclusion", "decision", "error",
        "bug", "fix", "requirement", "constraint", "remember", "always", "never",
        "priority", "summary",
    ];
    IMPORTANCE_KEYWORDS.iter().any(|kw| content.to_lowercase().contains(kw))
}
```

## 4. 三级压缩策略

### 4.1 轻量压缩（Light）：滑动窗口 + 低分消息裁剪

```rust
// crates/agent-core/src/compression.rs (目标设计)

pub async fn compress_light(
    messages: &[Message],
    budget: &TokenBudget,
) -> Vec<Message> {
    let history_budget = budget.history_budget();
    let mut result = Vec::new();
    let mut used_tokens = 0usize;

    // 从最新消息往前遍历，按评分排序后填充
    let mut scored: Vec<(usize, f32, &Message)> = messages.iter()
        .enumerate()
        .map(|(i, m)| {
            let pos_from_end = messages.len() - 1 - i;
            (i, MessageScorer::score(m, pos_from_end), m)
        })
        .collect();

    // 先保证最近 10 条完整保留（保证连贯性）
    let recent_cutoff = messages.len().saturating_sub(10);
    let (recent, older): (Vec<_>, Vec<_>) = scored.iter()
        .partition(|(i, _, _)| *i >= recent_cutoff);

    // 先填入最近消息
    for (_, _, msg) in recent.iter().rev() {
        let t = estimate_tokens(msg);
        if used_tokens + t <= history_budget {
            result.push((*msg).clone());
            used_tokens += t;
        }
    }

    // 再按评分从高到低填入较旧消息
    let mut older_sorted = older.to_vec();
    older_sorted.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap());

    for (orig_idx, _, msg) in older_sorted {
        let t = estimate_tokens(msg);
        if used_tokens + t <= history_budget {
            result.push((*msg).clone());
            used_tokens += t;
        }
    }

    // 按原始顺序重排（保证时序）
    result.sort_by_key(|m| messages.iter().position(|o| o.id == m.id));

    // Tool Call 配对保护
    enforce_tool_pairs(&mut result, messages);

    result
}
```

#### Tool Call 配对保护

压缩后必须保证 tool_call 与 tool_result 成对保留：

```rust
fn enforce_tool_pairs(selected: &mut Vec<&Message>, all: &[Message]) {
    let selected_ids: HashSet<&str> = selected.iter()
        .filter_map(|m| m.tool_call_id.as_deref())
        .collect();
    
    // 1. 对于已选中的 tool_result，确保其对应的 assistant tool_call 也被选中
    let mut needs_add = vec![];
    for msg in selected.iter() {
        if msg.role == Role::Tool {
            if let Some(call_id) = &msg.tool_call_id {
                // 找到发起此工具调用的 assistant 消息
                let caller = all.iter().find(|m| 
                    m.role == Role::Assistant && 
                    m.content.iter().any(|c| matches!(c, ContentPart::ToolCall(tc) if tc.id == *call_id))
                );
                if let Some(caller) = caller {
                    if !selected.iter().any(|s| s.id == caller.id) {
                        needs_add.push(caller);
                    }
                }
            }
        }
    }
    
    // 2. 对于已选中的 assistant tool_call，确保其所有 tool_result 也被选中
    for msg in selected.iter() {
        if msg.role == Role::Assistant {
            for part in &msg.content {
                if let ContentPart::ToolCall(tc) = part {
                    let result = all.iter().find(|m| 
                        m.role == Role::Tool && m.tool_call_id.as_deref() == Some(&tc.id)
                    );
                    if let Some(result) = result {
                        if !selected.iter().any(|s| s.id == result.id) {
                            needs_add.push(result);
                        }
                    }
                }
            }
        }
    }
    
    selected.extend(needs_add);
    // 重新按时间排序
    selected.sort_by_key(|m| m.created_at);
}
```

在 `compress_light()` 和 `compress_emergency()` 的消息选择之后、返回之前调用 `enforce_tool_pairs()`。

> **设计原则**：配对保护可能导致实际保留的 token 数超过预算。这是有意为之——宁可多保留几条配对消息，也不能产生违反 API 协议的畸形消息序列。

### 4.2 摘要压缩（Summary）：LLM 生成历史摘要

```rust
pub async fn compress_summary(
    messages: &[Message],
    budget: &TokenBudget,
    llm: &Arc<dyn ChatCompletionModel>,
) -> anyhow::Result<(Vec<Message>, String)> {
    // 1. 确定摘要边界：最近 20 条完整保留，其余归入摘要
    let keep_count = 20;
    let (to_summarize, to_keep) = if messages.len() > keep_count {
        messages.split_at(messages.len() - keep_count)
    } else {
        (&messages[..0], messages)
    };

    if to_summarize.is_empty() {
        // 消息不多，降级为 Light
        let compressed = compress_light(messages, budget).await;
        return Ok((compressed, String::new()));
    }

    // 2. 生成摘要（使用小模型降低成本）
    let dialog_text = format_messages_for_summary(to_summarize);
    let summary = agent_responses_prompt(
        provider,
        "Summarize conversation history",
        format!(
            "请将以下对话历史压缩为一段简洁摘要（300字以内），保留所有重要决策、\
             已完成的任务、关键代码变更和用户明确的偏好，省略闲聊和重复内容：\n\n{}",
            dialog_text
        ),
        &provider_config,
    ).await?;

    // 3. 将摘要作为 System 消息插入历史开头
    let summary_msg = Message {
        id: format!("summary-{}", Uuid::new_v4()),
        role: Role::System,
        content: format!("## 历史对话摘要（已压缩）\n\n{}", summary),
        created_at: to_summarize[0].created_at,
        ..Default::default()
    };

    let mut result = vec![summary_msg];
    result.extend_from_slice(to_keep);

    // 4. 对保留部分再做 Light 压缩（确保在预算内）
    let final_result = compress_light(&result, budget).await;
    Ok((final_result, summary))
}
```

### 4.3 紧急压缩（Emergency）：丢弃低分内容

```rust
pub async fn compress_emergency(
    messages: &[Message],
    budget: &TokenBudget,
) -> Vec<Message> {
    let emergency_budget = budget.history_budget() / 2;  // 紧急时只用一半预算

    // 仅保留评分最高的消息，直接按 token 填充
    let mut scored: Vec<_> = messages.iter().enumerate()
        .map(|(i, m)| {
            let pos = messages.len() - 1 - i;
            (MessageScorer::score(m, pos), m)
        })
        .collect();
    scored.sort_by(|a, b| b.0.partial_cmp(&a.0).unwrap());

    let mut result = Vec::new();
    let mut used = 0usize;

    // 始终保留最后一条用户消息（当前问题）
    if let Some(last_user) = messages.iter().rev().find(|m| m.role == Role::User) {
        result.push(last_user.clone());
        used += estimate_tokens(last_user);
    }

    for (_, msg) in scored {
        if result.iter().any(|r: &Message| r.id == msg.id) { continue; }
        let t = estimate_tokens(msg);
        if used + t <= emergency_budget {
            result.push(msg.clone());
            used += t;
        }
    }

    result.sort_by_key(|m| messages.iter().position(|o| o.id == m.id));

    // Tool Call 配对保护
    enforce_tool_pairs(&mut result, messages);

    result
}
```

## 5. Prompt Cache 保护

Anthropic Prompt Cache 要求 System Prompt 前缀稳定。压缩操作**不修改** Slot 1-4 的 System Prompt 内容（SOUL.md、工作区 Prompt、记忆快照等在会话启动时冻结，中途不变），只操作 messages 数组。

```rust
// 压缩时的不变性保证：
// 1. System Prompt（messages 中 role=system 且 is_cached=true 的消息）永不压缩
// 2. 摘要消息插入历史开头，不插入 System Prompt 之前
// 3. 工具 Schema 注入消息（role=system, is_tool_def=true）永不压缩

pub fn is_protected(msg: &Message) -> bool {
    // 现有保护
    msg.is_cached           // Anthropic Cache 标记
    || msg.is_tool_def      // 工具定义
    || msg.is_soul          // SOUL.md 快照
    || msg.is_pinned
    || msg.slot == ContextSlot::Pinned
    // 新增：round_loop 注入的控制消息
    || (msg.role == Role::System && msg.content.iter().any(|c| {
        if let ContentPart::Text { text } = c {
            text.contains("用户拒绝了此操作")
            || text.contains("连续 3 次调用了相同的工具")
            || text.contains("即将达到工具调用上限")
            || text.contains("submit_plan")
        } else { false }
    }))
}

// round_loop 动态注入的拒绝反馈、循环检测和软着陆消息必须在当前 session 内保留，
// 防止压缩后 LLM 重新尝试被拒绝的操作或陷入死循环。

pub async fn build_context_for_round(
    messages: &[Message],
    ctx: &SessionContext,
    budget: &TokenBudget,
) -> Vec<Message> {
    // 1. 受保护消息（永远在最前）
    let protected: Vec<_> = messages.iter().filter(|m| is_protected(m)).cloned().collect();

    // 2. 可压缩消息（历史对话）
    let compressible: Vec<_> = messages.iter().filter(|m| !is_protected(m)).cloned().collect();

    // 3. 按压缩级别处理
    let compressed = match ctx.compression_level(estimate_total_tokens(messages)) {
        CompressionLevel::None      => compressible,
        CompressionLevel::Light     => compress_light(&compressible, budget).await,
        CompressionLevel::Summary   => {
            let (c, _) = compress_summary(&compressible, budget, &ctx.llm).await
                .unwrap_or_else(|_| {
                    tracing::warn!("Summary LLM 调用失败，降级到 Emergency 压缩");
                    // 降级到 Emergency，而非返回原始消息（原始消息可能触发 ContextTooLong）
                    let emergency = compress_emergency(&compressible, budget).await;
                    (emergency, String::new())
                });
            c
        }
        CompressionLevel::Emergency => compress_emergency(&compressible, budget).await,
    };

    // 4. 拼合：受保护 + 压缩后历史
    let mut result = protected;
    result.extend(compressed);
    result
}
```

## 6. 大型工具结果处理

工具调用结果（如文件读取、搜索结果）可能很大，专项处理：

```rust
pub fn truncate_tool_result(result: &mut ToolResult, max_tokens: usize) {
    let tokens = estimate_tokens_str(&result.content);
    if tokens <= max_tokens { return; }

    // 策略：保留头部 + 尾部，中间替换为占位符
    let head_chars = max_tokens * 3 / 4 * 4;  // 约 75% token → 字符数
    let tail_chars = max_tokens * 1 / 4 * 4;  // 约 25%

    let content = &result.content;
    if content.len() > head_chars + tail_chars {
        let truncated = format!(
            "{}\n\n[... 内容已截断，原始长度 {} tokens，省略约 {} tokens ...]\n\n{}",
            &content[..head_chars],
            tokens,
            tokens - max_tokens,
            &content[content.len() - tail_chars..],
        );
        result.content = truncated;
        result.was_truncated = true;
    }
}

// 工具结果 token 上限（按工具类型）
const TOOL_RESULT_LIMITS: &[(&str, usize)] = &[
    ("file_read",      8_000),   // 文件读取：最多 8k tokens
    ("shell_exec",      4_000),   // 命令输出：最多 4k tokens
    ("web_search",     3_000),   // 搜索结果：最多 3k tokens
    ("knowledge_search", 5_000), // 知识库：最多 5k tokens
    ("_default",       2_000),   // 其他工具：默认 2k
];
```

## 9. 压缩质量保证

| 保证项 | 实现方式 |
|--------|---------|
| 最近消息完整保留 | Light 压缩强制保留最近 10 条；Summary 强制保留最近 20 条 |
| 用户当前问题不丢 | Emergency 压缩优先保留最后一条 user 消息 |
| 工具调用配对 | 有 tool_call 的 assistant 消息与其 tool_result 成对保留，不拆分 |
| 摘要幂等 | 摘要消息有固定格式头 `## 历史对话摘要`，不重复压缩已有摘要 |
| Cache 前缀稳定 | System Prompt 冻结，压缩只操作 messages 数组 |

---

## 10. 设计约束

- **压缩在发送前执行，不修改数据库**：`compress_*` 函数只处理内存中的消息列表，不写回 `messages` 表（数据库保存完整历史）
- **摘要使用 haiku 模型**：Summary 压缩使用 `claude-haiku-4-5` 而非主力模型，压缩本身的费用低于 $0.001/次
- **工具调用结果在压缩前先截断**：大型工具结果（超过上限）在加入 messages 列表时就截断，不等到压缩时
- **不跨对话压缩**：压缩算法只作用于当前对话的 messages，不合并多个对话的历史
- **Provider 上下文窗口差异**：`ToolCompressionManager` 从 Provider `Registry` 读取当前模型的实际窗口大小，不硬编码
