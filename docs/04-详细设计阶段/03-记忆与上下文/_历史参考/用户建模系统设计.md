# 用户建模系统设计

> **合并说明**：本文档中的 `user_memories` 独立表方案已被 `04-记忆系统详细设计.md` 的 L5 用户建模层（基于 `memory_entries` 表 + `USER.md`）取代。本文档保留作为设计历史参考，实现时以 `04-记忆系统详细设计.md` 为准。具体统一方案详见 `05-质量审查阶段/02-术语统一规范.md`。

> 版本：v1.0 | 日期：2026-08-07 | 状态：草稿
> 对应需求：F-11 Agent 人格与记忆、F-32 用户个性化、US-091 记忆管理界面

用户建模系统负责在会话之间积累"关于用户的事实"——技术背景、工作偏好、项目上下文——并在适当时机注入 System Prompt，使 Agent 的回答随时间推移变得更贴合用户。本文档描述记忆的提取、存储、冲突检测、注入与隐私控制全链路。

---

## 1. 两级记忆架构

```text
┌──────────────────────────────────────────────────────┐
│ 全局记忆（跨工作区）                                  │
│  · 用户身份：姓名/职业/母语                           │
│  · 长期偏好：回复语言/代码风格/回复详略               │
└────────────────────┬─────────────────────────────────┘
                     │ 叠加（不覆盖）
┌────────────────────▼─────────────────────────────────┐
│ 工作区记忆（隔离，属于当前工作区）                    │
│  · 项目背景：技术栈/团队规范/代码库结构               │
│  · 当前任务上下文：重构目标/已知 Bug/待办             │
│  · 工作区专属偏好：测试框架/部署方式/命名习惯         │
└──────────────────────────────────────────────────────┘
                     │ Slot 4 注入（见 03-Persona与SystemPrompt注入设计）
                     ▼
           System Prompt（每轮对话）
```

两级记忆各自存储在 `user_memories` 表中，通过 `workspace_id IS NULL`（全局）或 `workspace_id = '...'`（工作区级）区分。

## 2. 数据结构

### 2.1 user_memories 表

```sql
CREATE TABLE user_memories (
    id              TEXT PRIMARY KEY,
    workspace_id    TEXT,               -- NULL = 全局记忆
    category        TEXT NOT NULL,      -- 分类（见下表）
    content         TEXT NOT NULL,      -- 记忆正文（自然语言）
    source          TEXT NOT NULL,      -- 来源：'extracted' | 'manual' | 'imported'
    source_conv_id  TEXT,               -- 提取自哪条对话（可为 NULL）
    confidence      REAL NOT NULL DEFAULT 1.0,  -- 0.0-1.0，自动提取时可能 <1.0
    embedding       BLOB,               -- sqlite-vec 向量（用于相关性检索）
    token_count     INTEGER NOT NULL DEFAULT 0,
    is_active       INTEGER NOT NULL DEFAULT 1, -- 0 = 用户手动禁用
    created_at      INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000),
    updated_at      INTEGER NOT NULL DEFAULT (unixepoch('now','subsec')*1000),
    FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE CASCADE
);

CREATE INDEX idx_user_memories_ws ON user_memories(workspace_id, category, is_active);
CREATE INDEX idx_user_memories_global ON user_memories(category, is_active)
    WHERE workspace_id IS NULL;
```

## 3. 记忆提取管线

对话结束（用户关闭对话或触发对话总结）时，异步启动记忆提取任务：

```text
对话结束触发
    │
    ▼
MemoryExtractor::extract_from_conversation()
    │  输入：最近 N 条消息（不超过 4000 tokens）
    │  提取 Prompt → LLM（小模型，如 claude-haiku-4-5）
    │
    ▼
LLM 返回 ExtractedFacts[]（JSON）
    │
    ▼
FactMerger::merge()
    │  1. 对现有记忆做相似度检索（sqlite-vec）
    │  2. 冲突检测：如发现矛盾，标记旧记忆 confidence 降低或替换
    │  3. 重复过滤：相似度 > 0.92 的跳过
    │
    ▼
写入 user_memories 表
    │
    ▼
重建 System Prompt 记忆摘要快照（为下一会话准备）
```

### 3.1 提取 Prompt 模板

```text
你是一个记忆提取助手。阅读以下对话片段，提取所有关于"用户自身"的新事实。
只提取用户明确陈述或强烈暗示的信息；不要推测。
输出严格的 JSON 数组，每项包含：
  - category: identity | tech_stack | style_pref | project_ctx | team_norm | personal | goal | correction
  - content: 一句话事实（简洁，<80字）
  - confidence: 0.7-1.0

对话：
{{messages}}

如果没有新事实，返回空数组 []。
```

### 3.2 Rust 实现

```rust
// crates/agent-runtime/src/memory/extractor.rs

pub struct MemoryExtractor {
    pool: SqlitePool,
    text_client: Arc<dyn TextClient>,  // 使用小模型降低成本
    embedding_model: Arc<dyn EmbeddingClient>,
}

impl MemoryExtractor {
    pub async fn extract_from_conversation(
        &self,
        conversation_id: &str,
        workspace_id: Option<&str>,
    ) -> anyhow::Result<Vec<ExtractedFact>> {
        // 取最近 20 条消息（限 4000 tokens）
        let messages = self.fetch_recent_messages(conversation_id, 20).await?;
        if messages.is_empty() { return Ok(vec![]); }

        let prompt = build_extract_prompt(&messages);
        let response = self.text_client.complete(CompletionRequest {
            model: "claude-haiku-4-5-20251001".into(),
            messages: vec![Message::user(prompt)],
            max_tokens: 1000,
            ..Default::default()
        }).await?;

        let facts: Vec<ExtractedFact> = serde_json::from_str(&response.content)
            .unwrap_or_default();

        // 合并到数据库（冲突检测）
        self.merge_facts(facts, workspace_id).await
    }

    async fn merge_facts(
        &self,
        facts: Vec<ExtractedFact>,
        workspace_id: Option<&str>,
    ) -> anyhow::Result<Vec<ExtractedFact>> {
        let mut saved = Vec::new();

        for fact in facts {
            // 1. 生成嵌入向量
            let embedding = self.embedding_model.embed(&fact.content).await?;

            // 2. 相似度检索现有记忆（阈值 0.92）
            let similar = self.find_similar(&embedding, workspace_id, 0.92).await?;

            if similar.is_empty() {
                // 全新事实：直接写入
                self.insert_memory(&fact, &embedding, workspace_id).await?;
                saved.push(fact);
            } else {
                // 检测冲突：同类别相似记忆，置信度高的胜出
                let top = &similar[0];
                if fact.confidence > top.confidence {
                    // 新事实更可信：更新旧记忆
                    self.update_memory(top.id, &fact).await?;
                    saved.push(fact);
                }
                // 否则：新事实被已有记忆覆盖，跳过
            }
        }
        Ok(saved)
    }
}

#[derive(Debug, Serialize, Deserialize)]
pub struct ExtractedFact {
    pub category: MemoryCategory,
    pub content: String,
    pub confidence: f32,
}
```

## 4. System Prompt 注入（Slot 4）

记忆在 `SessionContext::init()` 时生成摘要快照，注入 System Prompt 的 Slot 4（详见 [03-Persona与SystemPrompt注入设计.md](../03-Persona与SystemPrompt注入设计.md)）：

```rust
// crates/agent-runtime/src/memory/snapshot.rs

pub async fn build_memory_snapshot(
    pool: &SqlitePool,
    workspace_id: &str,
    budget_tokens: usize,  // Slot 4 最大 token 数（默认 1200）
) -> anyhow::Result<String> {
    // 全局记忆 + 工作区记忆，按 updated_at 倒序
    let memories = sqlx::query_as!(
        UserMemory,
        "SELECT * FROM user_memories
         WHERE is_active = 1
           AND (workspace_id = ? OR workspace_id IS NULL)
         ORDER BY workspace_id DESC, -- 工作区记忆优先
                  updated_at DESC",
        workspace_id,
    )
    .fetch_all(pool)
    .await?;

    // 按 category 分组格式化，超出 token 预算则截断低优先级记忆
    let snapshot = format_memory_snapshot(memories, budget_tokens);
    Ok(snapshot)
}

fn format_memory_snapshot(memories: Vec<UserMemory>, budget: usize) -> String {
    let mut sections: IndexMap<&str, Vec<&str>> = IndexMap::new();
    // 优先级顺序决定截断时保留哪些
    let priority = ["correction", "style_pref", "tech_stack", "project_ctx",
                    "team_norm", "goal", "identity", "personal"];

    for cat in &priority {
        let items: Vec<_> = memories.iter()
            .filter(|m| m.category == *cat)
            .map(|m| m.content.as_str())
            .collect();
        if !items.is_empty() {
            sections.insert(cat, items);
        }
    }

    // 拼装并在 budget_tokens 处截断
    let mut result = String::from("## 关于你的记忆\n");
    for (cat, items) in &sections {
        result.push_str(&format!("**{}**：{}\n", category_label(cat), items.join("；")));
        if estimate_tokens(&result) >= budget { break; }
    }
    result
}
```

## 5. 行为统计（UsageStats）

从 `audit_logs` 和 `cost_records` 派生，不单独建表：

```sql
-- 工具使用频率统计视图
CREATE VIEW usage_tool_stats AS
SELECT
    workspace_id,
    json_extract(metadata, '$.tool_name') AS tool_name,
    COUNT(*) AS call_count,
    AVG(json_extract(metadata, '$.duration_ms')) AS avg_duration_ms
FROM audit_logs
WHERE action = 'tool_call'
GROUP BY workspace_id, tool_name;

-- 活跃时段分布（本地时间小时）
CREATE VIEW usage_hour_dist AS
SELECT
    workspace_id,
    (created_at / 3600000 % 24) AS hour_of_day,
    COUNT(*) AS message_count
FROM messages
WHERE role = 'user'
GROUP BY workspace_id, hour_of_day;
```

行为统计用于：
1. **技能推荐**（P2）：常用 `bash_exec` + Python → 推荐"Python 调试"Skill
2. **用量洞察**（设置界面）：工具调用频率、活跃时段热力图
3. **自动记忆提示**：检测到用户连续 5 次纠正同一行为 → 自动写入 `correction` 类记忆

export function MemoryCenter({ workspaceId }: { workspaceId?: string }) {
  const [memories, setMemories] = useState<UserMemory[]>([]);
  const [filter, setFilter] = useState<MemoryCategory | "all">("all");

  useEffect(() => {

  }, [workspaceId]);

    memories.filter(m => filter === "all" || m.category === filter)

  return (
    <div className="memory-center">
      <div className="memory-header">
        <h2>用户记忆</h2>

          <Button variant="ghost" onClick={handleExport}>导出</Button>

        </div>
      </div>

      {/* 分类筛选标签 */}
      <CategoryFilter value={filter} onChange={setFilter} />

      {/* 记忆列表，按分类分组 */}
      {Object.entries(grouped).map(([category, items]) => (
        <MemoryCategorySection key={category} category={category} items={items}
          onToggle={handleToggle} onEdit={handleEdit} onDelete={handleDelete} />
      ))}

      {/* 空状态 */}
      {memories.length === 0 && (
        <EmptyState
          icon="🧠"

        />

    </div>
  );

function MemoryCategorySection({ category, items, onToggle, onEdit, onDelete }) {
  return (
    <section className="memory-category">
      <h3>{categoryLabel(category)}</h3>
      {items.map(memory => (
        <MemoryItem key={memory.id} memory={memory}
          onToggle={() => onToggle(memory.id, !memory.isActive)}
          onEdit={() => onEdit(memory)}
          onDelete={() => onDelete(memory.id)} />
      ))}
    </section>
  );
}

function MemoryItem({ memory, onToggle, onEdit, onDelete }) {
  return (
    <div className={`memory-item ${memory.isActive ? "" : "disabled"}`}>
      <Switch checked={memory.isActive} onCheckedChange={onToggle} />
      <span className="content">{memory.content}</span>
      <span className="meta">
        {memory.source === "extracted" ? "自动提取" : "手动添加"}
        {memory.confidence < 1.0 && ` · 置信度 ${(memory.confidence * 100).toFixed(0)}%`}
      </span>
      <div className="actions">
        <Button size="icon" variant="ghost" onClick={onEdit}>✏️</Button>
        <Button size="icon" variant="ghost" onClick={onDelete}>🗑</Button>
      </div>
    </div>
  );
}

## 8. P2：个性化推荐

基于用户建模数据（记忆 + 行为统计），在以下场景提供推荐：

### 8.1 技能推荐

```text
场景：用户打开 Skills 浏览器
逻辑：
  1. 取 usage_tool_stats：top-5 高频工具
  2. 取 user_memories（tech_stack）：主力语言/框架
  3. 向量检索 skills 表，返回与用户画像最相关的 Skill
  4. 展示"推荐给你"区块（最多 5 条）
```

### 8.2 智能补全提示（对话输入框）

用户输入 `@` 时，除了触发知识库引用，还展示：
- 高频引用的项目文件（来自 `audit_logs` 的 `file_read` 调用统计）
- 常用命令模板（来自 `task_traces` 的高成功率工具序列）

### 8.3 主动记忆提醒

Agent 在回复时检测到与已有记忆冲突（如用户画像说"用 pnpm"，但当前消息说"npm install"）时，主动澄清：

> 我记得你们团队使用 pnpm，这里要用 `pnpm install` 吗？

## 9. 隐私控制

- **本地存储**：所有记忆存储在本机 SQLite，不上传到任何服务器
- **提取透明度**：每条自动提取的记忆都记录 `source_conv_id`，用户可查看"来自哪次对话"
- **用户随时可禁用/删除**：单条禁用（`is_active=0`，保留数据）或永久删除
- **工作区级隔离**：工作区记忆随工作区删除而级联删除（`ON DELETE CASCADE`）
- **导出自己的数据**：`export_user_profile` 命令提供完整 JSON 导出

## 10. 设计约束

- **不强制提取**：用户可在设置中关闭自动记忆提取，`MemoryExtractor` 在 `memory_extraction_enabled=false` 时静默跳过
- **小模型降成本**：记忆提取使用 `claude-haiku-4-5` 而非主力模型，避免因一次对话结束产生不必要的高费用
- **Slot 4 token 硬限**：记忆摘要最多占用 1200 tokens（可在设置中调节），超出部分按优先级截断（`correction` > `style_pref` > 其余）
- **记忆不影响 SOUL.md**：用户记忆从 Slot 4 注入，SOUL.md 从 Slot 1 注入，两者互不覆盖（见 [03-Persona与SystemPrompt注入设计.md](../03-Persona与SystemPrompt注入设计.md)）
- **全局记忆不超过 50 条**：超出时按 `updated_at` 淘汰最旧记忆（per category 最多 10 条），保持 Slot 4 摘要质量
